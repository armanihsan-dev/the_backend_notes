1. What are Response Headers?

Response headers are metadata lines the server sends to the client before the actual content (body).

They tell the client how to interpret the body (video, text, JSON, etc.), connection rules, caching, cookies, etc.

They are plain text key-value pairs.

Format:

Header-Name: Header-Value

2. Syntax of an HTTP Response

When a server sends back a response over TCP, the format is:

<Status Line>
<Header1>: <Value1>
<Header2>: <Value2>
...
(blank line)
<Body>

✅ Important:

  • Headers must end with CRLF (\r\n = Carriage Return + Line Feed).
  • After the last header, there is a blank line (\r\n\r\n).
  • Then the body starts (binary/text content).

3. Common Response Headers

Header Meaning
Content-Type Type of data (text/html, application/json, video/mp4)
Content-Length Exact byte length of body
Content-Disposition inline (show in browser) or attachment; filename=file.txt (download)
Access-Control-Allow-Origin CORS, allows cross-domain requests
Cache-Control Tells browser how to cache response
Connection keep-alive or close
Set-Cookie Send cookies

4. Full Example (Node.js TCP, no http module)

We’ll manually build an HTTP response with headers using net: 

import net from "node:net";
import { createReadStream } from "node:fs";
import { stat } from "node:fs/promises";

const server = net.createServer(async (socket) => {
  console.log("Client connected:", socket.remoteAddress);

  // File to serve
  const filePath = "C:\\Users\\Arman ihsan\\Videos\\Screen Recordings\\demo.mp4";
  const fileStat = await stat(filePath);
  const fileSize = fileStat.size;

  // 🔹 Step 1: Write Status Line
  socket.write("HTTP/1.1 200 OK\r\n");

  // 🔹 Step 2: Write Headers
  socket.write(`Content-Type: video/mp4\r\n`);
  socket.write(`Content-Length: ${fileSize}\r\n`);
  socket.write(`Access-Control-Allow-Origin: *\r\n`);
  socket.write(`Connection: close\r\n`);

  // (Optional) force download
  // socket.write(`Content-Disposition: attachment; filename="video.mp4"\r\n`);

  // 🔹 Step 3: Blank line (end of headers)
  socket.write("\r\n");

  // 🔹 Step 4: Send body (file content)
  const stream = createReadStream(filePath);
  stream.pipe(socket);

  stream.on("end", () => {
    console.log("File sent successfully.");
    socket.end();
  });

  socket.on("error", (err) => {
    console.log("Socket error:", err.message);
  });
});

server.listen(4000, () => {
  console.log("TCP server running on port 4000");
});

5. What Happens Here?

Browser connects → raw TCP socket.

Server writes:

HTTP/1.1 200 OK\r\nContent-Type: video/mp4\r\nContent-Length: 123456\r\nConnection: close\r\n
\r\n

Browser reads headers until blank line.

Browser now knows the body = binary MP4 file → opens video player.

If you change Content-Type: application/octet-stream → browser will download file instead of playing.

6. Key Takeaway

  • Response headers are just plain text instructions before the body.
  • The browser (or any HTTP client) uses them to decide what to do with the body.
  • Without proper headers, browser may default to download, error, or show garbage text.
