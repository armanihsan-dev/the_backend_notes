File Transfer with UDP in Node.js

Transferring files using UDP in Node.js can be tricky because UDP is a **connectionless protocol**, meaning it doesn't guarantee delivery, order, or integrity of packets. This is unlike TCP, which handles these concerns for you. To transfer a file, you need to implement a mechanism to break the file into chunks, send them over UDP, and then reassemble and verify them on the receiving end. Using readable and writable streams simplifies this process.

Sender (Client)

On the sender side, you'll create a readable stream from the file you want to send. You'll then listen for `data` events on this stream, and for each chunk of data, you'll send it as a separate UDP packet to the receiver.

JavaScript

const dgram = require('dgram');
const fs = require('fs');
const path = require('path');
const client = dgram.createSocket('udp4');
const receiverHost = '127.0.0.1'; // The IP address of the receiver
const receiverPort = 41234;     // The port the receiver is listening on
const filePath = 'path/to/your/file.txt'; // Replace with your file path
const fileStream = fs.createReadStream(filePath, { highWaterMark: 1024 }); // Read in 1KB chunks

fileStream.on('data', (chunk) => {
    // Send each chunk as a UDP packet
    client.send(chunk, receiverPort, receiverHost, (err) => {
        if (err) {
            console.error('Error sending data:', err);
            client.close();
        }
    });
});

fileStream.on('end', () => {
    console.log('File transfer complete.');
    // It's good practice to send a small "end of file" signal
    client.send(Buffer.from('EOF'), receiverPort, receiverHost, () => {
        client.close();
    });
});

fileStream.on('error', (err) => {
    console.error('Error reading file:', err);
    client.close();
});

Note: This example is a basic implementation. A robust solution would need to include packet numbering, acknowledgments, and retransmission logic to handle dropped packets. This is a form of implementing a reliable transfer protocol on top of UDP.

Receiver (Server)

On the receiver side, you'll set up a UDP server to listen for incoming packets. When a packet arrives, you'll write its content to a writable stream connected to the destination file.

JavaScript

const dgram = require('dgram');
const fs = require('fs');
const path = require('path');
const server = dgram.createSocket('udp4');
const destinationFile = 'received_file.txt'; // Name of the file to save to
const writeStream = fs.createWriteStream(destinationFile);

server.on('error', (err) => {
    console.error('Server error:', err);
    server.close();
});

server.on('message', (msg, rinfo) => {
    // Check for the "end of file" signal
    if (msg.toString() === 'EOF') {
        console.log('End of file signal received. Transfer complete.');
        writeStream.end();
        server.close();
        return;
    }

    // Write the received chunk to the file
    writeStream.write(msg, (err) => {
        if (err) {
            console.error('Error writing to file:', err);
            writeStream.end();
            server.close();
        }
    });
});

server.on('listening', () => {
    const address = server.address();
    console.log(`UDP server listening on ${address.address}:${address.port}`);
});

server.bind(41234); // The port to listen on

Note: The receiver needs to stay open until all packets are received. The EOF signal is a simple way to indicate the transfer is done. For large files, you'd want to handle multiple EOF signals or a more sophisticated protocol to confirm file completion. This simple method works best in a controlled environment where packet loss is minimal.

Why `writeStream.end();` and `server.close();`?

That code snippet, `writeStream.end(); server.close();`, is crucial for a complete and clean UDP file transfer. Here's a breakdown of why it's included:

1. `writeStream.end()`

This method signals to the writable stream that no more data will be written to it. It's a fundamental part of the Node.js stream API. Calling `end()`:

  • Finalizes the file write: It flushes any buffered data to the disk. Without it, the last chunk of data might not be fully written, resulting in a corrupted or incomplete file.
  • Emits the `finish` event: This is useful for other parts of your program that might need to know when the file has been successfully created and closed.

2. `server.close()`

This method properly shuts down the UDP server. It's essential for several reasons:

  • Releases the port: It unbinds the server from the port it was listening on. This allows other applications to use that port or allows your program to restart and rebind to it without an "address already in use" error.
  • Ends the process gracefully: It ensures that the Node.js process can exit cleanly once all pending operations are finished. If the server is not closed, the program might hang indefinitely, waiting for more data that will never arrive.

In the context of the UDP file transfer example, these two lines work together to signal the end of the operation. Once the receiver detects the EOF (End of File) message, it knows that it has received all the data. It then finalizes the file with `writeStream.end()` and shuts down the listening server with `server.close()`, completing the transfer and cleaning up resources.

Displaying Percentage Progress

To show a percentage of file transfer progress, you need to track the number of bytes sent against the total file size. You can't rely on a simple time delay since the data transfer rate will fluctuate. Instead, you'll update the progress after a specific number of chunks or a specific amount of time has passed since the last update.

Sender (Client) with Progress Bar

On the sender side, you'll get the total file size and keep a running total of the bytes sent. Then, inside the `data` event listener of the readable stream, you'll calculate the percentage and display it. A `setTimeout` or a simple counter can be used to control how often the progress is updated to avoid spamming the console.

JavaScript

const dgram = require('dgram');
const fs = require('fs');
const client = dgram.createSocket('udp4');
const receiverHost = '127.0.0.1';
const receiverPort = 41234;
const filePath = 'path/to/your/file.txt';
// Get the total file size
const stats = fs.statSync(filePath);
const totalBytes = stats.size;
let bytesSent = 0;
let lastPercentage = 0;
const fileStream = fs.createReadStream(filePath, { highWaterMark: 1024 });

fileStream.on('data', (chunk) => {
    // Increment the counter for each chunk sent
    bytesSent += chunk.length;
    const percentage = Math.floor((bytesSent / totalBytes) * 100);
    // Only log the percentage if it's a new integer value
    if (percentage > lastPercentage) {
        process.stdout.write(`Sending: ${percentage}%... `);
        lastPercentage = percentage;
    }
    // Send each chunk as a UDP packet
    client.send(chunk, receiverPort, receiverHost, (err) => {
        if (err) {
            console.error('\nError sending data:', err);
            client.close();
        }
    });
});

fileStream.on('end', () => {
    // When the stream ends, it's 100% complete
    console.log('\nSending: 100% - File transfer complete!');
    // Send the "end of file" signal
    client.send(Buffer.from('EOF'), receiverPort, receiverHost, () => {
        client.close();
    });
});

fileStream.on('error', (err) => {
    console.error('\nError reading file:', err);
    client.close();
});

Receiver (Server) with Progress Bar

The receiver needs to know the total file size to calculate the percentage. This is a significant challenge with UDP. A simple solution is to send the file size as the very first packet. The receiver then uses this information to track its progress.

Sender (Client) Modification

First, the sender must be modified to send the file size before any data chunks.

JavaScript

// ... previous code ...
const stats = fs.statSync(filePath);
const totalBytes = stats.size;
// Send the file size as the first packet
client.send(Buffer.from(totalBytes.toString()), receiverPort, receiverHost, (err) => {
    if (err) {
        console.error('Error sending file size:', err);
        client.close();
        return;
    }
    console.log(`Sending file of size ${totalBytes} bytes...`);
    // Now, start streaming the file data
    const fileStream = fs.createReadStream(filePath, { highWaterMark: 1024 });
    // ... rest of the 'fileStream.on' listeners as before
});
// ... rest of the code ...

Receiver (Server) Modification

The receiver will need a flag to differentiate the initial file size message from the data chunks.

JavaScript

const dgram = require('dgram');
const fs = require('fs');
const server = dgram.createSocket('udp4');
const destinationFile = 'received_file.txt';
const writeStream = fs.createWriteStream(destinationFile);
let totalBytes = 0;
let bytesReceived = 0;
let lastPercentage = 0;
let isFileSizeReceived = false;

server.on('message', (msg, rinfo) => {
    // The first message is the file size
    if (!isFileSizeReceived) {
        totalBytes = parseInt(msg.toString(), 10);
        console.log(`Receiving a file of total size: ${totalBytes} bytes.`);
        isFileSizeReceived = true;
        return; // Wait for the next message which will be data
    }
    // Check for "end of file" signal
    if (msg.toString() === 'EOF') {
        console.log('\nReceiving: 100% - File transfer complete!');
        writeStream.end();
        server.close();
        return;
    }
    // Write the received chunk and update progress
    writeStream.write(msg, (err) => {
        if (err) {
            console.error('Error writing to file:', err);
            writeStream.end();
            server.close();
        }
    });
    bytesReceived += msg.length;
    const percentage = Math.floor((bytesReceived / totalBytes) * 100);
    // Only log the percentage if it's a new integer value
    if (percentage > lastPercentage) {
        process.stdout.write(`\rReceiving: ${percentage}%...`); // '\r' overwrites the current line
        lastPercentage = percentage;
    }
});

server.on('listening', () => {
    const address = server.address();
    console.log(`UDP server listening on ${address.address}:${address.port}`);
});

server.bind(41234);

Key Concepts

  • `fs.statSync()`: This is a synchronous function that gets the status of a file, including its size in bytes. This is essential for calculating the total size of the file to be sent.
  • `bytesSent` and `bytesReceived`: These variables act as counters for the total number of bytes processed so far.
  • Percentage Calculation: The formula `(currentBytes / totalBytes) * 100` gives you the progress. `Math.floor()` rounds it down to a whole number percentage.
  • `process.stdout.write()`: This is used instead of `console.log()` to print the output without a newline character, allowing the progress to be updated on the same line. The `\r` (carriage return) character at the start of the receiving message overwrites the previous output on the line, creating a clean-looking progress bar.
  • Protocol Enhancement: The file size is sent as part of the application-level protocol. This is an example of how you build a more robust system on top of a low-level protocol like UDP. Without this, the receiver has no way of knowing how much data to expect.

Understanding `process.stdout.write(`\rSending: ${currentPercentage}%`);`

This is a core Node.js command used to display a progress bar on the console. It works by using a special character called the **carriage return** (`\r`).

How It Works

  • `process.stdout.write()`: This is a fundamental Node.js function for writing directly to the console's standard output. Unlike `console.log()`, it **does not automatically add a new line** (`\n`) at the end of the text. This is crucial because it allows us to overwrite the text on the same line.
  • `\r` (Carriage Return): This is the magic part. The `\r` character moves the cursor to the very beginning of the current line in the console. It doesn't clear the text, it just repositions the cursor.
  • The Overwriting Process: The first time the line runs (e.g., at 1% progress), it prints "Sending: 1%". The next time it runs (e.g., at 2%), the `\r` character moves the cursor back to the start of the line. Then, it prints the new text, "Sending: 2%". This new text overwrites the old text on the line.

This process gives the **visual illusion of a single-line progress bar** that updates in place, showing the percentage without cluttering the console with a new line for every single update.
