🌐 HTTP Request Methods – Complete Guide

An HTTP request method (or verb) tells the server what action a client wants to perform on a given resource (e.g., a user, product, file). The most common methods are GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS. Each method has its own behavior, idempotency, and safety rules.

🔑 Key Concepts

  • ✅ Resource

    A resource is any piece of data stored on a server (e.g., a user profile, product, or blog post).

    Creating a new resource → Telling the server:

    “Here’s some data, please store it and assign it an identity (like an ID or URL).”

    Example:

    POST /users
    Content-Type: application/json

    { "name": "Arman", "email": "arman@example.com" }

    ➡️ Creates a new user resource with its own ID (e.g., id: 101).

  • ✅ Idempotent

    A method is idempotent if making the same request multiple times results in the same final state on the server.

    Example:

    DELETE /users/101 → first time deletes the user, next times do nothing (final state = deleted).

    PUT /users/101 with the same data → overwrites the same state each time.

    Analogy:

    • Turning a light off = idempotent (no matter how many times you switch off, it stays off).
    • Dropping a coin in a vending machine = not idempotent (each time you insert, it adds more).

  • ✅ Safe

    A method is safe if it does not change server state (read-only).

    Example: GET is safe because it only retrieves data.

    POST is not safe because it creates/changes data.

🚀 HTTP Methods in Detail

1. GET

Definition: Retrieves data from the server.

Idempotent: ✅ Yes

Safe: ✅ Yes

Use cases: Fetching webpages, images, user details, product lists.

Extra: Can be cached & bookmarked, query parameters appear in URL.

Example:

GET /users/1 HTTP/1.1
Host: example.com

2. POST

Definition: Sends data to the server to create a new resource.

Idempotent: ❌ No (each request can create a new record).

Safe: ❌ No

Use cases: User registration, form submission, file upload.

Extra: Data is sent in the request body (not visible in URL).

Example:

POST /users HTTP/1.1
Host: example.com
Content-Type: application/json

{ "name": "Arman", "email": "arman@example.com" }

3. PUT

Definition: Creates or fully replaces a resource at a specific URL.

Idempotent: ✅ Yes (same data repeatedly → same result).

Safe: ❌ No

Use cases: Updating a user profile when you know the resource URL.

Example:

PUT /users/1 HTTP/1.1
Host: example.com
Content-Type: application/json

{ "name": "Arman", "email": "arman@newmail.com" }

4. PATCH

Definition: Partially updates a resource (only some fields).

Idempotent: ❌ No (can be, but not guaranteed).

Safe: ❌ No

Use cases: Updating just an email or password field.

Example:

PATCH /users/1 HTTP/1.1
Host: example.com
Content-Type: application/json

{ "email": "newmail@example.com" }

5. DELETE

Definition: Removes a resource from the server.

Idempotent: ✅ Yes (after deletion, further deletes have no effect).

Safe: ❌ No

Use cases: Deleting a user, post, or file.

Example:

DELETE /users/1 HTTP/1.1
Host: example.com

6. HEAD

Definition: Same as GET, but returns only headers (no body).

Idempotent: ✅ Yes

Safe: ✅ Yes

Use cases: Checking if a file exists, getting metadata like size (Content-Length).

Example:

HEAD /users/1 HTTP/1.1
Host: example.com

7. OPTIONS

Definition: Returns supported communication options for a resource.

Idempotent: ✅ Yes

Safe: ✅ Yes

Use cases: CORS preflight requests, API discovery.

Example:

OPTIONS /users HTTP/1.1
Host: example.com

Response:

HTTP/1.1 200 OK
Allow: GET, POST, PUT, DELETE, OPTIONS

📊 Summary Table

HTTP Method Description Idempotent Safe
GET Retrieves data from the server. ✅ Yes ✅ Yes
POST Creates a new resource. ❌ No ❌ No
PUT Creates or replaces a resource at a URL. ✅ Yes ❌ No
PATCH Partially updates a resource. ❌ No ❌ No
DELETE Removes a resource. ✅ Yes ❌ No
HEAD Same as GET, but only headers. ✅ Yes ✅ Yes
OPTIONS Describes communication options. ✅ Yes ✅ Yes

✨ Key Takeaway:

  • Use GET to read data.
  • Use POST to create new resources.
  • Use PUT to update or replace.
  • Use PATCH for partial updates.
  • Use DELETE to remove.
  • Use HEAD for metadata checks.
  • Use OPTIONS for allowed methods.
