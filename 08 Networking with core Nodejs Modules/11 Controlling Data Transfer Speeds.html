Controlling Data Transfer Speeds in a Node.js TCP Server

Controlling data transfer speeds in a Node.js TCP server using the net module is a really useful concept when you want to implement rate limiting / throttling for file transfers, streaming, or testing network conditions (like simulating slow internet).

Let’s go step by step.

🔹 1. Basics — Normal TCP Transfer in Node.js

Normally, when you write data to a socket, Node.js and the OS handle buffering and send it as fast as possible:

import net from "net"; import { createReadStream } from "fs"; const server = net.createServer((socket) => { console.log("Client connected"); // Sends file at max possible speed const stream = createReadStream("bigfile.mp4"); stream.pipe(socket); }); server.listen(3000, () => { console.log("Server listening on port 3000"); });

⚡ Here, the data flows at the maximum possible speed (limited only by CPU, RAM, and network bandwidth). But sometimes, we want to deliberately slow it down.

🔹 2. Why Control Data Transfer Speeds?

  • To simulate poor network conditions (like slow 3G).
  • To prevent bandwidth hogging by clients.
  • To stream data smoothly (like video streaming).
  • To avoid overwhelming clients with too much data at once.

Techniques to Control Speed

✅ A) Using setTimeout or setInterval (manual chunks)

You can manually send chunks of data with delays:

import net from "net"; import { createReadStream } from "fs"; const CHUNK_SIZE = 1024; // 1 KB per chunk const INTERVAL = 100; // every 100 ms → 10 KB/s speed const server = net.createServer((socket) => { console.log("Client connected"); const stream = createReadStream("bigfile.mp4", { highWaterMark: CHUNK_SIZE }); stream.on("data", (chunk) => { stream.pause(); // stop reading from file socket.write(chunk, () => { // resume after delay setTimeout(() => { stream.resume(); }, INTERVAL); }); }); stream.on("end", () => { console.log("File transfer completed"); socket.end(); }); }); server.listen(3000, () => { console.log("Server running on port 3000"); });

📌 Here:

  • highWaterMark: CHUNK_SIZE controls how much data we read at once.
  • We pause() and resume() the stream to inject delays.
  • Transfer speed ≈ CHUNK_SIZE / INTERVAL.
  • E.g. 1024 bytes / 100 ms = 10 KB/s.

✅ C) Using External Libraries (stream-throttle)

Instead of writing your own Throttle, you can use stream-throttle:

npm install stream-throttle
import net from "net"; import { createReadStream } from "fs"; import { Throttle } from "stream-throttle"; const server = net.createServer((socket) => { console.log("Client connected"); const stream = createReadStream("bigfile.mp4"); const throttle = new Throttle({ rate: 1024 * 100 }); // 100 KB/s stream.pipe(throttle).pipe(socket); }); server.listen(3000, () => { console.log("Server running on port 3000"); });

This is the simplest production-ready approach.

🔹 4. Controlling Speed Dynamically (per client)

You could even assign different speeds to different clients:

const speeds = [10, 50, 100]; // KB/s let clientId = 0; const server = net.createServer((socket) => { const speed = speeds[clientId % speeds.length]; clientId++; console.log(`Client ${clientId} → ${speed} KB/s`); const stream = createReadStream("bigfile.mp4"); const throttle = new Throttle({ rate: speed * 1024 }); stream.pipe(throttle).pipe(socket); });

🔹 5. Real-World Applications

  • Video/Audio Streaming → control buffer size.
  • Download Managers → let users choose bandwidth.
  • Testing apps → simulate slow 3G / 4G speeds.
  • Server fairness → prevent one client from hogging bandwidth.
