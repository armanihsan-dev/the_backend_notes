1. What happens when you don’t call socket.end()

socket.write(
  `HTTP/1.1 200 OK\r\n` +
  `Access-Control-Allow-Origin: *\r\n` +
  `\r\nHiii`
);// no socket.end()

👉 You’ve written headers + body "Hiii", but never told the browser that the response is finished.

In HTTP, either you need to set:

  • Content-Length → so the client knows exactly how many bytes to read, OR
  • use Transfer-Encoding: chunked → so the client knows when chunks stop, OR
  • close the connection (socket.end()) → which signals “response complete”.

If you don’t do any of these, the browser (and fetch()) will wait forever thinking “more data might still come”.

That’s why your await response.text() never resolves — the stream is never ended.

The image shows a client computer waiting for a response from a server. The connection between them is represented by an unfinished pipe, symbolizing that the server never sent a signal to close the connection or specify the content length. This causes the client to wait indefinitely, illustrating why response.body() never resolves.


2. Why do we await twice with fetch()?

const response = await fetch('http://localhost:4000');
const data = await response.text();

There are two levels here:

(a) await fetch(...)

  • This resolves when the headers have been received.
  • At this point, you get a Response object.
  • But the body is still a stream, not yet read.

(b) await response.text() (or .json(), .arrayBuffer(), .blob())

  • This reads the body stream until it’s done.
  • Only after the body is fully consumed will this resolve.

So essentially:

  • First await = wait for headers (server has responded).
  • Second await = wait for body (server has sent all data and ended the stream).

3. Why your code hangs

Because you never socket.end() and you didn’t specify Content-Length, the body never signals “I’m finished”.

So response.text() is waiting forever for the rest of the body.

✅ Fix option 1 (simple: close socket after sending): 

socket.write(
  `HTTP/1.1 200 OK\r\n` +
  `Content-Length: 4\r\n` +
  `Content-Type: text/plain\r\n` +
  `Access-Control-Allow-Origin: *\r\n\r\n` +
  `Hiii`
);
socket.end();

✅ Fix option 2 (chunked transfer):

socket.write(
  `HTTP/1.1 200 OK\r\n` +
  `Transfer-Encoding: chunked\r\n` +
  `Access-Control-Allow-Origin: *\r\n\r\n`
);
socket.write("4\r\nHiii\r\n"); // 4 bytes, then data
socket.write("0\r\n\r\n");     // end of chunks

🔑 Summary:

  • await fetch() = wait for headers.
  • await response.text() = wait for body stream.

If you don’t end the socket (or define content-length / chunked encoding), the body never finishes → promise never resolves.
