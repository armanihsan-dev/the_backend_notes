TCP vs. HTTP: The Fundamentals

1 What is TCP?

TCP is just a pipe of bytes between two computers. It does not know what those bytes mean. If I send hello over TCP, the other side just receives 5 bytes: h e l l o.

👉 No headers, no meaning — just data.

2 What is HTTP?

HTTP is a protocol built on top of TCP. It says: “We’re going to agree that our messages look like this:

  • A first line (status/request line)
  • Some headers (key: value)
  • A blank line
  • Then the body (the actual content)”

Example HTTP response text:

HTTP/1.1 200 OK
Content-Type: text/plain
Content-Length: 5

Hello

This is just text sent over TCP, but it has structure. That structure is what makes it HTTP.

3 Why do we need Headers?

Headers tell the client:

  • What kind of data is coming (Content-Type: text/html, application/json, etc.)
  • How big it is (Content-Length: 348)
  • How to cache it (Cache-Control: no-cache)
  • Who sent it (Server: nginx)

👉 Without headers, the client wouldn’t know how to read the response.

4 See Headers in JavaScript

In browser (client-side JS):

fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then(res => {
    console.log("Status:", res.status);

    // Show all headers
    for (let [key, value] of res.headers.entries()) {
      console.log(key, ":", value);
    }

    return res.json();
  })
  .then(data => console.log("Body:", data));

That shows you the response headers.

5 Simulating with a TCP Server (no http module)

Now let’s “pretend” we are HTTP, by writing raw HTTP text into a TCP socket.

// tcp_server.js

import net from "net";
const server = net.createServer((socket) => {
  socket.on("data", (data) => {
    console.log("Got request:\n" + data.toString());

    const body = "Hello from raw TCP HTTP!";
    const response =
      "HTTP/1.1 200 OK\r\n" +
      "Content-Type: text/plain\r\n" +
      "Content-Length: " + body.length + "\r\n" +
      "\r\n" + // <-- empty line separates headers from body
      body;

    socket.write(response);
  });
});

server.listen(8080, () => {
  console.log("TCP server running at http://localhost:8080");
});

Start it: node tcp_server.js

Open browser → http://localhost:8080

Browser will parse those headers, and you can see them in DevTools → Network → Headers.

Key takeaway:

  • TCP = raw bytes.
  • HTTP = rules on how to structure those bytes (headers + body).
  • We need headers so the client understands the data.
  • In JS, we can see headers with fetch or DevTools.

What is \r\n?

Good question — this is very important for understanding HTTP.

🔹 What is \r\n?

  • \r = Carriage Return (ASCII 13)
  • \n = Line Feed (ASCII 10)

When you put them together \r\n, it means:

👉 “Go to the beginning of the line and go down to the next line.”

So basically: a new line in network protocols (like HTTP, SMTP, etc.).

🔹 Why HTTP uses \r\n instead of just \n?

Because HTTP was designed to follow the old Internet standards (RFC 822, email format), where a line break is always CRLF (carriage return + line feed).

So in HTTP:

  • Each header line ends with \r\n
  • The headers section ends with an empty line (\r\n\r\n)

🔹 Example

This HTTP response:

HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\nContent-Length: 5\r\n
\r\n
Hello

When sent over TCP, actually looks like (invisible chars shown):

HTTP/1.1 200 OK
Content-Type: text/plain
Content-Length: 5
Hello

So:

  • \r\n = end of a line
  • \r\n\r\n = end of headers, start of body
