HTTP Response Status Codes

These codes tell the client (browser, app, etc.) what happened after it sent a request to the server.

Let’s break this down step by step with categories, meanings, examples, and best practices.

🌐 HTTP Response Status Codes – Complete Guide

🔑 What is a Status Code?

When a client sends a request to a server, the server replies with:

  • Status Line → contains a status code (3-digit number)
  • Headers
  • Optional Body

Example:

HTTP/1.1 200 OK
Content-Type: application/json

{ "id": 1, "name": "Arman" }

Here:

  • 200 = Status code
  • OK = Reason phrase

🏷 Categories of Status Codes

Category Range Meaning
1xx 100–199 Informational (request received, continue process)
2xx 200–299 Success (request was successful)
3xx 300–399 Redirection (client must take further action)
4xx 400–499 Client Error (problem with request)
5xx 500–599 Server Error (problem with server)

🔹 1xx – Informational Codes

These are rare but used to indicate request progress.

  • 100 Continue → Server received request headers, client can continue sending body.
  • 101 Switching Protocols → Protocol switch (e.g., upgrading to WebSocket).
  • 102 Processing → WebDAV extension, request received but still processing.

✅ Mostly used in advanced cases like streaming or protocol upgrades.

🔹 2xx – Success Codes

These mean the request was successful.

  • 200 OK → Standard success response. Example: Fetching user data.
  • 201 Created → New resource created (usually after POST). Example: User registered successfully.
  • 202 Accepted → Request accepted but processing is not finished.
  • 204 No Content → Success but no body returned. Example: DELETE operation succeeded.
  • 206 Partial Content → Used for partial downloads (range requests). Example: Streaming video in chunks.

🔹 3xx – Redirection Codes

Client must take additional steps (usually follow another URL).

  • 301 Moved Permanently → Resource moved to a new URL. Example: Old domain redirects to new domain.
  • 302 Found → Temporary redirection.
  • 303 See Other → Redirect after a POST to a different GET resource.
  • 304 Not Modified → Cached version is still valid, no need to re-download.
  • 307 Temporary Redirect → Same as 302 but method must not change (POST stays POST).
  • 308 Permanent Redirect → Same as 301 but method must not change.

🔹 4xx – Client Error Codes

Something is wrong with the request (client’s fault).

  • 400 Bad Request → Malformed syntax. Example: missing required JSON fields.
  • 401 Unauthorized → Authentication required.
  • 403 Forbidden → Authenticated but not allowed.
  • 404 Not Found → Resource doesn’t exist.
  • 405 Method Not Allowed → Request method not supported (e.g., PUT not allowed).
  • 408 Request Timeout → Client took too long.
  • 409 Conflict → Request conflicts with server state. Example: duplicate username.
  • 410 Gone → Resource permanently deleted.
  • 413 Payload Too Large → Request body too big.
  • 429 Too Many Requests → Rate limiting / throttling.

🔹 5xx – Server Error Codes

Server failed to process a valid request.

  • 500 Internal Server Error → Generic error.
  • 501 Not Implemented → Server doesn’t support this method.
  • 502 Bad Gateway → Gateway/proxy received invalid response from upstream server.
  • 503 Service Unavailable → Server overloaded or under maintenance.
  • 504 Gateway Timeout → Upstream server didn’t respond in time.
  • 505 HTTP Version Not Supported → Server doesn’t support client’s HTTP version.

⚡ Why Status Codes Matter

  • Debugging → Helps developers know if the problem is client-side or server-side.
  • Caching → Browsers use 304 Not Modified to save bandwidth.
  • APIs → Clients rely on 201 Created or 204 No Content to know the result.
  • Resilience → Idempotent methods + codes like 500/503 help you retry safely.

✅ Key takeaway:

1xx → Info / Progress

2xx → Success

3xx → Redirection

4xx → Client Errors

5xx → Server Errors

Working with Status Codes in Node.js

In a Node.js HTTP server (using the built-in http module), you can set status codes in the server’s response object.

The property is:

response.statusCode = <number>;

You can also add a status message (optional):

response.statusMessage = "Custom Message";

Finally, send the headers & body:

response.end("Your message here");

🔹 Example: Setting Status Codes in Node.js HTTP Server

import http from "node:http";

const server = http.createServer((req, res) => {
  // 200 OK
  if (req.url === "/") {
    res.statusCode = 200;
    res.setHeader("Content-Type", "text/plain");
    res.end("Welcome to the homepage!");
  }
  // 201 Created
  else if (req.url === "/create" && req.method === "POST") {
    res.statusCode = 201;
    res.setHeader("Content-Type", "application/json");
    res.end(JSON.stringify({ message: "Resource created successfully!" }));
  }
  // 403 Forbidden
  else if (req.url === "/secret") {
    res.statusCode = 403;
    res.end("Access Denied!");
  }
  // 404 Not Found
  else if (req.url === "/notfound") {
    res.statusCode = 404;
    res.end("Resource not found!");
  }
  // 500 Internal Server Error (default catch)
  else {
    res.statusCode = 500;
    res.end("Something went wrong on the server.");
  }
});

server.listen(3000, () => {
  console.log("Server running at http://localhost:3000");
});

🔹 Testing the Server

  • Visit http://localhost:3000/ → 200 OK
  • Send POST http://localhost:3000/create → 201 Created
  • Visit http://localhost:3000/secret → 403 Forbidden
  • Visit http://localhost:3000/notfound → 404 Not Found
  • Any other route → 500 Internal Server Error

🔹 Shorthand: res.writeHead()

You can also set status + headers together:

res.writeHead(404, { "Content-Type": "text/plain" });
res.end("Page not found");

⚡ Key takeaway:

Yes, you can set any status code (1xx – 5xx) manually in Node.js. This is crucial when building APIs or web servers because clients (browsers, apps, etc.) rely on status codes to know what happened.
