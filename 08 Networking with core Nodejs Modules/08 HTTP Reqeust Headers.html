Request Headers

Request Headers are an essential part of an HTTP request. They are key-value pairs that contain metadata about the request itself, the client making the request, and the body of the request. They are sent from the client (e.g., your browser) to the server.

What do they do?

Request headers provide the server with crucial information so it can correctly handle the request and send back an appropriate response. Without them, the server wouldn't know what type of content the client can accept, what language the client prefers, or where the request is coming from.

Common Examples

Here are some of the most common request headers and what they are for:

  • Host: Specifies the domain name of the server (e.g., www.google.com). This is required for HTTP/1.1 and helps the server know which website the client is trying to reach, especially on a shared server.
  • User-Agent: Contains information about the client's software, such as the browser and operating system (e.g., Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/108.0.0.0). This helps the server deliver content that is compatible with the client's device.
  • Accept: Informs the server about the media types the client can process (e.g., text/html, application/json, image/jpeg).
  • Accept-Language: Indicates the human language the client prefers (e.g., en-US, en).
  • Content-Type: Used when sending a request with a body (like a POST request), this header tells the server what kind of data is in the body (e.g., application/json, multipart/form-data).
  • Cookie: Sends cookies that the client has previously received from the server. This is used for session management and personalization.
  • Authorization: Contains authentication credentials for the client to authenticate with the server.
