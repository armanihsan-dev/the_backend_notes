All about UDP-Server in nodejs

A UDP server is a program that listens for and responds to UDP packets from clients, while a UDP client is a program that sends UDP packets to a server. Unlike TCP, UDP is a connectionless protocol, meaning there's no persistent connection established between the client and server.

A UDP request is a UDP packet sent by a client to a server, typically containing a query or data. A UDP response is a UDP packet sent by the server back to the client, containing the requested information or an acknowledgment.

Node.js UDP Module

Node.js provides the built-in dgram module for creating UDP servers and clients. The dgram module provides an API for sending and receiving datagrams (UDP packets).

What is a Datagram in UDP?

A datagram is the basic unit of data sent over a UDP (User Datagram Protocol) connection.

Unlike TCP, UDP is connectionless, so it doesn’t establish or maintain a session between sender and receiver. Instead, it just sends self-contained packets of information called datagrams.

Each datagram is independent — meaning if you send 10 datagrams, they may arrive out of order, get lost, or be duplicated.

Think of a UDP datagram like a sealed envelope that contains both the letter (data) and the addressing information needed to deliver it.

What a Single UDP Datagram Contains

A single UDP datagram consists of two main parts:

  • Header (8 bytes total)

    Source Port (16 bits) → The port of the sending application.

    Destination Port (16 bits) → The port of the receiving application (e.g., UDP server).

    Length (16 bits) → The total length of the UDP header + data in bytes.

    Checksum (16 bits) → Error-checking to verify data integrity (optional in IPv4, mandatory in IPv6).

  • Data (Payload)

    This is the actual application message you want to send (e.g., a text message, command, JSON, binary data, etc).

    Maximum payload size is usually 65,507 bytes (65,535 - 8 byte header - 20 byte IP header).

In a UDP Server context

When a UDP server receives a datagram, it gets:

  • The data payload (the actual message).
  • The sender’s IP address and port number (from the transport layer), which it can use to send a reply.

Creating a UDP Server in Node.js

To create a UDP server in Node.js, you'll use the dgram module. Here's a breakdown of the key steps and syntax:

Require the dgram module:

JavaScript 
const dgram = require('dgram');

Create a socket:

Use dgram.createSocket() to create a new UDP socket. The argument 'udp4' specifies an IPv4 socket.

JavaScript 
const server = dgram.createSocket('udp4');

Handle incoming messages:

The server.on('message', ...) event is triggered whenever the server receives a UDP packet.

  • msg: The incoming message data as a Buffer.
  • rinfo: An object containing the remote address information of the client (address, port, etc.).
JavaScript 
server.on('message', (msg, rinfo) => {
  console.log(`Server received: ${msg} from ${rinfo.address}:${rinfo.port}`);
  // Send a response back to the client
  const response = Buffer.from('Hello from the server!');
  server.send(response, rinfo.port, rinfo.address, (err) => {
    if (err) {
      console.error(err);
    } else {
      console.log('Response sent!');
    }
  });
});

Handle server listening:

The server.on('listening', ...) event is fired when the server is ready to accept incoming datagrams. You can get the server's address and port using server.address().

JavaScript 
server.on('listening', () => {
  const address = server.address();
  console.log(`UDP Server listening on ${address.address}:${address.port}`);
});

Bind the server to a port:

Use server.bind() to start listening for packets on a specific port. This is the final step to make the server active and ready to receive requests.

JavaScript 
const PORT = 41234;
server.bind(PORT);

Example: Complete UDP Server

Here's a complete, commented example combining all the steps.

JavaScript 
// server.js
const dgram = require('dgram');
const server = dgram.createSocket('udp4');
const PORT = 41234;

// Event fired when the server starts listening
server.on('listening', () => {
  const address = server.address();
  console.log(`UDP Server listening on ${address.address}:${address.port}`);
});

// Event fired when a message is received from a client
server.on('message', (msg, rinfo) => {
  console.log(`Server received: ${msg} from ${rinfo.address}:${rinfo.port}`);
  
  // Create a response message to send back
  const response = Buffer.from('ACK: Message received!');
  
  // Send the response back to the client
  // The parameters are: message, offset, length, port, address
  server.send(response, 0, response.length, rinfo.port, rinfo.address, (err) => {
    if (err) {
      console.error('Error sending response:', err);
    } else {
      console.log('Response sent back to client.');
    }
  });
});

// Event fired on error
server.on('error', (err) => {
  console.error(`Server error:\n${err.stack}`);
  server.close();
});

// Bind the server to the specified port
server.bind(PORT);

Example: UDP Client to connect to the Server

To test the server, you'll need a client. Here's a simple Node.js UDP client that sends a message to the server and handles the response.

JavaScript 
// client.js
const dgram = require('dgram');
const client = dgram.createSocket('udp4');
const SERVER_PORT = 41234;
const SERVER_HOST = 'localhost';

// Message to send to the server
const message = Buffer.from('Hello UDP Server!');

// Send the message to the server
client.send(message, SERVER_PORT, SERVER_HOST, (err) => {
  if (err) {
    console.error('Error sending message:', err);
    client.close();
  } else {
    console.log('Message sent to server.');
  }
});

// Event fired when a message is received from the server
client.on('message', (msg, rinfo) => {
  console.log(`Client received: ${msg} from ${rinfo.address}:${rinfo.port}`);
  client.close(); // Close the client after receiving the response
});

// Event fired on error
client.on('error', (err) => {
  console.error(`Client error:\n${err.stack}`);
  client.close();
});

To run this, save the code into two files (server.js and client.js), open two separate terminal windows, and run the server first:

Bash 
node server.js

Then, in the second terminal, run the client:

Bash 
node client.js

You will see the output in both terminals, demonstrating the client-server communication.

Events of `dgram.createSocket('udp4')`

When you create a UDP socket in Node.js using const server = dgram.createSocket('udp4');, the server object is an EventEmitter that emits several events at different stages of its lifecycle. Here are the key events and when they trigger.

`listening`

This event triggers when the UDP socket successfully starts listening for incoming datagrams on a specified port and address. It's emitted after you call server.bind().

Example:

JavaScript 
server.on('listening', () => {
  const address = server.address();
  console.log(`Server is now listening on ${address.address}:${address.port}`);
});

server.bind(41234); // The 'listening' event is emitted after this line executes successfully.

`message`

This is the most common and important event. It triggers whenever the server receives a new UDP datagram (a message) from a client. The callback function receives two arguments: the msg (the message content as a Buffer) and rinfo (remote address information).

Example:

JavaScript 
server.on('message', (msg, rinfo) => {
  console.log(`Received message from ${rinfo.address}:${rinfo.port}`);
  console.log(`Message content: ${msg.toString()}`);
  // This event triggers immediately upon receiving a packet from a client.
});

`error`

This event triggers if any error occurs with the socket. This could be due to issues like a failed bind operation (e.g., the port is already in use) or a network-related problem. When an error event is emitted, the socket won't be automatically closed unless you explicitly call server.close().

Example:

JavaScript 
server.on('error', (err) => {
  console.error(`Socket error: ${err.stack}`);
  server.close(); // It's a good practice to close the socket on error.
});

`close`

This event triggers when the socket is closed and no longer accepting new packets. This happens after you call server.close(). This event indicates that the process of shutting down the socket has been completed.

Example:

JavaScript 
server.on('close', () => {
  console.log('Socket has been closed.');
});

// A close can be triggered manually:
// server.close(); 

// or as a result of a an error or the process terminating.

What is `server.bind()`

server.bind() is a method provided by Node.js's dgram module to bind a UDP socket to a specific address and port, making it ready to listen for incoming data.

How It Works

When you create a UDP socket with dgram.createSocket(), it's just an object in memory and isn't yet connected to the network. The server.bind() method performs the essential step of associating the socket with a network interface (IP address) and a port number on your machine. This makes the socket a listening server, allowing it to receive UDP datagrams sent to that specific IP address and port.

Syntax

The server.bind() method can be used in a few different ways:

  • `server.bind(port)`: Binds the socket to the specified port and an arbitrary available IP address.
JavaScript 
server.bind(41234);
  • `server.bind(port, address)`: Binds the socket to a specific port and a particular address (e.g., '127.0.0.1' for localhost or '0.0.0.0' to listen on all available network interfaces).
JavaScript 
server.bind(41234, '127.0.0.0');
  • `server.bind(options)`: An object containing port, address, and an optional exclusive flag. This is the most flexible way.
JavaScript 
server.bind({
  port: 41234,
  address: '0.0.0.0'
});

Why it's Important

  • Establishing an Endpoint: It creates the "listening post" for your UDP server on the network. Without calling server.bind(), the server cannot receive any data.
  • Triggering the 'listening' Event: After a successful call to server.bind(), the socket emits the 'listening' event. This is the signal that your server is ready to handle requests.
  • Handling Errors: If the bind operation fails (e.g., the specified port is already in use), an 'error' event is emitted. The application must handle this to prevent unexpected crashes.

UDP Server and Client Communication

As shown in the image, the fundamental concept is that the UDP client sends a datagram (a self-contained packet of data) to the UDP server without first establishing a connection. The server, which is listening on a specific port, receives this datagram and can then send a response datagram back to the client's address and port. This is a key difference from TCP, which requires a connection handshake before any data is sent.
