Node.js TCP Server

Using the net module in Node.js, you can build a server that operates at the TCP level, which is the underlying protocol for HTTP. This allows for low-level control of the data stream, including sending files. Here's a breakdown of how to create such a server to transfer files.

⚙️ The net Module

The net module is a core Node.js module that provides an asynchronous network API for creating stream-based TCP or IPC (Inter-Process Communication) servers and clients. A key concept in this module is the socket object, which represents the connection between the client and the server.

The main method for creating a server is net.createServer(), which takes a callback function. This function is executed every time a new client connects and is passed the socket object for that connection. The socket object is a duplex stream, meaning you can both read from it (socket.on('data', ...)) and write to it (socket.write(...)).

📝 Example: File Transfer Server

The following example demonstrates a TCP server that listens for a client connection and then sends a specified file to the client.

server.js

const net = require('net');
const fs = require('fs');
const path = require('path');

const HOST = '127.0.0.1';
const PORT = 6969;
const FILE_TO_SEND = 'myFile.txt'; // Make sure this file exists in the same directory

// Create a new TCP server
const server = net.createServer(socket => {
  console.log('Client connected: ' + socket.remoteAddress + ':' + socket.remotePort);

  // Path to the file to be sent
  const filePath = path.join(__dirname, FILE_TO_SEND);

  // Check if the file exists
  if (!fs.existsSync(filePath)) {
    console.error('File not found: ' + filePath);
    socket.end('Error: File not found.\n');
    return;
  }

  // Create a readable stream for the file
  const fileStream = fs.createReadStream(filePath);
  
  // Pipe the file stream directly to the socket
  fileStream.pipe(socket);
  
  // Log when the file transfer is complete
  fileStream.on('end', () => {
    console.log('File ' + FILE_TO_SEND + ' sent successfully to client.');
    socket.end(); // Close the connection after the file is sent
  });

  // Handle errors during file transfer or connection
  fileStream.on('error', err => {
    console.error('File stream error:', err);
    socket.end('Error: Failed to read file.\n');
  });

  socket.on('end', () => {
    console.log('Client disconnected.');
  });
  
  socket.on('error', err => {
    console.log('Socket error:', err);
  });
});

// Start the server
server.listen(PORT, HOST, () => {
  console.log('Server listening on ' + HOST + ':' + PORT);
});

🧑‍💻 How the Code Works

Require Modules: We start by importing the necessary modules: net for the TCP server, fs (File System) for file operations, and path for handling file paths.

Server Creation: The net.createServer() method creates a new TCP server instance. The callback function (socket) => { ... } is the main event listener for new connections.

Connection Handling: When a client connects, the callback logs the client's address and port.

File Stream: We use fs.createReadStream() to create a readable stream of the file we want to send. Using a stream is more memory-efficient than reading the entire file into memory, especially for large files.

Piping: The fileStream.pipe(socket) method is the core of the file transfer. It efficiently "pipes" or redirects the data from the readable file stream directly to the writable socket stream. This handles the chunks of data being read and written automatically.

Events: The code includes event listeners for the fileStream (end, error) and the socket (end, error) to handle success and failure cases and to log connection status.

Listening: Finally, server.listen() starts the server on the specified host and port, making it ready to accept incoming connections.

This example provides a solid foundation for a TCP server that can transfer files. However, it's important to note that it's a very basic implementation. It doesn't handle HTTP protocol-specific headers (like Content-Type or Content-Length) or client requests for specific files. Building a full-fledged HTTP server from scratch would involve manual parsing of the incoming data stream to understand the HTTP request (e.g., GET /file.html HTTP/1.1) and then formatting the response accordingly.
