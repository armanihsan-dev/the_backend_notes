TCP Server in Nodejs

A **TCP server** is a program that listens for incoming connection requests from clients, while a **TCP client** is a program that initiates a connection to a server. They are fundamental components of a client-server architecture, enabling reliable, ordered, and error-checked communication over a network.

TCP Request and Response

In the context of TCP, the terms "request" and "response" refer to the data exchanged between the client and server. A **TCP request** is a message sent by the client to the server, and a **TCP response** is the message sent back by the server to the client. Unlike HTTP, which has a well-defined request-response structure, TCP is a stream-oriented protocol. This means data is sent as a continuous stream of bytes, and the application layer protocol (like HTTP or FTP) is responsible for defining how a request or a response is structured within that stream.

Creating a TCP Server in Node.js

Node.js has a built-in net module that makes it easy to create TCP servers and clients. Here's how to create a basic TCP server:

  • 1. Server Creation

    First, you'll need to import the net module and create a server instance using net.createServer(). This method takes a callback function that executes whenever a client connects. The callback receives a socket object, which represents the connection to the client.

    JavaScript 
    const net = require('net');
const server = net.createServer((socket) => {
  // This code runs when a client connects
  console.log('Client connected!');
});
  • 2. Listening for Connections

    Once the server is created, you must tell it to listen on a specific port and, optionally, on a specific IP address (e.g., localhost or 0.0.0.0). The server.listen() method does this.

    JavaScript 
    const port = 3000;

server.listen(port, () => {
  console.log(`Server listening on port ${port}`);
});

Handling Communication

The socket object provided in the connection callback is the key to communication. It's an EventEmitter that emits events for various connection states and data transmissions.

  • 1. Data Reception

    To receive data from a client, listen for the 'data' event on the socket. The callback for this event receives the data as a Buffer object.

    JavaScript 
    socket.on('data', (data) => {
  console.log(`Received data from client: ${data.toString()}`);
});

    The toString() method is used to convert the Buffer (a low-level representation of a sequence of bytes) into a readable string.

  • 2. Sending Data

    To send data back to the client, use the socket.write() method. It takes a string or a Buffer as an argument.

    JavaScript 
    socket.write('Hello, client!');
  • 3. Handling Disconnection

    When a client disconnects, the 'end' event is emitted. You can listen for this event to perform cleanup or log the disconnection.

    JavaScript 
    socket.on('end', () => {
  console.log('Client disconnected.');
});
  • 4. Handling Errors

    Errors can occur during the connection. It's good practice to listen for the 'error' event.

    JavaScript 
    socket.on('error', (err) => {
  console.error(`Socket error: ${err.message}`);
});

Full Server Example

Here is a complete, working example of a simple TCP server in Node.js that echoes back any data it receives from a client.

JavaScript 
const net = require('net');
const server = net.createServer((socket) => {
  console.log('Client connected!');

  // Handle incoming data
  socket.on('data', (data) => {
    const receivedData = data.toString();
    console.log(`Received from client: ${receivedData}`);
    
    // Echo back the received data
    socket.write(`Server received: ${receivedData}`);
  });

  // Handle client disconnection
  socket.on('end', () => {
    console.log('Client disconnected.');
  });

  // Handle errors
  socket.on('error', (err) => {
    console.error(`Socket error: ${err.message}`);
  });
});

const port = 3000;
server.listen(port, () => {
  console.log(`TCP server listening on port ${port}`);
});

To run this server, save the code as a file (e.g., server.js) and run node server.js in your terminal. You can then connect to it using a TCP client or a tool like netcat.

  1. Listening: The TCP server starts by creating a Listening Socket that waits for incoming connection requests. This is the server's passive state, where it's ready to accept new clients.
  2. Connection: A TCP Client initiates a connection by sending a Connect() request to the server's listening socket.
  3. Accepting: Upon receiving a connection request, the server's Accept() block creates a brand New Client Socket. This new socket is dedicated solely to communication with that specific client, allowing the listening socket to remain open and ready to accept other incoming connections.
  4. Data Transfer: Once the new socket is established, the client and server can begin Data Transfer. This is a duplex (Read/Write) process where data flows bi-directionally between the client and its dedicated new socket on the server.

Node.js Socket Object

The socket object is a crucial element in Node.js TCP programming. It represents the connection between the server and a client. When a client successfully connects to your server, the net.createServer() callback is executed, and Node.js automatically creates a new socket object specifically for that connection.

Think of the socket as a **duplex stream**—a two-way communication channel. It allows your server to both read data from the client and write data to the client over the same connection.

Most Important Built-in Methods

Basic Communication Methods

  • socket.write(data)

    This is a fundamental method for sending data to the client. The data can be a string or a Buffer.

    JavaScript 
    socket.write('Hello from the server!');
  • socket.end([data])

    This method ends the write half of the connection. You can optionally pass data to be sent before the connection is terminated. The client will still be able to send data until its own connection is closed.

    JavaScript 
    socket.end('Goodbye!');
  • socket.destroy([error])

    This method ensures that no more I/O activity happens on this socket. It is the definitive way to forcefully close the connection immediately, regardless of what's happening.

Event Emitters

The socket object is an EventEmitter, which means you can listen for various events to handle communication and connection states. The most common events are:

  • 'data'

    Emitted when data is received from the client. The data is passed to the callback as a Buffer object.

    JavaScript 
    socket.on('data', (data) => {
  console.log(`Received: ${data.toString()}`);
});
  • 'end'

    Emitted when the client has closed its side of the connection. This signals that no more data will be sent from the client.

    JavaScript 
    socket.on('end', () => {
  console.log('Client disconnected gracefully.');
});
  • 'error'

    Emitted when an error occurs during the connection. This is essential for handling network failures or other issues.

    JavaScript 
    socket.on('error', (err) => {
  console.error(`Socket error: ${err.message}`);
});
  • 'close'

    Emitted when the socket is fully closed. This event is fired after the end or error events, indicating the connection is completely terminated.

    JavaScript 
    socket.on('close', () => {
  console.log('Connection closed.');
});

Other Useful Properties and Methods

  • socket.remoteAddress

    A string representing the IP address of the client.

  • socket.remotePort

    The port number of the client.

  • socket.pause()

    Pauses the reading of data from the socket. This is useful for flow control if your application is overwhelmed.

  • socket.resume()

    Resumes the reading of data from the socket.
