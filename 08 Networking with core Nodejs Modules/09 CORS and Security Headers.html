CORS and Security Headers

Cross-Origin Resource Sharing (CORS) and security headers are crucial for modern web development, particularly in Node.js. CORS headers control how resources are requested from a different domain, while security headers protect against common web vulnerabilities. Since Node.js TCP servers operate at a lower level than HTTP, they don't inherently handle these headers. You must manually add them to your HTTP responses.

CORS Headers

CORS is a security feature that allows or denies cross-origin requests. A cross-origin request occurs when a web page loaded from one origin (domain, protocol, or port) requests a resource from a different origin. Without proper CORS headers, browsers block these requests. The most important CORS header is Access-Control-Allow-Origin.

Access-Control-Allow-Origin

This header specifies which origins are permitted to access the server's resources.

  • Syntax: Access-Control-Allow-Origin: <origin> | *
  • Definition:
    • <origin>: A specific domain, like https://example.com. This is the most secure option.
    • *: A wildcard that allows any domain to access the resources. Use this with caution, as it can be a security risk.

Other CORS Headers

  • Access-Control-Allow-Methods: Specifies which HTTP methods (e.g., GET, POST, PUT, DELETE) are allowed.
  • Access-Control-Allow-Headers: Lists the headers that a client can send in a request.
  • Access-Control-Allow-Credentials: Indicates whether the server allows credentials (like cookies and HTTP authentication) to be sent with the request.

Security Headers

Security headers are HTTP response headers that mitigate various types of attacks. Implementing these headers is a simple but effective way to improve your application's security.

Strict-Transport-Security (HSTS)

This header forces clients to use HTTPS for all future requests to the domain, preventing downgrade attacks.

  • Syntax: Strict-Transport-Security: max-age=<seconds>; includeSubDomains
  • Definition:
    • max-age: The time, in seconds, the browser should remember to use HTTPS.
    • includeSubDomains: An optional directive that applies the rule to all subdomains.

X-Content-Type-Options

This header prevents a browser from "sniffing" the content type of a response, which can lead to attacks where malicious files are executed with an incorrect MIME type.

  • Syntax: X-Content-Type-Options: nosniff
  • Definition: This instructs the browser to use the declared content type and not to guess it.

Content-Security-Policy (CSP)

CSP is an advanced security header that helps prevent Cross-Site Scripting (XSS) and other code injection attacks by specifying which content sources are allowed to be loaded by the browser.

  • Syntax: Content-Security-Policy: <directive> <source>
  • Definition: CSP uses a series of directives to define allowed sources for different resource types. For example:
    • default-src 'self': Only allows resources from the same origin.
    • script-src 'self' https://trusted-cdn.com: Only allows scripts from the current domain and a specified CDN.
    • img-src *: Allows images from any source.

Node.js TCP Server Example

A basic Node.js TCP server using the built-in net module is a low-level implementation. To add headers, you must craft the HTTP response manually. A more common approach is to use the http module, which simplifies header management.

Example Using http module

This is the standard and recommended way to create a web server in Node.js and apply headers. 

// JavaScript

const http = require('http');

const server = http.createServer((req, res) => {
  // Set CORS headers
  res.setHeader('Access-Control-Allow-Origin', 'https://your-frontend-domain.com'); // Be specific
  res.setHeader('Access-Control-Allow-Methods', 'GET, POST, OPTIONS');
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization');

  // Set Security headers
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
  res.setHeader('X-Content-Type-Options', 'nosniff');
  res.setHeader("Content-Security-Policy", "default-src 'self'; script-src 'self'");

  if (req.method === 'OPTIONS') {
    // Handle preflight requests for CORS
    res.writeHead(204); // No content
    res.end();
    return;
  }

  // Your server logic here
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello, World!');
});

const PORT = 3000;
server.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
});

Explanation of the Code

  • http.createServer(...): This function creates a server instance. The callback function is executed for every incoming HTTP request.
  • res.setHeader(name, value): This method is used to set a header on the response object. It is the correct way to add custom headers.
  • CORS Headers: We set Access-Control-Allow-Origin to a specific domain for security. We also define allowed methods and headers.
  • Security Headers: We add Strict-Transport-Security to enforce HTTPS, X-Content-Type-Options to prevent MIME sniffing, and Content-Security-Policy to control resource loading.
  • Preflight OPTIONS Request: When a browser makes a "non-simple" cross-origin request (e.g., using a POST method with a custom header), it first sends an OPTIONS request. The server must respond to this preflight request with the appropriate CORS headers before the actual request is sent.
  • Server Logic: After handling headers, the server can proceed with its main logic, like sending a Hello, World! response.
