Understanding UTF Encodings & `xxd` Commands

UTF (Unicode Transformation Format): Character encodings that specify how Unicode code points (numerical values assigned to characters) are represented as sequences of bytes.

The numbers 8, 16, and 32 refer to the minimum number of bits used per code unit in the encoding. A "code unit" is the basic unit of information for storing characters in that encoding.

Detailed Comparison of UTF Encodings:

UTF-8

  • Code Unit Size: 8 bits (1 byte).
  • Variable-width: Uses 1 to 4 bytes per character.
    • ASCII characters (U+0000 to U+007F): 1 byte (backward compatible with ASCII).
    • Common Latin (diacritics), Cyrillic, Greek: Typically 2 bytes.
    • Most CJK characters: 3 bytes.
    • Supplementary planes (emojis, ancient scripts): 4 bytes.
  • Endianness: Not an issue (byte-oriented).
  • Advantages:
    • Space-efficient for ASCII and Latin-heavy text.
    • Backward compatible with ASCII.
    • Widely adopted for web and OS.
  • Disadvantages:
    • Variable width can complicate string length calculations.
    • Less efficient than UTF-16 for some CJK characters (3 bytes vs. 2 code units/4 bytes).

UTF-16

  • Code Unit Size: 16 bits (2 bytes).
  • Variable-width (mostly):
    • BMP characters (U+0000 to U+FFFF): 1 code unit (2 bytes).
    • Supplementary characters: Two 16-bit code units ("surrogate pair"), totaling 4 bytes.
  • Endianness: Significant (UTF-16BE or UTF-16LE). Often uses a Byte Order Mark (BOM).
  • Advantages:
    • More space-efficient than UTF-8 for languages primarily in BMP but outside ASCII range (e.g., many CJK).
    • Used internally by some OS (e.g., Windows, Java).
  • Disadvantages:
    • Not ASCII compatible.
    • Still variable-width for supplementary characters.
    • Requires endianness consideration.

UTF-32

  • Code Unit Size: 32 bits (4 bytes).
  • Fixed-width: Every Unicode character uses exactly one 32-bit code unit (4 bytes).
  • Endianness: Significant (UTF-32BE or UTF-32LE). Often uses a BOM.
  • Advantages:
    • Simplicity: String length is simply the number of 32-bit units.
    • Direct mapping: Each code unit corresponds directly to a Unicode code point.
  • Disadvantages:
    • Least space-efficient: Uses 4 bytes for *every* character, leading to much larger file sizes.
    • Rarely used for storage/transmission due to inefficiency; mostly for internal representation.

Understanding `xxd` Terminal Commands:

`xxd` is a command-line utility for creating hex dumps, useful for inspecting raw byte content of files.

Assumed content of `example.txt` (UTF-8):
Hello, World! 👋

1. `xxd filename`

  • Default mode: Produces a standard hexadecimal dump.
  • Shows:
    • Offset: Hexadecimal offset from file beginning.
    • Hexadecimal Bytes: Raw bytes in hex (two hex digits per byte).
    • ASCII Representation: Best-effort ASCII interpretation (non-printable chars as `.` ).
  • Example Usage: xxd example.txt
  • Expected Output Snippet: 
    00000000: 4865 6c6c 6f2c 2057 6f72 6c64 2120 f09f  Hello, World! .
00000010: 918b                                      ..
  • Explanation: `48` for 'H', `f09f918b` is the 4-byte UTF-8 for 👋.

2. `xxd -b filename`

  • `-b` option: Displays output in binary format.
  • Shows:
    • Offset: Hexadecimal offset.
    • Binary Bytes: Raw bytes in binary (groups of 8 bits).
    • ASCII Representation: Best-effort ASCII interpretation.
  • Example Usage: xxd -b example.txt
  • Expected Output Snippet: 
    00000000: 01001000 01100101 01101100 01101100 01101111 00101100 00100000 01010111  Hello, W
00000008: 01101111 01110010 01101100 01100100 00100001 00100000 11110000 10011111  orld!  ..
00000010: 10010001 10001011                                                        ..
  • Explanation: Shows exact bit patterns. `01001000` is 'H'. Emoji bytes (`f09f918b`) appear as `11110000`, `10011111`, etc., revealing UTF-8 multi-byte pattern.

3. `xxd -g 1 filename`

  • `-g 1` option: Groups hexadecimal output by 1 byte (each byte displayed individually).
  • Shows:
    • Offset: Hexadecimal offset.
    • Hexadecimal Bytes (grouped by 1): Each byte as a separate two-digit hex value.
    • ASCII Representation: Best-effort ASCII interpretation.
  • Example Usage: xxd -g 1 example.txt
  • Expected Output Snippet: 
    00000000: 48 65 6c 6c 6f 2c 20 57 6f 72 6c 64 21 20 f0 9f  Hello, World! ..
00000010: 91 8b                                            ..
  • Explanation: Clearer visual separation of individual bytes, helpful for parsing multi-byte encodings.

`xxd` commands are indispensable for low-level file analysis and understanding character encodings by directly inspecting raw byte data.
