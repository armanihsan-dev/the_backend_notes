SameSite Cookies Attribute with Cross-Site Fetch Requests🍪

The SameSite cookie attribute is a crucial security feature that controls whether a browser should send cookies along with cross-site requests. It is a primary defense against Cross-Site Request Forgery (CSRF) attacks.

2 It is a primary defense against Cross-Site Request Forgery (CSRF) attacks.

🔥 1. What does browser consider SAME-SITE?

A “site” = scheme + registrable domain

⚠️ PORT IS IGNORED completely.

So "site" =

  • http://localhost
  • http://127.0.0.1
  • https://example.com
  • https://www.example.com

❌ Port is NOT included

Means:

  • http://localhost:80
  • http://localhost:3000
  • http://localhost:5500

All belong to the same site → http://localhost.

🔥 2. SAME-SITE vs CROSS-SITE (VERY IMPORTANT)

✔ SAME-SITE means:

scheme + registrable domain are same

(even if port is different)

❌ CROSS-SITE means:

Either scheme OR domain is different.

✔ Example A:

Frontend → http://localhost:5500
Backend → http://localhost:80

🟢 Same site

Because both share:

scheme = http   domain = localhost

So SameSite=Lax cookie WILL BE SET (not blocked)

❌ Example B:

Frontend → http://127.0.0.1:5500
Backend → http://localhost:80

🔴 NOT same-site

Because:

localhost != 127.0.0.1

Different domains → cross-site

So a SameSite=Lax cookie will NOT be set in a cross-site fetch POST request.

✔ Example C:

Frontend → http://localhost:5500
Backend → https://localhost:443

❌ Different scheme

http vs https

So → cross-site

Thus → Lax cookie will NOT be set

🍪 SameSite Attribute Definition and Values

The SameSite attribute is set on the server when a cookie is created, and it instructs the browser on how to handle that cookie in requests originating from a different site.

🔑 Key SameSite Values

The attribute can take one of three values:

Value Behavior in Cross-Site Requests Security Level Use Case
Strict Never sent with cross-site requests. The cookie is only sent when the request originates from the same site as the cookie's domain. Highest Essential session cookies that should never be used in a cross-site context.
Lax (Default) Only sent with cross-site requests that are top-level navigations using "safe" HTTP methods (like GET). It prevents cookies from being sent in fetch(), XMLHttpRequest, iframes, or non-GET form submissions from a different site. Medium General-purpose cookies. This is the default behavior in modern browsers if no SameSite attribute is specified.
None The cookie is sent with all cross-site requests. Requires the Secure attribute to be set, meaning the cookie will only be sent over HTTPS. Lowest Necessary for third-party contexts, such as embedded content (<iframe>), third-party analytics, or cross-site API calls.

🌐 Cross-Site Fetch Requests and Cookie Behavior

A cross-site fetch request occurs when the browser initiates an HTTP request (e.g., using the fetch() API or XMLHttpRequest) from one origin (the front-end/client) to a different origin (the server/API).3

  • Origin is defined by the combination of scheme, domain, and port (e.g., https://client.com:443).
  • Site is a more relaxed concept, typically defined as the registrable domain plus the scheme (e.g., https://client.com includes app.client.com).

The default behavior for a cross-site fetch() request is to not send any cookies associated with the target domain. However, to explicitly include cookies with a cross-site request (which is required for third-party cookies to work), the client-side fetch() call must include the credentials: 'include' option.

SameSite Behavior with fetch()

Even with credentials: 'include', the browser's decision to send the cookie is still governed by the SameSite attribute:

  • SameSite=Strict: The cookie is never sent in a cross-site fetch() request.
  • SameSite=Lax: The cookie is never sent in a cross-site fetch() request (since fetch() is not a top-level navigation).
  • SameSite=None; Secure: The cookie will be sent in a cross-site fetch() request, provided:
    1. The client-side fetch() includes credentials: 'include'.
    2. The request is made over HTTPS.
    3. The server's response includes the necessary CORS headers (especially Access-Control-Allow-Credentials: true).4

💾 When Will a Cookie Save and Sit?

A cookie is saved (or "sits") on the client's browser only after a successful HTTP response that contains the Set-Cookie header has been received and processed.

Two Critical Requirements for Saving a Cookie

  1. Server Response: The server must send a Set-Cookie header in the HTTP response. 
    Set-Cookie: session_id=abc12345; HttpOnly; SameSite=Lax; Secure
  2. Browser Policy Check: The browser must accept the cookie based on its policies.
    • Same-Origin Policy (CORS): If the response is from a cross-origin request (e.g., a cross-site fetch()):
      • The request must include credentials: 'include' on the client side.
      • The server response must include the Access-Control-Allow-Credentials: true CORS header, and the Access-Control-Allow-Origin header must not be the wildcard (*).
    • SameSite/Secure Policy: If the cookie has SameSite=None, it must also have Secure. If the cookie is being set over plain HTTP but has the Secure attribute, the browser will reject it.

🛠️ Practical Example with Express.js

Here's an example using Express.js to set a cookie with different SameSite attributes.

Express.js Backend Example (server.js)

This server runs on https://api.example.com (using a local server/proxy for HTTPS). 

const express = require('express');
const app = express();
const cors = require('cors');
const PORT = 3000;

// Configure CORS for cross-site requests that include credentials
app.use(cors({
    origin: 'https://client.example.com', // The domain of your frontend application
    credentials: true, // IMPORTANT: Allows cookies/auth headers to be sent
}));

// Route to set a SameSite=Lax cookie (Default)
app.get('/set-lax-cookie', (req, res) => {
    // Cookie is set with SameSite=Lax (or no attribute, as it's the default)
    res.cookie('lax_session', 'my_lax_data', {
        httpOnly: true,
        secure: true, // Best practice for production
        sameSite: 'Lax',
        maxAge: 3600000 // 1 hour
    });
    res.send('Lax cookie set');
});

// Route to set a SameSite=None cookie (Required for cross-site fetch)
app.get('/set-none-cookie', (req, res) => {
    // Cookie is set with SameSite=None; MUST include Secure: true
    res.cookie('cross_site_token', 'my_none_data', {
        httpOnly: true,
        secure: true, // REQUIRED for SameSite=None
        sameSite: 'None', // Allows the cookie to be sent cross-site
        maxAge: 3600000 // 1 hour
    });
    res.send('None cookie set (Requires HTTPS on server and client)');
});

app.listen(PORT, () => {
    console.log(`Server listening at https://api.example.com:${PORT}`);
});

Client-Side fetch() Example

This front-end code runs on a different domain, https://client.example.com. 

// This is a cross-site request from client.example.com to api.example.com
const API_URL = 'https://api.example.com:3000/set-none-cookie';

async function setAndFetchCookie() {
    try {
        // 1. Set the cookie: The request to set the cookie must also include
        //    'credentials: "include"' for the browser to process the Set-Cookie header
        //    if the request is cross-site.
        let response = await fetch(API_URL, {
            method: 'GET',
            credentials: 'include' // Allows the browser to send cookies AND process Set-Cookie
        });

        if (response.ok) {
            console.log('Cookie setting request successful.');
            // Cookie (SameSite=None; Secure) is now saved on the client.

            // 2. Fetch data, including the previously set cookie.
            // This subsequent cross-site fetch request WILL include the cookie
            // because it was set with SameSite=None; Secure and the request
            // includes credentials.
            let dataResponse = await fetch('https://api.example.com:3000/data', {
                credentials: 'include'
            });

            console.log('Data fetch status:', dataResponse.status);
        }
    } catch (error) {
        console.error('Error:', error);
    }
}

// NOTE: If you tried to fetch a cookie set with SameSite=Lax here, 
// the browser would NOT include it in the cross-site fetch request, 
// even with credentials: 'include'.

setAndFetchCookie();
