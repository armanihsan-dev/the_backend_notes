🛡️ Content Security Policy (CSP) Reporting Fundamentals

CSP violation reporting is the mechanism browsers use to notify a server when an attempted action (e.g., loading an external script) breaks the security rules defined by the CSP. **OR** A Content Security Policy is just a set of rules you send in **HTTP headers**.

These rules tell the browser:

“Only load scripts/images/styles from these trustworthy places. If anything else tries to run → **BLOCK it**.” It protects against **XSS**, **clickjacking**, malicious scripts, etc.

2. What Is a "CSP Violation"?

A **“violation”** happens when:

  • A script loads from a domain not allowed
  • Inline JS tries to run (if not allowed)
  • An image loads from blocked domain
  • A style loads from blocked domain

Example:

Policy is: script-src 'self';

Then someone tries:

<script src="https://evil.com/hack.js"></script>

➡️ Browser blocks it

➡️ Browser also reports this violation (if you configured reporting)

3. What is report-uri?

Old CSP standard allowed:

report-uri https://yourserver.com/csp-report

Meaning:

“If any violation happens, send a **JSON report** to this URL.”

Browser sends that report **automatically**.

Key Components

Component Definition Syntax Example
Content-Security-Policy (Header) Enforces the policy and reports violations. The browser **blocks** the offending resource. Content-Security-Policy: default-src 'self'; script-src 'self'; report-uri /csp-report;
Content-Security-Policy-Report-Only (Header) Reports the violation but **does not block** the offending resource. Crucial for testing new policies. Content-Security-Policy-Report-Only: default-src 'self'; report-uri /csp-report;
report-uri (Directive) Specifies the full URI where the browser should send the violation report (a **JSON payload**) via an HTTP **POST** request. report-uri https://example.com/reports/csp
CSP Report (Payload) The JSON body sent by the browser containing details about the violation.

JSON (See structure below)

CSP Report JSON Structure

{
  "csp-report": {
    "document-uri": "https://myapp.com/index.html",
    "referrer": "",
    "blocked-uri": "https://unsafe.com/script.js",
    "violated-directive": "script-src",
    "effective-directive": "script-src-elem",
    "original-policy": "default-src 'self'; script-src 'self'; report-uri /csp-report-endpoint;",
    "disposition": "report"
  }
}

💻 Practical Express Setup (server.js)

We will use the built-in express.json() middleware but will configure it to also handle the special application/csp-report content type. 

import express from "express";
import mongoose from "mongoose";

const app = express();

app.use(express.json());

await mongoose.connect(
    "mongodb://admin:admin@localhost/socialApp?authSource=admin"
);

const postSchema = new mongoose.Schema({
    content: String,
    createdAt: { type: Date, default: Date.now },
});

const Post = mongoose.model("Post", postSchema);

app.use((req, res, next) => {
    if (req.headers.accept?.includes('text/html')) {
        res.setHeader(
            'Content-Security-Policy',
            "default-src 'self';\
            script-src 'self'  https://cdn.tailwindcss.com;\
            img-src 'self' https://images.unsplash.com/;\
            style-src 'unsafe-inline';\
            connect-src 'self';\
            report-uri /csp-report;\
            "
        )
    }
    next()
})
app.use(express.static("./public"));


// Routes
app.get("/posts", async (req, res) => {
    const posts = await Post.find().sort({ createdAt: -1 });
    res.setHeader("Set-Cookie", "loginSecret=hdxhw7yrx.k;");
    res.json(posts);
});

// Route to receive violation reports
app.post("/csp-report", express.json({ type: "application/csp-report" }), (req, res) => {
    console.log("📢 CSP VIOLATION REPORT RECEIVED:");
    console.log(JSON.stringify(req.body, null, 2));
    res.status(204).end(); // No response needed
});

app.post("/posts", async (req, res) => {
    const post = new Post({ content: req.body.content });
    await post.save();
    res.status(201).json(post);
});

// Start server
app.listen(4000, () => console.log("Server running on http://localhost:4000"));

🛡️ CSP Header Implementation

The server sets the Content-Security-Policy header in a middleware function: 

app.use((req, res, next) => {
    if (req.headers.accept?.includes('text/html')) {
        res.setHeader(
            'Content-Security-Policy',
            "/* ... other directives ... */\
            report-uri /csp-report;\
            "
        )
    }
    next()
})

The key part for reporting is the report-uri /csp-report; directive.

  • **report-uri Directive:** This directive tells the client's browser where to send a report if a resource loading or execution attempt violates any of the rules defined in the CSP.
  • **Policy Violation:** If a browser tries to load a resource (e.g., an image, a script, or a font) from a source **not listed** in the policy (for example, trying to load a script from evil.com), the browser will **block** the resource.
  • **Report Generation:** When a violation occurs, the browser compiles a **JSON object** detailing the violation (the blocked URL, the violating directive, the document URI, etc.).
  • **Report Transmission:** The browser then sends this JSON report via an HTTP **POST** request to the specified URI, which is /csp-report in this case.

📢 Server-Side Report Handling

The server has a specific route designed to receive and process these reports: 

app.post("/csp-report", express.json({ type: "application/csp-report" }), (req, res) => {
    console.log("📢 CSP VIOLATION REPORT RECEIVED:");
    console.log(JSON.stringify(req.body, null, 2));
    res.status(204).end(); // No response needed
});
  • **Route:** The server sets up a **POST** route at /csp-report, matching the URI specified in the CSP header.
  • **Middleware** (express.json({ type: "application/csp-report" })): This is **crucial**. Browsers send CSP reports with the specific content type of application/csp-report. This custom middleware configuration ensures that the Express server correctly **parses the incoming JSON body** from the report.
  • **Logging:** The route handler simply logs the received violation report (req.body) to the server console. In a production application, this information would typically be saved to a database or a log file for later analysis.
  • **Response:** The server sends a **204 No Content** status code. This is the standard practice for report endpoints, as the server acknowledges receipt of the report but has no content to send back to the browser.

🛠️ Summary of a CSP Violation Event

  1. A client loads an HTML page from the Express server.
  2. The server sends the Content-Security-Policy header, which includes report-uri /csp-report;.
  3. The client's browser parses and enforces the policy.
  4. The client's code attempts to load a **forbidden resource** (e.g., a script from http://malicious.com).
  5. The browser **blocks** the resource.
  6. The browser generates a **JSON report** about the violation.
  7. The browser sends an HTTP **POST** request with the report to http://localhost:4000/csp-report.
  8. The Express server receives the request, parses the JSON body, logs the violation details, and sends back a **204 response**.
