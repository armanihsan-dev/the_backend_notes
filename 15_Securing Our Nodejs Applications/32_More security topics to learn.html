🛡️ Network & Transport Attacks

Man-in-the-Middle (MitM) Attacks

MitM attacks are primarily defeated by your previous work on HTTPS/TLS (17_HTTPS server in nodejs.html).

How it works:

An attacker secretly relays and possibly alters the communication between two parties who believe they are directly communicating.

MERN Defense:

When you serve your MERN API via HTTPS, you enforce encryption in transit. This means even if an attacker sniffs the packet (Packet Sniffing), the content (like session tokens or user data) will be unreadable (encrypted).

🔐 Application-Layer Vulnerabilities

SSRF (Server-Side Request Forgery)

This is a critical vulnerability for backend developers.

The Flaw:

An attacker manipulates your server-side application (Node.js) to make HTTP requests to an arbitrary domain of their choosing.

The Impact:

The attacker can potentially scan your internal network (e.g., accessing an internal database or cloud metadata service like AWS IAM keys) which is normally inaccessible from the public internet.

MERN Defense:

When your Node.js server needs to fetch a URL provided by a user (e.g., fetching a profile picture from an external link), you must rigorously validate the destination IP address. Use a library to ensure the resolved IP is not a private IP (e.g., 10.x.x.x, 172.16.x.x, 192.168.x.x) or a local host IP (127.0.0.1).

ReDoS (Regular Expression Denial of Service)

This relates directly to your previous notes on Dependency Vulnerabilities.

The Flaw:

Using poorly constructed regular expressions that can cause excessive back-tracking when processing specific, malicious input strings (often called "catastrophic backtracking").

The Impact:

A single malicious request can cause the Node.js event loop to block, spiking the CPU to 100% and leading to a Denial of Service (DoS) for all users.

MERN Defense:

  • Use safe regex libraries that automatically prevent catastrophic backtracking.
  • Use static analysis tools (like the Linters and Semgrep you listed) to flag vulnerable regex patterns during development.

Session Fixation

This is a risk when a session is created before a user authenticates.

The Flaw:

An attacker tricks a user into logging in using a session ID that the attacker already knows (and possibly controlled).

The Impact:

Once the user logs in, the known session ID is now authenticated, allowing the attacker to immediately use it to impersonate the user.

MERN Defense:

The standard fix is to always regenerate the session ID after a successful login. When using libraries like express-session in Node.js, ensure you call the relevant function (e.g., session.regenerate()) upon successful authentication.

🧠 Security Architecture & Design

Defense in Depth

This is a foundational concept.

The Principle:

Do not rely on a single security mechanism to protect an asset. Apply multiple, overlapping security controls so that if one fails, others are still in place.

MERN Examples:

  • Protecting an API route with Authentication (JWT check).
  • Adding Authorization (Role check) inside the route handler.
  • Adding Input Validation (Zod) on the request body.
  • Adding Rate Limiting (Express Rate Limit) before the route.
  • Adding a WAF (Cloudflare/AWS) before the entire server.

Replay Attack Protection

This is crucial for securing actions that should only happen once, like transferring funds.

The Flaw:

An attacker captures a valid request (e.g., "transfer $100") and attempts to replay the exact same request to execute the action multiple times.

MERN Defense:

Use a unique, single-use token for sensitive operations, often called a nonce (Number used once) or a unique transaction ID. The server must track and ensure that any given nonce/ID is accepted only a single time.

🔍 Input Constraints & Hardening

Secure File Uploads - Storing Outside Web Root

This is a crucial detail for mitigating web shell attacks.

The Concept:

The "web root" is the directory where the web server (e.g., Nginx, Express static middleware) serves files directly to the public internet.

The Risk:

If an attacker uploads a malicious file that the server executes (like a PHP script, or a poorly configured image that runs JS), and it's placed in the web root, the attacker can execute code by simply browsing to the file's URL.

The Fix:

Store uploaded files in a separate, non-public directory or, ideally, in an object storage service (like AWS S3). The web server should only provide access to these files through a dedicated, authorized endpoint that streams the content, checking permissions first.

🌐 Infrastructural Defenses

Web Application Firewall (WAF)

Function:

A WAF sits in front of your web server (Node.js) and inspects incoming HTTP traffic for common attack patterns before it reaches your application code.

Value for MERN:

WAFs can automatically block high-volume DDoS attempts and filter patterns typical of SQL Injection (which also helps with NoSQL Injection), XSS, and Directory Traversal before they ever hit your code.

Security Testing Tools

  • OWASP ZAP (Zed Attack Proxy): This tool is essential. You can run it manually or integrate it into your CI/CD pipeline (DAST - Dynamic Application Security Testing). It actively attacks your running MERN application and reports the findings.
  • Burp Suite: The industry-standard tool for professional security testing, often used for manual penetration testing.
