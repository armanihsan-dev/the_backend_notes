Zod Validation Notes

Zod is a powerful TypeScript-first schema declaration and validation library that works excellently in both TypeScript and plain JavaScript. It provides a simple, declarative syntax for defining the expected **shape** and **constraints** of data, ensuring data integrity at runtime.

💡 How Zod Works

Zod's core principle is defining a **schema** (a blueprint for your data) and then using that schema to **parse** untrusted input data.

  • Schema Definition: You use Zod's fluent API to define the structure and rules your data must follow. These schemas are built using methods chained onto the main z object (e.g., z.string(), z.object({})).
  • Parsing/Validation: You pass your raw, untrusted data to the schema's .parse() or .safeParse() method.
    • .parse(data): If the data is valid, it returns the validated data. If validation fails, it **throws a ZodError exception**.
    • .safeParse(data): This method is safer for error handling. It never throws. It returns an object with a success boolean. If successful, it contains the validated data; otherwise, it contains the error object.
  • Type Safety (in TypeScript): A major feature is that Zod can **automatically infer** the static TypeScript type from the runtime schema, eliminating the need to define types twice.

📜 Clear Syntax and Basic Examples

To get started, you typically install Zod via npm (npm install zod) and import the main object.

JavaScript
import { z } from "zod";

// --- Basic Primitives ---
const StringSchema = z.string();
const NumberSchema = z.number();
const BooleanSchema = z.boolean();

// --- Validation Examples (using .parse) ---
try {
    // 1. Success: Returns the string
    const validString = StringSchema.parse("hello world"); 
    console.log(validString); // "hello world"

    // 2. Failure: Throws a ZodError
    NumberSchema.parse("not a number"); 
} catch (error) {
    // Will catch the error from the failed parse
    console.error(error.errors);
}

Basic Object Schema and Constraints

You use z.object() to define the structure of an object. You can chain methods to add constraints.

JavaScript
// 📦 Defines an object with a required string (min 3 chars) and a required email
const UserSchema = z.object({
  name: z.string().min(3, { message: "Name must be 3 or more characters." }),
  email: z.string().email({ message: "Invalid email address." }),
  age: z.number().int().positive().optional(), // optional number, must be positive integer
});

// --- Safe Parsing Example (.safeParse) ---
const invalidUser = {
  name: "Jo", // too short
  email: "invalid-email", // not an email
};

const result = UserSchema.safeParse(invalidUser);

if (!result.success) {
  console.log("Validation Failed:");
  // result.error is a ZodError instance
  result.error.issues.forEach(issue => {
    console.log(`- Field: ${issue.path[0]}, Message: ${issue.message}`);
  });
  /* Output:
  - Field: name, Message: Name must be 3 or more characters.
  - Field: email, Message: Invalid email address.
  */
} else {
  // result.data contains the validated, type-safe data
  console.log("Validation Succeeded:", result.data);
}

🚀 Advanced Zod Schemas and Features

1. Complex Types

Schema Type Syntax Description
Array z.array(z.string()) An array of strings.
Literal z.literal("admin") Must be the exact value "admin".
Union z.string().or(z.number()) Can be a string **OR** a number.
Enum z.enum(["red", "green", "blue"]) Must be one of the specified strings.
Nullable/Optional z.string().nullable() Can be a string or null.
z.string().optional() Can be a string or undefined (or omitted).
Combined z.string().optional().nullable() Can be string, undefined, or null.

2. Custom Validation with .refine()

The .refine() method is used to add custom, schema-wide or field-specific validation logic that cannot be covered by built-in methods.

JavaScript
// Validates that password and confirm_password fields match
const SignupSchema = z.object({
  password: z.string().min(8),
  confirmPassword: z.string().min(8),
}).refine((data) => data.password === data.confirmPassword, {
  message: "Passwords don't match",
  path: ["confirmPassword"], // Point the error to the confirmPassword field
});

SignupSchema.safeParse({ password: "123", confirmPassword: "456" });
// => { success: false, error: ... } with "Passwords don't match" on confirmPassword

3. Data Transformation with .transform()

The .transform() method allows you to convert the data's type or value after it has been successfully validated.

JavaScript
// Accepts a string, validates it's a number, and transforms it to an actual Date object
const DateSchema = z.string().datetime().transform((str) => new Date(str));

const result = DateSchema.safeParse("2025-11-30T10:00:00.000Z");

if (result.success) {
  console.log(result.data); // Output: A Date object
  console.log(typeof result.data); // "object"
}
