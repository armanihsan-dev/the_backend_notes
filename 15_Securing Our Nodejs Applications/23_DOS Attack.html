🚨 Denial-of-Service (DoS) Attack Deep Dive 💥

A Denial-of-Service (DoS) attack is a cyberattack aimed at making a machine or network resource unavailable to its legitimate users. This is typically achieved by overwhelming the target system with a flood of traffic or resource requests, causing it to slow down or crash.

🛠️ Purpose of a DoS Attack

The primary goal of a DoS attack is to cause disruption and unavailability of services. The motivations behind this disruption can vary:

  • Extortion: Attackers may demand a ransom (known as RDoS or Ransom DoS) to stop the attack.
  • Vandalism/Activism (Hacktivism): Disrupting the operations of a target organization (like a government agency or corporation) to protest or make a statement.
  • Malicious Competition: Sabotaging a competitor's online services, especially during peak sales periods, to gain an unfair advantage.
  • Distraction: Launching a DoS attack to preoccupy security teams while a more insidious attack, like data exfiltration or ransomware deployment, occurs unnoticed.

⚡ How It Works

A DoS attack generally exploits the finite capacity of a system (its bandwidth, memory, CPU, or number of available connections).

Single-Source vs. Distributed

  • Denial-of-Service (DoS) Attack: The attack traffic originates from a single source/machine. These are generally easier to detect and block.
  • Distributed Denial-of-Service (DDoS) Attack: The attack traffic comes from multiple, distributed sources (often thousands of compromised devices, known as a botnet). This is far more powerful and much harder to defend against, as the malicious traffic is disguised among many sources.

Common Attack Techniques

  • Volumetric Attacks (Flooding): Aims to consume all available bandwidth between the target and the internet.

    Example: Sending a massive volume of ICMP (Ping) or UDP packets to the target.

  • Protocol Attacks: Exploits weaknesses in the network protocols (like TCP/IP) to consume server resources.

    Example: SYN Flood. An attacker sends a flood of TCP connection requests (SYN packets) but never completes the "three-way handshake." This leaves the server's connection ports open and waiting for a response that never comes, exhausting the server's connection table.

  • Application Layer Attacks (Layer 7): Targets the layer where the application or website runs, focusing on resource-intensive processes.

    Example: HTTP Flood. The attacker sends a high volume of seemingly legitimate HTTP requests (like continuously refreshing a webpage or querying a database endpoint) that forces the server to expend significant CPU and memory resources to process them.

    Example: Slowloris. The attacker sends legitimate requests but does so slowly and fragmented, keeping connections open for a long time and tying up the server's limited concurrent connections.

✅ Prevention Techniques

  • Rate limiting: Restrict the number of requests per client/IP.
  • Firewalls & WAFs: Block suspicious traffic patterns.
  • Timeouts: Close idle connections quickly.
  • Monitoring: Detect traffic spikes early.

⚠️ Limitation

A DoS attack comes from a single source, so it’s usually easier to detect and block compared to DDoS (Distributed Denial of Service) attacks.

🏢 Real-Life Analogy

A DoS or DDoS attack is like a huge crowd of people trying to enter a small store at the same time.

  • The store is the target server.
  • The legitimate customers are the normal users trying to access the service.
  • The crowd (or bots in a DDoS attack) are the attackers flooding the system with superfluous requests.
  • The purpose of the attack is not to steal anything, but simply to block the entrance so the legitimate customers cannot get in, shutting down the store's business.

💻 Practical Example in Express.js

This approach will allow you to understand the vulnerability and, more importantly, how to defend against it. The demonstration includes:

  • A Simple, Vulnerable Express.js Server that demonstrates the potential for a DoS condition due to an intentional, heavy, blocking operation.
  • A Benign Node.js Script that simulates a flood of requests against the server to demonstrate the effect of a DoS attack (server slowdown/unavailability) and to test the mitigation.
  • The Necessary Mitigation (Rate Limiting) to protect the server.

1️⃣ The Vulnerable Express.js Server (Server.js) 🚨

This server has a route (/heavy) that deliberately performs a CPU-intensive, blocking calculation to simulate a poor-performing resource. Since Node.js is single-threaded, this will block the entire event loop, causing a temporary DoS for all other users. 

// server.js
const express = require('express');
const app = express();
const PORT = 3000;

// Function to perform a CPU-intensive, synchronous calculation (intentional vulnerability for demonstration)
function calculateFactorial(n) {
    if (n === 0) {
        return 1;
    }
    // This loop is synchronous and blocking.
    let result = 1;
    for (let i = n; i > 0; i--) {
        result *= i;
    }
    return result;
}

// ⚠️ VULNERABLE ENDPOINT: This endpoint is easily exploited by a DoS attack.
app.get('/heavy', (req, res) => {
    // A large number forces a long, blocking calculation
    const result = calculateFactorial(50000); 
    console.log(`Heavy request processed. Result length: ${String(result).length}`);
    res.status(200).send(`Factorial calculated. Result length: ${String(result).length}`);
});

// SAFE ENDPOINT: A simple, non-blocking endpoint to test availability
app.get('/light', (req, res) => {
    const timestamp = new Date().toISOString();
    console.log(`Light request processed at ${timestamp}`);
    res.status(200).send(`Light response at ${timestamp}`);
});

app.listen(PORT, () => {
    console.log(`Server running on http://localhost:${PORT}`);
});

To Run: Save as server.js and run npm install express then node server.js.

2️⃣ The Benign Attacker (Flooder.js) 🚀

This script uses the axios library to simulate 50 simultaneous users repeatedly hitting the vulnerable /heavy endpoint. This is how you demonstrate the effect of a DoS attack. 

// flooder.js (Benign Test Script)
const axios = require('axios');

const URL = 'http://localhost:3000/heavy';
const LIGHT_URL = 'http://localhost:3000/light';
const CONCURRENCY = 50; // Number of simultaneous requests

// Function to make a single request and measure time
async function makeRequest(url, id) {
    const startTime = Date.now();
    try {
        await axios.get(url, { timeout: 10000 }); // 10 second timeout
        const duration = Date.now() - startTime;
        console.log(`[${id}] Success. Response Time: ${duration}ms`);
    } catch (error) {
        if (error.code === 'ECONNABORTED' || error.code === 'ETIMEDOUT') {
            console.error(`[${id}] Timed out or Aborted. Server is overloaded.`);
        } else {
            // console.error(`[${id}] Error: ${error.message}`);
        }
    }
}

// Main function to launch concurrent requests
async function launchFloodTest() {
    console.log(`--- Launching ${CONCURRENCY} simultaneous requests against ${URL} ---`);
    const heavyPromises = [];
    for (let i = 1; i <= CONCURRENCY; i++) {
        heavyPromises.push(makeRequest(URL, `Heavy-${i}`));
    }
    await Promise.allSettled(heavyPromises);
    console.log(`\n--- Heavy load finished. Testing 'light' endpoint availability ---`);

    // Test the /light endpoint after the heavy load has started/finished
    await makeRequest(LIGHT_URL, 'Light Test 1');
    await makeRequest(LIGHT_URL, 'Light Test 2');
}

launchFloodTest();

To Run: Save as flooder.js and run npm install axios then node flooder.js.

Observation: When you run flooder.js, you'll see the response times for both the /heavy and even the simple /light endpoint dramatically increase (or timeout). This proves the entire server is blocked, illustrating the DoS.
