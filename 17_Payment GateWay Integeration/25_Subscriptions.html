Lemon Squeezy Subscriptions

A complete guide to handling subscriptions using REST API, Node.js, and Best Practices. This document covers everything from initial setup to advanced cancellation logic and event handling.

1. Understanding Subscriptions

What are Subscriptions?

Lemon Squeezy subscriptions allow you to create recurring billing for your products/services. Key characteristics include:

  • Recurring Payments: Charge customers at regular intervals (monthly, yearly, etc.)
  • Flexible Billing: Multiple billing intervals, trial periods, usage-based billing
  • Subscription Management: Pause, cancel, upgrade/downgrade capabilities
  • Dunning Management: Automated failed payment handling

Subscription Components

3. Working with Subscriptions via Manual API

Endpoints Overview
  • GET /subscriptions - List subscriptions
  • GET /subscriptions/{id} - Get specific subscription
  • POST /subscriptions - Create subscription (through checkout)
  • PATCH /subscriptions/{id} - Update subscription
  • DELETE /subscriptions/{id} - Cancel subscription

1. Creating a Subscription

Creating a subscription happens through checkouts. You can't directly create subscriptions via API. 

async function createSubscription() {
  const checkoutData = {
    data: {
      type: "checkouts",
      attributes: {
        checkout_options: {
          media: false,
          logo: true
        },
        checkout_data: {
          custom: {
            user_id: "user_123"
          },
          variant_quantities: [
            {
              variant_id: "VARIANT_ID",
              quantity: 1
            }
          ]
        },
        product_options: {
          redirect_url: "https://yourdomain.com/thank-you",
          receipt_button_text: "Go to Dashboard",
          receipt_link_url: "https://yourdomain.com/dashboard"
        },
        expires_at: null,
        preview: true,
        test_mode: true
      },
      relationships: {
        store: {
          data: {
            type: "stores",
            id: storeId
          }
        },
        variant: {
          data: {
            type: "variants",
            id: "VARIANT_ID"
          }
        }
      }
    }
  };

  try {
    const response = await lemonSqueezyAPI.post('/checkouts', checkoutData);
    return response.data.data.attributes.url;
  } catch (error) {
    console.error('Error creating checkout:', error.response?.data || error.message);
  }
}

2. Listing Subscriptions

async function listSubscriptions(filters = {}) {
  try {
    const params = new URLSearchParams();
    
    // Add filters
    if (filters.status) params.append('filter[status]', filters.status);
    if (filters.store_id) params.append('filter[store_id]', filters.store_id);
    if (filters.email) params.append('filter[user_email]', filters.email);
    if (filters.page) params.append('page[number]', filters.page);
    
    const response = await lemonSqueezyAPI.get(`/subscriptions?${params}`);
    
    return {
      data: response.data.data.map(sub => ({
        id: sub.id,
        ...sub.attributes,
        relationships: sub.relationships
      })),
      meta: response.data.meta,
      links: response.data.links
    };
  } catch (error) {
    console.error('Error listing subscriptions:', error.response?.data || error.message);
  }
}

// Usage examples:
listSubscriptions({ status: 'active', page: 1 });
listSubscriptions({ email: 'customer@example.com' });

3. Retrieving a Specific Subscription

async function getSubscription(subscriptionId) {
  try {
    const response = await lemonSqueezyAPI.get(`/subscriptions/${subscriptionId}`, {
      params: {
        include: 'customer,order,product,variant' // Include related resources
      }
    });
    
    const subscription = response.data.data;
    const included = response.data.included || [];
    
    // Process included relationships
    const customer = included.find(item => 
      item.type === 'customers' && item.id === subscription.relationships.customer.data.id
    );
    
    return {
      id: subscription.id,
      ...subscription.attributes,
      customer: customer ? customer.attributes : null
    };
  } catch (error) {
    console.error('Error getting subscription:', error.response?.data || error.message);
  }
}

4. Updating a Subscription

async function updateSubscription(subscriptionId, updates) {
  try {
    const updateData = {
      data: {
        type: "subscriptions",
        id: subscriptionId,
        attributes: updates
      }
    };
    
    const response = await lemonSqueezyAPI.patch(
      `/subscriptions/${subscriptionId}`,
      updateData
    );
    
    return response.data.data;
  } catch (error) {
    console.error('Error updating subscription:', error.response?.data || error.message);
  }
}

// Usage examples:
// Update billing anchor (day of month)
updateSubscription('sub_123', { billing_anchor: 25 });

// Pause a subscription
updateSubscription('sub_123', { pause: { mode: 'free' } });

// Unpause a subscription
updateSubscription('sub_123', { pause: null });

5. Cancelling a Subscription

async function cancelSubscription(subscriptionId, immediate = false) {
  try {
    const updateData = {
      data: {
        type: "subscriptions",
        id: subscriptionId,
        attributes: {
          cancelled: true
        }
      }
    };
    
    const response = await lemonSqueezyAPI.patch(
      `/subscriptions/${subscriptionId}`,
      updateData
    );
    
    // For immediate cancellation (not at period end), use DELETE
    if (immediate) {
      await lemonSqueezyAPI.delete(`/subscriptions/${subscriptionId}`);
    }
    
    return response.data.data;
  } catch (error) {
    console.error('Error cancelling subscription:', error.response?.data || error.message);
  }
}

5. Life Cycle, Statuses & Security

What Does "Subscription Created" Mean?

When a subscription is "created," it means a customer has successfully:

  • Signed up for a recurring payment plan
  • Completed the initial payment
  • Entered into a billing agreement
  • Has been granted access to your product/service
Creation Process Flow Customer Action → Checkout Created → Payment Processed → Webhook Fired → Subscription Created

Clicks "Subscribe" → Unique URL generated → Card charged (initial payment) → subscription_created event sent to you

Subscription Statuses: Detailed Breakdown

Status Meaning Customer Access Auto-Retries Manual Action Next Billing
active Good standing ✅ Full access ❌ No ❌ No Scheduled
past_due Recent payment failed ⚠️ Grace period ✅ Yes (3 attempts) ❌ No Will retry
unpaid All retries failed ❌ No access ❌ No ✅ Yes Stopped
cancelled Ends at period end ✅ Until period end ❌ No ✅ Taken Stopped
expired Ended naturally ❌ No access ❌ No ❌ No Stopped
paused Temporarily paused ⚠️ Limited/None ❌ No ✅ Resume needed Paused

Status Logic Examples

Handling PAST_DUE (Most Important)

// Business logic for past_due subscriptions
async function handlePastDueSubscription(subscription) {
  // 1. Determine grace period access
  const gracePeriodDays = getGracePeriod(subscription.plan);
  const isInGracePeriod = checkIfInGracePeriod(subscription);
  
  if (isInGracePeriod) {
    // Allow continued access during grace period
    grantAccess({
      userId: subscription.custom_data.user_id,
      tier: 'premium',
      features: ['all'],
      restriction_note: 'Payment overdue - grace period'
    });
  } else {
    // Restrict access after grace period
    restrictAccess({
      userId: subscription.custom_data.user_id,
      allowed_features: ['basic_only']
    });
  }
  
  // 2. Notify customer (if not already notified)
  // ... notification logic
}

Handling CANCELLED (Graceful Wind-down)

function handleCancelledSubscription(subscription) {
  const endsAt = new Date(subscription.ends_at);
  const today = new Date();
  const daysRemaining = Math.ceil((endsAt - today) / (1000 * 60 * 60 * 24));
  
  // 1. Determine access level based on remaining time
  if (daysRemaining > 0) {
    // Still in paid period - full access
    grantAccess({
      userId: subscription.custom_data.user_id,
      note: `Access until ${subscription.ends_at}`
    });
  } else {
    // Past end date - revoke access
    revokeAccess(subscription.custom_data.user_id);
  }
}

6. Webhooks & Subscription Events

Subscription events are real-time notifications sent by Lemon Squeezy to your application whenever something significant happens.

Common Events

const SUBSCRIPTION_EVENTS = {
  // Lifecycle Events
  'subscription_created': 'New subscription started',

  'subscription_cancelled': 'Customer cancelled',

  'subscription_resumed': 'Paused subscription resumed',
  
  // Payment Events
  'subscription_payment_success': 'Recurring payment succeeded',
  'subscription_payment_failed': 'Payment attempt failed',
  'subscription_payment_recovered': 'Failed payment later succeeded',
  
  // Trial Events
  'subscription_trial_ended': 'Trial period ended',
  
  // Plan Change Events
  'subscription_plan_changed': 'Customer upgraded/downgraded'
};

WHEN to Listen (Scenarios)

Immediately After Payment

Listen to: subscription_created, subscription_payment_success

Don't make customers wait. Immediately create user accounts, grant access, and send welcome emails.

Payment Failures

Listen to: subscription_payment_failed

Notify customer immediately, start grace period, and limit features gradually.

Cancellations

Listen to: subscription_cancelled

Schedule access removal for the future and start retention campaigns.

Changes

Listen to: subscription_updated

Handle upgrades/downgrades instantly by adjusting permissions and billing.

WHY Listen? (Benefits)

  1. Real-Time User Experience: No polling every hour. Access is instant.
  2. Automated Business Processes: Auto-add to CRM, assign Customer Success Managers.
  3. Accurate Revenue Recognition: Real-time MRR/ARR tracking.
  4. Proactive Customer Success: Detect churn risks (downgrades, failures) early.
  5. Fraud Detection: Catch velocity attacks or card testing.

7. Real-World Use Cases

 
    
import express from 'express';
import crypto from 'crypto';

const app = express();

const WEBHOOK_SECRET = 'your_webhook_secret';

/**
 * IMPORTANT:
 * ❌ Do NOT use express.json() before this route
 * ✅ Use raw body for signature verification
 */
app.post(
    '/lemonsqueezy-webhook',
    express.raw({ type: 'application/json' }),
    (req, res) => {
        try {
            const signature = req.headers['x-signature'];

            // ✅ RAW BUFFER (do NOT stringify)
            const payload = req.body;

            // Verify signature
            const digest = crypto
                .createHmac('sha256', WEBHOOK_SECRET)
                .update(payload)
                .digest('hex');

            if (signature !== digest) {
                console.log('❌ Invalid signature');
                return res.sendStatus(401);
            }

            // ✅ Parse JSON AFTER verification
            const event = JSON.parse(payload.toString());
            const eventName = event.meta.event_name;
            const subscription = event.data.attributes;

            console.log('✅ Webhook event:', eventName);

            switch (eventName) {
                case 'subscription_created':
                    handleSubscriptionCreated(subscription);
                    break;

                case 'subscription_updated':
                    handleSubscriptionUpdated(subscription);
                    break;

                case 'subscription_cancelled': // ✅ correct spelling
                    handleSubscriptionCanceled(subscription);
                    break;

                case 'subscription_resumed':
                    handleSubscriptionResumed(subscription);
                    break;

                case 'subscription_expired':
                    handleSubscriptionExpired(subscription);
                    break;

                case 'subscription_payment_failed':
                    handlePaymentFailed(subscription);
                    break;

                case 'subscription_payment_recovered':
                    handlePaymentRecovered(subscription);
                    break;

                case 'subscription_payment_success':
                    handlePaymentSuccess(subscription);
                    break;

                default:
                    console.log('⚠️ Unhandled event:', eventName);
            }

            res.sendStatus(200);
        } catch (err) {
            console.error('🔥 Webhook error:', err);
            res.sendStatus(500);
        }
    }
);

8. Cancel vs Resume vs Pause

Cancel vs Resume

Cancel (The Goodbye)
  • Action: End subscription permanently.
  • Billing: Stops at period end (or immediately).
  • Access: Loses access at period end.
  • Reversal: Cannot auto-resume. Must create NEW subscription.
Resume (The Welcome Back)
  • Precondition: Must be CANCELLED (not expired).
  • Action: Reactivate a cancelled subscription.
  • Billing: Restarts billing immediately.
  • Reversal: You are resuming the SAME subscription.

Pause vs Unpause

Pause (The Break)
  • Action: Temporary hold.
  • Mode: 'Free' (Keep access) or 'Void' (No access).
  • Billing: Paused.
  • Use Case: Vacation, hardship.
Unpause (I'm Back)
  • Precondition: Must be PAUSED.
  • Action: Continue original subscription.
  • Billing: Resumes payments.
  • Continuity: Same subscription ID.

Cancel Subscription

  // 2. Delete (triggers refund logic)
  await lemonSqueezy.deleteSubscription(subscriptionId);

Grace Peroid

If a subscription is cancelled mid billing period (either by the customer or by the store owner), it will enter a “grace period” before it expires at the next scheduled renewal date (refected in a subscription’s ends_at value). The customer should still have access to your app or product until this date because they have paid for that time period.

During this cancelled grace period, it’s possible to resume the subscription with a quick API call with cancelled set to false.

// Resuming a cancelled subscription
async function resumeCancelledSubscription(subscriptionId) {
  // IMPORTANT: Can only resume if status is 'cancelled' (not expired)
  const response = await lemonSqueezy.updateSubscription(subscriptionId, {
    cancelled: false  // Flip the cancelled flag
  });

}

9. Common Pitfalls & Checklist

Pitfalls to Avoid

  1. Duplicate Events: Do not process every event without idempotency. Check if event ID was already processed.
  2. Event Order: Do not assume events arrive in order. Handle out-of-order events (e.g., cancellation arriving before creation) by checking API state.
  3. Webhook Failures: Don't just return 500. Return 200 to LS to stop retries, but queue the task internally for your own retry logic.

Implementation Checklist

✅ Required

  • Webhook endpoint HTTPS
  • Signature verification
  • Idempotency handling
  • Error logging & monitoring
  • Event validation

🚀 Recommended

  • Real-time notifications
  • CRM/Email integration
  • Automated follow-ups
  • Compliance logging
  • Periodic reconciliation job
