1. x-signature Header: Simple Explanation

The Analogy Think of it like a wax seal on an ancient letter - it proves the message is authentic and hasn't been tampered with during transit.

What is x-signature?

x-signature is a custom HTTP header (custom headers start with x-) that contains a cryptographic signature to:

  • Authenticate: Verify the sender is who they claim to be.
  • Ensure Integrity: Confirm the data wasn't modified in transit.
  • Prevent Replay Attacks: Stop attackers from reusing the same request.

Purpose & Usage

Common Use Cases:

  • API Security: Protect APIs from unauthorized access.
  • Webhook Verification: Verify webhooks come from legitimate sources (Stripe, GitHub, Lemon Squeezy, etc.).
  • Microservice Communication: Secure internal service-to-service calls.
  • Mobile/Web App APIs: Authenticate app requests.
  • Secure Data Transfer Over Network (Webhook Integrity): Ensure that data sent over the network has not been tampered with. Even if an attacker intercepts the request, they cannot modify the payload without invalidating the signature. This guarantees authenticity and integrity of webhook data.

How It Works (Simplified)

Sender Side:

  1. Take request data + secret key
  2. Create a hash/signature
  3. Add signature as x-signature header

Receiver Side:

  1. Take received request data + same secret key
  2. Create hash/signature again
  3. Compare with x-signature header
  4. If match → Request is valid

JavaScript/Node.js Implementation

1. Creating x-signature (Sender Side)

const crypto = require('crypto');

function createSignature(secretKey, data, timestamp) {
    // Combine data + timestamp
    const payload = JSON.stringify(data) + timestamp;
    
    // Create HMAC SHA256 signature
    const signature = crypto
        .createHmac('sha256', secretKey)
        .update(payload)
        .digest('hex');
    
    return signature;
}

// Example usage
const secretKey = 'my-secret-key-123';
const data = { userId: 123, action: 'delete' };
const timestamp = Date.now();

const signature = createSignature(secretKey, data, timestamp);

// Making request
const axios = require('axios');
axios.post('https://api.example.com/endpoint', data, {
    headers: {
        'x-signature': signature,
        'x-timestamp': timestamp,
        'Content-Type': 'application/json'
    }
});

2. Verifying x-signature (Receiver Side)

const express = require('express');
const crypto = require('crypto');
const app = express();

app.use(express.json());

function verifySignature(req, res, next) {
    const signature = req.headers['x-signature'];
    const timestamp = req.headers['x-timestamp'];
    const secretKey = 'my-secret-key-123'; 
    
    // 1. Check if timestamp is recent (prevent replay attacks)
    const now = Date.now();
    const timeDiff = now - parseInt(timestamp);
    
    if (timeDiff > 300000) { // 5 minutes tolerance
        return res.status(400).json({ error: 'Request too old' });
    }
    
    // 2. Recreate the signature
    const payload = JSON.stringify(req.body) + timestamp;
    const expectedSignature = crypto
        .createHmac('sha256', secretKey)
        .update(payload)
        .digest('hex');
    
    // 3. Compare signatures (use constant-time comparison)
    const isValid = crypto.timingSafeEqual(
        Buffer.from(expectedSignature),
        Buffer.from(signature)
    );
    
    if (!isValid) return res.status(401).json({ error: 'Invalid signature' });
    
    next();
}

app.post('/api/protected', verifySignature, (req, res) => {
    res.json({ message: 'Access granted!', data: req.body });
});

Advanced Implementation with Full Headers

class SignatureAuth {
    constructor(apiKey, secretKey) {
        this.apiKey = apiKey;
        this.secretKey = secretKey;
    }
    
    generateHeaders(method, path, body = {}) {
        const timestamp = Date.now();
        const nonce = crypto.randomBytes(16).toString('hex'); // Random string
        
        // Create signature string (order matters!)
        const signatureData = [
            method.toUpperCase(),
            path,
            timestamp,
            nonce,
            JSON.stringify(body)
        ].join('');
        
        const signature = crypto
            .createHmac('sha256', this.secretKey)
            .update(signatureData)
            .digest('hex');
        
        return {
            'x-api-key': this.apiKey,
            'x-signature': signature,
            'x-timestamp': timestamp,
            'x-nonce': nonce,
            'Content-Type': 'application/json'
        };
    }
}
Important Security Notes
  • Never expose secret keys in client-side code.
  • Use HTTPS - x-signature alone doesn't encrypt data.
  • Include Timestamp to prevent replay attacks.
  • Rotate Keys periodically.

2. timingSafeEqual: Simple Explanation

Analogy Imagine a security guard checking two barcodes.

❌ Normal comparison: The guard scans and stops immediately when one digit doesn’t match. An attacker watching can see "Oh, it failed fast, the first digit is wrong."

✅ timingSafeEqual: The guard always scans every digit of both barcodes, even if the first digit is wrong. It always takes the same amount of time. The attacker learns nothing.

The Problem (Very Simple)

You have two strings:

secret = "abc123"
input  = "abx999"

If your server checks secret === input, the computer compares letter by letter:

  • a === a ✅
  • b === b ✅
  • c === x ❌ → STOP

This means:

  • Wrong at pos 1 → Very fast response
  • Wrong at pos 5 → Slower response

An attacker can measure time and slowly guess: a → ab → abc → abc1.... This is a Timing Attack.

Node.js Implementation

Vulnerable Code ❌

// DANGEROUS: Stops early at first mismatch
function compareNormal(a, b) {
    if (a.length !== b.length) return false;
    for (let i = 0; i < a.length; i++) {
        if (a[i] !== b[i]) return false; 
    }
    return true;
}

Safe Code ✅

const crypto = require('crypto');

function safeCompare(a, b) {
    try {
        const bufA = Buffer.from(a, 'utf8');
        const bufB = Buffer.from(b, 'utf8');
        
        if (bufA.length !== bufB.length) return false;
        
        // Constant-time comparison
        return crypto.timingSafeEqual(bufA, bufB);
    } catch {
        return false;
    }
}

Visualizing the Timing Difference

Normal Comparison Timing:
Comparing "abc123" with "abc456" -> 1 vs 4 mismatch -> STOPS (Medium time)
Comparing "xyz123" with "abc123" -> x vs a mismatch -> STOPS (Very Fast)
Result: Attacker learns "x" is wrong immediately.

timingSafeEqual Timing:
Comparing "abc123" with "abc456" -> Checks all 6 chars -> Constant Time
Comparing "xyz123" with "abc123" -> Checks all 6 chars -> SAME Constant Time
Result: Attacker learns nothing.

Browser JavaScript Alternative

Node.js has crypto.timingSafeEqual, but browsers don't. Here is a workaround: 

function constantTimeCompare(a, b) {
    const aBytes = new TextEncoder().encode(a);
    const bBytes = new TextEncoder().encode(b);
    
    let result = 0;
    // Always loop through max length
    const maxLength = Math.max(aBytes.length, bBytes.length);
    
    for (let i = 0; i < maxLength; i++) {
        // Use bitwise OR to accumulate differences
        result |= (aBytes[i] || 0) ^ (bBytes[i] || 0);
    }
    
    return result === 0;
}

3. Replay Attacks

Analogy Think of it like someone recording your voice saying "Open sesame" and replaying it later to open the door themselves.

What is a Replay Attack?

An attacker intercepts and retransmits valid data to:

  • Reuse authentication tokens/sessions.
  • Repeat transactions (e.g., pay twice).
  • Gain unauthorized access.

How It Works

Legitimate User: [Login Request] → Server → [Session Token]
Attacker:
1. Eavesdrops and captures the Session Token.
2. Waits for user to log out.
3. Replays the same Session Token.
4. Gains access as the user!

Real-World Examples

API Request Replay

// 1. Legitimate request
POST /transfer-money
Body: {to: "account123", amount: 1000}

// 2. Attacker captures and replays exact same request
POST /transfer-money
Body: {to: "account123", amount: 1000}

// Result: Money transferred AGAIN without user's knowledge!

Prevention Techniques

1. Timestamps (Most Common)

function preventReplayWithTimestamp(timestamp) {
    const now = Date.now();
    const requestTime = parseInt(timestamp);
    
    // Reject if too old (e.g., > 5 minutes)
    if (now - requestTime > 5 * 60 * 1000) {
        return false; 
    }
    
    // Reject if from the future
    if (requestTime > now + 60 * 1000) {
        return false;
    }
    
    return true;
}

2. Nonces (Number Used Once)

class ReplayProtection {
    constructor() {
        this.usedNonces = new Set();
    }
    
    validateNonce(nonce) {
        if (this.usedNonces.has(nonce)) {
            return false; // Replay attack!
        }
        this.usedNonces.add(nonce);
        return true;
    }
}

3. Sequence Numbers

Each client maintains a counter. The server ensures the sequence number of a new request is greater than the last one.
