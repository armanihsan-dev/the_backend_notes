What is Bearer Authentication?

Bearer authentication is an HTTP authentication scheme where the client provides a **bearer token** (typically a cryptographic string) in the Authorization header. The name "bearer" means anyone who possesses this token can use it to access protected resources - much like how anyone holding a physical bearer bond can redeem it.

OR

A Bearer token means: “If you have this token, you are allowed.”

How It Works

Imagine a room with a door.

The door guard says:

“I don’t care who you are.
If you carry this key, you can enter.”

That key = Bearer token

The rule =

Bearer rule: possession = permission

The precise truth (clean and simple)

🔑 Bearer = the rule

“Whoever carries the token is trusted”

📦 Token type = what’s inside

  • If the token is JWT → guard reads fields inside
  • If the token is a random key → guard looks it up in database

Bearer itself says nothing about contents.

Core Flow:

text
Client → Server: Request with Authorization: Bearer <token>
Server → Client: Validates token → Grants/Denies access

Is It Stateless or Stateful?

Bearer authentication is inherently STATELESS on the server side, but with important caveats:

  • Server Perspective: Stateless - server validates the token without storing session data
  • Token Itself: Contains all necessary claims/authorizations
  • Validation: Server verifies token signature and checks claims
  • No Server Session Storage: Each request carries its own authentication

However, token **issuance/revocation** requires state management:

  • Token blacklists (for invalidation)
  • Refresh token rotations
  • Key rotation for signing

Server-to-Server Authentication (Node.js → Lemon Squeezy)

Why Use Bearer Auth Between Servers:

javascript
// Example Node.js server making request to Lemon Squeezy
const axios = require('axios');

async function getLemonSqueezyData() {
    const API_TOKEN = process.env.LEMON_SQUEEZY_API_KEY;
    
    const response = await axios.get('https://api.lemonsqueezy.com/v1/products', {
        headers: {
            'Authorization': `Bearer ${API_TOKEN}`,
            'Accept': 'application/vnd.api+json',
            'Content-Type': 'application/vnd.api+json'
        }
    });
    return response.data;
}

Token Exposure API tokens visible in browser DevTools, JavaScript source Attacker can **steal token** and make unlimited API calls
No IP Restrictions Requests come from user's IP, not your server IP Cannot whitelist IPs at Lemon Squeezy

Secure Alternatives for Client-Server Communication

Option 1: Backend Proxy Pattern (Recommended)

// React (Frontend) → Your Node.js Backend → Lemon Squeezy

// FRONTEND (React):
async function getProducts() {
    // Call YOUR server endpoint
    const response = await fetch('/api/lemonsqueezy/products');
    return response.json();
}

// BACKEND (Node.js):
app.get('/api/lemonsqueezy/products', async (req, res) => {
    // Validate user session first
    if (!req.session.userId) return res.status(401).send();
    
    // Then proxy to Lemon Squeezy with server token
    const lemonResponse = await fetch('https://api.lemonsqueezy.com/v1/products', {
        headers: {
            'Authorization': `Bearer ${process.env.LEMON_SQUEEZY_API_KEY}`
        }
    });
    
    // Optional: Transform data, add logging, implement caching
    const data = await lemonResponse.json();
    res.json(data);
});

Option 2: Temporary Signed URLs

javascript
// Node.js Backend creates time-limited access
app.post('/api/lemonsqueezy/signed-url', (req, res) => {
    const { userId, resource } = req.body;
    
    // Validate user authorization
    if (!authorized(userId, resource)) return res.status(403).send();
    
    // Create time-limited token (e.g., 5 minutes)
    const token = jwt.sign(
        { 
            userId, 
            resource, 
            exp: Math.floor(Date.now() / 1000) + 300 
        },
        process.env.JWT_SECRET
    );
    
    res.json({
        url: `https://api.lemonsqueezy.com/v1/${resource}?temp_token=${token}`
    });
});

Option 3: Backend-Generated Client Tokens (Most Secure)

javascript
// Backend issues short-lived, scoped tokens
class TokenService {
    generateClientToken(userId, permissions) {
        return jwt.sign(
            {
                sub: userId,
                permissions, // Limited scopes: ['read:products']
                iss: 'your-backend-service',
                aud: 'lemonsqueezy-api',
                exp: Math.floor(Date.now() / 1000) + 3600 // 1 hour
            },
            process.env.JWT_SECRET
        );
    }
}
// Lemon Squeezy would need to accept and validate these JWTs

Bearer Token Security Best Practices

For Server-to-Server:

  • **Use Environment Variables:** Never hardcode tokens
  • **Implement Token Rotation:** Automated, regular rotation
  • **Use Different Tokens:** Separate tokens for different services
  • **Monitor Usage:** Alert on abnormal patterns
  • **Implement Retry Logic:** With exponential backoff
  • **Use HTTPS Only:** Always enforce TLS

For Any Bearer Token Usage:

  • **Short Expiration:** Keep token lifetimes minimal
  • **Limited Scope:** Principle of least privilege
  • **Secure Storage:** Key management systems (AWS Secrets Manager, HashiCorp Vault)
  • **Revocation Plan:** Ability to quickly revoke compromised tokens
  • **Audit Logging:** Track all token usage

JWT vs. Opaque Tokens in Bearer Auth

javascript
// JWT Bearer Token (Self-contained):
// Header.Payload.Signature
// Contains claims, verifiable signature
// Stateless validation

// Opaque Bearer Token (Reference token):
// Random string, server must look up
// More control over revocation
// Stateful on token validation server

Key Token Flow Explained

1. User Authentication (Your App)

// React → Your Node.js Server
// User gets YOUR JWT token, NOT Lemon Squeezy token
fetch('/api/login', {
  method: 'POST',
  body: JSON.stringify({ email, password })
});
// Response: { token: "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..." }

2. Making Purchase Request

// React sends YOUR JWT to YOUR backend
fetch('/api/create-checkout', {
  headers: {
    'Authorization': `Bearer ${userJWT}`,  // YOUR app's JWT
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ productId: '123' })
});

3. Backend Validates & Forwards to Lemon Squeezy

// Node.js backend code
app.post('/api/create-checkout', async (req, res) => {
  // 1. Validate YOUR user's JWT
  const userData = jwt.verify(req.headers.authorization.split(' ')[1], 'your-secret');
  
  // 2. Prepare Lemon Squeezy request with THEIR token
  const lemonResponse = await fetch('https://api.lemonsqueezy.com/v1/checkouts', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.LEMON_SQUEEZY_API_KEY}`, // LS token
      'Accept': 'application/vnd.api+json'
    },
    body: JSON.stringify({
      // Checkout data...
    })
  });
  
  // 3. Return checkout URL to frontend
  res.json({ checkoutUrl: lemonResponse.data.url });
});

4. Lemon Squeezy Validates THEIR Token

text
Lemon Squeezy receives:
Authorization: Bearer ls_sk_abcdef123456...

Validation steps:
1. Extract token: ls_sk_abcdef123456...
2. Check if token exists in their system
3. Verify token hasn't expired
4. Check token permissions (scope)
5. Validate store_id access
6. Process request if valid

Payment Flow Steps (Non-Technical)

  1. User logs into **YOUR website** → Gets **YOUR** authentication token
  2. User clicks "Buy Now" → Sends request to **YOUR server** with **THEIR** token
  3. **YOUR server** checks: Is this a valid user? Do they have permission?
  4. **YOUR server** calls Lemon Squeezy using Lemon's **secret API key** (user never sees this)
  5. Lemon Squeezy validates their API key, creates checkout
  6. Your server gets checkout URL, sends to user's browser
  7. User redirected to Lemon Squeezy checkout page
  8. User enters payment directly on Lemon Squeezy (PCI compliant)
  9. Lemon Squeezy processes payment, sends **webhook** to **YOUR server**
  10. Your server updates user's order status

Critical Security Points

  • **API Token Location:** Only in backend environment variables
  • **User Authentication:** Separate from Lemon Squeezy authentication
  • **Payment Page:** Always on Lemon Squeezy domain (never embedded)
  • **Webhook Verification:** Always verify signatures
  • **Error Handling:** Never leak API errors to frontend

Simple Analogy

Think of it like a **restaurant**:

  • **Customer (React App):** Shows ID to get in (your JWT)
  • **Waiter (Your Backend):** Takes order, goes to kitchen
  • **Kitchen (Lemon Squeezy):** Only listens to waiters (API tokens), not customers directly
  • **Payment:** Done at cashier (Lemon Squeezy checkout), not with waiter

Customer never enters kitchen, kitchen only trusts waiters with proper uniform (API tokens).
