Usage Records Guide

A complete guide for developers to track and report customer usage (metered billing) for subscription items in Lemon Squeezy.

1. What Are Usage Records?

Usage records are how you track and report customer usage for subscription items with usage-based billing in Lemon Squeezy. Think of them as meter readings for your service - each record tells Lemon Squeezy "this customer used X amount of this feature during this billing period."

Key Concepts

1. The Usage Record Object Structure

{
  "subscription_item_id": "123",
  "quantity": 5,
  "action": "increment",  // or "set"
  "created_at": "2024-01-15T10:30:00Z"
}

2. Two Types of Actions

  • increment: Adds to existing usage (like adding more units to a counter).
    Current total: 100 → New total: 105
  • set: Replaces the usage (like setting a new meter reading).
    Previous value ignored → New total: 50

2. The Taxi Analogy

Imagine you run a taxi company (your SaaS app):

  • Subscription Item = Taxi ride
  • Usage Records = Each kilometer/mile driven
  • Billing Period = The ride (or monthly bill)
1. "Increment" Meter

Counting things

  • Start: 0 km
  • After 5 minutes: 2 km → +2 km
  • After 10 minutes: 3 km → +1 km
  • Total bill: 3 km × $2/km = $6

Good for: API calls, Emails sent, Tasks processed

2. "Set" Meter

Measuring current state

  • Day 1: 5GB stored → Set to "5GB"
  • Day 2: 8GB stored → Set to "8GB" (NOT 13GB!)
  • Day 3: 3GB stored → Set to "3GB"
  • Bill: They pay for MAXIMUM storage used = 8GB

Good for: Storage space, Number of users, Current plan level

3. As a Developer: Core Code

As a Developer, Here's ALL You Need to Know:

The ONE LINE of Code That Matters:

// Tell Lemon Squeezy: "Customer used X more of Feature Y"
await lemonSqueezy.createUsageRecord({
  subscription_item_id: "123",  // WHICH feature they're using
  quantity: 5,                  // HOW MUCH they used
  action: "increment"           // ADD to total ("set" = REPLACE total)
});

Real Examples

Example 1: Email Service (Increment)

// When customer sends 1 email
await lemonSqueezy.createUsageRecord({
  subscription_item_id: customer.email_sub_id,
  quantity: 1,
  action: "increment" // ADD count
});

// Result: 95 emails → 96 emails

Example 2: Cloud Storage (Set)

// Check how much storage used
const storageUsed = getCustomerStorage(userId); 

await lemonSqueezy.createUsageRecord({
  subscription_item_id: customer.storage_sub_id,
  quantity: 9, // Round up to 9GB
  action: "set" // SET usage (not add)
});

// Result: Pay for 9GB total

4. Logic & Reporting Strategy

The 3 Things You Actually Need:

1. Find the subscription_item_id

When customer subscribes, Lemon Squeezy gives you this ID.

{
  user_id: "user_456",
  subscription_item_id: "sub_item_789",  // ← THIS is what you need
  feature: "api_calls"
}

2. Decide: "increment" or "set"?

Ask yourself: "Am I counting HOW MANY TIMES they did something, or measuring HOW MUCH they're using RIGHT NOW?"

If tracking... Use... Because...
API calls increment Each call ADDS to total
Emails sent increment Each email ADDS to total
Storage used set You measure CURRENT usage
Active users set You count CURRENT users

3. Report at the right time

// Option A: Report immediately (simple)
app.post("/api/send-email", async (req, res) => {
  await sendEmail(req.body);
  await lemonSqueezy.createUsageRecord({
    subscription_item_id: user.email_subscription_id,
    quantity: 1,
    action: "increment"
  });
  res.send("Email sent!");
});

// Option B: Report in batches (efficient)
setInterval(async () => {
  const emailsSent = await countEmailsLastHour();
  if (emailsSent > 0) {
    await lemonSqueezy.createUsageRecord({
      subscription_item_id: "global_email_subscription",
      quantity: emailsSent,
      action: "increment"
    });
  }
}, 60 * 60 * 1000); // Every hour

5. The Usage Record Object (REST API)

A usage record reports the usage amount for a subscription item with usage-based billing. A usage record belongs to a Subscription Item.

Attributes

  • subscription_item_id: The ID of the subscription item this usage record belongs to.
  • quantity: A positive integer representing the usage to be reported.
  • action: The type of record. One of:
    • increment - The provided quantity was added to existing records.
    • set - The provided quantity was set as the total usage.
  • created_at: ISO 8601 formatted date-time string.
  • updated_at: ISO 8601 formatted date-time string.

6. API Endpoints

Create a Usage Record

POST /v1/usage-records

Note on Defaults: Defaults to increment if action is omitted.

Aggregation Settings increment should only be used alongside the "Sum of usage during period" setting.
set should only be used alongside "Most recent usage during a period" setting. 
curl -X "POST" "https://api.lemonsqueezy.com/v1/usage-records" \
  -H "Accept: application/vnd.api+json" \
  -H "Content-Type: application/vnd.api+json" \
  -H "Authorization: Bearer {api_key}" \
  -d '{
    "data": {
      "type": "usage-records",
      "attributes": {
        "quantity": 5
      },
      "relationships": {
        "subscription-item": {
          "data": {
            "type": "subscription-items",
            "id": "1"
          }		
        }
      }
    }
  }'

Retrieve a Usage Record

GET /v1/usage-records/:id

Note: To retrieve the current total usage for a subscription, use the subscription item current usage endpoint. 

curl "https://api.lemonsqueezy.com/v1/usage-records/1" \
  -H 'Accept: application/vnd.api+json' \
  -H 'Content-Type: application/vnd.api+json' \
  -H 'Authorization: Bearer {api_key}'

List All Usage Records

GET /v1/usage-records

Filter: subscription_item_id - Only return usage records belonging to this ID. 

curl "https://api.lemonsqueezy.com/v1/usage-records?filter[subscription_item_id]=1" \
  -H 'Accept: application/vnd.api+json' \
  -H 'Content-Type: application/vnd.api+json' \
  -H 'Authorization: Bearer {api_key}'

Returns a paginated list of Usage Records objects ordered by created_at in descending order.

7. Common Mistakes

Mistake 1: Using "increment" for storage 
// WRONG:
await lemonSqueezy.createUsageRecord({
  quantity: 5,
  action: "increment"  // ← NO! Customer adds 5GB every day!
});
// Result: Day1: 5GB, Day2: 10GB, Day3: 15GB... (Billed for 30GB total!)

// RIGHT:
await lemonSqueezy.createUsageRecord({
  quantity: 5,
  action: "set"  // ← YES! They use 5GB total
});
Mistake 2: Not handling errors

BAD - if Lemon Squeezy is down, usage isn't recorded.

// GOOD - retry if it fails
async function reportUsageWithRetry(itemId, quantity) {
  try {
    await lemonSqueezy.createUsageRecord({...});
  } catch (error) {
    // Save to database and retry later
    await saveFailedReport(itemId, quantity);
  }
}

8. Quick Start Guide

  1. Set up in Dashboard: Create product, enable "Usage-based billing", choose "Sum usage" (increment) or "Most recent usage" (set).
  2. Get subscription_item_id: 
    webhook.on("subscription_created", (event) => {
  console.log("Got subscription item ID:", event.data.subscription_item_id);
});
  3. Report usage: 
    await lemonSqueezy.createUsageRecord({
  subscription_item_id: subscriptionItemId,
  quantity: 1,
  action: "increment"
});
  4. Check it worked: Use getSubscriptionItemCurrentUsage.
The Simple Answer Usage records are just you telling Lemon Squeezy:
"Hey, customer X just used Y more of feature Z."

As a developer, you need to:
  • Save the subscription_item_id when customer subscribes
  • Choose increment (counting) or set (measuring)
  • Call createUsageRecord() when customer uses your service
That's it! The rest (billing, limits, overages) - Lemon Squeezy handles automatically.
