Webhooks Guide

Definition

Webhooks are automated messages sent from one application to another when a specific event occurs. They are essentially "user-defined HTTP callbacks" triggered by events.

Simple Analogy Imagine you order pizza delivery:

Polling (API): You call every 5 minutes: "Is my pizza ready yet?"

Webhook: Pizza place calls YOU: "Your pizza is ready for delivery!" 
// Traditional API (Polling) - Inefficient
setInterval(async () => {
  const order = await checkPizzaStatus();
  if (order.ready) {
    // Pizza is ready
  }
}, 5000); // Check every 5 seconds

// Webhook (Event-driven) - Efficient
// Pizza shop automatically notifies you when ready

Technical Definition

A webhook is an HTTP POST request sent to a pre-configured URL (your server) when an event occurs in a third-party service (like Lemon Squeezy).

1. Why is it called "Web Hooks"?

The name comes from the programming concept of "hooks" combined with "web":

  • Hooks: In programming, hooks are points where you can insert custom code to be executed when specific events occur. Like hanging your code on a "hook" that gets triggered.
  • Web: Because these hooks work over HTTP/HTTPS on the web.

Think of it as web-based callbacks - instead of your application constantly asking "Has something happened?" (polling), services can "hook into" your application by calling your URL when events occur.

2. ⚙️ How Webhooks Work

Architecture Flow

┌─────────────┐      Event      ┌─────────────┐
│             │   (Order placed)  │             │
│  Lemon      ├──────────────────►│  Your       │
│  Squeezy    │                  │  Server     │
│             │  HTTP POST       │             │
│  (Sender)   │  with JSON data  │ (Receiver)  │
└─────────────┘                  └─────────────┘
        ▲                                │
        │                                │ Process
        │                                ▼
        │                         ┌─────────────┐
        │    Response (200 OK)    │  Your       │
        └─────────────────────────┤  Database   │
                                  │  / Logic    │
                                  └─────────────┘

Step-by-Step Process

  1. Configuration: You provide a URL endpoint to Lemon Squeezy
  2. Event Occurs: Customer makes a purchase on Lemon Squeezy
  3. Notification: Lemon Squeezy sends HTTP POST to your endpoint
  4. Processing: Your server receives and processes the data
  5. Response: Your server returns HTTP 200 (success) or error
  6. Retry: If error, Lemon Squeezy retries (usually 3 times)

🎯 Purpose & Benefits

Primary Purposes

  • ⚡ Efficiency

    Problem with traditional polling: Your server keeps asking “Any updates?” every few minutes—even when nothing has changed.

    With webhooks: Lemon Squeezy notifies your server only when something actually happens. No wasted API calls.

    Example: 1,000 users × polling every 5 minutes = 12,000 checks per hour. With webhooks: only real events (maybe 10–20 per hour).

  • ⏱️ Real-time

    Traditional polling: Updates are delayed by the polling interval (5–10 minutes).

    With webhooks: Instant notifications. User cancels or upgrades → your app knows immediately.

    Example: User upgrades to PRO. Polling: waits up to 5 minutes. Webhooks: PRO features unlocked instantly.

  • 📈 Scalability

    Traditional polling: As users grow, API calls explode (10,000 users × 12 checks/hour = 120,000 calls/hour).

    With webhooks: You only process real events, no matter how large your user base becomes.

    Example: Black Friday sale with 5,000 purchases in one hour. Webhooks process each purchase as it happens.

  • 🔗 Decoupled

    Traditional polling: Your app depends on Lemon Squeezy’s API being constantly available.

    With webhooks: Services remain independent. Events are delivered when ready.

    Example: Lemon Squeezy maintenance for 1 hour. Polling: your app breaks. Webhooks: events queue and deliver afterward.

  • 🤖 Automation

    Traditional polling: You manually check status and trigger actions.

    With webhooks: Fully automated workflows.

    Example: User subscribes → Webhook triggers → Create account → Send welcome email → Setup dashboard → Notify sales team.

Convention for webhook endpoint in Express.js

// Standard convention: POST /api/webhooks/{service-name}
const express = require('express');
const app = express();

// Use raw body for signature verification
app.use('/api/webhooks/stripe', express.raw({type: 'application/json'}));

// Endpoint pattern
app.post('/api/webhooks/stripe', (req, res) => {
    const signature = req.headers['stripe-signature'];
    const payload = req.body;
    
    try {
        // Verify signature first
        const event = stripe.webhooks.constructEvent(
            payload, 
            signature, 
            process.env.STRIPE_WEBHOOK_SECRET
        );
        
        // Handle event types
        switch(event.type) {
            case 'payment_intent.succeeded':
                // Update order status
                break;
            case 'invoice.payment_failed':
                // Notify customer
                break;
            default:
                console.log(`Unhandled event: ${event.type}`);
        }
        
        res.json({received: true});
    } catch (err) {
        res.status(400).send(`Webhook Error: ${err.message}`);
    }
});

// For other services
app.post('/api/webhooks/paypal', handlePaypalWebhook);

Best Practices:

  • Use POST only (webhooks should not use GET)
  • Return 2xx quickly (within 5-10 seconds)
  • Log webhook receipts for debugging
  • Implement idempotency (handle duplicate events)

How X-Signature makes webhooks secure

The signature header (like stripe-signature, x-hub-signature-256) works like this: 

// Simplified concept:
const secret = 'your_webhook_secret';
const payload = req.body; // Raw request body
const receivedSignature = req.headers['x-signature'];

// Server creates expected signature:
const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');

// Compare signatures
if (receivedSignature !== expectedSignature) {
    // REJECT - request is forged or tampered with
    return res.status(401).send('Invalid signature');
}

// Only if signatures match, process webhook

Security Guarantees:

  • Authentication: Proves the request came from the legitimate service
  • Integrity: Ensures payload wasn't modified in transit
  • Anti-replay: Timestamps in signatures prevent old requests from being replayed

Why HTTPS instead of HTTP?

Security reasons:

  • Encryption: HTTPS encrypts the entire request/response, preventing:
    • Eavesdropping on sensitive data (customer info, payment details)
    • Man-in-the-middle attacks
  • Data Integrity: HTTPS ensures data isn't modified between sender and receiver
  • Server Authentication: HTTPS certificates verify you're sending data to the actual server (not a phishing site)
  • Required by Standards: PCI DSS (payment security standard) requires HTTPS for any payment-related data transmission
  • Trust: Services like Stripe, GitHub, etc., often require HTTPS endpoints and refuse to send to HTTP URLs
Example danger with HTTP: 
Attacker intercepts HTTP webhook about $1000 payment
↓
Modifies it to $10 payment before it reaches your server  
↓
Your system processes $10 payment instead of $1000
↓
You ship $1000 product but only get paid $10

What is express.raw({type: 'application/json'})?

It's a special Express middleware that parses the raw request body as a Buffer instead of automatically parsing it as JSON.

Normal Express JSON parsing (what you usually use):

app.use(express.json()); // Parses JSON automatically into req.body
// Result: req.body is already a JavaScript object

Raw body parsing:

app.use(express.raw({type: 'application/json'})); 
// Result: req.body is a Buffer (raw bytes)

Key difference:

  • express.json() → req.body = { "event": "payment.succeeded", "amount": 1000 } (object)
  • express.raw() → req.body = <Buffer 7b 22 65 76 65 6e 74 22 3a 22...> (raw buffer)

Why Webhooks Need Raw Body Parsing?

1. Signature Verification Requires Raw Data

Webhook signatures are computed from the exact raw bytes sent. Even minor differences break verification: 

// ❌ PROBLEM with express.json():
// Express might modify whitespace or formatting when parsing JSON
const payload1 = '{"event":"payment","amount":1000}';
const payload2 = '{"event": "payment", "amount": 1000}'; // Same content, different spacing

// These create DIFFERENT signatures even though content is same!
const sig1 = createSignature(payload1);
const sig2 = createSignature(payload2);
// sig1 !== sig2 !!!
// ✅ SOLUTION with express.raw():
// You get the EXACT bytes that were sent
const signature = req.headers['stripe-signature'];
const rawBody = req.body; // Exact bytes received

// Stripe computes signature from same raw bytes
const event = stripe.webhooks.constructEvent(
    rawBody,          // Raw Buffer
    signature,        // Signature header
    webhookSecret     // Your secret
);

2. Middleware Order Matters

// ❌ WRONG ORDER - Breaks signature verification
app.use(express.json()); // Parses ALL incoming JSON requests
app.use('/webhooks/stripe', stripeWebhookHandler); // Too late! Body already modified

// ✅ CORRECT ORDER - Isolate webhook endpoint
app.use('/webhooks/stripe', 
    express.raw({type: 'application/json'}), // Only for this route
    stripeWebhookHandler
);

// Other routes still use normal JSON parsing
app.use(express.json()); 
app.post('/api/orders', normalJsonHandler); // req.body is parsed JSON here

3. Complete Example with Proper Isolation

const express = require('express');
const app = express();

// Route-specific raw parsing for webhooks
app.post('/webhooks/stripe', 
    // Step 1: Get raw body for this specific route only
    express.raw({type: 'application/json'}),
    
    // Step 2: Handle webhook with signature verification
    async (req, res) => {
        const sig = req.headers['stripe-signature'];
        const rawBody = req.body; // Buffer, not parsed JSON
        
        try {
            // Verify with raw bytes
            const event = stripe.webhooks.constructEvent(
                rawBody, 
                sig, 
                process.env.STRIPE_SECRET
            );
            
            // Now you can safely parse as JSON
            const eventData = JSON.parse(rawBody.toString());
            
            // Process event...
            res.json({received: true});
        } catch (err) {
            res.status(400).send(`Webhook Error: ${err.message}`);
        }
    }
);

// All other routes use normal JSON parsing
app.use(express.json());

// Normal API endpoint
app.post('/api/orders', (req, res) => {
    // req.body is already a JavaScript object here
    const { productId, quantity } = req.body;
    // Process order...
});

Summary:

  • Use express.raw() for webhook endpoints needing signature verification
  • Use express.json() for normal API endpoints
  • Never mix them globally - apply to specific routes only
  • Signature verification is cryptographic - it needs the exact original bytes

const app = express();
const verifyWebhookSignature = (req, res, next) => {
  try {
    const signature = req.headers['x-signature'];
    const secret = process.env.LEMONSQUEEZY_WEBHOOK_SECRET;

    if (!signature) {
      return res.status(401).json({ error: 'No signature' });
    }

    const hmac = crypto.createHmac('sha256', secret);
    const digest = hmac.update(req.body).digest('hex');

    const sigBuffer = Buffer.from(signature, 'hex');
    const digestBuffer = Buffer.from(digest, 'hex');

    if (
      sigBuffer.length !== digestBuffer.length ||
      !crypto.timingSafeEqual(sigBuffer, digestBuffer)
    ) {
      return res.status(401).json({ error: 'Invalid signature' });
    }

    // ✅ IMPORTANT PART
    req.parsedBody = JSON.parse(req.body.toString());

    console.log('✅ Webhook signature verified');
    next();
  } catch (err) {
    console.error('❌ Verification error:', err);
    res.status(500).json({ error: 'Webhook verification failed' });
  }
};

// Main handler function
async function handleWebhookEvent(event) {
  const eventName = event.meta.event_name;
  const handler = eventHandlers[eventName];
  
  if (!handler) {
    console.log(`⚠️ No handler for event: ${eventName}`);
    return;
  }
  
  try {
    await handler(event);
    console.log(`🎉 Successfully processed ${eventName}`);
  } catch (error) {
    console.error(`❌ Error processing ${eventName}:`, error);
    // Re-throw to be handled by main webhook endpoint
    throw error;
  }
}

  console.log(`🎯 Processing job for event: ${event.meta.event_name}`);

// Simplified webhook endpoint
app.post('/api/webhooks/lemon', 
  express.json(),
  async (req, res) => {
    try {
      const signature = req.headers['x-signature'];
      const event = req.body;
      
      // 1. Verify signature synchronously (fast)
      if (!verifySignature(signature, event)) {
        return res.status(401).json({ error: 'Invalid signature' });
      }
      
      // 2. Add to queue for async processing (fast response)
      await webhookQueue.add('process', {
        event,
        signature,
        receivedAt: new Date()
      }, {
        attempts: 3, // Retry 3 times on failure
        backoff: {
          type: 'exponential',
          delay: 1000
        }
      });
      
      // 3. Respond immediately (important!)
      console.log(`📨 Webhook received and queued: ${event.meta.event_name}`);
      res.sendStatus(200);
      
    } catch (error) {
      console.error('❌ Webhook error:', error);
      res.sendStatus(200); // Still return 200 to prevent retries
    }
  }
);

// security.js
const crypto = require('crypto');

class WebhookSecurity {
  constructor(secret) {
    this.secret = secret;
  }
  
  // 1. Verify signature
  verifySignature(signature, payload) {
    if (!signature) return false;
    
    const hmac = crypto.createHmac('sha256', this.secret);
    const digest = hmac.update(JSON.stringify(payload)).digest('hex');
    
    return crypto.timingSafeEqual(
      Buffer.from(signature),
      Buffer.from(digest)
    );
  }
  
  // 2. Validate payload structure
  validatePayload(payload) {
    if (!payload || typeof payload !== 'object') {
      throw new Error('Invalid payload format');
    }
    
    if (!payload.meta || !payload.meta.event_name) {
      throw new Error('Missing event metadata');
    }
    
    if (!payload.data || !payload.data.id) {
      throw new Error('Missing event data');
    }
    
    return true;
  }
  
  // 3. Check for replay attacks (optional)
  async checkReplayAttack(eventId, timestamp) {
    const eventAge = Date.now() - new Date(timestamp).getTime();
    
    // Reject events older than 5 minutes
    if (eventAge > 5 * 60 * 1000) {
      throw new Error('Event too old, possible replay attack');
    }
    
    // Check if we've already processed this event
    const isDuplicate = await this.isEventProcessed(eventId);
    if (isDuplicate) {
      throw new Error('Duplicate event detected');
    }
    
    return false;
  }
  
  // 4. Rate limiting
  setupRateLimiting(app) {
    const rateLimit = require('express-rate-limit');
    
    const webhookLimiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 minutes
      max: 100, // Limit each IP to 100 requests per window
      message: 'Too many webhook requests from this IP',
      skipSuccessfulRequests: false
    });
    
    app.use('/webhooks', webhookLimiter);
  }
}

// middleware/security.js
const crypto = require('crypto');

const securityMiddleware = (secret) => {
  return async (req, res, next) => {
    try {
      const signature = req.headers['x-signature'];
      const payload = req.body;
      
      // 1. Check if webhook secret is configured
      if (!secret) {
        console.error('Webhook secret not configured');
        return res.status(500).json({ error: 'Server misconfigured' });
      }
      
      // 2. Verify signature exists
      if (!signature) {
        console.warn('Webhook request without signature');
        return res.status(401).json({ error: 'Missing signature' });
      }
      
      // 3. Verify signature validity
      const isValid = verifySignature(signature, payload, secret);
      if (!isValid) {
        console.warn('Invalid webhook signature');
        return res.status(401).json({ error: 'Invalid signature' });
      }
      
      // 4. Validate payload structure
      validatePayloadStructure(payload);
      
      // 5. Optional: Check timestamp (prevent replay attacks)
      if (payload.meta.timestamp) {
        const eventTime = new Date(payload.meta.timestamp).getTime();
        const currentTime = Date.now();
        const maxAge = 5 * 60 * 1000; // 5 minutes
        
        if (currentTime - eventTime > maxAge) {
          console.warn('Stale webhook event');
          return res.status(400).json({ error: 'Event too old' });
        }
      }
      
      // 6. Optional: Check for test mode if needed
      if (process.env.NODE_ENV === 'production' && payload.meta.test_mode) {
        console.log('Ignoring test mode webhook in production');
        return res.status(200).json({ received: true });
      }
      
      next();
      
    } catch (error) {
      console.error('Security middleware error:', error);
      res.status(400).json({ error: error.message });
    }
  };
};

function verifySignature(signature, payload, secret) {
  try {
    const hmac = crypto.createHmac('sha256', secret);
    const digest = hmac.update(JSON.stringify(payload)).digest('hex');
    
    // Use timing-safe comparison to prevent timing attacks
    return crypto.timingSafeEqual(
      Buffer.from(signature),
      Buffer.from(digest)
    );
  } catch (error) {
    return false;
  }
}

function validatePayloadStructure(payload) {
  const requiredFields = ['meta', 'data'];
  const requiredMeta = ['event_name'];
  
  // Check top-level structure
  requiredFields.forEach(field => {
    if (!payload[field]) {
      throw new Error(`Missing required field: ${field}`);
    }
  });
  
  // Check meta structure
  requiredMeta.forEach(field => {
    if (!payload.meta[field]) {
      throw new Error(`Missing required meta field: ${field}`);
    }
  });
  
  // Check data structure
  if (!payload.data.id || !payload.data.type) {
    throw new Error('Invalid data structure');
  }
}

// Webhook specific logger
class WebhookLogger {
  static logIncoming(event) {
    logger.info('INCOMING_WEBHOOK', {
      event: event.meta.event_name,
      resourceId: event.data.id,
      timestamp: new Date().toISOString(),
      testMode: event.meta.test_mode || false
    });
  }
  
  static logProcessing(event, success = true, error = null) {
    logger.info('PROCESSING_WEBHOOK', {
      event: event.meta.event_name,
      resourceId: event.data.id,
      success,
      error: error?.message,
      duration: `${Date.now() - event._receivedAt}ms`
    });
  }
  
  static logError(event, error) {
    logger.error('WEBHOOK_ERROR', {
      event: event.meta.event_name,
      resourceId: event.data.id,
      error: error.message,
      stack: error.stack,
      timestamp: new Date().toISOString()
    });
  }
}
