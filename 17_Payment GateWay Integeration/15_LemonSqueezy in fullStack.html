Lemon Squeezy Integration in React and Nodejs

A secure, full-stack implementation guide for selling digital products using React, Node.js, and Lemon Squeezy.

1. The Mental Model

Core Security Principle Frontend requests a purchase. Backend authorizes the product. Lemon Squeezy controls the money. Webhook confirms the payment.

Everything else is just implementation detail. Here is the flow:

  • Frontend: Displays products (read-only) and collects business data (Name, Mobile).
  • Backend: Validates if the product ID is allowed (Gatekeeper).
  • Lemon Squeezy: Locks price, handles currency, charges card.
  • Webhook (Future): The only source of truth for "Payment Success".

2. The Backend

The backend acts as the gatekeeper. It holds the secrets and validation logic.

Server Entry Point

Standard Express setup with CORS allowed for your frontend URL.

import express from "express";
import bodyParser from 'body-parser';
import cors from "cors";
import { createNewCheckout, getAllProducts, getDefaultVariant } from './LSFunctions.js'

const app = express();
app.use(express.json());
app.use(cors({ origin: process.env.FRONTEND_URL }));

// 1. Fetch all products (Safe for public)
app.get('/getProducts', async (req, res) => {
  const products = await getAllProducts()
  res.json(products)
})

// 2. Create Checkout (The Sensitive Logic)
app.post('/create-checkout', async (req, res) => {
  const { productId, buyer } = req.body;
  
  // ALLOW LIST: Blocks ID guessing attacks
  const LMS_PRODUCTS = new Set([
    '746644', // ReactJs
    '746639', // Nodejs
    '746646', // NextJs
  ]);

  if (!LMS_PRODUCTS.has(productId)) {
    return res.status(400).json({ error: 'Invalid product ID' });
  }

  // Resolve Variant Server-Side
  const defaultVariant = await getDefaultVariant(productId);
  if (!defaultVariant) {
    return res.status(404).json({ error: 'Variant not found' });
  }

  // Generate secure URL
  const url = await createNewCheckout(defaultVariant.id);
  res.json({ url });
});

app.listen(4000, () => console.log("Server started"));

Lemon Squeezy Functions

These helper functions communicate with the Lemon Squeezy API securely. 

import { createCheckout, listProducts, listVariants } from "@lemonsqueezy/lemonsqueezy.js";
import './Ls_Config.js'

// Helper: Get Product Data for UI
export async function getAllProducts() {
    const response = await listProducts();
    if (response.error) return [];

    return response.data.data.map((product) => ({
        id: product.id,
        name: product.attributes.name,
        description: product.attributes.description,
        priceFormatted: product.attributes.price_formatted,
        thumbnail: product.attributes.thumb_url,
    }));
}

// Helper: Generate Checkout URL
export async function createNewCheckout(variantId) {
    const storeId = process.env.STORE_ID;
    const checkoutData = {
        checkoutOptions: { buttonColor: '#3b82f6' },
    };
    // This uses your Secret API Key on the server
    const response = await createCheckout(storeId, variantId, checkoutData);
    return response.data.data.attributes.url
}

// Helper: Find Variant from Product ID
export async function getDefaultVariant(productId) {
    const response = await listVariants({
        include: ['product', 'price-model']
    });
    const allVariants = response.data.data
    // Find the specific variant logic
    const productVariant = allVariants.filter(
        (variant) => variant.attributes.product_id == productId
    )
    return productVariant[0];
}

3. The Frontend

Frontend API Callers

Simple fetch wrappers to communicate with your backend.

export async function fetchProducts() {
    const res = await fetch('http://localhost:4000/getProducts');
    if (!res.ok) throw new Error('Failed to fetch products');
    return res.json();
}

export async function createCheckout(payload) {
    const res = await fetch('http://localhost:4000/create-checkout', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payload),
    });
    if (!res.ok) throw new Error('Failed to create checkout');
    return res.json();
}

📘 Lemon Squeezy Payment Processing

(Explained using YOUR Frontend + Backend)

1️⃣ Big picture

Your frontend never controls money. It only asks your Node.js server:

“Please create a checkout for this product.”

Your server then talks privately to Lemon Squeezy using a secret API key. Lemon Squeezy:

  • decides the price
  • collects the payment
  • notifies your server when payment succeeds
This separation of responsibility is what makes the system secure.

2️⃣ Your Frontend: What it does (and what it DOES NOT do)

What your frontend does ✅

From your code:

setSelectedProduct(product)

User selects a product, then on Proceed you collect: 

{
  productId,
  name,
  price,
  buyer: { fullName, mobile }
}

Important:

  • 👉 UI-level data only
  • 👉 NOT trusted for payment

The frontend does NOT ❌

  • decide the price
  • create a checkout
  • mark payment as successful

Why frontend is untrusted

  • Users can open DevTools
  • Modify JavaScript
  • Change productId or price
  • Call APIs manually
❌ Frontend data can be fake
✅ Backend must re-validate everything

3️⃣ Your Backend: The real authority

Step 1: Product allow-list

const LMS_PRODUCTS = new Set([
  '746644',
  '746639',
  '746646',
]);

Why this exists:

  • test products
  • cheap products
  • unrelated products
  • future products

Without restriction:

  • Attacker guesses IDs
  • Buys $1 product
  • Accesses $99 course
“I will ONLY sell these exact products.”

Step 2: Server resolves variant

const defaultVariant = await getDefaultVariant(productId);

Client sends productId
Server finds the real variant
Variant price is fixed inside Lemon Squeezy

Client never sends:

  • price
  • variantId
  • amount

Step 3: Server creates checkout

const url = await createNewCheckout(defaultVariant.id);

What happens:

  • Server calls Lemon Squeezy API
  • Uses secret API key
  • Checkout session created
  • Price, currency, tax are locked

4️⃣ Why users CANNOT reduce price

Attack Result
Change price in frontend ❌ Ignored
Change productId ❌ Blocked by Set
Guess variantId ❌ Never sent
Replay checkout URL ❌ Already used
Fake payment success ❌ No webhook

Why price is safe:
Price lives inside Lemon Squeezy’s database, not your code.

5️⃣ Payment success: how your server knows

Your server does NOT trust the frontend.

Lemon Squeezy
      ↓
POST /webhooks/lemonsqueezy
      ↓
Your Node.js backend

Webhook contains:

  • order ID
  • product ID
  • variant ID
  • total amount
  • buyer email

6️⃣ Why webhooks are trustworthy

  • server → server
  • signed with secret
  • cannot be called from browser
No webhook = No access

7️⃣ When access should be granted

  • ❌ Never on redirect
  • ❌ Never on frontend success
  • ✅ ONLY after webhook confirmation
Checkout URL ≠ Payment
Webhook = Payment

8️⃣ What is still your responsibility

  • Save orders in DB
  • Mark PAID via webhook
  • Prevent duplicate unlocks
  • Link order → user → course
  • Rate limit checkout endpoint

9️⃣ Security level

🟢 HIGH SECURITY
  • Server-side checkout
  • Product allow-list
  • Variant resolved server-side
  • Lemon-controlled pricing
  • Webhook confirmation

🔐 Final mental summary

Frontend asks
Backend decides
Lemon Squeezy charges
Webhook confirms
Server unlocks

Again the Missing Piece: Webhooks

window.location.href = url does not mean payment succeeded. It just means the user went to the payment page.

To actually unlock the course, you must listen for a Webhook. 

Lemon Squeezy Server 
       ↓ 
POST /webhooks/lemonsqueezy (Signed with Secret)
       ↓ 
Your Node.js Backend (Verifies Signature -> Unlocks Course)
