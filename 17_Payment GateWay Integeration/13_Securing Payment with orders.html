1. Core Security Principle (This changes everything)

In Lemon Squeezy, the frontend NEVER decides the price.

That single rule is why:

  • DevTools hacks don’t work
  • Amounts cannot be overridden
  • Orders are secure by default

This is fundamentally different from Razorpay.

2. What “Order” Means in Lemon Squeezy

In Lemon Squeezy, an Order is:

  • A server-side record
  • Created only after successful payment
  • Contains:
    • product
    • variant
    • locked price
    • tax
    • currency
    • customer
    • payment status
⚠️ Developers never create orders manually.
Lemon Squeezy auto-creates orders after payment is completed.

3. Who Controls the Price? (Source of Truth)

Lemon Squeezy Price Authority

Lemon Squeezy Dashboard └── Store └── Product └── Variant └── Price (LOCKED) (LOCKED)

This price:

  • Lives only on Lemon Squeezy servers
  • Is never sent from frontend
  • Is never accepted from backend

4. What the Frontend Actually Does (React)

❌ What React does NOT do

  • Does NOT send price
  • Does NOT send amount
  • Does NOT calculate tax
  • Does NOT talk to Lemon squeezy

✅ What React actually does

// React
fetch("/api/checkout", {
  method: "POST"
});

That’s it.

Even if someone opens DevTools:

  • There is no amount variable
  • Nothing meaningful to modify

5. Backend Role (Node.js + Lemon Squeezy SDK)

Your backend does one safe thing only:

Backend API

POST /api/checkout

Node.js Code (SAFE)

import { lemonSqueezy } from "@lemonsqueezy/lemonsqueezy.js";
const client = lemonSqueezy({
  apiKey: process.env.LEMON_SQUEEZY_API_KEY
});
const checkout = await client.checkouts.create({
  store_id: process.env.STORE_ID,
  variant_id: process.env.VARIANT_ID
});

res.json({ url: checkout.data.attributes.url });

Key Observations

  • ❌ no amount
  • ❌ no price
  • ❌ no currency
  • ❌ no tax

You are not allowed to pass them.

6. Where the Real Payment Logic Lives (LS Servers)

Once backend calls Lemon Squeezy:

Node.js Server ↓ Lemon Squeezy Server ├─ Validate variant_id ├─ Fetch price from DB ├─ Lock amount ├─ Calculate tax ├─ Create checkout session └─ Return checkout URL

⚠️ This all happens before the checkout page exists.

7. Checkout Page (Why DevTools Is Useless)

The checkout page:

  • Is hosted on lemonsqueezy.com
  • Is server-rendered
  • Is backed by Lemon Squeezy’s database
  • Sends payment details directly to Stripe

Even if attacker:

  • Changes displayed price
  • Modifies DOM
  • Overrides JS

👉 Stripe still receives the original locked amount.

8. Stripe Charge Flow (Critical)

Stripe charge request comes from:

Lemon Squeezy Server → Stripe API

NOT from:

Browser → Stripe

Stripe receives:

{
  "amount": 9900,
  "currency": "usd"
}

This value:

  • Was never visible in frontend
  • Was never editable
  • Was locked on LS servers

9. Order Creation (Automatic & Secure)

After successful payment:

Stripe → Lemon Squeezy

Lemon Squeezy:

  • └── creates Order

Order includes:

  • final amount
  • taxes
  • receipt
  • license key (if applicable)

Developers cannot tamper with this.

10. Webhooks (Verification Layer)

Your backend listens to: order_created

Example payload:

{
  "data": {
    "attributes": {
      "total": 9900,
      "currency": "USD",
      "status": "paid"
    }
  }
}

This webhook:

  • Comes from Lemon Squeezy
  • Is signed
  • Is the final authority

11. Why DevTools Attacks Fail (Explicit Reasons)

There is NO:

  • amount variable
  • price input
  • currency param
  • client-side order creation

There IS:

  • Variant ID → Server price lookup
  • Server-side Stripe charge
  • Immutable order record

So DevTools can only change visuals, not money.

12. Razorpay vs Lemon Squeezy (Security Difference)

Razorpay Flow (Risky by design)

// Backend
razorpay.orders.create({
  amount: req.body.amount // ⚠️ frontend controlled
});

If backend trusts frontend → money can be overridden.

Lemon Squeezy Flow (Secure by design)

checkouts.create({
  variant_id: "456"
});

No amount exists to override.

13. Mental Model (Remember This)

Razorpay = “Charge THIS amount” Lemon Squeezy = “Sell THIS product”

Product has a price already known.

14. Security Guarantees Lemon Squeezy Provides

  • Price authority on server
  • Stripe charge isolation
  • No client-side payment logic
  • Automatic order creation
  • Signed webhooks
  • PCI-compliant checkout

15. Final One-Line Truth

If the client never sends the price, the client can never cheat the price.

That is why Lemon Squeezy payments are secure by architecture, not by developer discipline.
