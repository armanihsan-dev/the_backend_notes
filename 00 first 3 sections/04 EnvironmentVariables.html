Understanding Environment Variables

What is an "Environment"?

Imagine you're going to bake a cake. Before you even start mixing, you need an "environment" for baking. This environment includes:

  • The kitchen: Where you'll do the baking.
  • The ingredients: Flour, sugar, eggs, etc.
  • The tools: Bowls, spoons, oven.
  • The recipe: Instructions on what to do.

All these things together form your "baking environment." You can't bake a cake without them, right?

Now, let's switch from cake baking to a computer program. When a program runs on your computer, it also needs an "environment" to operate. This computer environment includes:

  • The Operating System (OS): Like Windows, macOS, or Linux – it's the "kitchen" where programs run.
  • Files and Folders: Where the program itself is located, and where it might need to save or read data.
  • Other programs/libraries: Sometimes a program needs to use functions from other programs.

So, the "environment" in "environment variable" simply refers to the set of conditions and settings in which a computer program operates.

Definition

Environment variables are settings you give to your program(Process right here) from outside the code to tell it how to behave.

OR

An environment variable is just a special kind of variable. It's a named storage location that holds a piece of information that is part of the program's operating environment.

Think of it like a **global sticky note** for a program. When a program starts, it looks around its environment. It might see these sticky notes (environment variables) and read the information written on them.

They are like a shared notepad where your operating system stores important information that programs need to know. Just like how you might leave a note saying "milk is in the fridge" for your roommate, your computer leaves notes like "Python is installed in this folder" for programs to find.

Loaction :

🗂️ Where are environment variables stored? Environment variables are stored in memory, inside the process (like your terminal or running program). They are not saved permanently unless you set them in a configuration file or system setting.

Example: MyPictureViewer

Imagine you have a program called "MyPictureViewer". Instead of MyPictureViewer always looking for pictures in C:\MyPictures (on Windows), what if you want it to look in D:\VacationPhotos sometimes, or E:\SharedImages at other times?

You could put a sticky note (an environment variable) on your computer saying:

Sticky Note Name: PICTURE_FOLDER
Information on Sticky Note: D:\VacationPhotos

When "MyPictureViewer" starts, it reads the PICTURE_FOLDER sticky note and knows, "Ah, okay, I need to look for pictures in D:\VacationPhotos!"

Later, if you want it to look somewhere else, you just change the information on the sticky note:

Sticky Note Name: PICTURE_FOLDER
Information on Sticky Note: E:\SharedImages

You don't have to change "MyPictureViewer" itself! This is the power.

They are not variables within the program's code (like a variable x = 5 you write in Python). Instead, they are variables that are external to the program, provided to the program by the operating system or the user. The program then reads these external variables to understand its surroundings and behave accordingly.

Some Common Environment Variable Names

Some common environment variable names you'll encounter on most operating systems:

  • PATH: This is probably the most famous one. Its value is a list of directories where the operating system should look for executable programs. When you type notepad (on Windows) or ls (on Linux/macOS) into your command line, the OS checks each folder listed in PATH until it finds the notepad.exe or ls program.
  • HOME (on Linux/macOS) or USERPROFILE (on Windows): The value of this variable is the path to your personal user directory (e.g., /home/yourusername or C:\Users\YourUsername). Programs often use this to find your personal configuration files or documents.
  • TEMP or TMP: The value is a directory where programs can store temporary files.
  • LANG: The value indicates your preferred language and locale settings (e.g., en_US.UTF-8 for English, United States).

Types of Environment Variables

  1. User Variables (Your Personal Floor)

    These are just for you - like your private bedroom where you keep your personal stuff.

    Examples:

    • Your desktop wallpaper settings
    • Your personal Python packages location
    • Your custom shortcuts

    Who can see them: Only you (your user account)
    When they work: Only when you're logged in

  2. System Variables (The Building's Common Areas)

    These are shared by everyone who uses the computer - like the building's lobby that everyone can access.

    Examples:

    • WHERE Windows is installed (C:\Windows)
    • WHERE programs should look for files (PATH)
    • System-wide settings that all users need

    Who can see them: Every user on the computer
    When they work: Always, for everyone

  3. Process-Specific Variables (Temporary Guest Rooms)

    These are created just for one running program - like a hotel room that exists only while a guest is staying.

    Examples:

    • A web browser might create a variable to remember what page you're on
    • A game might store your current level temporarily
    • A script might create variables just for that one run

    Who can see them: Only that specific running program
    When they work: Only while that program is running - they disappear when it closes
