Node.js Process Notes 📝

What is a Node.js Process?

Suppose I open a folder only with an app.js file in VS Code and run 'node app.js' in the terminal. What happened? What is this?

When you run 'node app.js', you are initiating a Node.js process. A Node.js process is an instance of the Node.js runtime environment that is executing your JavaScript code. It's the environment where your application's code lives and runs, interacting with the operating system.

Understanding process.argv

And then when I try to write process.argv, it returns... I mean it represents which process is this? Is this black folder a process or which?

When you type process.argv, it returns an array containing the command-line arguments passed when the current Node.js process was launched. The "black folder" itself is not a process; it's just a directory. The process is the running instance of Node.js that is executing your app.js file.

process.argv will typically show:

  • process.argv[0]: The path to the Node.js executable (e.g., /usr/local/bin/node or C:\Program Files\nodejs\node.exe).
  • process.argv[1]: The path to the JavaScript file being executed (e.g., /path/to/your/folder/app.js).
  • Subsequent elements: Any additional arguments you passed after app.js (e.g., node app.js arg1 arg2 would make arg1 process.argv[2] and arg2 process.argv[3]).

So, process.argv reflects the specific command that started this particular Node.js process.

Difference between node.exe and node app.js

The difference between node.exe and node app.js lies in their roles during the execution of a Node.js application.

node.exe (or simply node) 🚀

  • node.exe (or node on Linux/macOS) is the Node.js runtime executable itself.
  • It's the core program that allows your computer to understand and execute JavaScript code outside of a web browser.
  • Think of it as the interpreter for your JavaScript files.
  • When you install Node.js, this executable file is placed on your system (often in a directory added to your system's PATH environment variable).
  • If you simply type node in your terminal and press Enter, it will launch the Node.js REPL (Read-Eval-Print Loop). This is an interactive environment where you can type JavaScript code directly, and Node.js will execute it and print the result immediately. It's useful for quick tests and experiments.

node app.js 💻

  • node app.js is a command you use in your terminal to instruct the node.exe runtime to execute a specific JavaScript file.
  • In this command:
    • node (or node.exe) is the executable that starts the Node.js environment.
    • app.js is the argument passed to the node executable, specifying the JavaScript file that you want to run.

Analogy 💡

  • Imagine node.exe as a car engine 🚗. It's the fundamental component that makes the car move.
  • And node app.js is like turning the ignition key and telling the car where to go (e.g., "start the engine and drive to the grocery store"). You're using the engine (node.exe) to perform a specific task (run app.js).

Summary of Differences ✨

  • node.exe: The Node.js runtime program itself. It's the "engine" that processes JavaScript.
  • node app.js: A command that tells the node.exe runtime to load and execute the JavaScript code contained within the app.js file. It's the instruction to "use the Node.js engine to run this specific script."

In essence, node.exe is the tool, and node app.js is an instruction to use that tool to accomplish a task.

When I run node.exe and then write process.argv? From where does this process come?

When you run node.exe directly in your terminal and then type process.argv in the Node.js REPL (Read-Eval-Print Loop), the process object, including process.argv, comes from the global process object that Node.js automatically provides in every running Node.js environment.

The process Global Object 🌐

  • The process object is a global object in Node.js, meaning you don't need to import or require it; it's always available.
  • It provides information about, and control over, the current Node.js process.
  • Think of it as Node.js's built-in way to interact with the underlying operating system and the environment in which your Node.js code is running.

Where process.argv Comes From in the REPL 🤔

  • When you simply run node.exe (or node) without specifying a file, Node.js starts its REPL. Even in this interactive mode, a Node.js process is active.
  • The process object is instantiated (created) by the Node.js runtime as soon as the node.exe executable is launched.
  • process.argv is a property of this process object. It's an array that holds the command-line arguments that were used to launch the current Node.js process.
  • In the case of just running node.exe to enter the REPL, process.argv will typically look like this: 
    [
  '/usr/local/bin/node', // or similar path to the Node.js executable
  // No second argument because you didn't specify a file to run
]
  • The first element (process.argv[0]) is always the path to the Node.js executable itself (node.exe or node).
  • There's no second element (process.argv[1]) because you didn't provide a JavaScript file name as an argument when you started the REPL.

So, process.argv isn't coming "from" the REPL itself, but rather it's a property of the global process object that is inherent to every Node.js process, including the one running the REPL. It reflects the arguments used to start that particular Node.js process.
