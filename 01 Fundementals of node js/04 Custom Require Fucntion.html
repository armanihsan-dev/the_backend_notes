Understanding Your Custom Node.js `require` Function 🎓

Alright class, settle down! 👋 Today, we're going to dissect a fascinating piece of code you've written: your very own simplified require function, inspired by Node.js. This is an excellent way to understand how modules work under the hood and how JavaScript's vm module plays a crucial role in creating isolated environments.

Let's break down your code file by file, and then we'll tie it all together.

`main.js` - The Conductor 🎬

This is your main script, the one that kicks everything off.

const load = loadModule('./math.js');
const vm = require('vm');
var num = 6;

vm.runInThisContext('var a=5');
vm.runInNewContext('console.log(num)', { num, console });

function loadModule(path) {
  const fs = require('fs');
  let fileContent = fs.readFileSync(path).toString();

  return (function (send) {
    const vm = require('vm');
    vm.runInNewContext(fileContent, { send, loadModule, console });
    return send;
  })({});
}

console.log(load);

`require('vm')`

First things first, you're bringing in the `vm` module. Think of `vm` (Virtual Machine) as a mini-JavaScript engine within your Node.js application. It allows you to execute JavaScript code in different contexts.

`var num = 6;`

This declares a variable `num` in the global scope of your `main.js` file. In Node.js, `var` declarations at the top level of a module are scoped to that module, not truly global to the entire process, but within the context of `main.js`, `num` is accessible everywhere.

`vm.runInThisContext('var a=5');`

This is where it gets interesting! 🧐 `vm.runInThisContext()` executes the provided code string (`'var a=5'`) within the current V8 context. This means `var a=5` is run as if you had typed `var a=5;` directly into `main.js` at that line. So, `a` becomes a variable accessible within `main.js`'s scope. It essentially "pumps" new code into the existing execution environment.

`vm.runInNewContext('console.log(num)', { num, console });`

Now, this is crucial for understanding how the `num` variable is logged. `vm.runInNewContext()` creates a brand new, isolated V8 context. It's like a fresh, empty JavaScript environment. The second argument is the `sandbox` object.

How `console.log(num)` works:

When `vm.runInNewContext` executes `'console.log(num)'`, it looks for `num` within the `sandbox` object. You've explicitly passed `{ num, console }` into the sandbox. This means:

  • The `num` from your `main.js`'s scope (which has a value of 6) is copied into the new context's `num` variable.
  • Your `console` object (the one you use for `console.log` in `main.js`) is also copied into the new context's `console` variable. This is why the `console.log` inside the new context actually outputs to your terminal – it's using the same underlying `console` object.

Therefore, the `console.log(num)` inside `runInNewContext` successfully prints 6 because you explicitly provided `num` to its isolated environment via the sandbox. It doesn't have direct access to `main.js`'s `num`; it only has access to what you give it in the sandbox.

`function loadModule(path)` - Your Custom `require` 🏗️

This is the heart of your custom module loader.

function loadModule(path) {
  const fs = require('fs');
  let fileContent = fs.readFileSync(path).toString();

  return (function (send) {
    const vm = require('vm');
    vm.runInNewContext(fileContent, { send, loadModule, console });
    return send;
  })({});
}
  • `const fs = require('fs');`: You need the Node.js `fs` (File System) module to read the content of your module files.
  • `let fileContent = fs.readFileSync(path).toString();`: This reads the entire content of the specified file (e.g., `math.js` or `sum.js`) as a string.
  • `return (function (send) { ... })({});`: This is a crucial pattern. You're immediately invoking an anonymous function and passing an empty object `{}` as its `send` argument. This `send` object will act as the `exports` object for your modules.
  • `vm.runInNewContext(fileContent, { send, loadModule, console });`: This is where your module's code (`fileContent`) is executed.
    • It's run in a new, isolated context again.
    • The `sandbox` is populated with three key items:
      • `send`: This is the empty object we just discussed. This object is what your modules will attach their exported functionalities to (e.g., `send.a = 5`, `send.addition = ...`).
      • `loadModule`: This is how `math.js` and `sum.js` get access to your `loadModule` function! You explicitly pass it into their sandbox. Without this, they wouldn't be able to `loadModule` other files. This mimics how Node.js makes `require` available within every module.
      • `console`: Again, you're providing the standard `console` object so your modules can log messages.
  • `return send;`: After the module's code (`fileContent`) has been executed in its isolated context, the `send` object (which now contains all the exported properties) is returned by `loadModule`. This is similar to what `require()` in Node.js returns: the `exports` object of the loaded module.

`math.js` - The First Loaded Module ➗

const { addition } = loadModule('./sum.js');
console.log(addition(5, 6));
send.a = 5;

When `main.js` calls `loadModule('./math.js')`, the content of `math.js` is executed in a new `vm.runInNewContext` environment with `send`, `loadModule`, and `console` in its sandbox.

  • `const { addition } = loadModule('./sum.js');`: Inside `math.js`, you're calling `loadModule` again! This works because, as we just discussed, `loadModule` was passed into `math.js`'s sandbox. It then proceeds to load `sum.js`.
    • The `loadModule('./sum.js')` call will return the `send` object from `sum.js` (which will have the `addition` function attached to it).
    • The object destructuring `{ addition }` then extracts the `addition` property from that `send` object.
  • `console.log(addition(5, 6));`: `math.js` can now use the `addition` function it just received from `sum.js` and log the result. This `console.log` works because `console` was also passed into `math.js`'s sandbox.
  • `send.a = 5;`: This is how `math.js` "exports" a value. It attaches a property `a` with the value `5` to the `send` object that was provided to it. Remember, this `send` object is what `loadModule('./math.js')` in `main.js` will ultimately return.

`sum.js` - The Utility Module ➕

send.addition = (a, b) => a + b;

When `math.js` calls `loadModule('./sum.js')`, the content of `sum.js` is executed in yet another new `vm.runInNewContext` environment, also with `send`, `loadModule`, and `console` in its sandbox.

  • `send.addition = (a, b) => a + b;`: This is how `sum.js` "exports" its `addition` function. It attaches a property named `addition` to the `send` object that was given to it. This `send` object is then returned by the `loadModule('./sum.js')` call back to `math.js`.

The Grand Finale: `console.log(load);` in `main.js`

Finally, back in `main.js`, after all the modules have been loaded and executed:

console.log(load);

The `load` variable holds the return value of `loadModule('./math.js')`. As we saw, `loadModule('./math.js')` returns the `send` object that `math.js` was given. And what did `math.js` do to its `send` object? It added `send.a = 5;`.

So, `console.log(load)` will output:

{ a: 5 }

Summary and Key Takeaways 🎓

Here's a recap of the key concepts and your questions:

How `vm` runs in the global scope / accesses local scope (`console.log(num)`)

  • `vm.runInThisContext()` directly executes code in the current global scope of the script it's called from. So, `var a=5` in `main.js` is truly in `main.js`'s scope.
  • `vm.runInNewContext()` creates an isolated sandbox. It doesn't inherently have access to your local or global variables. You explicitly pass what you want it to have access to via the `sandbox` object. The `num` variable was accessible to `vm.runInNewContext('console.log(num)', { num, console });` because you copied `num` (and `console`) into its sandbox.

How `math.js` has access to `loadModule` function

  • When you call `loadModule('./math.js')`, your `loadModule` function executes `vm.runInNewContext(fileContent, { send, loadModule, console });`.
  • Notice that `loadModule` itself is passed as a property into the `sandbox` object. This makes your `loadModule` function available as `loadModule` *inside* the `math.js` context, allowing `math.js` to then call `loadModule('./sum.js')`. This is exactly how Node.js makes `require` available to every module.

Your implementation beautifully demonstrates the core principles of module loading:

  • Isolation: Each module runs in its own distinct context, preventing global variable pollution between modules.
  • Dependency Injection: You explicitly "inject" (pass into the sandbox) the necessary functionalities (like `send` for exports, `loadModule` for loading other modules, and `console` for logging) into each module's environment.
  • Export Mechanism: The `send` object acts as the container for exporting values from one module to another.
