CommonJS: module.exports vs. exports

In CommonJS, both module.exports and exports are used to expose values from a module, but they function differently.

---

module.exports

  • This is the actual object that gets returned when a module is require()d.
  • If you assign a new value to module.exports, that new value becomes the sole export of the module.
---

exports

  • This is a reference to module.exports.
  • Initially, exports points to the same empty object that module.exports points to.
  • You can add properties to exports (e.g., exports.foo = 'bar'), and these properties will be added to the object that module.exports refers to.
  • However, if you reassign exports to a new object (e.g., exports = { foo: 'bar' }), it breaks the reference to module.exports. In this case, module.exports will still be the original empty object (or whatever it was previously assigned), and your changes to the re-assigned exports will not be reflected in the module's actual exports.
---

Key Differences

Assignment vs. Property Assignment:

  • You can assign a new value to module.exports to completely replace what the module exports. This is common when you want to export a single function, class, or primitive value.
  • You can only add properties to exports. You cannot reassign exports itself if you want those changes to be reflected in the module's actual exports.

Return Value:

  • The require() function always returns the value of module.exports.

Use Cases:

  • Use module.exports when you want to export a single entity (e.g., a function, a class, an object literal).
  • Use exports when you want to export multiple named properties from your module. This is essentially a shorthand for module.exports.propertyName = value.
---

Examples

Using module.exports

// myModule.js
function sayHello(name) {
  return `Hello, ${name}!`;
}

module.exports = sayHello; // Exporting the function directly

// anotherFile.js
const greet = require('./myModule');
console.log(greet('Alice')); // Output: Hello, Alice!

Using exports

// myOtherModule.js
exports.add = (a, b) => a + b;
exports.subtract = (a, b) => a - b;

// anotherFile.js
const math = require('./myOtherModule');
console.log(math.add(5, 3));      // Output: 8
console.log(math.subtract(10, 4)); // Output: 6

Incorrect Use of exports (Reassigning exports)

// problematicModule.js
exports = {
  name: 'John Doe' // This assignment will NOT be exported
};

module.exports.age = 30; // This will be exported

// anotherFile.js
const data = require('./problematicModule');
console.log(data);         // Output: { age: 30 }
console.log(data.name);    // Output: undefined (because `exports = { name: 'John Doe' }` was ignored)

Important Note: In problematicModule.js, reassigning exports broke its reference to module.exports. Therefore, when anotherFile.js requires the module, it only receives the properties attached to the original module.exports object.
