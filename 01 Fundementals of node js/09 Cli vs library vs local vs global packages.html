The terms "CLI packages," "library," "local," and "global" refer to different aspects of software components and how they're installed and used, especially in the context of programming languages and their package managers (like npm for JavaScript, pip for Python, etc.).

// BREAKDOWN_01.1 //

📦 Package

In general, a package (or module) is a bundle of code that provides specific functionalities. It's designed to be easily shared and reused in various projects. Packages often contain both executable code and other resources (like data or documentation).

📚 Library

A library is a type of package that provides a collection of pre-written code (functions, classes, modules, etc.) that you can import and use within your own program's code. Libraries are typically focused on providing functionalities that are called programmatically, meaning you interact with them by writing code that uses their exposed methods or properties.

Example: In JavaScript, libraries like React (for building user interfaces) or Lodash (for utility functions) are used by importing them into your .js files and then calling their functions.

🖥️ CLI Package (Command Line Interface Package)

A CLI package is a type of package that provides executable commands you run directly from your terminal or command line. Instead of being imported into your code, these packages are tools designed to be used by developers to perform various tasks, automate workflows, or interact with systems.

  • Key Trait: CLI packages often include a "bin" folder that exposes terminal commands.

Example: Create React App is a CLI tool that helps you set up a new React project quickly. You don't import create-react-app into your JavaScript code; you run npx create-react-app my-app in your terminal. Other examples include nodemon (for automatically restarting Node.js applications during development) or webpack (a module bundler).

🏠 Local Installation

When you install a package locally, it means the package is installed within the directory of your specific project. It's typically placed in a node_modules (for Node.js) or similar folder inside your project.

  • Scope: Only the current project can access and use this installed package.
  • Benefits:
    • Project Isolation: Each project can have its own version of a package, preventing conflicts if different projects require different versions of the same package.
    • Version Control: The exact versions of dependencies for a project are typically recorded in a package.json (or similar) file, ensuring consistent environments across different developers or deployment stages.
  • When to Use: This is the default and generally preferred method for installing packages that are direct dependencies of your project's code (libraries) or development tools that are specific to that project.

🌐 Global Installation

When you install a package globally, it means the package is installed in a single, system-wide location, making it accessible from any directory on your computer.

  • Scope: The package is available to all projects and can be run from any terminal location.
  • Benefits:
    • Convenience for CLI Tools: Ideal for CLI tools that you use frequently across multiple projects and don't need to be tied to a specific project's dependencies.
    • Reduced Duplication: Avoids installing the same package repeatedly in every project.
  • Drawbacks:
    • Version Conflicts: If you update a globally installed package, all projects using that package will use the new version, which can lead to compatibility issues if an older project relies on a specific older version.
    • Less Predictable Environments: Makes it harder to ensure consistent build environments across different machines or for different team members.
  • When to Use: Primarily for CLI packages/tools that you want to use as system-wide utilities (e.g., a global code formatter, a tool to scaffold new projects, or a server runner like http-server). For Node.js, npx (Node Package Execute) is often preferred for running locally installed CLI tools without needing a global installation.

To install a package globally, you typically use a specific flag or command with your language's package manager. The exact command varies depending on the programming language and its package manager.

npm (Node.js) 📦

npm install -g <package-name>

Example: To install the nodemon CLI tool globally:

npm install -g nodemon

This makes nodemon accessible from any directory in your terminal.

Important Note for npm: While global installs are convenient for CLI tools, for project dependencies, local installation is generally preferred. For running local CLI tools without a global install, consider using npx:

npx <package-name> <command-arguments>

For example: to run create-react-app without installing it globally:

npx create-react-app my-new-app

pip (Python) 🐍

pip install <package-name>

By default, pip install without an active virtual environment often installs packages globally (or to a user-specific global location if permissions are an issue). However, it's highly recommended to use virtual environments (like venv or conda) for project-specific dependencies to avoid conflicts.

To explicitly install a package globally (to your system's Python site-packages directory), you might need administrator/root privileges on some systems:

sudo pip install <package-name> # On Linux/macOS
pip install <package-name> # On Windows (from an elevated command prompt)

Example: To install a package like black (a code formatter) globally:

sudo pip install black

Alternative for Python CLI tools (Recommended): For Python-based command-line tools that you want to use globally, pipx is a much better alternative than pip install -g. pipx installs packages into isolated environments, preventing conflicts while still making them globally accessible.

First, install pipx:

pip install --user pipx
pipx ensurepath

Then, install your desired tool with pipx:

pipx install <package-name>

Example:

pipx install black

gem (Ruby) 💎

gem install <gem-name>

Similar to pip, installing gems globally might require sudo on some systems depending on your Ruby installation:

sudo gem install <gem-name>

Example: To install the rails gem (the Ruby on Rails framework) globally:

sudo gem install rails

Important Note for Ruby: While you can install gems globally, for Ruby projects, Bundler and Gemfile are the standard for managing project-specific dependencies, similar to npm's package.json. Bundler installs gems locally within your project's context.

General Considerations:

  • Permissions: You might encounter permission errors (e.g., EACCES on macOS/Linux for npm, or permission denied for pip/gem) if you try to install globally without sufficient privileges. Using sudo (on Linux/macOS) or running your command prompt/terminal as an administrator (on Windows) usually resolves this, but it should be done with caution.
  • Virtual Environments: For project development, it's almost always recommended to use local installations within virtual environments to isolate dependencies and avoid conflicts between different projects. Global installations are best reserved for standalone command-line tools that aren't tied to a specific project.

// INSTALL_GLOBAL_NODEJS_03.0 //

To install a package globally in Node.js, you use the npm (Node Package Manager) command with the -g or --global flag.

npm install -g <package-name>

What does this do?

When you install a package globally, npm places it in a single, system-wide directory. This makes the package's executable commands (if it's a CLI tool) accessible from any location in your terminal, without needing to be in a specific project's directory.

When to use global installation?

Global installations are primarily used for Command Line Interface (CLI) tools that you want to use across multiple projects or as standalone utilities. Examples include:

  • nodemon: A tool that helps develop Node.js based applications by automatically restarting the node application when file changes in the directory are detected.
  • create-react-app: A tool for quickly setting up a new React project.
  • http-server: A simple zero-configuration command-line http server.

Example

To install nodemon globally, you would run:

npm install -g nodemon

After this, you can open your terminal in any project directory and run nodemon to start your Node.js application, assuming your package.json has a start script defined, or you specify a file like nodemon app.js.

Important Considerations

  • Permissions: You might encounter permission errors (e.g., EACCES) when trying to install globally on macOS or Linux. If this happens, you might need to use sudo:
    sudo npm install -g <package-name>
    However, using sudo with npm is generally discouraged due to potential security risks. A better long-term solution is to fix your npm permissions.
  • npx for Local CLI Tools: For many modern Node.js projects, especially when dealing with project-specific CLI tools (like create-react-app or build tools), it's often preferable to use npx to run packages that are installed locally or even fetch and run a package remotely without installing it globally. npx comes bundled with npm (version 5.2 and later). For example, instead of globally installing create-react-app, you can run it directly with npx:
    npx create-react-app my-new-app
    This ensures that you're always using the latest version of the tool or the version specified in your project's package.json for consistency.
  • Project Dependencies: For packages that your project's code directly relies on (libraries like React, Express, Lodash, etc.), you should always install them locally within your project directory (e.g., npm install <package-name>). This ensures project isolation and version control.
