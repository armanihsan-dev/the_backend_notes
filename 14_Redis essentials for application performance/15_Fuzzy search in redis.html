Implementing Fuzzy Search in Redis from Node.js

Implementing **fuzzy search** in Redis from Node.js is primarily done using the **Redis Stack** (specifically the **RediSearch** module) and a compatible **Node.js client** or **Object-Mapping (OM) library**.

Fuzzy search allows you to find strings that are **approximately equal** to a given pattern, which is great for handling misspellings or typos. The core mechanism in RediSearch for fuzzy matching is the use of the **percent sign (%)** around terms in your query.

Here is a general overview of the steps involved:

1. Prerequisites and Setup ⚙️

You'll need a Redis server running with the **RediSearch module** enabled (which is included by default in **Redis Stack**).

A. Install Node.js Dependencies

You will typically use the @redis/search module or a higher-level library like redis-om-node (Redis Object Mapper for Node.js). For this example, we'll focus on the raw **node-redis client**, which includes the necessary search commands. 

Bash
npm install redis

B. Connect to Redis

Establish a connection in your Node.js application:

JavaScript
import { createClient } from 'redis';
// Connect to your Redis server (ensure it's running Redis Stack/RediSearch)
const client = createClient(); 

client.on('error', err => console.error('Redis Client Error', err));
await client.connect();

2. Creating a Search Index 📝

RediSearch works by creating a **secondary index** over your data (which is typically stored as **Redis Hashes** or **JSON documents**).

A. Define the Schema

You need to tell RediSearch which fields to index and what type of data they hold (e.g., TEXT, TAG, NUMERIC).

In this example, let's index a field called name as TEXT. 

JavaScript
import { SchemaFieldTypes } from 'redis';
const indexName = 'productIdx';
try {
    await client.ft.create(indexName, {
        name: {
            type: SchemaFieldTypes.TEXT,
            SORTABLE: true // Optional: allows sorting by this field
        },
        description: {
            type: SchemaFieldTypes.TEXT
        }
    }, {
        ON: 'HASH', // Index Redis Hashes
        PREFIX: 'product:' // Only index keys starting with 'product:'
    });
    console.log(`Index ${indexName} created.`);
} catch (e) {
    if (e.message === 'Index already exists') {
        console.log(`Index ${indexName} already exists.`);
    } else {
        throw e;
    }
}

B. Add Documents

Store some data (products) using the defined key prefix (product:): 

JavaScript
await client.hSet('product:1', { name: 'Apple Watch Series 9', description: 'The latest smart watch from Apple.' });
await client.hSet('product:2', { name: 'Samsung Galaxy Watch 6', description: 'A sleek Android-compatible smartwatch.' });
await client.hSet('product:3', { name: 'Googal Pixel Watch 2', description: 'A stylish smart watch.' });

3. Performing a Fuzzy Search 🔍

The key to fuzzy search in RediSearch is wrapping the search term in the **percent symbol (%)**.

  • %term%: This performs a fuzzy match with a **Levenshtein distance of 1**. This means it can find terms with one character substitution, insertion, or deletion.
  • %%term%%: This increases the Levenshtein distance to **2** (more "fuzzy" results, but potentially less accurate).
  • %%%term%%%: **Distance of 3**.

Let's search for "Googal" (which is a misspelling of "Google"):

JavaScript
/**
 * @param {string} index The name of the index
 * @param {string} searchTerm The term to search for (e.g., 'watch')
 * @param {boolean} fuzzy Use true for fuzzy search (%term%)
 */
async function performSearch(index, searchTerm, fuzzy = false) {
    const queryTerm = fuzzy ? `%${searchTerm}%` : searchTerm;
    
    // The query targets the 'name' field using the syntax: @field:term
    const query = `@name:${queryTerm}`;
    
    const results = await client.ft.search(index, query);

    console.log(`\nSearch for '${searchTerm}' (Fuzzy: ${fuzzy})`);
    console.log(`Found ${results.total} results:`);
    results.documents.forEach(doc => {
        console.log(`- Key: ${doc.id}, Name: ${doc.value.name}`);
    });
}
// 1. Exact/Prefix Search (No results for the typo)
await performSearch(indexName, 'Googal', false); // Output: Found 0 results
// 2. Fuzzy Search (Finds the match)
await performSearch(indexName, 'Googal', true); // Output: Found 1 results, Name: Googal Pixel Watch 2

Summary of the Fuzzy Query Syntax

When building your query string for client.ft.search(), remember the fuzzy syntax:

$$@\text{field}:\%\text{term}\%$$

This approach leverages the power of the RediSearch module to efficiently handle the complex task of approximate string matching.

1. Logical Operations (OR and Exclusion)

RediSearch uses standard logical operators to combine or exclude terms. By default, terms are combined with a logical **AND**.

🌠 Search by Any Word (Logical OR)

JavaScript
await client.ft.search("userIdx", "Bhupesh|Sahil");
  • **Syntax:** The **vertical bar (|)** acts as the logical **OR** operator.
  • **Result:** This query searches the userIdx index for documents that contain **either** the word "Bhupesh" **or** the word "Sahil" in any indexed field.
  • **Example:** If one document has "Bhupesh is a developer" and another has "Sahil is a designer," both will be returned.

🚫 Excluding Words from Search (Logical NOT) 

JavaScript
await client.ft.search("userIdx", "-Sanat");
  • **Syntax:** The **minus sign (-)** acts as the logical **NOT** operator.
  • **Result:** This query returns **all** documents in the userIdx index **except** for those that contain the word "Sanat".
  • **Combining:** Exclusion is often used with other terms, e.g., Delhi -Gurgaon returns documents that contain "Delhi" but not "Gurgaon".

2. Paging Results (Pagination)

This is crucial for handling large result sets and displaying them to a user across multiple pages. 

JavaScript
await client.ft.search("userIdx", "Delhi", {
  LIMIT: {
    from: 10,
    size: 5,
  },
});
  • **Purpose:** The LIMIT parameter allows you to control which slice of the total result set is returned.
  • from **(Offset):** This is the **starting index** (zero-based) of the first document you want to retrieve. A value of 10 skips the first 10 matching documents.
  • size **(Count):** This is the **maximum number of documents** to return in the current page. A value of 5 returns the next 5 documents.
  • **Result:** This specific query finds all documents containing the word "Delhi," skips the first 10, and returns the **next 5 documents** (documents 11 through 15 from the full, sorted list).

3. Partial Word Search (Wildcards)

RediSearch supports **wildcard matching** using the **asterisk (*)**, which is similar to prefix, suffix, and substring matching in traditional SQL databases.

🔠 Prefix Match

JavaScript
await client.ft.search("userIdx", "Kum*");
  • **Syntax:** The asterisk (*) is placed at the **end** of the term.
  • **Result:** This query searches for all words that **start** with "Kum" (e.g., "Kumar", "Kumari", "Kumbh").
  • **Efficiency Note:** Prefix searches are generally very fast in RediSearch because of the underlying data structures (like a **Trie**).

Suffix Match

JavaScript
await client.ft.search("userIdx", "*mar");
  • **Syntax:** The asterisk (*) is placed at the **beginning** of the term.
  • **Result:** This searches for all words that **end** with "mar" (e.g., "Kumar", "Omar", "Samar").
  • **Efficiency Note:** Suffix searches are **slower** than prefix searches, as the index is optimized for prefixes. For better performance on frequent suffix searches, you might use a special indexing technique called **suffix indexing**.

Specific Suffix Match

JavaScript
await client.ft.search("userIdx", "*maar");
  • **Syntax:** Same as a general suffix match.
  • **Result:** This searches for all words that **end** with "maar". It is simply a more specific version of the suffix query above, looking for terms like "Gumaar" or "Nirmaar."
  • **Substring/Infix Match:** You can also combine wildcards for a substring search (e.g., *ma* would find "Kumar," "Samar," "Manual," etc.).

Summary Table of Query Modifiers

Query Type Syntax Example Meaning
**OR** `term1|term2` Match documents containing *either* term1 *or* term2.
**NOT** `-term1` Match documents that *do not* contain term1.
**Prefix** `term*` Match words that *start* with the prefix.
**Suffix** `*term` Match words that *end* with the suffix.
**Paging** LIMIT: {from: X, size: Y} Skip X results and return the next Y results.
