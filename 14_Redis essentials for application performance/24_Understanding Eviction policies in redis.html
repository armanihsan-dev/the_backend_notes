🧠 Redis Eviction Policy Explained

Redis Eviction Policies are rules that determine which keys to remove when the Redis instance reaches its configured **maximum memory limit** (maxmemory). Since Redis is an **in-memory data store**, this mechanism is crucial for using it as a fixed-size cache to prevent **out-of-memory errors** and ensure continuous operation.

When a client command attempts to add new data and the memory usage exceeds the maxmemory limit, Redis executes the chosen eviction policy to free up space. This policy is set using the maxmemory-policy configuration directive.

🛠️ Available Eviction Policies

Redis offers several policies, which can be grouped into two main categories: those that consider **all keys** and those that consider only **volatile keys** (keys that have an expiration or Time-To-Live, **TTL**, set).

Policy Category Policy Name Eviction Logic
No Eviction noeviction No keys are evicted. Instead, write commands that would cause more memory to be used are blocked and return an error. Read-only commands still work.
All Keys Policies allkeys-lru Evicts the **Least Recently Used (LRU)** keys out of **all keys**, regardless of whether they have a TTL set.
allkeys-lfu Evicts the **Least Frequently Used (LFU)** keys out of **all keys**, regardless of whether they have a TTL set.
allkeys-random Evicts keys **randomly** from **all keys**.
Volatile Keys Policies volatile-lru Evicts the **Least Recently Used (LRU)** keys only among those that **have a TTL set** (volatile keys).
volatile-lfu Evicts the **Least Frequently Used (LFU)** keys only among those that **have a TTL set** (volatile keys).
volatile-ttl Evicts volatile keys with the **shortest remaining Time-To-Live (TTL)**.
volatile-random Evicts keys **randomly** only among those that **have a TTL set** (volatile keys).

💡 Key Mechanisms Explained

Least Recently Used (LRU) and Least Frequently Used (LFU)

  • LRU (allkeys-lru / volatile-lru): This strategy assumes that a key that hasn't been accessed for the longest time is the least likely to be needed again. Redis uses an **approximated LRU algorithm** which works by sampling a small number of keys (default is 5) and evicting the oldest key among the sample. This is an efficient way to achieve near-perfect LRU without high overhead.
  • LFU (allkeys-lfu / volatile-lfu): This strategy is generally better for preserving **hot data**. It tracks an approximate frequency counter for each key. Keys that have been used the least number of times are evicted first, on the assumption that frequently accessed keys are more valuable.

Volatile vs. Allkeys

The difference between the allkeys-*** and volatile-*** policies is whether the eviction scope is **all keys** in the database or only the **volatile keys** (those created with an expiration time, e.g., using EXPIRE or SETEX).

  • If you are using Redis purely as a cache where all keys are temporary, an allkeys policy is a good choice.
  • If you have a mix of permanent data (no TTL) and cache data (with TTL), a volatile policy allows you to **protect your permanent keys** from being evicted.

Default and Recommended Policies

  • The historical default for Redis is often noeviction, but the common default in managed services like AWS ElastiCache is volatile-lru.
  • allkeys-lru is often the **recommended starting point** when using Redis as a general-purpose cache, as it reliably keeps the most recently used data in memory.

Checking Current Max Memory Limit

You can check the current maximum memory limit and the associated eviction policy in Redis using the CONFIG GET command via the redis-cli.

The two primary configuration parameters you'll want to check are:

  • maxmemory: The memory limit set in bytes.
  • maxmemory-policy: The eviction policy that is activated when the limit is reached.

1. Using CONFIG GET

Connect to your Redis instance using the command-line interface (redis-cli) and run the following commands:

A. Check the Max Memory Limit

The maxmemory directive returns the memory limit in bytes. 

redis-cli
127.0.0.1:6379> CONFIG GET maxmemory

Example Output:

1) "maxmemory"
2) "0"

Result 2: "0" - This is the **default value**, which means **no explicit memory limit is set**. Redis will continue to consume memory until the operating system runs out and potentially kills the process.

Result 2: "536870912" - This value (536,870,912 bytes) would indicate the limit is set to **512 MB**.

B. Check the Eviction Policy

The maxmemory-policy directive returns the name of the eviction policy in use. 

redis-cli
127.0.0.1:6379> CONFIG GET maxmemory-policy

Example Output:

1) "maxmemory-policy"
2) "noeviction"

Result 2: "noeviction" - This is the **default policy** when maxmemory is 0. If maxmemory is set to a non-zero value and this policy is active, all write commands will return an OOM (Out Of Memory) error when the limit is hit.

Result 2: "allkeys-lru" - This indicates the policy is set to evict the **Least Recently Used** keys from **all** keys when the limit is reached.

2. Using INFO

You can also retrieve memory information as part of the general server diagnostics using the INFO command. 

redis-cli
127.0.0.1:6379> INFO memory

Look for the following fields in the output:

Field Description
maxmemory The configured maximum memory limit in bytes.
used_memory The total number of bytes currently allocated by Redis.
used_memory_human The used_memory value displayed in human-readable format (e.g., 1.23G).

📝 Note on Configuration

The CONFIG GET command shows the **current runtime configuration**. If you set a value with CONFIG SET (e.g., CONFIG SET maxmemory 512mb), this change is immediate but will be lost when Redis restarts unless you also use CONFIG REWRITE to persist the change to the redis.conf file.

Setting Max Memory and Eviction Policy

You have two main ways to set the maxmemory limit and the maxmemory-policy (eviction policy) in Redis: **Runtime Configuration** and **Configuration File**.

The recommended best practice is to set these values in the configuration file to ensure the settings persist after a server restart.

1. Runtime Configuration (Using CONFIG SET)

This method modifies the configuration on a running Redis instance immediately, without requiring a restart.

A. Set the Max Memory Limit

The maxmemory value can be set in bytes, or using a human-readable format like KB, MB, or GB.

Unit Example Bytes Equivalent
KB 100kb 102,400
MB 256mb 268,435,456
GB 2gb 2,147,483,648

Example Command (Setting limit to 512 MB):

redis-cli
127.0.0.1:6379> CONFIG SET maxmemory 512mb
OK

B. Set the Eviction Policy

Choose one of the policies (e.g., allkeys-lru) and set it using CONFIG SET:

Example Command (Setting policy to All Keys - Least Recently Used): 

redis-cli
127.0.0.1:6379> CONFIG SET maxmemory-policy allkeys-lru
OK

C. Persist Changes (Crucial Step!)

Changes made via CONFIG SET are lost upon server restart unless you explicitly save them to the configuration file using CONFIG REWRITE. 

redis-cli
127.0.0.1:6379> CONFIG REWRITE
OK

Note: If you are using a managed service (like AWS ElastiCache, Azure Cache for Redis, or a cloud provider's Redis), you typically configure these settings through the provider's console/API, not via redis-cli.

2. Configuration File Method

This is the standard, permanent way to configure Redis. You modify the redis.conf file, and the settings take effect when Redis starts.

Steps:

  1. Locate the redis.conf file. The location varies by installation, but is often found at /etc/redis/redis.conf or in the Redis installation directory.
  2. Edit the file and find or add the following two directives. Uncomment them if they are commented out (often indicated by a # at the start of the line).

A. Set Max Memory:

Specify the limit. Using the human-readable format is recommended.

# Set the max memory limit to 1 Gigabyte
maxmemory 1gb

B. Set Eviction Policy:

Specify your desired eviction policy. allkeys-lru is a common and effective choice for general caching. 

# Set the eviction policy to allkeys-lru
maxmemory-policy allkeys-lru

C. Restart Redis

For the changes in the redis.conf file to take effect, you must restart the Redis server service: 

sudo systemctl restart redis-server
# OR (depending on your system)
sudo service redis restart

Recommended Policy Choices

Use Case Recommended Policy Rationale
General-Purpose Caching allkeys-lru Evicts the least-used items from **all** keys, maintaining the hottest data.
LFU-Optimized Caching allkeys-lfu Better than LRU if some keys are used frequently but not recently (e.g., a few popular landing pages).
Mixed Data (Permanent + Cache) volatile-lru Only evicts keys that have an explicit expiration (TTL) set, protecting your permanent data.
TTL-Based Prioritization volatile-ttl Evicts keys that are closest to expiring, making space for new data while ensuring time-sensitive keys live out their intended duration.

🚫 What Happens If maxmemory-policy is Set to noeviction?

When maxmemory-policy is set to noeviction (which is the default), Redis **will not remove any keys** when the memory limit is reached.

Instead:

  • Redis **refuses to accept new write operations** that require more memory.
  • It throws an OOM (Out Of Memory) error: 
    (error) OOM command not allowed when used memory > 'maxmemory'.
  • Read operations will still succeed.

This is useful when you want **strict control over key deletion**, but it requires careful memory monitoring.
