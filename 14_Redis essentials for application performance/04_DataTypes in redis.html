🧠 Redis Data Types: The Data Structure Store

That's a great topic! Redis is often called a **"Data Structure Store"** because it supports a wide variety of advanced data types beyond simple strings. Understanding these types is key to leveraging Redis effectively.

Here are the five primary supported data types in Redis:

1. 🔠 Strings (The Basic Type)

This is the **simplest type**, capable of holding any kind of data—**binary safe** (meaning you can store JPEGs, serialized Ruby objects, or simple text).

  • **Structure**: A sequence of bytes up to 512 MB.
  • **Use Cases**:
    • Caching HTML fragments or pages.
    • Simple key-value storage (e.g., storing a user's name: 
      SET user:1:name "Alice"
      ).
    • Counters and rate limiting (Redis provides commands to **atomically increment/decrement** strings, treating them as integers: 
      INCR user:1:visits
      ).

2. 📝 Lists

Redis Lists are essentially **linked lists** of strings, allowing **fast insertion and deletion at the head or tail**. This is different from the array-based lists found in many programming languages.

  • **Structure**: A collection of strings, maintained in **insertion order**.
  • **Key Feature**: Fast $O(1)$ (constant time) operations for pushing/popping elements from the left or right side.
  • **Use Cases**:
    • Implementing a **queue** (e.g., using LPUSH to add tasks and RPOP to consume them).
    • Implementing a **stack** (e.g., using LPUSH and LPOP).
    • Maintaining **recent items** (e.g., LPUSH new comments and trim the list using LTRIM to keep only the latest 500).

3. 🏷️ Sets

Redis Sets are an **unordered collection of unique strings**. You cannot have **duplicate members** in a set.

  • **Structure**: An **unordered collection** of strings with **no duplicates**.
  • **Key Feature**: Fast $O(1)$ membership testing (SISMEMBER) and powerful commands for performing **set operations** (union, intersection, difference).
  • **Use Cases**:
    • Tracking **unique visitors** (e.g., 
      SADD visitors:2025-11-25 user:101
      ).
    • Finding **common users** between groups (using SINTER).
    • Storing **unique tags** associated with a product.

4. 📊 Hashes

Redis Hashes are perfect for representing **objects or records**, similar to a map or dictionary in programming languages. They store a collection of **field-value pairs** under a **single key**.

  • **Structure**: A map where the key is the object identifier, and the values are field-value pairs (both strings).
  • **Key Feature**: Allows you to store many fields without consuming many unique keys in the Redis database, **saving memory overhead**.
  • **Use Cases**:
    • Storing **user profiles** (e.g., 
      HSET user:1 name "Alice" email "a@a.com"
      ).
    • Storing **product details** (e.g., title, price, stock count).
    • **Efficiently retrieving individual fields** of an object using HGET.

5. 🏆 Sorted Sets (ZSETs)

Sorted Sets are similar to regular Sets, but every member is associated with a **score** (a floating-point number). Members are always **ordered by their score**.

  • **Structure**: A collection of unique strings, where each string member has an associated **score** used for ordering.
  • **Key Feature**: Allows for very fast retrieval of members by **score range or rank** (e.g., the top 10 members).
  • **Use Cases**:
    • **Leaderboards** (e.g., storing game players and their scores).
    • **Ranking systems** (e.g., storing content popularity).
    • Implementing a **range-based queue** where you process tasks based on a timestamp (the score).

💡 Beyond the Basics (Geospatial & Bitmaps)

While the five above are the core types, Redis also offers advanced capabilities built on top of them:

  • **Geospatial (Geo)**: Uses a **Sorted Set internally** (via GeoHash encoding) to store coordinates (longitude, latitude) and efficiently query nearby points (e.g., "Find all users within 5km of this location").
  • **Bitmaps**: Treats a **String type** as a collection of bits. Excellent for **memory-efficient tracking of millions of items** (e.g., "Has user 10 million logged in today?").
  • **HyperLogLog**: A **probabilistic data structure** used to **estimate the count of unique items** (cardinality) with very low memory usage, but with a small standard error. Ideal for counting unique page views.
