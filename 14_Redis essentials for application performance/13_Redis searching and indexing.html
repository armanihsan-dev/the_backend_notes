Redis Search: Deep Dive & Indexing

Redis Search, powered by the RediSearch module (part of Redis Stack), provides powerful full-text search, secondary indexing, and query capabilities on top of Redis's in-memory data structures. It allows for complex queries, filtering, and sorting that go beyond simple key lookups.

📚 Core Definitions and Concepts

  • RediSearch: A Redis module that enables full-text search, secondary indexing, and aggregation.
  • Index: A data structure that RediSearch uses to quickly look up documents based on the values of specified fields.
  • Document: The data record being indexed and searched. In Redis, this is typically stored as a Hash or a JSON object.
  • Schema: The definition of which fields in your documents should be indexed and what type of index they should have (e.g., TEXT, NUMERIC, TAG).
  • Query Syntax: A specialized language used in the FT.SEARCH command to perform complex searches, including full-text, phrase matching, numerical ranges, and tag filtering.

RediSearch and JSON Components

Before diving into the code, it's helpful to understand the core components.

Concept Definition Key Role in Searching
JSON Data Type A native Redis data type (available with Redis Stack/v7+) that stores JSON documents efficiently. The storage format for your documents. Searching targets fields within this structure.
FT.CREATE The command used to define an index on specific Redis keys. Defines the schema (which fields to index) and the searchable structure (how to search them).
JSON Path A syntax (e.g., $.name, $.info.tags[*]['_']) used in RediSearch to specify fields inside a JSON document. Specifies exactly which nested fields within your JSON documents should be indexed.
FT.SEARCH The command used to query the index. Executes the search query against the index and returns matching JSON documents or fragments.

💻 Redis-CLI Syntax and Example

The redis-cli commands are fundamental for managing indexes and executing searches directly in ubuntu redis client or any redis-client (redis insight cli).

📌 Check Existing Indexes

FT._LIST // This command lists all existing Redis Search indexes.

📋 Get Information About an Index

FT.INFO indexName
// Example:
FT.INFO cityIdx // This command provides detailed information about the specified index, such such as: indexed fields and their types, number of documents, memory usage, failure stats, index options and definition. Use this to inspect and debug your indexes.

📌 Create Indexes for JSON Data

// 🔹 Index on city field (as TAG)
FT.CREATE cityIdx ON JSON PREFIX 1 "user:" SCHEMA $.city AS city TAG

// 🔹 Index on age field (as NUMERIC)
FT.CREATE ageIdx ON JSON PREFIX 1 "user:" SCHEMA $.age AS age NUMERIC

// 🔹 Index on name field (as TEXT)
FT.CREATE nameIdx ON JSON PREFIX 1 "user:" SCHEMA $.name AS name TEXT

🔍 Searching with Redis CLI

// 🔸 Search by City (exact match)
FT.SEARCH cityIdx "@city:{Delhi}"

// 🔸 Search Users by Exact Age
FT.SEARCH ageIdx "@age:[25 25]"

// 🔸 Search Users if the index is set as TEXT
FT.SEARCH nameIdx "@age:fancy"

// 🔸 Search Users with Age Greater Than or Equal to 28
FT.SEARCH ageIdx "@age:[28 +inf]"

// 🔸 Search Users with Age Less Than 28
FT.SEARCH ageIdx "@age:[-inf (28]"

// Note: +inf and -inf represent unbounded upper and lower limits.
// Use square brackets [] for inclusive bounds. Use parenthesis () for exclusive bounds.
// Examples: [25 30] → age between 25 and 30 (inclusive) | [25 (30] → age ≥ 25 and < 30

// 🔸 Search by Name (full-text)
FT.SEARCH nameIdx "@name:Anurag"

// 🔸 Command to Get Only the Matched Count
FT.SEARCH nameIdx "@name:Kumar" LIMIT 0 0

// 🔸 Command to Get the Selected Fields (only works for the field on which the search is being performed)
FT.SEARCH nameIdx "@name:Kumar" RETURN 1 name

❌ Drop an Index

// 🔹 Drop Index Only (keep documents)
FT.DROPINDEX nameIdx

// 🔹 Drop Index and Delete Documents
FT.DROPINDEX ageIdx DD

Schema Data Types: TEXT, TAG, NUMERIC

These are the three fundamental data types used when defining a RediSearch index schema on a Redis data type (like JSON or Hash). They tell the search engine how to store, process, and query the data in that specific field.

📝 TEXT Type

The TEXT field type is designed for full-text search. It's the standard type for any long-form, human-readable content.

Feature Description Example Use Case
Indexing Tokenized, lower-cased, and stemmed (by default). This means words are broken down, common endings are removed, and capitalization is ignored. Product descriptions, article bodies, email subjects.
Search Supports partial word matches, fuzzy matching, phrase matching, and complex Boolean queries (AND, OR, NOT). Searching for "running shoes" will often match documents containing the word "run" or "ran".
Syntax Standard query syntax: FT.SEARCH index "@field:keyword" Search for "premium wireless": FT.SEARCH idx "@desc:premium wireless"

🏷️ TAG Type

The TAG field type is designed for exact filtering and classification. It treats the entire field value as a single, atomic token.

Feature Description Example Use Case
Indexing Not tokenized or stemmed. The entire value is indexed as a single string (a "tag"). Ideal for discrete, categorical data. User IDs, product categories (e.g., 'Electronics', 'Apparel'), country codes (e.g., 'US', 'UK').
Search Supports exact matches only. You can efficiently check if a document has one or more specific tags. This is often used for faceted search. Filtering by multiple categories, languages, or features.
Syntax Requires curly braces {} and supports OR logic (using |): FT.SEARCH index "@field:{value1 | value2}" Search for tags 'Sci-Fi' OR 'Fantasy': FT.SEARCH idx "@genre:{Sci-Fi | Fantasy}"

🔢 NUMERIC Type

The NUMERIC field type is designed for storing numerical values and enabling range queries.

Feature Description Example Use Case
Indexing Stored as a floating-point number, enabling efficient mathematical comparisons. Price, quantity, age, rating, timestamp.
Search Supports querying for values within a specific range (inclusive or exclusive). Finding items within a budget or people within an age group.
Syntax Requires brackets [] to define the inclusive range: FT.SEARCH index "@field:[min max]" Search for products priced between 50 and 100: FT.SEARCH idx "@price:[50 100]"
Open Ranges You can use the special tokens -inf (negative infinity) or +inf (positive infinity) for open-ended ranges. Search for prices greater than 200: FT.SEARCH idx "@price:[200 +inf]"

🔍 Redis Search Numeric Range Examples (Exclusive & Inclusive)

This guide provides examples of how to use inclusive [] brackets and exclusive bounds using () within numeric ranges in Redis Search. Redis Search supports inclusive bounds on both sides or exclusive bounds on either or both sides within square brackets.

🔢 Common Range Query Variations with @age 

// 🔸 Exact Match (inclusive)
@age:[25 25] 	 # age == 25

// 🔸 Greater Than or Equal (inclusive)
@age:[25 +inf] 	 # age >= 25

// 🔸 Greater Than (exclusive)
@age:[(25 +inf] 	# age > 25

// 🔸 Less Than or Equal (inclusive)
@age:[-inf 28] 	 # age <= 28

// 🔸 Less Than (exclusive)
@age:[-inf (28] 	# age < 28

// 🔸 Between (inclusive on both ends)
@age:[25 30] 	 	 # 25 <= age <= 30

// 🔸 Between (inclusive lower, exclusive upper)
@age:[25 (30] 	 	# 25 <= age < 30

// 🔸 Between (exclusive lower, inclusive upper)
@age:[(25 30] 	 	# 25 < age <= 30

// 🔸 Between (exclusive on both ends)
@age:[(25 (30] 	# 25 < age < 30

✅ Use square brackets [] to wrap the entire range.
✅ Use ( on either side inside the square brackets to make a bound exclusive.
✅ Use +inf and -inf for unbounded ends.

🔍 Example Full Search Command

FT.SEARCH ageIdx "@age:[(25 (30]" // This returns users where age is strictly greater than 25 and strictly less than 30

🟢 Node.js Implementation
The most common way to interact with Redis/RediSearch in Node.js is using the node-redis client (v4.x+).

1. Setup

You'll need the redis package:

Bash

npm install redis

2. Client and Data Insertion

JavaScript

import { createClient } from 'redis';

// Connect to Redis
const client = createClient();
client.on('error', (err) => console.log('Redis Client Error', err));
await client.connect();

// Sample product data
const productData = {
  name: "Noise-Cancelling Earbuds",
  price: 129.99,
  description: "Small, powerful earbuds with active noise cancellation and clear sound.",
  features: ["ANC", "IPX4", "Touch Controls"]
};

// Insert the JSON document
await client.json.set('product:501', '$', productData);
console.log('JSON document inserted.');

3. Creating the Index (In Node.js)

You can define the schema programmatically using the client's ft.create method.

JavaScript

const indexName = 'idx:products_node';

try {
  await client.ft.create(indexName, {
    // Defines the scope of the index
    ON: 'JSON',
    PREFIX: 'product:',
    // Defines the schema fields
    SCHEMA: {
      '$.name': { type: 'TEXT', AS: 'name', WEIGHT: 5.0 },
      '$.price': { type: 'NUMERIC', AS: 'price' },
      '$.description': { type: 'TEXT', AS: 'desc' },
      '$.features[*]': { type: 'TAG', AS: 'features' },
    }
  });
  console.log(`Index ${indexName} created successfully.`);
} catch (e) {
  // RediSearch throws an error if the index already exists.
  if (e.message.includes('Index already exists')) {
    console.log(`Index ${indexName} already exists.`);
  } else {
    throw e;
  }
}

4. Searching the Index (In Node.js)

The ft.search method executes the query and returns results.

JavaScript

// --- 4.1: Search for "earbuds" in the name or description ---
const queryText = '@name|desc:earbuds';
const resultsText = await client.ft.search(indexName, queryText);

console.log(`\nResults for "${queryText});
console.log(resultsText);

/* Example Output Structure:
{
  total: 1,
  documents: [
    {
      id: 'product:501',
      value: { $: {
          name: 'Noise-Cancelling Earbuds',
          price: 129.99,
          // ... other fields ...
      }}
    }
  ]
}
*/

// --- 4.2: Search by Tag and Price Range ---
// Find products with the "ANC" tag AND a price greater than $100
const queryFilter = '@features:{ANC} @price:[100 +inf]';
const resultsFilter = await client.ft.search(indexName, queryFilter);

console.log(`\nResults for "${queryFilter});
console.log(resultsFilter);
