🗄️ Database Management in Redis using redis-cli

Redis is often referred to as a "single database instance," but it supports **multiple, logical databases** (numbered **0 to 15 by default**) within a single server instance. While modern applications often prefer dedicated Redis instances or key prefixes for isolation, these databases are still useful for simple separation.

Here is a deep dive into the commands for managing these logical databases using redis-cli.

1. 🌐 Connecting and Switching Databases

The core of managing databases in Redis is selecting which one you are currently working with.

SELECT

This command switches the current connection to a specified logical database.

  • Syntax: SELECT index
  • Arguments:
    • index: An integer between 0 and the maximum number of databases configured (usually 15).

Example:

# Connects to database 0 (the default)
127.0.0.1:6379> SET app:name "DatabaseZero"
OK
# Switch to database 1
127.0.0.1:6379> SELECT 1
OK
# Set a key in database 1
127.0.0.1:6379[1]> SET app:name "DatabaseOne"
OK
# Check that the key in database 0 is isolated
127.0.0.1:6379[1]> SELECT 0
OK
127.0.0.1:6379> GET app:name
"DatabaseZero"

2. 🔢 Database Information

You can check the size and current database number from the command line.

DBSIZE

Returns the **number of keys** in the currently selected database.

  • Syntax: DBSIZE

Example:

127.0.0.1:6379> SELECT 1
OK
127.0.0.1:6379[1]> SET key1 value1
OK
127.0.0.1:6379[1]> DBSIZE
(integer) 1

127.0.0.1:6379[1]> SET key2 value2
OK
127.0.0.1:6379[1]> DBSIZE
(integer) 2

📦 View the Number of Databases

To find out how many databases your Redis server is configured to use: 

CONFIG GET databases
or
redis-cli CONFIG GET databases

This will return the configured number of databases (default is **16**).

4. 🔀 Moving Keys Between Databases

MOVE

Moves a key from the **current database** to a specified destination database.

  • Syntax: MOVE key db
  • Return Values:
    • (integer) 1: The key was moved successfully.
    • (integer) 0: The key was not moved (either it didn't exist in the source or it already exists in the destination).

Example: Move the key user:101 from database 0 to database 3. 

# Start in database 0 and set the key
127.0.0.1:6379> SET user:101 "profile_data"
OK
127.0.0.1:6379> DBSIZE
(integer) 1
# Move the key to database 3
127.0.0.1:6379> MOVE user:101 3
(integer) 1
# Verify the move in database 0 (source)
127.0.0.1:6379> GET user:101
(nil)
# Verify the move in database 3 (destination)
127.0.0.1:6379> SELECT 3
OK
127.0.0.1:6379[3]> GET user:101
"profile_data"

⚙️ Configure the Number of Databases

By default, Redis supports up to 16 databases (0 to 15). You can change this limit by editing the Redis configuration file.

🔹 Modify redis.conf:

Mean create a file touch redis.conf and open it using nano editor nano redis.conf and write the number of datbase 

databases 40

Then close the file and close the redis server and start again by providing the create file like this : 

redis-server redis-conf

After this try to check the number of databses from redis-cli it will return 40

This restricts Redis to use only databases **0 to 3**.

Note: In modern Redis usage, most applications rely solely on database **0** and use **namespacing** (e.g., user:123, session:abc) to logically separate data.

📝 Key Points to Remember

  • Redis supports **numbered databases only** — no custom names.
  • All databases share the **same memory space**.
  • Redis does **not** track memory usage per database.
  • Consider using **key namespacing** instead of multiple databases.
