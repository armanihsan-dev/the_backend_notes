📄 Working with Redis Strings: CRUD Operations via `redis-cli`

This guide details the **CRUD (Create, Read, Update, Delete)** operations for Redis Strings using `redis-cli` with clear syntax, examples, and functional explanations.

1. 📝 Create/Update (C & U) Operations: `SET`

The SET command is the primary way to create or fully replace a String value associated with a key. Because it **overwrites** the value if the key already exists, it handles both initial **Creation** and a full **Update**.

Syntax and Example

Command Syntax Description Example
SET SET <key> <value> Sets the string value of a key. Overwrites the value if the key already exists. SET user:1:status "online"
SETNX SETNX <key> <value> SET if Not EXists. Only sets the key if it doesn't already exist. SETNX user:2:status "offline"

How It Works: `SET`

  • **Creation**: If user:1:status does not exist, Redis creates it and stores the value "online".
  • **Update**: If user:1:status already exists (e.g., value is "offline"), Redis **replaces** the value entirely with "online".

Incremental Updates

Redis provides specific commands to treat a String as a number and perform **atomic updates**.

Command Syntax Description Example
INCR INCR <key> Atomically increments the integer value of the key by 1. INCR page:views
INCRBY INCRBY <key> <amount> Atomically increments the integer value of the key by the specified amount. INCRBY user:1:score 15
APPEND APPEND <key> <string> Appends the value to an existing key's string. Creates the key if it doesn't exist. APPEND email:subject " (URGENT)"

How It Works: `INCR`

  • If page:views doesn't exist, Redis initializes it to 0, then increments it to 1, returning 1.
  • If the value is "9", it is incremented to "10", returning 10. This operation is **atomic** (safe from race conditions).

2. 📖 Read (R) Operations: `GET`

The GET command is the **fundamental way** to retrieve the value stored at a specific key.

Syntax and Example

Command Syntax Description Example
GET GET <key> Returns the string value associated with the key. GET user:1:status
MGET MGET <key1> <key2> ... Returns the values of all specified keys. MGET user:1:name user:2:name
GETSET GETSET <key> <new_value> Atomically sets a new value and returns the **old** value. GETSET process:lock "new_owner"

How It Works: `GET`

  • If the key exists and holds a String, Redis returns the value (e.g., "online").
  • If the key does not exist, Redis returns (nil).
  • If the key exists but holds a different data type (e.g., a List or Set), Redis returns an **error**.

3. 🗑️ Delete (D) Operation: `DEL`

While DEL can remove **any data type** in Redis, it is essential for the **Delete** operation on Strings.

Syntax and Example

Command Syntax Description Example
DEL DEL <key1> <key2> ... Removes the specified keys. A key is ignored if it does not exist. DEL user:1:status page:views

How It Works: `DEL`

  • Redis attempts to locate the specified keys.
  • Any keys that are found are completely **removed** from the database, along with their associated String value.
  • The command returns the **number of keys that were removed**.

4. Time-to-Live (TTL) Operations

While not strictly CRUD, controlling the lifespan of a key is **fundamental to using Strings for caching**.

Syntax and Example

Command Syntax Description Example
EXPIRE EXPIRE <key> <seconds> Sets a timeout on key. After the specified number of seconds, the key will be automatically deleted. EXPIRE auth:token:123 3600
TTL TTL <key> Returns the remaining time to live (TTL) in seconds for a key. TTL auth:token:123

How It Works: `EXPIRE`

The EXPIRE command sets a **volatile flag** on the key. Once the time runs out, Redis performs the DEL operation automatically, making it perfect for **temporary data** like session tokens or cached results.

⚡ Summary Example Flow (Combined Session)

Here is a quick session combining all String operations:

# 1. CREATE
127.0.0.1:6379> SET user:current:name "John"
OK

# 2. READ
127.0.0.1:6379> GET user:current:name
"John"

# 3. INCREMENT (Update)
127.0.0.1:6379> INCR job:queue:counter
(integer) 1

# 4. APPEND (Update)
127.0.0.1:6379> APPEND user:current:name " Doe"
(integer) 8

# 5. READ Updated value
127.0.0.1:6379> GET user:current:name
"John Doe"

# 6. SET Expiration
127.0.0.1:6379> EXPIRE user:current:name 60
(integer) 1

# 7. DELETE
127.0.0.1:6379> DEL user:current:name
(integer) 1

# 8. READ (Confirm Deletion)
127.0.0.1:6379> GET user:current:name
(nil)
