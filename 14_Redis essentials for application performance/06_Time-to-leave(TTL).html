Redis Time-To-Live (TTL) Deep Dive

Time-To-Live (TTL) in Redis allows you to associate an expiration timer with a key, causing Redis to automatically delete the key once the time limit is reached. This feature is vital for caching, session management, and temporary data storage.

Here is a deep dive into the most common TTL-related commands using redis-cli.

🔑 Setting a Key's TTL

You can set a key's expiration in several ways using redis-cli:

  1. EXPIRE: Set Expiration in Seconds

    This is the most common command for setting a key's relative expiration time.

    Syntax: EXPIRE key seconds [NX | XX | GT | LT]

    Example: Set user:session:123 to expire in 300 seconds (5 minutes). 

    # 1. Set the key's value (optional if the key already exists)
127.0.0.1:6379> SET user:session:123 "active"
OK
# 2. Set the expiration to 300 seconds
127.0.0.1:6379> EXPIRE user:session:123 300
(integer) 1 # Output (integer) 1 indicates the timeout was set.

  2. PEXPIRE: Set Expiration in Milliseconds

    Similar to EXPIRE, but allows for finer-grained control over the expiration time.

    Syntax: PEXPIRE key milliseconds [NX | XX | GT | LT]

    Example: Set temp:data:456 to expire in 1500 milliseconds (1.5 seconds). 

    # Set the key's value
127.0.0.1:6379> SET temp:data:456 "ephemeral"
OK
# Set the expiration to 1500 milliseconds
127.0.0.1:6379> PEXPIRE temp:data:456 1500
(integer) 1

  3. SETEX: Set Value and Expiration in One Command

    This is a convenient atomic command for setting a string key's value and its expiration time simultaneously. This is generally preferred over a separate SET and EXPIRE combination, especially for setting new keys.

    Syntax: SETEX key seconds value

    Example: Set cache:item:789 to the value "data" and expire in 60 seconds. 

    127.0.0.1:6379> SETEX cache:item:789 60 "data"
OK

  4. EXPIREAT and PEXPIREAT: Set Expiration at an Absolute Time

    These commands set the expiration to a specific absolute Unix timestamp, rather than a relative time (like "in 60 seconds").

    • EXPIREAT: Uses a Unix timestamp in seconds.
    • PEXPIREAT: Uses a Unix timestamp in milliseconds.

    Example (EXPIREAT): Assuming the Unix timestamp for 9:00 AM on January 1, 2026, is 1767292800. 

    127.0.0.1:6379> SET scheduled:job "pending"
OK
# Set the key to expire exactly at the timestamp
127.0.0.1:6379> EXPIREAT scheduled:job 1767292800
(integer) 1

🔍 Checking a Key's TTL

To check the remaining Time-To-Live of a key, you use the TTL or PTTL commands.

  1. TTL: Remaining Time in Seconds

    Syntax: TTL key

    Return Values:

    Value Description
    Positive Integer Remaining time in seconds.
    -1 The key exists but has no expiration set (it's persistent).
    -2 The key does not exist.

    Example:

    127.0.0.1:6379> SETEX temp:key 120 "testing_ttl"
OK
127.0.0.1:6379> TTL temp:key
(integer) 117 # Returns remaining seconds

# After the key expires or is deleted
127.0.0.1:6379> TTL temp:key
(integer) -2 

# For a persistent key
127.0.0.1:6379> SET persistent:key "data"
OK
127.0.0.1:6379> TTL persistent:key
(integer) -1

  2. PTTL: Remaining Time in Milliseconds

    Syntax: PTTL key

    Return Values:

    Value Description
    Positive Integer Remaining time in milliseconds.
    -1 The key exists but has no expiration set.
    -2 The key does not exist.

🗑️ Removing and Modifying TTL

  1. PERSIST: Remove Expiration

    The PERSIST command removes the expiration associated with a key, making it a permanent key again.

    Syntax: PERSIST key

    Example: Make user:session:123 persistent. 

    127.0.0.1:6379> TTL user:session:123
(integer) 290 # Key has 290 seconds left
127.0.0.1:6379> PERSIST user:session:123
(integer) 1 # Output (integer) 1 means the timeout was removed.
127.0.0.1:6379> TTL user:session:123
(integer) -1 # Now it's a persistent key

  2. Modifying TTL

    Calling EXPIRE or PEXPIRE on a key that already has an expiration will overwrite the existing TTL with the new value.

    Example: Extend the expiration of a key.

    127.0.0.1:6379> SETEX mykey 60 "value"
OK
127.0.0.1:6379> TTL mykey
(integer) 58
# Extend the TTL to 300 seconds
127.0.0.1:6379> EXPIRE mykey 300
(integer) 1
127.0.0.1:6379> TTL mykey
(integer) 300

📝 Key Considerations

  • Overwrite Behavior: Most Redis commands that modify a key's value (like SET, LPUSH, HSET) will not change the existing TTL. However, the basic SET key value command will remove the key's TTL if the key is updated without explicitly passing the EX or PX options.

    To retain TTL: Use the KEEPTTL option with SET: SET mykey "new_value" KEEPTTL.

  • Expirations on Containers: TTL is set on the entire key, not individual elements within container data structures (like Lists, Hashes, Sets, or Sorted Sets). If a key holding a Hash expires, the entire Hash is deleted.

  • TTL Granularity: Since Redis 2.6, key expiration is accurate to **1 millisecond**.
