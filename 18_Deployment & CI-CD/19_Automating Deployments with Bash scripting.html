WHAT IS DEPLOYMENT AUTOMATION WITH BASH SCRIPTING?

Deployment Automation is the process of automating the steps required to deploy software applications to various environments (development, staging, production).

Bash Scripting in this context means writing shell scripts (.sh files) that execute deployment commands automatically, replacing manual command-by-command execution.

WHY AUTOMATE DEPLOYMENTS?

  • Consistency: Same steps every time
  • Speed: Deploy in minutes instead of hours
  • Reliability: Fewer human errors
  • Reproducibility: Easy to deploy to multiple environments
  • Documentation: Scripts serve as deployment documentation

BASH BASICS

What is Bash?

Think of Bash as "talking to your computer in a way it understands". Instead of clicking buttons, you type commands.

What is a Bash Script?

A script is just a text file with a list of commands that your computer can run automatically.

Real-Life Analogy

Manual deployment = Following a recipe step-by-step yourself

Automated deployment with bash script = A robot chef that follows the recipe for you

PART 1: BASIC BASH - THE ABSOLUTE BASICS

1. Creating Your First Script

Step 1: Create a text file

# Type this in your terminal:
nano simple-script.sh

This opens a text editor. Type:

#!/bin/bash
# This is my first script
echo "Hello, I'm learning Bash!"
echo "Today is: $(date)"

What each line means:

  • #!/bin/bash = "Hey computer, this is a bash script, read it with bash!"
  • # This is my first script = Just a comment (computer ignores it)
  • echo = "Print this text on screen"
  • $(date) = "Get today's date and put it here"

Step 2: Save and exit

  • Press Ctrl + X
  • Press Y (for Yes to save)
  • Press Enter

2. MAKING IT EXECUTABLE: CHMOD +X

Problem: Your computer says "Permission denied" when you try to run the script.

Why? Because by default, text files aren't "executable" (can't be run like a program).

Solution: Make it executable with chmod +x

# Let's break down what this means:
chmod +x simple-script.sh

What chmod +x means:

  • chmod = "Change Mode" (change permissions)
  • +x = "Add eXecute permission" (make it runnable)
  • simple-script.sh = The file you want to change
Think of it like this 
File permissions = Lock on a door
- r (read) = Can look through the window
- w (write) = Can open the door and change things
- x (execute) = Can actually go inside and use it

chmod +x = Give the key to go inside and run it

3. RUNNING YOUR SCRIPT: ./DEPLOY.SH

# This is how you run it:
./simple-script.sh

What ./ means:

  • . = "Current folder" (where you are now)
  • / = Separator
  • So ./ = "Look in the current folder"

Why not just simple-script.sh?

Because your computer looks in special places for programs. ./ says "Look RIGHT HERE in this folder".

PART 2: YOUR FIRST REAL DEPLOYMENT SCRIPT

Let's create a super simple MERN deployment script.

Step-by-Step Manual Process (What you do now):

  1. Go to React folder
  2. Install packages: npm install
  3. Build React app: npm run build
  4. Go to backend folder
  5. Install backend packages: npm install
  6. Restart the server

NOW AUTOMATE IT!

Create the script:

nano deploy.sh

Type this (I'll explain line-by-line):

#!/bin/bash

echo "🚀 Starting MERN Deployment..."

# ask commit message
read -p "Enter commit message: " msg

echo "Building React app..."
cd client

npm install
npm run build

git add .
git commit -m "$msg"
git push

echo "Setting up backend..."
cd ../server

npm install

echo "Restarting server..."
npm run dev

echo "✅ Deployment complete!"

Make it executable:

chmod +x deploy.sh

Run it:

./deploy.sh
Terminal Interaction

Terminal will ask:

Enter commit message:

You type:

fixed login bug

PART 3: BREAKING DOWN A COMPLETE SCRIPT

Let me explain a REAL but simple deployment script piece by piece:

#!/bin/bash
# ----------------------------
# PART 1: SETUP
# ----------------------------
echo "Starting deployment..."

# Store the current folder path
PROJECT_DIR="/home/ubuntu/my-mern-app"
BACKUP_DIR="/home/ubuntu/backups"

# ----------------------------
# PART 2: FUNCTIONS
# ----------------------------
# Functions are like mini-scripts inside your script

# Function to backup the database
backup_database() {
    echo "Backing up database..."
    # This would backup MongoDB
    mongodump --out="$BACKUP_DIR/backup-$(date +%Y%m%d)"
}

# Function to deploy frontend
deploy_frontend() {
    echo "Deploying frontend..."
    cd "$PROJECT_DIR/client"
    npm install
    npm run build
}

# Function to deploy backend
deploy_backend() {
    echo "Deploying backend..."
    cd "$PROJECT_DIR/server"
    npm install
    # Copy the React build to backend public folder
    cp -r ../client/build/* public/
}

# ----------------------------
# PART 3: MAIN DEPLOYMENT
# ----------------------------
# This is where everything runs

echo "=== MERN DEPLOYMENT STARTED ==="

# Step 1: Backup
backup_database

# Step 2: Update code from GitHub
echo "Getting latest code..."
cd "$PROJECT_DIR"
git pull origin main

# Step 3: Deploy both parts
deploy_frontend
deploy_backend

# Step 4: Restart
echo "Restarting application..."
pm2 restart all

echo "=== DEPLOYMENT COMPLETE ==="
