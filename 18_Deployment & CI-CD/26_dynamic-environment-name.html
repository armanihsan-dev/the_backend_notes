DYNAMIC ENVIRONMENTS

RUNTIME ENVIRONMENT SELECTION IN GITHUB ACTIONS

WHAT IS IT? 🎯

Setting Environments Dynamically means creating or selecting GitHub Environments during workflow execution (at runtime) instead of hardcoding them beforehand. Environments in GitHub are deployment targets (like Production, Staging, Development) with specific protections, variables, and secrets.

Key Benefit

Dynamic environments allow a single workflow to adapt to different deployment targets based on runtime conditions like branch names, tags, or manual inputs.

STATIC VS DYNAMIC ENVIRONMENTS 🔄

Static Environment (Traditional)

jobs:
  deploy:
    environment: production
    runs-on: ubuntu-latest

❌ Fixed, can't change during runtime

Dynamic Environment (Modern)

jobs:
  deploy:
    environment: ${{ steps.env.outputs.environment_name }}
    runs-on: ubuntu-latest

✅ Set during workflow execution

1️⃣ DYNAMICALLY CHOOSE ENVIRONMENT FROM BRANCH 🌿

Goal

  • If branch is main → use environment PROD
  • If branch is develop → use environment TEST

We can do this directly in the environment: key using an expression.

Implementation

name: Branch based deploy

on:
  push:
    branches:
      - main
      - develop

jobs:
  deploy:
    runs-on: ubuntu-latest

    # Pick environment based on branch
    environment: ${{ github.ref_name == 'main' && 'PROD' || 'TEST' }}

    steps:
      - name: Show environment choice
        run: |
          echo "Branch: ${{ github.ref_name }}"
          echo "Environment used: ${{ job.environment.name }}"
Expression Pattern

This pattern is used because the expression language does not have a real ternary operator. So we simulate it with:

condition && 'valueIfTrue' || 'valueIfFalse'
