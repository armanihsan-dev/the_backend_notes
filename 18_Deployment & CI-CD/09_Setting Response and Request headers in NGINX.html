⚠️ Key idea:
NGINX sits in the middle. It can read, add, change, or delete headers in both directions.

2️⃣ Request headers: Browser → NGINX → Node

Example browser request

GET /api/users HTTP/1.1
Host: example.com
User-Agent: Chrome
Authorization: Bearer abc123
Cookie: sessionId=xyz

What NGINX does with request headers

By default: NGINX forwards most headers, BUT some headers are changed or lost unless you explicitly forward them.

This is why these lines are critical:

proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;

How Node receives request headers

In Express:

app.get("/api/users", (req, res) => {
  console.log(req.headers);
});

Example output:

{
  host: 'example.com',
  'user-agent': 'Chrome',
  authorization: 'Bearer abc123',
  cookie: 'sessionId=xyz',
  'x-real-ip': '192.168.1.10',
  'x-forwarded-for': '192.168.1.10',
  'x-forwarded-proto': 'https'
}
⚠️ Node NEVER sees the browser directly. It only sees what NGINX passes forward.

3️⃣ Setting request headers in NGINX

Add custom header:

proxy_set_header X-App-Source "nginx";

Node can read it: req.headers["x-app-source"]; // "nginx"

Override a browser header:

proxy_set_header Authorization "Bearer server-token";
🚨 This overrides the browser Authorization header. Node will NEVER see the original one.

4️⃣ Response headers: Node → NGINX → Browser

Now reverse direction. Setting headers in Node.js:

res.setHeader("X-Powered-By", "Node.js");
res.setHeader("Cache-Control", "no-store");
res.json({ ok: true });

Response sent to NGINX:

HTTP/1.1 200 OK
X-Powered-By: Node.js
Cache-Control: no-store

NGINX receives this response

NGINX can: Pass headers as-is, Add new headers, Override existing ones, or Hide headers.

Adding headers in NGINX:

add_header X-Server "nginx";

Browser receives: X-Powered-By: Node.js, Cache-Control: no-store, X-Server: nginx

Overriding Node headers in NGINX:

add_header Cache-Control "public, max-age=3600" always;
🚨 NGINX WINS. Browser sees Cache-Control: public, max-age=3600. Node’s value is ignored.

Removing headers (security):

proxy_hide_header X-Powered-By;

Now Node sets it → but browser never sees it.

5️⃣ Who wins? (IMPORTANT RULES)

🔑 Golden Rule: NGINX always has the final say.
Scenario Result
Node sets header Passed unless NGINX changes it
NGINX sets same header NGINX overrides Node
Browser sets header Can be overridden by NGINX
Node tries to remove header NGINX can re-add it

6️⃣ Common headers you MUST understand

🔹 Client & Proxy headers

Header Purpose
Host Original domain
X-Real-IP Client IP
X-Forwarded-For Chain of client IPs
X-Forwarded-Proto http / https

👉 Required for auth, logging, rate-limiting

🔹 Auth & session

Authorization: JWT / Bearer token | Cookie: Sessions | Set-Cookie: Session creation.
⚠️ Cookies flow both ways.

🔹 Security headers (usually set in NGINX)

add_header X-Frame-Options DENY;
add_header X-Content-Type-Options nosniff;
add_header Referrer-Policy strict-origin;

🔹 CORS headers

Can be set in Node OR NGINX (not both). Setting CORS in both = bugs.

7️⃣ Real-world best practice (IMPORTANT)

Do this (Node) Do this (NGINX)
Auth logic, App-specific headers, Cookies Security headers, CORS, Cache, SSL, Compression

Avoid this: Same header in both places, Guessing header behavior, Blind copy-paste configs.

8️⃣ Debugging headers (skill check)

  • Browser/CLI: curl -I http://localhost
  • NGINX logs: sudo tail -f /var/log/nginx/access.log
  • Node: console.log(req.headers);

How to hide the server in NGINX header

1️⃣ What is leaking by default?
Headers like Server: nginx/1.24.0 or X-Powered-By: Express tell attackers what server and version you use. This is unnecessary attack surface.

2️⃣ Hide NGINX “Server” header (MOST IMPORTANT)

Edit /etc/nginx/nginx.conf. Inside http {}, add: 

server_tokens off;

Reload: sudo systemctl reload nginx. Result: Server: nginx (no version).

3️⃣ Remove “Server” header completely (advanced)

Requires headers-more module.

sudo apt install libnginx-mod-http-headers-more-filter
# Add to config:
more_clear_headers Server;

4️⃣ Hide Express / Node headers

// In Express
app.disable("x-powered-by");

5️⃣ Hide upstream headers via NGINX

proxy_hide_header X-Powered-By;
proxy_hide_header Server;

7️⃣ Production-grade hardening (recommended)

add_header X-Frame-Options DENY always;
add_header X-Content-Type-Options nosniff always;
add_header Referrer-Policy strict-origin always;
add_header Permissions-Policy "geolocation=()" always;
8️⃣ TL;DR Table
Goal Method
Hide nginx version server_tokens off;
Remove Server header headers-more module
Hide Express info app.disable("x-powered-by")
Final control NGINX proxy_hide_header

Final mental model: Browser → NGINX decides what Node sees | Node → NGINX decides what Browser sees.
