🌩️ AWS CloudFront Functions: Deep Dive + CloudWatch Integration

🔍 What is AWS CloudFront Functions?

CloudFront Functions are ultra-lightweight, serverless JavaScript functions that execute at AWS's global edge locations (400+ points worldwide). They operate at the viewer level in CloudFront's request-response cycle, making them the fastest edge compute option AWS offers.

Key Architectural Features:

  • Runtime: Pure JavaScript (ES5.1 compliant) with Node.js-like environment
  • Memory: ~2MB memory limit
  • Execution Time: Max 1-2 milliseconds
  • Code Size: Maximum 10KB (compressed)
  • Global Deployment: Single deployment propagates worldwide in seconds

📋 Detailed Use Case Breakdown

1. Request Modification

// Redirect HTTP → HTTPS
function handler(event) {
  const request = event.request;
  const headers = request.headers;
  
  if (!headers['cloudfront-forwarded-proto'] || 
      headers['cloudfront-forwarded-proto'].value !== 'https') {
    return {
      statusCode: 301,
      statusDescription: 'Moved Permanently',
      headers: {
        'location': { value: `https://${request.headers.host.value}${request.uri}` }
      }
    };
  }
  return request;
}

2. A/B Testing & Feature Flags

// Route users based on cookies/headers
function handler(event) {
  const request = event.request;
  const cookies = parseCookies(request.headers.cookie);
  
  if (cookies['experiment-group'] === 'variant-b') {
    // Serve different content path
    request.uri = `/variant-b${request.uri}`;
  }
  
  return request;
}

3. Bot Detection & Security

// Basic bot mitigation
function handler(event) {
  const request = event.request;
  const ua = request.headers['user-agent']?.value || '';
  
  const badBots = ['scrapy', 'httrack', 'masscan'];
  if (badBots.some(bot => ua.toLowerCase().includes(bot))) {
    return {
      statusCode: 403,
      statusDescription: 'Forbidden'
    };
  }
  
  return request;
}

📊 Monitoring & Debugging with AWS CloudWatch

What is AWS CloudWatch?

CloudWatch is AWS's monitoring and observability service that collects metrics, logs, and events from AWS resources (including CloudFront Functions).

CloudFront Functions + CloudWatch Integration

1. Accessing Logs

// Your function with logging
function handler(event) {
  console.log('Event received:', JSON.stringify(event));
  console.log('URI:', event.request.uri);
  console.log('Method:', event.request.method);
  
  // Logs appear in CloudWatch Logs under:
  // /aws/cloudfront/function/[distribution-id]/[function-name]
  
  return event.request;
}

2. Viewing Logs in CloudWatch:

  • Navigate to CloudWatch → Logs → Log groups
  • Find: /aws/cloudfront/function/
  • Contains: console.log() output, Error messages, Execution metadata

3. CloudWatch Metrics for CloudFront Functions:

  • Invocations: Number of function executions
  • Execution Errors: Failed invocations
  • Throttles: Rate-limited executions
  • Compute Utilization: Performance metrics

4. Setting Up Alarms:

🚀 Best Practices & Pro Tips

Performance Optimization:

  • Minimize dependencies: No external libraries allowed
  • Cache computations: Reuse values within execution
  • Early returns: Exit quickly for invalid requests
  • String operations: Use built-in methods efficiently

Security Considerations:

// Add security headers
function handler(event) {
  const response = event.response;
  const headers = response.headers;
  
  const securityHeaders = {
    'content-security-policy': "default-src 'self'",
    'x-xss-protection': '1; mode=block',
    'referrer-policy': 'strict-origin-when-cross-origin',
    'permissions-policy': 'geolocation=()'
  };
  
  Object.entries(securityHeaders).forEach(([key, value]) => {
    headers[key] = { value };
  });
  
  return response;
}

Testing Strategy:

  • Local Testing: Use CloudFront Functions test harness
  • Staging Distribution: Test on non-production CloudFront
  • Canary Deployment: Use CloudFront's staging feature
  • Validation: Test all edge cases (malformed inputs, missing headers)

💰 Cost Optimization Example

Scenario: E-commerce site with 10M monthly visits

  • Each visit triggers 20 requests → 200M monthly invocations
  • Cost: 200M ÷ 1M × $0.10 = $20/month
  • Compare to Lambda@Edge: Would be ~$100+ for same workload

🔧 Deployment Workflow

  1. Develop: Write function in CloudFront console or CLI
  2. Test: Use built-in test harness with sample events
  3. Stage: Deploy to staging environment
  4. Associate: Link function to CloudFront behavior
  5. Publish: Deploy globally (takes ~30 seconds)
  6. Monitor: Watch CloudWatch metrics and logs

📈 Real-World Success Pattern

// Complete example: SPA + Security + Analytics
function handler(event) {
  const request = event.request;
  const response = event.response;
  
  // 1. SPA Routing
  if (!request.uri.includes('.') && !request.uri.includes('api/')) {
    request.uri = '/index.html';
  }
  
  // 2. Add security headers (response phase only)
  if (response) {
    response.headers['x-custom-header'] = { value: 'processed-by-edge' };
  }
  
  // 3. Bot detection
  const ua = request.headers['user-agent']?.value || '';
  if (ua.includes('bad-bot')) {
    return { statusCode: 429 };
  }
  
  return request || response;
}

🎯 When NOT to Use CloudFront Functions

Use Case Better Alternative
Database queries Lambda@Edge or Origin
Image resizing CloudFront + Lambda@Edge
Complex auth Lambda@Edge or CloudFront signed URLs
>1ms processing Lambda@Edge or Origin
External API calls Lambda@Edge

📚 Summary

CloudFront Functions give you microsecond-scale JavaScript execution at the edge for simple HTTP manipulations, while AWS CloudWatch provides the visibility and monitoring to ensure they run reliably and efficiently. Together, they form a powerful duo for building performant, secure, and cost-effective edge applications.

Key takeaway: If your edge logic fits in 10KB, executes in <1ms, and doesn't need external dependencies, CloudFront Functions will likely be your most cost-effective and fastest option.
