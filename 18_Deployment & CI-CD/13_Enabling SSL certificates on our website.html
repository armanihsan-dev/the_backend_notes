Part 6: Certbot Installation & SSL Setup Guide (Ubuntu + Nginx)

⚙️ 1. Understanding Certbot

Certbot is the official tool from the Electronic Frontier Foundation (EFF) that automates:

  • Getting SSL/TLS certificates from Let’s Encrypt
  • Installing them in your web server (like Nginx)
  • Renewing them automatically

Let’s Encrypt certificates are 100% free, trusted by all browsers, and valid for 90 days (Certbot handles auto-renewal).

🧩 2. Installing Certbot using APT (Old Method)

📦 Step 1 — Install Certbot

sudo apt update
sudo apt install -y certbot python3-certbot-nginx

This installs Certbot and its Nginx plugin.

🧠 Step 2 — Verify installation

certbot --version

Example output: certbot 2.9.0

❌ 3. Uninstalling Certbot (APT version)

If you ever installed Certbot via apt, you should remove it before switching to Snap (as recommended by Let’s Encrypt).

Run:

sudo apt remove --purge certbot python3-certbot-nginx -y
sudo apt autoremove -y

Check if any remnants remain: which certbot. If it shows /usr/bin/certbot, it’s the APT version. If it shows nothing — good, it’s fully removed.

✅ 4. Installing Certbot using SNAP (Recommended Method)

Let’s Encrypt officially recommends using Snap for new installations because:

  • Snap version is always up-to-date
  • It includes all necessary dependencies
  • It auto-updates automatically in the background

📦 Step 1 — Install Snap (if not already installed)

sudo apt update
sudo apt install -y snapd
sudo snap install core
sudo snap refresh core

⚙️ Step 2 — Install Certbot (latest)

sudo snap install --classic certbot

Then create a symlink for convenience:

sudo ln -s /snap/bin/certbot /usr/bin/certbot

🧠 Step 3 — Verify installation

certbot --version

You should see something like: certbot 5.1.0

🌐 5. Prepare Nginx for SSL

Before generating the certificate, make sure:

  • Your domain points to your EC2 public IP.
  • Your Nginx configuration listens on port 80 (HTTP).

Example minimal config:

server {
    listen 80;
    server_name api.procodrr.org;

    location / {
        proxy_pass http://localhost:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Check syntax and reload: sudo nginx -t && sudo systemctl reload nginx

🔐 6. Generate and Install SSL Certificate Automatically

The easiest one-liner:

sudo certbot --nginx -d api.procodrr.org --redirect

This will: Detect Nginx server block, use HTTP-01 challenge, obtain certificates, install them, add HTTPS redirection, and reload Nginx.

✅ Result

Your config will now include lines like:

listen 443 ssl;
ssl_certificate /etc/letsencrypt/live/api.procodrrlabs.com/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/api.procodrrlabs.com/privkey.pem;
include /etc/letsencrypt/options-ssl-nginx.conf;
ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

🔁 7. Auto-Renewal

Certbot installs a systemd timer that runs twice a day. Check status: 

sudo systemctl list-timers | grep certbot

Test renewal manually: sudo certbot renew --dry-run

📂 8. Certificate File Locations

Certs are stored under: /etc/letsencrypt/live/<your-domain>/

  • fullchain.pem: SSL certificate + intermediate
  • privkey.pem: Private key

🧩 9. List all existing certificates

sudo certbot certificates

🧩 10. Delete a certificate

sudo certbot delete --cert-name <certificate_name>

Understanding Let’s Encrypt, EFF, and Certbot

🏛️ 1. Let’s Encrypt — The Certificate Authority (CA)

The authority that creates and signs your SSL certificate. Non-profit and automated.

🧭 2. Electronic Frontier Foundation (EFF) — The Organization

Non-profit digital rights organization that created and maintains Certbot.

⚙️ 3. Certbot — The ACME Client (Tool You Use)

The tool you run on your server to talk to Let’s Encrypt and manage certificates.

✅ Summary

Name Role
Let’s Encrypt Issues free certificates
EFF Advocates for privacy; created Certbot
Certbot Automatically obtains/renews certificates

🧩 Analogy (The Passport)

  • Government issues passport: Let’s Encrypt issues cert.
  • NGO promotes digital identity: EFF promotes privacy.
  • Application software fills forms: Certbot automates the process.

Wildcard SSL Setup (Manual DNS Method)

⚙️ Step 1 — Run Certbot command

sudo certbot certonly --manual --preferred-challenges=dns -d "*.procodrrlabs.com" -d procodrrlabs.com

🧩 Step 2 — Add TXT record in GoDaddy DNS

Add a record with Type: TXT, Name: _acme-challenge, and the value provided by Certbot.

🧩 Step 4 — Configure Nginx for HTTPS

server {
    listen 443 ssl;
    server_name api.procodrrlabs.com;

    ssl_certificate     /etc/letsencrypt/live/procodrrlabs.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/procodrrlabs.com/privkey.pem;
}
⚠️ Important Note — Manual Renewal:
Since you used the --manual method, auto-renew will not work. You must re-run the same command every 90 days.
