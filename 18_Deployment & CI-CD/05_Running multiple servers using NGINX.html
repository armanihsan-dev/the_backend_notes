Creating Multiple Servers Using NGINX on Ubuntu

📌 What is NGINX?

NGINX is a web server and reverse proxy that can handle multiple websites/domains on a single server. It's like a traffic cop that directs visitors to the right website based on their request.

📁 NGINX Directory Structure

/etc/nginx/
├── nginx.conf          # Main configuration file
├── sites-available/    # Available server configurations
├── sites-enabled/      # Enabled server configurations (symlinks)
└── conf.d/             # Additional configuration files

🔧 Basic NGINX Server Block Syntax

server {
    listen 80;
    server_name domain1.com www.domain1.com;
    
    root /var/www/domain1.com/html;
    index index.html index.htm;
    
    location / {
        try_files $uri $uri/ =404;
    }
}

Directives Explained:

  • listen: Port to listen on (80 for HTTP, 443 for HTTPS)
  • server_name: Domain name(s) for this server
  • root: Directory where website files are stored
  • index: Default files to serve
  • location: Configuration for specific URL patterns

🚀 Step-by-Step Guide

Step 1: Install NGINX

sudo apt update
sudo apt install nginx
sudo systemctl start nginx
sudo systemctl enable nginx

Step 2: Create Website Directories

# Create directories for two websites
sudo mkdir -p /var/www/example1.com/html
sudo mkdir -p /var/www/example2.com/html

# Set proper permissions
sudo chown -R $USER:$USER /var/www/example1.com/html
sudo chown -R $USER:$USER /var/www/example2.com/html
sudo chmod -R 755 /var/www

Step 3: Create Sample HTML Files

# Website 1
echo "<h1>Welcome to Example1.com!</h1><p>This is site 1.</p>" | sudo tee /var/www/example1.com/html/index.html

# Website 2
echo "<h1>Welcome to Example2.com!</h1><p>This is site 2.</p>" | sudo tee /var/www/example2.com/html/index.html

Step 4: Create Server Block Configurations

File 1: /etc/nginx/sites-available/example1.com

server {
    listen 80;
    server_name example1.com www.example1.com;
    
    root /var/www/example1.com/html;
    index index.html index.htm;
    
    location / {
        try_files $uri $uri/ =404;
    }
    
    # Logging
    access_log /var/log/nginx/example1_access.log;
    error_log /var/log/nginx/example1_error.log;
}

File 2: /etc/nginx/sites-available/example2.com

server {
    listen 80;
    server_name example2.com www.example2.com;
    
    root /var/www/example2.com/html;
    index index.html index.htm;
    
    location / {
        try_files $uri $uri/ =404;
    }
    
    # Different logging files
    access_log /var/log/nginx/example2_access.log;
    error_log /var/log/nginx/example2_error.log;
}

Step 5: Enable the Sites

# Create symbolic links to enable sites
sudo ln -s /etc/nginx/sites-available/example1.com /etc/nginx/sites-enabled/
sudo ln -s /etc/nginx/sites-available/example2.com /etc/nginx/sites-enabled/

# Test configuration
sudo nginx -t

# Reload NGINX
sudo systemctl reload nginx

🌐 How It Works: Request Flow

1. User requests "http://example1.com"
    ↓
2. Request arrives at server IP on port 80
    ↓
3. NGINX checks all enabled server blocks
    ↓
4. Finds match in server_name "example1.com"
    ↓
5. Serves files from /var/www/example1.com/html
    ↓
6. Returns content to user

🔄 NGINX Processing Order

  • Port-based matching: NGINX first looks at the port (80, 443, etc.)
  • Server_name matching: Then matches the domain name
  • Default server: If no match, uses the first server block as default

📝 Example with IP-Based Virtual Hosting

# Different sites on different IPs
server {
    listen 192.168.1.10:80;
    server_name _;
    root /var/www/site1;
}

server {
    listen 192.168.1.20:80;
    server_name _;
    root /var/www/site2;
}

🎯 Example with Port-Based Virtual Hosting

# Same IP, different ports
server {
    listen 8080;
    server_name example.com;
    root /var/www/example8080;
}

server {
    listen 8081;
    server_name example.com;
    root /var/www/example8081;
}

🛠️ Common Commands

# Check configuration syntax
sudo nginx -t

# Reload NGINX (apply changes without downtime)
sudo systemctl reload nginx

# Restart NGINX
sudo systemctl restart nginx

# Check NGINX status
sudo systemctl status nginx

# View access logs
sudo tail -f /var/log/nginx/access.log

# Disable a site
sudo rm /etc/nginx/sites-enabled/example1.com
sudo systemctl reload nginx

📊 Default Server Block

To set a default/catch-all server:

server {
    listen 80 default_server;
    server_name _;
    return 444;  # Close connection without response
}

🚨 Troubleshooting Tips

  • Check for conflicts: sudo netstat -tulpn | grep :80
  • Check error logs: sudo tail -f /var/log/nginx/error.log
  • Check if sites are enabled: ls -la /etc/nginx/sites-enabled/
  • Verify DNS/hosts file: For local testing, add to /etc/hosts: 
127.0.0.1 example1.com
127.0.0.1 example2.com

🎓 Best Practices

  • One service per server block: Keep configurations separate
  • Use descriptive names: Name config files by domain
  • Keep logs separate: Each site should have its own log files
  • Test before reloading: Always run nginx -t
  • Backup configurations: Before making changes

📚 Complete Working Example

Domain 1 - Business Site:

server {
    listen 80;
    server_name mybusiness.com www.mybusiness.com;
    
    root /var/www/mybusiness/public_html;
    index index.html index.php;
    
    location / {
        try_files $uri $uri/ /index.php?$args;
    }
    
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/var/run/php/php8.1-fpm.sock;
    }
    
    location ~ /\.ht {
        deny all;
    }
}

Domain 2 - Blog:

server {
    listen 80;
    server_name blog.mybusiness.com;
    
    root /var/www/blog;
    index index.html;
    
    location / {
        try_files $uri $uri/ =404;
    }
    
    location /images/ {
        expires 30d;
        add_header Cache-Control "public";
    }
}

This setup allows you to host unlimited websites on a single Ubuntu server!
