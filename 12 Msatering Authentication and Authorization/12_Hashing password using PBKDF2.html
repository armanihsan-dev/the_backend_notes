🔐 Implementing PBKDF2 for Password Hashing in Express.js

Using PBKDF2 (Password-Based Key Derivation Function 2) is a great way to securely hash passwords in your Express.js application. It's a standard and robust algorithm that makes password cracking significantly harder.

Node.js provides the necessary functionality through its built-in crypto module, so you don't need to install any external libraries for PBKDF2 itself.

1. Understanding PBKDF2 Parameters

PBKDF2 takes several inputs to produce a secure hash. Here's what they mean:

  • password: The user's plaintext password.
  • salt: A random string generated for each password. Salts ensure that two identical passwords result in two different hashes, defeating pre-computed attack tables like Rainbow Tables. This must be stored with the hash in your database.
  • iterations: The number of times the hashing function is applied. More iterations mean more time for hashing, which is a good thing for security as it slows down brute-force attacks. The current recommended minimum is often 310,000.
  • keylen: The desired length of the resulting hash key (in bytes). For sha256, 32 bytes is typical.
  • digest: The underlying cryptographic hash function to use (e.g., 'sha256', 'sha512').

2. Express.js Implementation: Setup

First, make sure you have Express.js and the Node.js crypto module:

  • Initialize your project: npm init -y
  • Install Express: npm install express
  • Create your server file (e.g., server.js).

JavaScript

// server.js
const express = require('express');
const crypto = require('crypto');
const app = express();
const port = 3000;

// Middleware to parse JSON bodies
app.use(express.json());

// Configuration constants for PBKDF2
const PBKDF2_ITERATIONS = 310000; // Recommended minimum for security
const KEY_LENGTH = 32;          // 32 bytes for SHA256 (256 bits)
const DIGEST_ALGORITHM = 'sha256';

// **Mock Database (for demonstration only - replace with a real database)**
const usersDB = [];

3. Registration Route (POST /register)

This route handles creating a new user by generating a unique salt, hashing the password, and storing the salt and hash.

📝 Code for Registration

JavaScript

app.post('/register', (req, res) => {
    const { username, password } = req.body;

    // 1. Generate a unique Salt (16 bytes = 32 hex chars)
    const salt = crypto.randomBytes(16).toString('hex');

    // 2. Hash the password using PBKDF2
    crypto.pbkdf2(
        password, 
        salt, 
        PBKDF2_ITERATIONS, 
        KEY_LENGTH, 
        DIGEST_ALGORITHM, 
        (err, hashedPassword) => {
            if (err) {
                console.error(err);
                return res.status(500).json({ message: 'Error hashing password' });
            }

            // 3. Store the user data (Username, Salt, Iterations, and Hash)
            const newUser = {
                username,
                salt,
                hash: hashedPassword.toString('hex'), // Convert Buffer to hex string for storage
                iterations: PBKDF2_ITERATIONS 
            };
            
            usersDB.push(newUser); // Save to mock DB
            console.log('User registered:', newUser);

            res.status(201).json({ message: 'User registered successfully!' });
        }
    );
});

💡 How It Works (Registration)

  • Salt Generation: crypto.randomBytes(16).toString('hex') creates a cryptographically strong, random 16-byte buffer and converts it to a hexadecimal string. This is the unique salt.
  • PBKDF2 Hashing: crypto.pbkdf2() is the core function. It takes the plaintext password, the unique salt, the iteration count, the key length, and the digest algorithm.
  • Storage: We never store the original password. We store the hashed password (hashedPassword.toString('hex')), the unique salt, and the iteration count. This trio is necessary to verify the password later.

4. Login Route (POST /login)

This route handles user login by retrieving the stored salt and hash, re-hashing the submitted password, and comparing the results.

📝 Code for Login

JavaScript

app.post('/login', (req, res) => {
    const { username, password } = req.body;

    // 1. Find the user in the database
    const user = usersDB.find(u => u.username === username);

    if (!user) {
        return res.status(401).json({ message: 'Invalid credentials' });
    }

    // 2. Re-hash the submitted password using the stored salt and iterations
    crypto.pbkdf2(
        password, 
        user.salt, 
        user.iterations, // Use the stored number of iterations
        KEY_LENGTH, 
        DIGEST_ALGORITHM, 
        (err, submittedHashedPassword) => {
            if (err) {
                console.error(err);
                return res.status(500).json({ message: 'Error during login' });
            }

            // 3. Compare the newly created hash with the stored hash
            const submittedHashHex = submittedHashedPassword.toString('hex');

            if (submittedHashHex === user.hash) {
                // Passwords match! Authentication successful.
                res.json({ message: 'Login successful!', user: { username: user.username } });
            } else {
                // Passwords do not match
                res.status(401).json({ message: 'Invalid credentials' });
            }
        }
    );
});

💡 How It Works (Login)

  • Retrieve Credentials: Find the user by their username in the database to get their stored hash, salt, and iterations.
  • Re-hashing: Call crypto.pbkdf2() again, passing the plaintext password submitted by the user, along with the stored salt and stored iterations. This creates a new hash.
  • Comparison: The newly computed hash is compared to the stored hash. If they are an exact match, the user is authenticated. If not, the login fails.

5. Running the Application

Add the listener to the end of your server.js:

JavaScript

app.listen(port, () => {
    console.log(`Server running on http://localhost:${port}`);
});

You can start your server with node server.js.

This PBKDF2 implementation is more secure than a simple one-time hash because the high iteration count makes it computationally expensive for an attacker to guess passwords, and the unique salt prevents attacks like Rainbow Tables.
