🗝️ Understanding Guest and Authorized Sessions

The concept of Guest Session and Authorized Session is fundamentally about Authentication and Authorization—determining who the user is and what they are allowed to do.

1. Guest Session

A Guest Session is created for an unauthenticated user, meaning the user has not yet logged in.

  • Identity: Anonymous. The server only knows them by a unique Session ID.
  • Authorization: Limited. They can typically access public resources (e.g., viewing a product catalog, reading a blog post) and perform actions that don't require an identity (e.g., adding items to a shopping cart).
  • Behind the Scenes:
    • The user's first request arrives.
    • The server generates a Session ID (a long, random, unique string).
    • This Session ID is stored server-side (often in a session store like MongoDB) along with minimal data (e.g., creation time, cart contents).
    • The server sends the Session ID back to the client as an HTTP-only cookie (e.g., connect.sid).
    • On subsequent requests, the browser sends the cookie, and the server uses the Session ID to look up the session data.

2. Authorized Session

An Authorized Session is the same session after the user has successfully logged in and their identity has been verified.

  • Identity: Known. The session data is updated to include the User ID (e.g., MongoDB _id) and potentially the user's role or permissions.
  • Authorization: Expanded. They can now access protected resources (e.g., a dashboard, settings page, user profile) and perform privileged actions (e.g., purchasing, editing their profile).
  • Behind the Scenes:
    • The user submits their credentials (username/password).
    • The server verifies the credentials against the User database (e.g., a users collection in MongoDB).
    • If successful, the existing Guest Session record in the session store is updated to include the user's identifier (e.g., req.session.userId = user._id;).
    • The Session ID cookie remains the same, but the session data it points to now includes authentication information.

3. Impact on Database (MongoDB) 💾

Aspect Session Store (e.g., a sessions collection) User Data Store (e.g., a users collection)
Guest Session A new session document is created with a unique ID and general session data (e.g., cart). No direct interaction.
Authorized Session The existing session document is updated to link to the User ID. A read operation occurs during login to verify credentials.
Protected Access A read operation occurs on every protected request to verify the session and fetch the User ID. Secondary read/query may occur to retrieve specific user details (like role/permissions) if not stored in the session.

Express.js and MongoDB Example (using express-session and connect-mongo)

This example demonstrates how to set up server-side sessions stored in MongoDB and how to differentiate between guest and authorized access using middleware.

Prerequisites

Install the required packages:

Bash

npm install express express-session connect-mongo mongoose

Code Example

JavaScript

// server.js

import express from 'express';
import session from 'express-session';
import MongoStore from 'connect-mongo';
import mongoose from 'mongoose';

// --- Configuration ---
const app = express();
const PORT = 3000;
const MONGO_URI = 'mongodb://localhost:27017/myAppSessions';
const SESSION_SECRET = 'your-secret-key-that-should-be-long-and-random';

// Connect to MongoDB
mongoose.connect(MONGO_URI)
  .then(() => console.log('MongoDB connected...'))
  .catch(err => console.error(err));

// User Schema (Simplified for example)
const UserSchema = new mongoose.Schema({
    username: String,
    password: String, // In a real app, use a hashed password!
    role: { type: String, default: 'user' }
});
const User = mongoose.model('User', UserSchema);

// Middleware to use and store sessions in MongoDB
app.use(session({
    secret: SESSION_SECRET,
    resave: false, // Don't save session if unmodified
    saveUninitialized: true, // Create session for unauthenticated users (Guests)
    store: MongoStore.create({
        mongoUrl: MONGO_URI,
        collectionName: 'sessions', // Name of the collection in MongoDB
        ttl: 14 * 24 * 60 * 60 // Session TTL (time-to-live) in seconds (14 days)
    }),
    cookie: {
        maxAge: 1000 * 60 * 60 * 24 * 14, // 14 days
        httpOnly: true, // Prevents client-side JS access
        secure: false // Set to true in production with HTTPS
    }
}));

// Dummy data/function for login (replace with actual auth logic)
const findUserByCredentials = (username, password) => {
    // In a real app, you'd check a hashed password.
    if (username === 'testuser' && password === 'password') {
        // Return a mock user object with MongoDB _id
        return { _id: '6543210fedcba9876543210f', username: 'testuser', role: 'admin' };
    }
    return null;
};

// --- Middleware for Authorization ---

// Middleware to check for an Authorized Session
const requireAuth = (req, res, next) => {
    // Check if req.session has a userId (is an authorized session)
    if (req.session && req.session.userId) {
        next(); // User is logged in, proceed
    } else {
        res.status(401).send('Access Denied: Please log in.');
    }
};

// --- Routes ---

// 1. Guest Route (Accessible by both Guest and Authorized Sessions)
app.get('/', (req, res) => {
    const status = req.session.userId ? 'Authorized' : 'Guest';
    res.send(`Welcome! This is a public page. Session ID: ${req.sessionID}. Status: ${status}`);
});

// 2. Login Route (Promotes Guest Session to Authorized Session)
app.post('/login', express.json(), (req, res) => {
    const { username, password } = req.body;
    const user = findUserByCredentials(username, password);

    if (user) {
        // Successful login: UPGRADE Guest Session to Authorized Session
        req.session.userId = user._id; // Key change: store user identifier
        req.session.role = user.role;   // Store role for authorization checks
        res.send({ message: `Login successful. Welcome, ${user.username}!`, userId: user._id });
    } else {
        res.status(401).send('Invalid credentials.');
    }
});

// 3. Protected Route (Requires Authorized Session)
app.get('/dashboard', requireAuth, (req, res) => {
    // req.session.userId is available here
    res.send(`Welcome to the protected dashboard, User ID: ${req.session.userId}. Your role is: ${req.session.role}`);
});

// 4. Logout Route (Reverts Authorized Session to Guest Session state, or destroys it)
app.post('/logout', (req, res) => {
    // The preferred method for full session invalidation:
    req.session.destroy(err => {
        if (err) {
            return res.status(500).send('Could not log out.');
        }
        res.clearCookie('connect.sid'); // Clear the session cookie on the client
        res.send('Logged out successfully.');
    });
});

app.listen(PORT, () => {
    console.log(`Server running on http://localhost:${PORT}`);
});
