🔑 Deep Dive into **Bcrypt KDF**

**Bcrypt** is an **adaptive, one-way password hashing function** based on the **Blowfish cipher**. It is a **Key Derivation Function (KDF)**, designed to derive a secure output key (the **password hash**) from a secret input (the **password**).

Its primary security feature is **slowness-by-design** and **adaptability**, which protects against **brute-force attacks** and precomputed **rainbow table attacks**.

  • **Blowfish-based**: **Bcrypt** leverages **Blowfish's expensive key setup phase**. The password and the salt are used to initialize Blowfish's **S-boxes** and **P-array**, a process that is intentionally time-consuming.
  • **Adaptive Work Factor (Cost)**: This is the core of its defense. The **cost factor** is a logarithmic parameter ($2^{\text{cost}}$) that determines the number of times the Blowfish-based hashing is performed. As computing power increases over time, the cost factor can be raised to maintain a desirable level of computational difficulty, keeping the function **slow and resistant to brute-force attacks**.
  • **Built-in Salt**: **Bcrypt** requires a **unique, random salt** for every password. This salt is generated and embedded within the final hash, ensuring that even two users with the same password will have **different, unique hashes**. This **thwarts rainbow table attacks**.

🔁 **Bcrypt** vs. **bcrypt.js**

When developing in Node.js, the two main **bcrypt** packages have a key difference: their underlying implementation.

Feature **bcrypt** (e.g., npm i bcrypt) **bcrypt.js** (e.g., npm i bcryptjs)
Implementation **Native C++ bindings** **Pure JavaScript**
Performance **Significantly faster** (The fastest implementation of a slow algorithm is recommended) Slower (approximately **30% slower** than the native version)
Installation Requires compilation, which can sometimes lead to issues on certain platforms (e.g., Windows, some CI/CD pipelines) as it relies on build tools. **Easier to install** (no compilation needed), runs everywhere JavaScript does, including the browser.
Recommendation Recommended for **production** environments where speed is critical, given its superior performance. Useful for **development/testing** or environments where native modules are problematic.

Both libraries are functionally **compatible**, producing and verifying hashes with the same format. For performance-critical Node.js applications, the **C++ based bcrypt** is generally the preferred choice.

💻 npm i bcrypt Package and Usage

The **bcrypt** package provides both synchronous and **asynchronous** (callback-based or Promise-based) methods. **Asynchronous methods** (.hash and .compare) are preferred in Node.js to prevent the **CPU-intensive hashing process** from **blocking the event loop**.

Clear Syntax and Complete Example

Here is a complete, recommended, Promise-based asynchronous example using async/await: 

JavaScript

const bcrypt = require('bcrypt');
const saltRounds = 10; // This is the COST FACTOR (2^10 = 1024 rounds)

async function hashAndVerify(password) {
    try {
        // 1. Hashing the Password
        // bcrypt.hash() generates a new salt internally and combines it with the cost factor and the final hash.
        const hashedPassword = await bcrypt.hash(password, saltRounds);

        console.log(`Original Password: ${password}`);
        console.log(`Hashed Password (Hash + Salt + Cost): ${hashedPassword}`);

        // 2. Comparing the Password
        const match = await bcrypt.compare(password, hashedPassword);

        console.log(`Password Match Status: ${match}`); // Should log: true

        // 3. Comparing with a wrong password
        const wrongMatch = await bcrypt.compare('wrongpassword', hashedPassword);
        
        console.log(`Wrong Password Match Status: ${wrongMatch}`); // Should log: false

    } catch (err) {
        console.error('Bcrypt Error:', err);
    }
}

// Example usage:
hashAndVerify('mySuperSecretPassword123');

/*
Output will be similar to this (the salt and hash parts will be unique):
Original Password: mySuperSecretPassword123
Hashed Password (Hash + Salt + Cost): $2b$10$oF/1/f/i.1aB3r/G.uE72vF9K7M0PV/mauoF/1/f/i.1aB3r/G.uE72vF9K7M0PV/mauoF/
Password Match Status: true
Wrong Password Match Status: false 
*/

How Things Work (bcrypt.hash(password, saltRounds))

  • **Generate Salt**: The function first generates a **16-byte cryptographically secure random salt** based on the saltRounds **cost factor**.
  • **Hashing**: It then runs the password through the adaptive **Blowfish-based KDF process**, using the **password**, the **generated salt**, and the **cost factor**.
  • **Format and Output**: The resulting **hash string** is formatted to include the **algorithm version**, the **cost factor**, the **salt**, and the **final hash value**—all concatenated together.

🔬 Dissecting the Output

The output from bcrypt.genSalt or the full hash from bcrypt.hash follows a **standardized format**.

Complete Hash Example (60 Characters)

A typical **bcrypt** hash is **60 characters long** and is structured into four parts, separated by the $ delimiter: 

$2b$10$oF/1/f/i.1aB3r/G.uE72vF9K7M0PV/mauoF/1/f/i.1aB3r/G.uE72vF9K7M0PV/mauoF/
    
[Algorithm ID]$[Cost Factor]$[Salt][Hash Value]

Output Breakdown by Character Count

The total length is **60 characters**. This is how the length breaks down:

Part Characters Index Range Value Example
1: **Algorithm ID** 4 characters Index 0 to 3 $2b$
2: **Cost Factor** 3 characters Index 4 to 6 10$
3: **Salt Value** **22 characters** **Index 7 to 28** oF/1/f/i.1aB3r/G.uE72
4: **Final Hash Value** **31 characters** **Index 29 to 59** vF9K7M0PV/mauoF/1/f/i.1aB3r/G.uE72vF9K7M0PV/mauoF/

**Crucial Point**: The **Salt Value** occupies the characters from **Index 7 to 28** (**22 characters**), and the **Final Hash Value** occupies the characters from **Index 29 to 59** (**31 characters**). Together with the 7 characters for the Algorithm ID and Cost Factor, the total length is $4 + 3 + 22 + 31 = \mathbf{60}$ characters.

When you use bcrypt.compare(), it automatically **extracts** the **algorithm ID**, **cost factor**, and **salt** from the stored hash string. It then **re-hashes** the plain-text password using the **extracted salt** and **cost factor**, and finally compares the newly generated hash with the stored hash value. This makes bcrypt.compare() a single, secure function for verification.
