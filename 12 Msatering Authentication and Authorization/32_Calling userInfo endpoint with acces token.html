Calling userInfo endpoint with acces token

Calling the **UserInfo endpoint** using an **Access Token** is a **core step** in the OpenID Connect (OIDC) flow to retrieve authenticated user details. Here is a deep dive into the process, clear syntax in Node.js, and how it works.

🧐 How the UserInfo Endpoint Works

The UserInfo endpoint is a **protected resource** provided by the **Authorization Server** (or Identity Provider) as part of the OpenID Connect specification.

  • **Request Protection:** To access this endpoint, a client application must provide a valid Access Token. This token serves as a credential to prove the application's authorization to request information on behalf of the user.
  • **Access Token Transmission:** The Access Token is typically passed in the **Authorization HTTP header** using the **Bearer scheme**.
  • **Scope Validation:** The Authorization Server verifies the token's validity, checks if it has expired, and—crucially—ensures the token's associated scopes (permissions) allow access to the user attributes requested. The required scope is usually **openid**, and often **profile**, **email**, etc., to request specific claims.
  • **Response:** If the token is valid and the scopes are sufficient, the server returns the user's information (called **claims**) in a **JSON object** format.

💻 Node.js Syntax with Google UserInfo Endpoint

Since you are using the modern fetch API syntax, we'll use a standard Node.js environment that supports it (Node.js v18+ or an environment with a polyfill like node-fetch).

Node.js Code Snippet (using fetch)

JavaScript

// NOTE: This code assumes a modern Node.js environment (v18+)
// or that the 'node-fetch' package has been imported/polyfilled.

// 1. Define the UserInfo Endpoint and Access Token
const GOOGLE_USERINFO_URL = "https://openidconnect.googleapis.com/v1/userinfo";
const accessToken = 'YOUR_GOOGLE_OBTAINED_ACCESS_TOKEN_HERE'; 

async function getGoogleUserInfo(token) {
  try {
    // 2. Make the GET request
    const response = await fetch(GOOGLE_USERINFO_URL, {
      method: 'GET',
      headers: {
        // Crucially, the Access Token is passed using the Bearer scheme
        'Authorization': `Bearer ${token}`
      }
    });

    // 3. Handle non-200 status codes (e.g., 401 Unauthorized)
    if (!response.ok) {
      const errorBody = await response.text();
      throw new Error(`HTTP Error! Status: ${response.status}. Response: ${errorBody}`);
    }

    // 4. Parse the JSON response body to get user claims
    const userInfo = await response.json();
    
    console.log('Successfully fetched Google User Info:');
    console.log(userInfo); 

    return userInfo;
  } catch (error) {
    console.error('An error occurred during UserInfo fetch:', error.message);
  }
}

// Call the function
getGoogleUserInfo(accessToken);

⚙️ How It Works with Google's OIDC Service

This interaction is the **final step** in using an OAuth 2.0 Access Token to identify a user via the OpenID Connect (OIDC) protocol.

  • **Authorization:** The request is sent to the Google Identity Service. The Authorization: Bearer ${token} header is the **credential** that proves the request is authorized on behalf of the user.
  • **Google's Validation:** Google validates the Access Token by checking several factors:
    • Is the token correctly signed and valid?
    • Has the token expired?
    • Does the token have the necessary **scopes** (permissions) to retrieve user information? (For Google OIDC, the required scopes usually include **openid**, **email**, and **profile**).
  • **Claim Retrieval:** If the validation succeeds, Google retrieves the user's data (known as **Claims** in OIDC) that correspond to the scopes granted.
  • **Response:** Google returns a **JSON object** with the user's details.

Example Claims from Google

If your Access Token included the scopes openid, email, and profile, the successful response (HTTP 200 OK) would look similar to this:

JSON

{
  "sub": "123456789012345678901",
  "name": "Alex Gemini",
  "given_name": "Alex",
  "family_name": "Gemini",
  "picture": "https://lh3.googleusercontent.com/a/...",
  "email": "alex.g@gmail.com",
  "email_verified": true,
  "locale": "en"
}
  • **sub (Subject Identifier):** This is the **unique and persistent ID** for the user provided by Google. It is the primary way to identify the user in your application.
  • **email and email_verified:** Provided if the email scope was requested.
