🔐 OAuth 2.0 & OpenID Connect (OIDC) Flow

Specifically using the **popup window flow**.

The core communication mechanism between the popup and the main window is the postMessage API.

💻 JavaScript Code Breakdown

The script.js file handles four main parts of the OpenID Connect flow:

  • **Initiating the Flow** (Opening the popup).
  • **Parent Window Communication** (Receiving the authorization code).
  • **Popup Logic** (Sending the authorization code back to the parent).
  • **Token Exchange** (Fetching the ID Token).

  • **clientSecret**: This is a **sensitive secret** that should **never be exposed in client-side code** (like a static JS file). In a real application, this should be stored and used only on your **secure backend server**.
  • **clientId**: Public identifier for your application.
  • **redirect_uri**: The URI Google will send the user back to after they sign in and grant permission.
  • **authURL**: The complete URL used to start the OAuth/OIDC process.
    • response_type=code: Specifies the **Authorization Code flow**.
    • scope=openid email profile: Requests access to the user's basic profile, email, and asserts the request is for OIDC (openid).

2. Open Popup (Parent Window)

JavaScript

// 1️⃣ Open popup
button.addEventListener('click', () => {
    window.open(authURL, 'auth-popup', 'left=100,top=100,width=500,height=600')
})
  • When the "Sign in with Google" button is clicked, the parent window calls window.open().
  • It opens a new, small browser window (the **popup**) and immediately navigates it to the authURL (Google's login/consent page).

3. Parent Listens for Message (Parent Window)

JavaScript

// 2️⃣ Parent listens for message
window.addEventListener('message', (event) => {
    // allow localhost in dev
    if (!event.origin.includes('localhost')) return
    if (!event.data?.code) return

    fetchIdToken(event.data.code)
})
  • The parent window sets up an **event listener** for the 'message' event. This is the **crucial part for communication**.
  • It's waiting for a message sent from a different window (in this case, the popup).
  • **event.origin**: Checks the origin (domain) of the sender to prevent Cross-Site Scripting (XSS) attacks. It only accepts messages from the expected origin (localhost).
  • **event.data?.code**: Checks if the message contains the expected **authorization code**.
  • If valid, it calls the fetchIdToken function with the received code.

4. Code Detection and Message Sending (Popup Window)

JavaScript

// 3️⃣ This runs inside popup after redirect
window.addEventListener('DOMContentLoaded', () => {
    // detect if popup contains code
    const code = new URLSearchParams(location.search).get('code')
    if (code && window.opener) {
        window.opener.postMessage({ code }, window.location.origin)
        window.close()
    }
})
  • This logic executes **inside the popup window** after Google redirects it to the configured redirect_uri (http://localhost:5500), appending the authorization code in the URL query string: http://localhost:5500?code=4/0AX.....
  • **const code = ...**: This extracts the authorization code from the URL after the redirect.
  • **if (code && window.opener)**: Checks if the code exists and if the popup was opened by a parent window (window.opener).
  • **window.opener.postMessage({ code }, window.location.origin)**: **This is the actual communication.**
    • window.opener: Refers to the main window that opened the popup.
    • postMessage: Sends a message (the object { code }) to the parent.
    • window.location.origin: Specifies the **target origin** for security. The parent window must have the same origin to receive the message (a security measure to prevent data leaks).
  • **window.close()**: Once the code is sent, the popup closes itself.

🗣️ How Popup Communication Works

The communication between the parent window and the popup (and vice-versa) is achieved using the window.postMessage() API.

The **postMessage() API** provides a secure, controlled way for windows/frames with different origins to communicate with each other.

  • **Parent opens Popup**: The parent window uses window.open() to create the popup and holds a reference to it (implicitly, as the popup's opener).
  • **Popup Redirects**: The popup navigates to Google, authenticates the user, and is redirected back to your redirect_uri with the authorization code.
  • **Popup Sends Message**: Now that the popup is back on your domain and has the code, it uses the window.opener property to reference the original parent window and calls: 
    window.opener.postMessage({ code: '...' }, 'http://localhost:5500')
  • **Parent Receives Message**: The parent window's 'message' event listener catches this message, verifies the sender's origin, and extracts the code to continue the authentication process.

This pattern is a robust way to implement OAuth/OIDC when you need a smooth, non-redirecting experience on the main page.
