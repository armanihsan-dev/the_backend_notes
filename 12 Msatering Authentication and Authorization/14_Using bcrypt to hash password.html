Using **bcrypt** with **Node.js** and **MongoDB** is the **standard, secure way** to handle user authentication.

Here is a step-by-step guide covering the syntax and how things work for both **registration** (**hashing**) and **login** (**comparison**).

🚀 Setup & Installation

Before writing the code, ensure you have the necessary package installed. We will use the **native C++ version** (bcrypt) for better performance in a production Node.js environment. 

Bash

npm install bcrypt

🔑 1. User Registration (Hashing the Password)

The core principle here is to **hash the user's plaintext password** before saving it to the MongoDB database. This makes the stored password **safe** even if the database is breached.

How it Works (Registration)

  • **Generate Salt and Hash**: The bcrypt.hash() method handles two steps in one call:
    • It internally generates a cryptographically secure, random **salt**.
    • It uses the provided **cost factor** (saltRounds) to **repeatedly run** the hashing algorithm on the password and the new salt.
  • **Save to MongoDB**: The resulting **60-character hash string** (which contains the algorithm ID, cost, salt, and final hash) is then saved to the database. The **original plaintext password is never stored**.

💻 Syntax Example (Register Route)

This assumes you have an Express server and a Mongoose model for your User. 

JavaScript

const express = require('express');
const router = express.Router();
const bcrypt = require('bcrypt');
const User = require('../models/User'); // Assuming you have a Mongoose User model

// 1. Define the cost factor for hashing (standard is 10 to 12)
const saltRounds = 10; 

router.post('/register', async (req, res) => {
    const { username, password } = req.body;

    try {
        // A. Generate the Hash (ASYNC - recommended)
        // bcrypt.hash() returns the 60-character hash string
        const hashedPassword = await bcrypt.hash(password, saltRounds);

        // B. Create and Save the New User
        const newUser = new User({
            username: username,
            // IMPORTANT: Store the hash, not the plaintext password!
            password: hashedPassword 
        });

        await newUser.save();
        
        res.status(201).send('User registered successfully.');
    } catch (error) {
        if (error.code === 11000) { // MongoDB duplicate key error (e.g., duplicate username)
            return res.status(400).send('Username already exists.');
        }
        console.error(error);
        res.status(500).send('Server error during registration.');
    }
});

🔓 2. User Login (Comparing the Password)

When a user attempts to log in, you must **verify** their provided plaintext password against the stored hash.

How it Works (Login)

  • **Retrieve Hash**: You first find the user in the database by their username and retrieve their **stored hash string**.
  • **Comparison**: The bcrypt.compare() method takes two arguments: the new **plaintext password** and the **stored hash**.
    • bcrypt.compare() automatically **extracts the salt and cost factor** from the stored hash string.
    • It then **re-hashes** the provided plaintext password using the extracted salt and cost.
    • Finally, it **compares** the newly generated hash with the stored hash.
  • **Result**: If the two hashes match, the function returns true, and the user is authenticated. This comparison is done securely without ever exposing the original password.

💻 Syntax Example (Login Route)

JavaScript

router.post('/login', async (req, res) => {
    const { username, password } = req.body;

    try {
        // A. Find the User in MongoDB
        const user = await User.findOne({ username });
        
        if (!user) {
            return res.status(401).send('Invalid credentials.');
        }

        // B. Compare the Plaintext Password with the Stored Hash
        // The stored hash is retrieved from user.password
        const match = await bcrypt.compare(password, user.password);

        if (match) {
            // SUCCESS: Passwords match. Handle session/token creation here.
            res.status(200).send('Login successful!');
        } else {
            // FAILURE: Passwords do not match.
            res.status(401).send('Invalid credentials.');
        }
    } catch (error) {
        console.error(error);
        res.status(500).send('Server error during login.');
    }
});

// Remember to export your router
module.exports = router;

💡 Key Security Takeaways

Feature Registration (hash) Login (compare)
Input Plaintext Password + Cost Factor Plaintext Password + Stored Hash
Output **60-character Hash String** true or false (Boolean)
Security Mechanism **Adaptive Cost Factor** (Slowness) and **Built-in Salt** **Automatic Salt Extraction** and **Hash Recomputation**
