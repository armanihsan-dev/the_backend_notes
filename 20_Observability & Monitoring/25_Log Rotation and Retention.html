LOG ROTATION & RETENTION

DEEP DIVE INTO MANAGING LOG FILES IN PRODUCTION

WHAT IS LOG ROTATION?

Log rotation is the process of splitting a log file when it reaches a certain size or age, creating a new file for new logs and archiving the old one.

❌ Without Rotation 

app.log → grows forever
       → 10GB
       → disk full 💥

✅ With Rotation 

app.log (current, 100MB)
  → rename to app.log.1
  → create new app.log ✅

WHY ROTATION MATTERS

At any point, three processes work on a log file simultaneously:

Process Role Example
Appender Writes logs Your Node.js application (pino)
Tailer Reads logs Promtail / Grafana Alloy
Log Rotator Rotates the file pino-roll / logrotate
Risk

Without proper rotation coordination, you can lose logs or have your log collector read corrupted data.

TWO ROTATION METHODS

Method 1: Copy and Truncate

1. Copy  app.log → app.log.1
2. Truncate app.log (clear it)
3. Appender continues writing to same file descriptor

PROS

Appender never needs to reopen file

CONS

Risk of log loss — tailer may miss logs between copy and truncate

Method 2: Rename and Create (RECOMMENDED)

1. Rename app.log → app.log.1
2. Create new app.log
3. Appender must reopen new file

PROS

No log loss — tailer keeps reading app.log.1 until done

CONS

Appender must support log file reopening

WHAT IS LOG RETENTION?

Log retention is the process of automatically deleting old logs after they exceed a specified age. Unlike rotation (which creates new files), retention permanently removes data.

Why Retention Matters

Without retention, logs accumulate forever:

  • Storage costs increase linearly with time
  • Query performance degrades as more data is scanned
  • Compliance requirements may mandate deletion after certain periods
Key Distinction

Rotation = manages the current log file (splits it when too big)
Retention = manages old log files (deletes them after they expire)

WHY PINO-ROLL?

When pino writes to a file, it opens a file descriptor — a direct OS-level handle to that file. If you manually rename that file, pino doesn't know — it keeps writing to the renamed file via the same descriptor.

pino-roll solves this by managing the file internally
  • Watches the file size as it writes
  • When the limit hits, closes the current file and opens a new one
  • Numbers them: app.1.log → app.2.log → app.3.log
  • Auto-deletes old files beyond your limit.count

STEP 1 — logger.js (The Heart of Everything)

Two targets: pino-roll for file rotation, pino-pretty for console.

import pino from 'pino';

export const logger = pino({
    level: process.env.LOG_LEVEL || 'info',
    transport: {
        targets: [
            // TARGET 1: pino-roll — writes logs to rotating files
            // WHY: pino alone writes to one file forever. pino-roll monitors
            //      the file size internally and handles opening/closing files
            //      safely — no stale file descriptor problem.
            {
                target: 'pino-roll',
                level: 'info',         // only info and above go to file
                options: {
                    file: './logs/app.log',

                    // SIZE-BASED ROTATION
                    // WHY: Once app.1.log hits 5KB, pino-roll closes it and
                    //      creates app.2.log. New logs go into app.2.log.
                    //      (Use '1m' for 1MB in production)
                    size: '5k',

                    // RETENTION — how many rotated files to keep
                    // WHY: Without this, old files pile up forever.
                    //      count: 3 means only 3 rotated files are kept.
                    //      When app.4.log would be created, app.1.log is deleted.
                    limit: { count: 3 },

                    // mkdir: true — auto-creates the logs/ folder if it doesn't exist
                    mkdir: true
                }
            },
            // TARGET 2: pino-pretty — colorized console output for development
            // WHY: Raw pino logs are JSON. During development you want
            //      human-readable colored output in the terminal.
            {
                target: 'pino-pretty',
                level: 'debug',        // show everything including debug in console
                options: {
                    colorize: true,
                    translateTime: 'SYS:standard',
                    destination: 1     // 1 = stdout (your terminal)
                }
            }
        ]
    }
});

STEP 2 — retentionCleanup.js (Time-Based Auto-Delete)

This is separate from pino-roll. pino-roll handles size-based rotation. For deleting files older than N days, you need this: 

import fs from 'fs';
import path from 'path';

const LOG_DIR = './logs';
const RETENTION_MINUTES = 1; // TESTING: delete files older than 1 minute

// WHY THIS FILE EXISTS:
// pino-roll handles size-based rotation (app.1.log, app.2.log...)
// and keeps a max COUNT of files. But it doesn't know about TIME.
// If you want to delete files older than 1 minute (testing) or 7 days (production),
// you need this separate time-based cleanup.

function deleteOldLogs() {
    if (!fs.existsSync(LOG_DIR)) {
        console.log(`[${new Date().toISOString()}] Log directory does not exist: ${LOG_DIR}`);
        return;
    }

    const files = fs.readdirSync(LOG_DIR);
    const now = Date.now();
    const maxAgeMs = RETENTION_MINUTES * 60 * 1000;

    console.log(`[${new Date().toISOString()}] Checking ${files.length} files (max age: ${RETENTION_MINUTES} minute(s))`);

    let deletedCount = 0;

    files.forEach(file => {
        const filePath = path.join(LOG_DIR, file);
        const stats = fs.statSync(filePath);
        if (!stats.isFile()) return;

        const ageMs = now - stats.mtimeMs; // mtime = last modified time
        const ageMinutes = Math.floor(ageMs / 60000);
        const ageSeconds = Math.floor((ageMs % 60000) / 1000);

        if (ageMs > maxAgeMs) {
            fs.unlinkSync(filePath);
            deletedCount++;
            console.log(`DELETED: ${file} (age: ${ageMinutes}m ${ageSeconds}s)`);
        } else {
            console.log(`KEPT:    ${file} (age: ${ageMinutes}m ${ageSeconds}s)`);
        }
    });

    if (deletedCount === 0) {
        console.log(`No files deleted. All files within retention period.`);
    } else {
        console.log(`Deleted ${deletedCount} file(s).`);
    }
}

export function startRetentionCleanup() {
    console.log(`Starting retention cleanup — period: ${RETENTION_MINUTES} minute(s)`);

    deleteOldLogs(); // run immediately on startup

    // TESTING: Run every 10 seconds
    // In production, change to: 24 * 60 * 60 * 1000 (24 hours)
    const CHECK_INTERVAL_MS = 10 * 1000;
    setInterval(deleteOldLogs, CHECK_INTERVAL_MS);
}

// With stop control (useful for graceful shutdown)
let cleanupInterval = null;

export function startRetentionCleanupWithControl() {
    if (cleanupInterval) clearInterval(cleanupInterval);
    deleteOldLogs();
    cleanupInterval = setInterval(deleteOldLogs, 10 * 1000);

    return () => {
        if (cleanupInterval) {
            clearInterval(cleanupInterval);
            cleanupInterval = null;
            console.log(`Retention cleanup stopped`);
        }
    };
}

UNDERSTANDING THE KEY PARAMETERS

Parameter Testing Value Production Value Explanation
RETENTION_MINUTES 1 10080 (7 days) How old a file must be before deletion
maxAgeMs 60,000ms 604,800,000ms Age threshold in milliseconds
CHECK_INTERVAL_MS 10,000ms (10s) 86,400,000ms (24h) How often to check for old files
stats.mtimeMs Last modified time Same Uses file's modification timestamp

VISUAL TIMELINE OF TESTING

Time 0s:   App starts, files created
           - fresh.log    (0 min old)  → KEPT
           - one_min.log  (1 min old)  → KEPT (equal to limit)
           - two_min.log  (2 min old)  → will be DELETED
           - five_min.log (5 min old)  → will be DELETED

Time 10s:  First cleanup check
           - fresh.log    (0.16 min old) → KEPT
           - one_min.log  (1.16 min old) → DELETE ❌ (older than 1 minute!)
           - two_min.log  (2.16 min old) → DELETE ❌
           - five_min.log (5.16 min old) → DELETE ❌

Time 20s:  Second cleanup check
           - fresh.log    (0.33 min old) → KEPT ✅ (still fresh)

Time 60s:  Third cleanup check
           - fresh.log    (1.0 min old)  → DELETE ❌ (now 1 minute old)

RUN THE RETENTION SERVICE

services/retention.js

import { startRetentionCleanup } from './retentionCleanup.js';

console.log('Starting retention test...');
console.log('Files older than 1 minute will be deleted');
console.log('Check runs every 10 seconds');
console.log('Press Ctrl+C to stop\n');

const stop = startRetentionCleanup();

process.on('SIGINT', () => {
    console.log('\nShutting down...');
    if (stop) stop();
    process.exit();
});
node services/retention.js

STEP 3 — app.js (Wire Everything Together)

import express from 'express';
import { logger } from './logger.js';
import './retentionService.js'; // auto-starts retention cleanup

const app = express();
const PORT = 1000;

app.use((req, res, next) => {
    logger.info({ method: req.method, url: req.url, ip: req.ip }, 'Incoming request');
    next();
});

app.get('/', (req, res) => {
    logger.info('Home page accessed');
    res.send('Hello World!');
});

app.get('/users', (req, res) => {
    logger.info({ endpoint: '/users' }, 'Fetching users');
    res.json([{ id: 1, name: 'John' }]);
});

app.get('/error', (req, res) => {
    logger.error('Something went wrong!');
    res.status(500).send('Error!');
});

app.listen(PORT, () => {
    logger.info(`Server running on http://localhost:${PORT}`);
});
Testing

Hit http://localhost:1000/users several times and watch app.1.log → app.2.log → app.3.log get created as each file hits 5KB.

LOKI + ALLOY INTEGRATION

Alloy is Grafana's log collector. It tails your log files and ships them to Loki. The key is the app.*.log glob pattern — Alloy automatically picks up every numbered file pino-roll creates.

alloy/config.alloy

// WHY: We use a glob pattern logs/app.*.log so Alloy
// automatically picks up app.1.log, app.2.log, app.3.log etc.
// When pino-roll creates a new file, Alloy starts tailing it automatically.

loki.source.file "app_logs" {
  targets = [
    {
      __path__ = "F:/your-project/logs/app.*.log",
      job      = "node-app",
      env      = "development",
    },
  ]
  forward_to = [loki.write.default.receiver]
}

loki.write "default" {
  endpoint {
    url = "http://localhost:3100/loki/api/v1/push"
  }
}
After Config Change

Restart the Alloy background service and Loki, then query with {job="node-app"} in Grafana Explore.

SUMMARY — WHAT EACH PIECE DOES

Piece Responsibility
pino Writes structured JSON logs
pino-roll Rotates files by size, keeps max N files
retentionCleanup.js Deletes files older than N days (time-based)
pino-pretty Human-readable console logs (dev only)
Grafana Alloy Tails all rotated files and ships to Loki
app.*.log glob Alloy auto-discovers new rotated files
💡 The Full Flow 
pino writes JSON
  → pino-roll rotates at 5KB → app.1.log, app.2.log, app.3.log
  → retentionCleanup.js deletes files older than 7 days
  → Alloy tails app.*.log automatically
  → Loki stores logs
  → Grafana visualizes them
