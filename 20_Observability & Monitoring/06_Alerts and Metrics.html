🎯 What are Metrics?

Metrics are numerical measurements collected over time. They answer questions like "How many?", "How much?", "How fast?"

Simple Analogy

Real World Metrics
Your car speedometer Current speed (value over time)
Your body temperature 98.6°F → 99.2°F → 98.9°F
Website visitors 100 visitors → 150 visitors → 120 visitors

Common Metric Examples

Metric Name What it measures Example Value
http_requests_total Total number of HTTP requests 1,547,231
cpu_usage_percent CPU utilization 45.2%
memory_usage_bytes RAM used 2.4 GB
response_time_seconds How long requests take 0.125 seconds
error_count Number of errors 23

📈 Types of Metrics

1. Counter (Only goes up)

Requests received: 100 → 150 → 200 → 250
Never decreases

Example: Total visitors, total errors

2. Gauge (Goes up and down)

CPU usage: 45% → 60% → 30% → 55%
Can increase or decrease

Example: Temperature, memory usage, active connections

3. Histogram (Distribution of values)

Request durations:
  < 100ms: 500 requests
  100-200ms: 300 requests
  200-500ms: 100 requests
  > 500ms: 20 requests

Shows how values are distributed

4. Summary (Percentiles)

95% of requests finish in: 150ms
99% of requests finish in: 300ms

Shows statistical percentiles

🔔 What are Alerts?

Alerts are automatic notifications triggered when metrics cross certain thresholds.

Simple Analogy

Real World Alerting
Smoke detector If smoke detected → Sound alarm
Car fuel light If fuel < 10% → Light up warning
Thermostat If temp > 75°F → Turn on AC

Alert Example

IF cpu_usage_percent > 80%
FOR 5 minutes
THEN send notification: "CPU is high!"

Metrics You'd Collect:

# Metrics from a web server

Alerts You'd Create:

# Alert 1: High error rate
alert: HighErrorRate
expr: error_rate_percent > 5
for: 2m
annotations:
  summary: "Error rate is {{ $value }}%"

# Alert 2: Slow responses
alert: SlowResponses
expr: response_time_avg_ms > 1000
for: 5m
annotations:
  summary: "Responses taking {{ $value }}ms"

# Alert 3: Server down
alert: ServerDown
expr: up == 0
for: 1m
annotations:
  summary: "Server is not responding"

🚀 Setting Up Prometheus & Grafana

Step 1: Install Prometheus

# prometheus.yml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'my-app'
    static_configs:
      - targets: ['localhost:8080']

Step 2: Expose Metrics in Your App

Node.js Example:

const express = require('express');
const client = require('prom-client');

const app = express();
const httpRequestsTotal = new client.Counter({
  name: 'http_requests_total',
  help: 'Total HTTP requests'
});

app.get('/api', (req, res) => {
  httpRequestsTotal.inc();
  res.send('OK');
});

app.get('/metrics', async (req, res) => {
  res.set('Content-Type', client.register.contentType);
  res.end(await client.register.metrics());
});

Python Example:

from prometheus_client import Counter, generate_latest
import flask

app = flask.Flask(__name__)
requests_total = Counter('http_requests_total', 'Total requests')

@app.route('/api')
def api():
    requests_total.inc()
    return 'OK'

@app.route('/metrics')
def metrics():
    return generate_latest()

Step 3: Create Alerts

# alerts.yml
groups:
  - name: myapp_alerts
    rules:
      - alert: HighRequestRate
        expr: rate(http_requests_total[1m]) > 100
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "High request rate detected"
      
      - alert: ServiceDown
        expr: up == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "Service is down"

Step 4: Visualize in Grafana

  • Add Prometheus as data source
  • Create dashboard with queries like:
    • rate(http_requests_total[5m])
    • avg(response_time_seconds)
  • Add alert thresholds in Grafana panels

📊 Metrics vs Logs Comparison

Feature Metrics Logs (Loki)
Data type Numbers Text
Storage size Small (efficient) Large
Query speed Very fast Slower
Use case "Is something wrong?" "What exactly happened?"
Example CPU: 45% "Error: DB connection failed"
Tool Prometheus Loki

When to use which:

┌─────────────────────────────────────────────────────────┐
│  "Is the server CPU high?"                              │
│  → METRICS (Prometheus) ✓                               │
├─────────────────────────────────────────────────────────┤
│  "Why is CPU high? What process is causing it?"        │
│  → LOGS (Loki) ✓                                        │
├─────────────────────────────────────────────────────────┤
│  "How many errors occurred in the last hour?"          │
│  → METRICS (counter) ✓                                  │
├─────────────────────────────────────────────────────────┤
│  "What were the exact error messages?"                  │
│  → LOGS (full text) ✓                                   │
└─────────────────────────────────────────────────────────┘

🔔 Alert States

State Meaning
Pending Condition met but not long enough
Firing Alert is active
Resolved Condition returned to normal

Alert Flow:

Normal → Condition met → PENDING (for 5 min) → FIRING → Send notification
                                                          ↓
                                                   Condition fixed
                                                          ↓
                                                   RESOLVED → Send resolved notification

📝 Common Alert Examples

Infrastructure Alerts:

# CPU too high
CPU > 80% for 5 minutes

# Memory low  
Memory < 10% free

# Disk full
Disk usage > 90%

# Service down
HTTP probe returns 5xx for 30 seconds

Application Alerts:

# High error rate
Error rate > 1% for 2 minutes

# Slow responses
P99 latency > 500ms

# No data
No metrics received for 5 minutes

# Business metric
No orders placed in last 10 minutes

💡 Best Practices

Do Don't
✅ Alert on symptoms, not causes ❌ Alert on every tiny change
✅ Use for clause to avoid flapping ❌ Fire alerts instantly
✅ Set reasonable thresholds ❌ Use thresholds that are too tight
✅ Include runbook links ❌ Send alerts without context
✅ Test alert rules ❌ Set and forget
