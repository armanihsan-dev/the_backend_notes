GRAFANA LOKI

THE COMPLETE GUIDE TO LOG AGGREGATION WITH LOKI

WHAT IS GRAFANA LOKI?

Grafana Loki is a horizontally-scalable, cost-effective log aggregation system inspired by Prometheus. Unlike traditional logging tools (like Elasticsearch) that index the full content of logs, Loki only indexes metadata labels — not the log content itself.

Key Idea

Think of Loki as Prometheus, but for logs. Same label-based approach, same Grafana integration, but stores log lines instead of numeric metrics.

WHAT KIND OF DATABASE IS LOKI?

Loki is a log aggregation database specifically designed for storing and querying structured log data — especially from containers and microservices.

Property Loki Elasticsearch
What it indexes Labels only Full log content
Storage cost Low (2–3x overhead) High (10–20x overhead)
Query speed Fast (label-based) Fast (full-text index)
Grafana integration Native Plugin required
Best for Containers, microservices Full-text search

THE CORE INNOVATION

❌ Traditional (Elasticsearch)

  • Index everything: timestamp, message, all fields
  • Expensive storage
  • Slower at scale

✅ Loki's Approach

  • Index only labels (like Prometheus)
  • Compress and store log content separately
  • Cheap storage, fast label queries
# Traditional loggers (Elasticsearch):
- Index everything: timestamp, message, all fields
- Expensive storage, slower queries

# Loki's approach:
- Index only labels (like Prometheus)
- Compress and store log content separately
- Cheap storage, fast queries using labels

WHY USE LOKI IN OBSERVABILITY (O11Y)?

O11y (Observability) has three pillars: Metrics, Logs, and Traces. Loki handles the Logs pillar with unique advantages:

1. Cost Efficiency

Traditional: Index full log text → 10-20x storage overhead
Loki:        Index only labels  →  2-3x storage overhead

2. Seamless Grafana Integration

  • Use same labels as Prometheus metrics
  • Switch from metric dashboards to logs instantly
  • Single UI for metrics AND logs

3. Kubernetes Native

  • Designed for containerized environments
  • Works perfectly with Prometheus service discovery
  • Labels automatically from k8s metadata

4. The LGTM Stack

Loki (Logs) + Grafana (UI) + Tempo (Traces) + Mimir (Metrics)

Loki is part of Grafana Labs' full observability stack. If you already use Prometheus + Grafana, adding Loki gives you logs with zero extra UI overhead.

WINDOWS INSTALLATION

# 1. Download latest Loki from GitHub
# Visit: https://github.com/grafana/loki/releases
# Download: loki-windows-amd64.exe.zip

# 2. Extract and rename
Expand-Archive loki-windows-amd64.exe.zip
Move-Item .\loki-windows-amd64.exe C:\loki\loki.exe

# 3. Add to PATH
[Environment]::SetEnvironmentVariable("PATH", $env:PATH + ";C:\loki", "User")

# 4. Create config directory
New-Item -ItemType Directory -Path C:\loki\config
New-Item C:\loki\config\config.yaml

CONFIGURATION FILE

Download the Default Config

wget https://raw.githubusercontent.com/grafana/loki/main/cmd/loki/loki-local-config.yaml

Custom Configuration

Place this file at C:\loki\config\config.yaml: 

auth_enabled: false

server:
  http_listen_port: 3100  # Loki API endpoint (for Grafana, applications)

common:
  instance_addr: 127.0.0.1
  path_prefix: /tmp/loki
  storage:
    filesystem:
      chunks_directory: /tmp/loki/chunks
      rules_directory: /tmp/loki/rules
  replication_factor: 1
  ring:
    kvstore:
      store: inmemory

query_range:
  results_cache:
    cache:
      embedded_cache:
        enabled: true
        max_size_mb: 100

limits_config:
  metric_aggregation_enabled: true
  enable_multi_variant_queries: true

schema_config:
  configs:
    - from: 2020-10-24
      store: tsdb
      object_store: filesystem
      schema: v13
      index:
        prefix: index_
        period: 24h

pattern_ingester:
  enabled: true
  metric_aggregation:
    loki_address: localhost:3100

ruler:
  alertmanager_url: http://localhost:9093

frontend:
  encoding: protobuf

Key Config Fields Explained

Field Value What It Does
auth_enabled false Disables multi-tenancy (fine for local dev)
http_listen_port 3100 Port Grafana and apps use to talk to Loki
chunks_directory /tmp/loki/chunks Where compressed log chunks are stored
schema: v13 — Latest storage schema version
period: 24h — New index file created every 24 hours

HOW TO RUN LOKI AFTER CONFIGURATION

Option 1: Direct Execution (Windows)

# From any directory (if PATH is set)
loki -config.file=C:\loki\config\config.yaml

# Or specify full path
C:\loki\loki.exe -config.file=C:\loki\config\config.yaml

Option 2: As a Windows Service

# Using NSSM (Non-Sucking Service Manager)
nssm install Loki C:\loki\loki.exe -config.file=C:\loki\config\config.yaml
nssm start Loki

Option 3: Using Docker

docker run -d --name loki \
  -p 3100:3100 \
  -v $(pwd)/config.yaml:/etc/loki/config.yaml \
  grafana/loki:latest \
  -config.file=/etc/loki/config.yaml
Windows Path Note

On Windows, use backslashes in the config path: C:\loki\config\config.yaml. Docker uses forward slashes regardless of OS.

HOW TO VERIFY LOKI IS RUNNING

# Check if listening on port 3100
netstat -an | findstr 3100

# Test the API
curl http://localhost:3100/ready
# Should return: ready

curl http://localhost:3100/metrics
# Should return Prometheus metrics

curl http://localhost:3100/loki/api/v1/labels

Expected Responses

Endpoint Expected Response Meaning
/ready ready ✅ Loki is up and healthy
/metrics Prometheus metrics text ✅ Metrics endpoint working
/loki/api/v1/labels JSON list of labels ✅ API is responding
