PROMQL AGGREGATION OPERATORS — FROM ZERO TO HERO

WHAT IS AGGREGATION?

When Prometheus returns an instant vector, you often get many time series — one per unique label combination. Aggregation operators let you collapse those series into fewer (or one) by combining their values mathematically.

The Problem It Solves

Without aggregation, http_requests_total returns one row per endpoint, method, and status code — potentially hundreds of series. Aggregation lets you ask:

  • sum — "What is the total traffic across all routes?"
  • avg — "What is the average CPU across all servers?"
  • max — "Which endpoint is getting the most traffic?"
  • count — "How many active instances do I have?"

Quick Reference

OperatorWhat It DoesReturns
sum()Adds all values togetherTotal
avg()Arithmetic mean of all valuesAverage
min()Smallest value among seriesMinimum
max()Largest value among seriesMaximum
count()Number of time seriesCount

1. sum() — ADD VALUES TOGETHER

sum() adds the values of all matching time series into a single number. It's the most commonly used aggregation operator.

Syntax

sum(metric_name)

Example — Total Requests Across All Routes

Without aggregation you get one row per series:

http_requests_total{method="GET",  path="/"}      → 1,200
http_requests_total{method="GET",  path="/fancy"} → 800
http_requests_total{method="POST", path="/users"} → 300

With sum() you get one number:

sum(http_requests_total)
→ 2,300

Use Cases

QueryAnswers
sum(http_requests_total)Total requests ever received
sum(rate(http_requests_total[1m]))Total requests per second right now
sum(node_memory_used_bytes)Total memory used across all servers

2. avg() — ARITHMETIC MEAN

avg() calculates the average value across all matching time series. Useful when you want a representative single value instead of a total.

Example — Average Request Rate Across Routes

avg(rate(http_requests_total[1m]))
rate per series:
  {path="/"}      → 20 req/s
  {path="/fancy"} → 13 req/s
  {path="/users"} → 5  req/s

avg → (20 + 13 + 5) / 3 = 12.67 req/s

Use Cases

QueryAnswers
avg(node_cpu_usage)Average CPU across all servers
avg(response_time_seconds)Average response time across all endpoints
avg() vs sum()

Use sum() when you want the total load on your system. Use avg() when you want a typical value — e.g. average CPU per server, not total CPU across all servers.

3. min() — LOWEST VALUE

min() returns the smallest value among all matching time series. Useful for finding the least-loaded instance or the fastest endpoint.

Example — Lowest RPS Among Routes

min(rate(http_requests_total[1m]))
rate per series:
  {path="/"}      → 20 req/s
  {path="/fancy"} → 13 req/s
  {path="/users"} → 5  req/s

min → 5 req/s  ← /users is least busy

Use Cases

QueryAnswers
min(node_cpu_usage)Find the least-loaded server
min(rate(http_requests_total[1m]))Find the least-used endpoint

4. max() — HIGHEST VALUE

max() returns the largest value among all matching time series. Useful for finding the hottest endpoint or the most-loaded server.

Example — Highest RPS Route

max(rate(http_requests_total[1m]))
rate per series:
  {path="/"}      → 20 req/s
  {path="/fancy"} → 13 req/s
  {path="/users"} → 5  req/s

max → 20 req/s  ← / is the busiest route

Use Cases

QueryAnswers
max(node_cpu_usage)Find the most-loaded server
max(rate(http_requests_total[1m]))Find the hottest endpoint
max(node_memory_used_bytes)Peak memory usage across all servers

5. count() — NUMBER OF SERIES

count() does not add up values — it counts how many time series match the selector. Each unique label combination is one series.

Example — How Many Endpoints Exist

count(http_requests_total)
Matching series:
  http_requests_total{method="GET",  path="/"}
  http_requests_total{method="GET",  path="/fancy"}
  http_requests_total{method="POST", path="/users"}

count → 3
Key Distinction

count() counts series, not requests. If you have 3 endpoints, count(http_requests_total) returns 3 — regardless of how many requests each endpoint received.

Use Cases

QueryAnswers
count(up)How many targets are being scraped
count(up == 1)How many targets are currently UP
count(http_requests_total)How many unique endpoint/method combinations exist

GROUPING WITH by() — KEEP SPECIFIC LABELS

By default, aggregation drops all labels and returns one single value. by() tells Prometheus which labels to preserve — creating one result per unique value of those labels.

Mental Model

Think of by(path) like SQL's GROUP BY path. You get one aggregated row per unique value of path.

Without by() — One Result

sum(rate(http_requests_total[1m]))
→ 38  (all routes combined)

With by(path) — One Result Per Route

sum by (path) (rate(http_requests_total[1m]))
{path="/"}      → 20
{path="/fancy"} → 13
{path="/users"} → 5

With by(method, status_code) — One Result Per Combination

sum by (method, status_code) (rate(http_requests_total[1m]))
{method="GET",  status_code="200"} → 30
{method="GET",  status_code="404"} → 2
{method="POST", status_code="200"} → 5
{method="POST", status_code="500"} → 1

Common Patterns

QueryAnswers
sum by (path) (rate(...))RPS broken down per route
sum by (method) (rate(...))RPS broken down per HTTP method
avg by (instance) (node_cpu_usage)Average CPU per server instance
max by (job) (node_memory_used_bytes)Peak memory per job

GROUPING WITH without() — DROP SPECIFIC LABELS

without() is the opposite of by(). Instead of listing labels to keep, you list labels to remove — everything else is preserved.

Example — Drop instance, Keep Everything Else

sum without (instance) (rate(http_requests_total[1m]))
Before (per instance):
  {instance="server-1", path="/", method="GET"} → 10
  {instance="server-2", path="/", method="GET"} → 12
  {instance="server-3", path="/", method="GET"} → 8

After (instance dropped, path + method kept):
  {path="/", method="GET"} → 30

by() vs without() — When to Use Which

ScenarioUseWhy
You know exactly which labels you want by(path, method) Explicit — only keep what you name
You want everything except one noisy label without(instance) Easier than listing all other labels
Multi-instance setup, aggregate across instances without(instance) Most common real-world use case
Prefer by() in Production

by() is safer because it's explicit — you won't accidentally keep a label you didn't intend to. Use without() when you have many labels and only want to drop one or two.

ACROSS SERIES vs ACROSS TIME

There are two completely different dimensions you can aggregate across:

TypeOperatorsCollapsesInput
Across series sum(), avg(), min(), max() Multiple series → fewer series Instant Vector
Across time sum_over_time(), avg_over_time(), max_over_time() Multiple timestamps → one value per series Range Vector
Key Difference

sum(metric) adds up values across different series at one moment. sum_over_time(metric[5m]) adds up values across time for each individual series.

sum_over_time() — TOTAL OVER A TIME WINDOW

Adds up all scraped values of a metric within the time window for each series. Note: this sums the raw counter values, not the increases — use increase() if you want growth.

Syntax

sum_over_time(metric_name[time_window])

Example

sum_over_time(http_requests_total[10s])
Scraped values in last 10s:
  t=0s  → 1,000
  t=5s  → 1,030
  t=10s → 1,070

sum_over_time → 1,000 + 1,030 + 1,070 = 3,100

Use Cases

QueryAnswers
sum_over_time(errors_total[1h])Sum of all error counter snapshots in the last hour
sum_over_time(cpu_usage[5m])Cumulative CPU readings over 5 minutes

avg_over_time() — AVERAGE OVER A TIME WINDOW

Calculates the average of all scraped values within the time window. Great for smoothing out spikes and getting a representative value.

Example

avg_over_time(node_cpu_usage[5m])
Scraped values in last 5m:
  45, 52, 48, 61, 55, 49

avg_over_time → (45+52+48+61+55+49) / 6 = 51.67

Use Cases

QueryAnswers
avg_over_time(node_cpu_usage[1h])Average CPU over the last hour (smoothed)
avg_over_time(response_time_seconds[10m])Average response time over last 10 minutes

max_over_time() — PEAK VALUE IN A TIME WINDOW

Returns the highest value seen within the time window for each series. Useful for finding spikes that might have been missed in a dashboard.

Example

max_over_time(node_cpu_usage[5m])
Scraped values in last 5m:
  45, 52, 48, 61, 55, 49

max_over_time → 61  ← peak CPU in last 5 minutes

Use Cases

QueryAnswers
max_over_time(node_cpu_usage[1h])Peak CPU in the last hour
max_over_time(response_time_seconds[10m])Worst response time in last 10 minutes
max_over_time(error_rate[30m])Highest error rate spike in last 30 minutes
💡 Golden Rule

Remember which dimension you're aggregating across: 

sum(metric)              → collapse many series   → one number
sum by(label)(metric)    → collapse many series   → one per label group
sum_over_time(metric[t]) → collapse time window   → one per series
avg_over_time(metric[t]) → average over time      → one per series
max_over_time(metric[t]) → peak over time         → one per series
