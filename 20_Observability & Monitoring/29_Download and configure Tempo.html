DOWNLOAD, CONFIGURE & RUN TEMPO

A complete step-by-step guide to running Grafana Tempo natively on Windows 11.

STEP 1 — DOWNLOAD TEMPO FOR WINDOWS

  1. Go to the Grafana Tempo Releases page on GitHub.
  2. Find the latest stable release (not a pre-release).
  3. Expand the "Assets" section.
  4. Look for the Windows binary file, typically named:
    • tempo_X.X.X_windows_amd64.zip
    • tempo_X.X.X_windows_amd64.tar.gz
  5. Download this file to your computer.

STEP 2 — INSTALL AND SET UP TEMPO

  1. Create a dedicated folder for Tempo: C:\tempo
  2. Extract the downloaded archive into this folder. You should see an executable named tempo.exe.
  3. Create the following folders inside C:\tempo:
    • data
    • wal
    • blocks

STEP 3 — CREATE THE CONFIGURATION FILE

In the C:\tempo folder, create a file named config.yaml and paste the following configuration: 

# C:\tempo\config.yaml

stream_over_http_enabled: true

server:
  http_listen_port: 3200

distributor:
  receivers:
    otlp:
      protocols:
        grpc:
          endpoint: "0.0.0.0:4317"
        http:
          endpoint: "0.0.0.0:4318"

storage:
  trace:
    backend: local
    wal:
      path: C:/tempo/data/wal
    local:
      path: C:/tempo/data/blocks

usage_report:
  reporting_enabled: false

Start the tempo

Running Tempo as a service ensures it starts automatically with Windows.

  1. Open PowerShell as Administrator.
  2. Run the following command to create the service:
cd C:\tempo
.\tempo.exe -config.file=tempo.yaml

STEP 4 — CONFIGURE TEMPO AS A WINDOWS SERVICE

Running Tempo as a service ensures it starts automatically with Windows.

  1. Open PowerShell as Administrator.
  2. Run the following command to create the service:
New-Service -Name "Tempo" -BinaryPathName "C:\tempo\tempo.exe -config.file=C:\tempo\config.yaml" -DisplayName "Grafana Tempo" -StartupType Automatic

STEP 5 — START TEMPO AND VERIFY

A. Start the Service

Start-Service -Name Tempo

B. Verify the Service

Get-Service -Name Tempo

Verify that the Status is Running.

C. Check the API Endpoints

Confirm Tempo is running correctly by checking its API:

Invoke-RestMethod -Uri http://localhost:3200/ready
Heads Up

Immediately checking the /ready endpoint can return:
"Ingester not ready: ingester check ready failed: waiting for 15s after being ready"
Wait 15 seconds — it will then respond with only ready. 

Invoke-RestMethod -Uri http://localhost:3200/status

If everything is set up correctly, both commands should return ready.

TROUBLESHOOTING — PORT 9095 CONFLICT

When you run Tempo with the command below, you may see this error:

tempo.exe -config.file=tempo.yaml
level=info  msg="Starting Tempo" version="(version=2.10.7, branch=HEAD, revision=8100f5a7b)" target=all
level=info  msg="caches available to storage backend" parquet-footer=false bloom=false ...
level=error msg="error running Tempo" err="failed to init module services: error initialising module:
  server: failed to create server: listen tcp :9095: bind: Only one usage of each socket
  address (protocol/network address/port) is normally permitted."

The Problem

listen tcp :9095: bind: Only one usage of each socket address

Both Loki and Tempo try to use port 9095 by default:

ServiceDefault gRPC PortHTTP Port
Loki90953100
Tempo9095 ← conflict!3200
Why This Happens

Both services default to port 9095 for internal gRPC communication. If Loki is already running when you start Tempo, Tempo cannot bind to the same port and crashes immediately.

Quick Fix — Change Tempo's gRPC Port

Edit your tempo.yaml and add grpc_listen_port: 9096 under the server section:

server:
  http_listen_port: 3200
  grpc_listen_port: 9096  # ← change this (default 9095 conflicts with Loki)

distributor:
  receivers:
    otlp:
      protocols:
        grpc:
          endpoint: "0.0.0.0:4317"
        http:
          endpoint: "0.0.0.0:4318"

# Rest of your config remains the same...
After the Fix

Save the file and restart Tempo. It will now bind to port 9096 for gRPC and no longer conflict with Loki on 9095.
