COLLECTING CUSTOM METRICS

COUNTERS, GAUGES & LABELS IN PROMETHEUS WITH NODE.JS

INSTALLATION

Install the official Prometheus client library for Node.js:

npm install prom-client
ES6 Modules

All examples below use ES6 import/export syntax. Make sure your package.json has "type": "module" or use .mjs file extensions.

COMPLETE EXAMPLE

A full Express.js application with custom Counter and Gauge metrics:

import express from 'express';
import client from 'prom-client';

const app = express();

// Create a Registry to register all metrics
const register = new client.Registry();

// ─── 1. COUNTER: HTTP Request Total ───────────────────────────
// Counters only increase — perfect for counting total requests
const httpRequestTotal = new client.Counter({
  name: 'http_requests_total',
  help: 'Total number of HTTP requests received',
  labelNames: ['method', 'route', 'status_code']
});

// ─── 2. GAUGE: Active HTTP Requests ───────────────────────────
// Gauges go up and down — perfect for current active requests
const activeHttpRequests = new client.Gauge({
  name: 'http_requests_active',
  help: 'Number of HTTP requests currently being processed'
});

// Register both metrics
register.registerMetric(httpRequestTotal);
register.registerMetric(activeHttpRequests);

// Collect default Node.js metrics (memory, CPU, event loop, etc.)
client.collectDefaultMetrics({ register });

// ─── MIDDLEWARE: Track metrics for every request ───────────────
app.use((req, res, next) => {
  activeHttpRequests.inc();

  res.on('finish', () => {
    activeHttpRequests.dec();

    httpRequestTotal.inc({
      method: req.method,
      route: req.route ? req.route.path : req.path,
      status_code: res.statusCode
    });
  });

  next();
});

// ─── ROUTES ────────────────────────────────────────────────────
app.get('/', (req, res) => {
  res.json({ message: 'Hello World!' });
});

app.get('/api/users', (req, res) => {
  setTimeout(() => {
    res.json({ users: ['Alice', 'Bob', 'Charlie'] });
  }, 100);
});

app.post('/api/users', (req, res) => {
  res.status(201).json({ message: 'User created' });
});

// ─── /metrics ENDPOINT for Prometheus to scrape ────────────────
app.get('/metrics', async (req, res) => {
  try {
    res.set('Content-Type', register.contentType);
    const metrics = await register.metrics();
    res.end(metrics);
  } catch (err) {
    res.status(500).end(err);
  }
});

const PORT = 3000;
app.listen(PORT, () => {
  console.log(`Server running on http://localhost:${PORT}`);
  console.log(`Metrics available at http://localhost:${PORT}/metrics`);
});

COUNTER METRIC: http_requests_total

What is a Counter?

Counters are metrics that only increase over time. They reset when the application restarts — perfect for counting events like requests, errors, or tasks completed.

Key Methods

// Increment by 1
httpRequestTotal.inc();

// Increment by a specific value
httpRequestTotal.inc(5);

// Increment with labels
httpRequestTotal.inc({ method: 'GET', route: '/api', status_code: 200 });

When to Use a Counter

  • Total HTTP requests received
  • Total errors thrown
  • Total tasks completed
  • Total bytes sent/received

GAUGE METRIC: http_requests_active

What is a Gauge?

Gauges can go up or down — ideal for tracking current values like active requests, memory usage, or queue sizes.

Key Methods

// Set to a specific value
activeHttpRequests.set(10);

// Increment (increase by 1)
activeHttpRequests.inc();

// Decrement (decrease by 1)
activeHttpRequests.dec();

// Increment by specific value
activeHttpRequests.inc(5);

// Decrement by specific value
activeHttpRequests.dec(3);

When to Use a Gauge

  • Active/in-flight requests
  • Current memory usage
  • Queue depth
  • Number of connected users
  • Temperature or CPU usage

Counter vs Gauge — At a Glance

Counter

  • Only goes up ↑
  • Resets on restart
  • Use rate() to query
  • Example: total requests

Gauge

  • Goes up and down ↕
  • Reflects current state
  • Query directly
  • Example: active requests

ADDING LABELS FOR BETTER INSIGHTS

Labels allow you to segment your metrics by dimensions like HTTP method, route, or status code. 

import client from 'prom-client';

const httpRequestDuration = new client.Histogram({
  name: 'http_request_duration_seconds',
  help: 'HTTP request duration in seconds',
  labelNames: ['method', 'route', 'status_code'],
  buckets: [0.1, 0.5, 1, 2, 5]   // buckets in seconds
});

// In your middleware
app.use((req, res, next) => {
  const end = httpRequestDuration.startTimer();

  res.on('finish', () => {
    end({
      method: req.method,
      route: req.route ? req.route.path : req.path,
      status_code: res.statusCode
    });
  });

  next();
});
High Cardinality Warning

Never use user IDs, session tokens, or request IDs as label values. Each unique combination creates a new time series — millions of users = millions of series = Prometheus crashes.

BEST PRACTICES

✅ Do's

  • Use meaningful metric names — follow Prometheus naming conventions: snake_case, include units (_seconds, _bytes, _total)
  • Always add help text — describe what the metric measures so future-you understands it
  • Use labels for dimensions — method, route, status code are good label candidates
  • Register all metrics — always call register.registerMetric() for custom metrics
  • Use histograms for latency — they give you percentiles (p95, p99) which are far more useful than averages

❌ Don'ts

  • Don't use high-cardinality labels — avoid user_id, request_id, session_token
  • Don't track averages — use histograms instead
  • Don't expose sensitive data — no passwords or tokens in metric names or labels
💡 Golden Rule

Start with the Four Golden Signals — Latency, Traffic, Errors, Saturation. Add custom metrics only when you need to answer a specific question that default metrics can't answer.
