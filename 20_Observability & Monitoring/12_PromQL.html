PROMETHEUS QUERY LANGUAGE — FROM ZERO TO HERO

WHAT IS PROMQL?

PromQL (Prometheus Query Language) is the query language used to extract and analyze metrics stored in Prometheus. Think of it as SQL for time-series data — but specifically designed for monitoring and observability.

What Problem Does It Solve?

Imagine you have millions of data points coming from your servers every second. PromQL lets you ask questions like:

Questions You Can Ask

  • "What was the average CPU usage in the last hour?"
  • "Which endpoints are showing 5xx errors right now?"
  • "How much has memory grown compared to yesterday?"
  • "What is the p99 latency of my checkout API?"

Data It Works With

  • CPU usage over time
  • Memory consumption
  • HTTP request rates
  • Error counts
  • Custom business metrics

DATA TYPES OVERVIEW

PromQL has 4 data types. Understanding them is the key to writing correct queries.

TypeWhat It IsExampleResult Type
Scalar A plain number, no labels 10 + 5 scalar
String A text value "hello" string
Instant Vector One value per series, right now node_cpu_usage vector
Range Vector Multiple values per series, over time node_cpu_usage[5m] matrix

1. SCALAR — JUST A NUMBER

Think of It As

A calculator display. You see 42. That's it. No context, no history, no "when" — just a plain number.

Real-World Analogy

Someone asks: "How many fingers am I holding up?" You answer: "3" — not "3 at 2:30 PM". Just 3. That's a scalar.

Examples

# Simple math → scalar
10 + 5
# Returns: 15

# Counting series → scalar
count(http_requests_total)
# Returns: 42

How to Identify a Scalar

QuestionAnswer
Does it have labels (server, method, etc.)?❌ No
Does it have a timestamp?❌ No
Is it just a plain number?✅ Yes

2. STRING — TEXT VALUE

"hello world"
# Returns: "hello world"
Rarely Used

Strings are rarely used in daily PromQL work — mostly for metadata and labels. Focus your energy on Instant Vectors and Range Vectors.

3. INSTANT VECTOR — ONE VALUE PER SERIES, RIGHT NOW

Definition

A vector in math is a list of values. In PromQL, an Instant Vector is a list of (metric + labels) → single value pairs, all captured at the same point in time.

Think of it as a column in a spreadsheet — each row is a different time series, and the column holds exactly one number per row, taken right now.

Think of It As

A class photo taken right now. You see every student's face (each series) at this exact moment (one value each).

Real-World Analogy

You're a manager checking server room monitors right now:

ServerTemperature RIGHT NOW
Server A45°C
Server B62°C
Server C38°C
Server D91°C ⚠️

That table is an instant vector — one value per server, at this instant.

How It Looks in Prometheus

# Simple query — returns instant vector
node_cpu_usage
# Returns:
node_cpu_usage{server="A"} → 45
node_cpu_usage{server="B"} → 62
node_cpu_usage{server="C"} → 38
node_cpu_usage{server="D"} → 91

How to Identify an Instant Vector

QuestionAnswer
Does it have labels?✅ Yes
Does each series have ONE value?✅ Yes
Are you seeing "current" values?✅ Yes
Is there NO time range like [5m]?✅ Yes
Result type in Prometheus UI?✅ "vector"

4. RANGE VECTOR — MULTIPLE VALUES OVER TIME

Definition

A Range Vector is a list of (metric + labels) → multiple values over time pairs. Instead of one value per series, you get a slice of history — every data point Prometheus scraped within the time window.

Think of it as a spreadsheet with multiple columns — each row is a time series, but now each row holds a whole list of timestamped values, not just one. This is why it's also called a matrix in Prometheus.

Think of It As

A video recording of the classroom over 5 minutes. You see every student's movement, every second — not just a snapshot.

Real-World Analogy

You're reviewing server temperature history:

ServerTemperature over last 5 minutes
Server A45°, 47°, 52°, 49°, 44°, 46°
Server B62°, 61°, 63°, 60°, 62°, 65°

How It Looks in Prometheus

# The [5m] is what makes it a range vector
node_cpu_usage[5m]
# Returns:
node_cpu_usage{server="A"} → 45@10:00, 47@10:01, 52@10:02, 49@10:03, 44@10:04
node_cpu_usage{server="B"} → 62@10:00, 61@10:01, 63@10:02, 60@10:03, 62@10:04

How to Identify a Range Vector

QuestionAnswer
Does it have labels?✅ Yes
Does each series have MULTIPLE values?✅ Yes
Does it have [time] like [5m] or [1h]?✅ Yes
Can you graph it directly?❌ No — needs processing first
Result type in Prometheus UI?✅ "matrix"
You Can't Graph a Range Vector Directly

A range vector is raw data. You must wrap it in a function like rate(), avg_over_time(), or max_over_time() to turn it into something graphable.

HOW rate() WORKS

The rate() function calculates how fast a counter is increasing per second over a specified time window.

Step-by-Step Walkthrough

The Time Window [1m]

When you write [1m], Prometheus looks back at the last 1 minute of data from the current moment.

What Data Points Are Included 
Current time: 10:04:30

Time:     10:03:30    10:04:00    10:04:30 (now)
               ↑           ↑           ↑
               └───────────┴───────────┘
                     Last 1 minute window
Concrete Calculation

Scenario: counter tracking total HTTP requests (only goes up):

TimeTotal Requests So Far
10:03:001,000
10:03:151,030
10:03:301,070
10:03:451,120
10:04:001,180
10:04:151,250
10:04:301,330
 
Query: rate(http_requests_total[1m]) at 10:04:30

Step 1 — Window: 10:03:30 → 10:04:30
  Start value: 1,070
  End value:   1,330

Step 2 — Increase:
  1,330 - 1,070 = 260 requests

Step 3 — Divide by seconds:
  260 / 60 = 4.33 requests per second

Result: Over the last minute, requests came in at an average rate of 4.33 per second.

READING A PROMQL RESULT

Let's decode a real result you'd see in Prometheus:

{instance="localhost:4000", job="my-express-app", method="GET", path="/fancy", status_code="200"}
→ 0.06666666666666665

What Does 0.0666 Mean?

It's Requests Per Second

0.0666 = approximately 1 request every 15 seconds

Breaking It Down

Time WindowRequests Expected
Per second0.066 requests
Per 15 seconds~1 request
Per minute~4 requests (0.066 × 60)
Per 3 minutes~12 requests (4 × 3)

How Prometheus Calculated This

Query used: rate(http_requests_total[3m])

Step 1 — Look back 3 minutes (180 seconds)
  3 minutes ago: counter = 1,000
  Now:           counter = 1,012

Step 2 — Calculate increase
  1,012 - 1,000 = 12 requests

Step 3 — Divide by window in seconds
  12 / 180 = 0.0666 requests per second

What This Tells You

QuestionAnswer
Is my API busy?Not really — 1 request every 15 seconds
What if this drops to 0?Your API might be down or not receiving traffic
What if this spikes to 10?Sudden traffic surge!

Convert to Human-Readable Units

# Requests per minute (multiply by 60)
rate(http_requests_total[3m]) * 60
# Returns: 4 (requests per minute)

# Requests per hour (multiply by 3600)
rate(http_requests_total[3m]) * 3600
# Returns: 240 (requests per hour)

AGGREGATION ACROSS LABELS

Use sum() to combine multiple series into one:

# Total requests across ALL endpoints
sum(http_requests_total)

# Total requests grouped by method
sum(http_requests_total) by (method)

# Error rate across all services
sum(rate(http_requests_total{status_code=~"5.."}[5m]))
/
sum(rate(http_requests_total[5m]))
💡 Golden Rule

Remember the data type flow: 

metric_name        → Instant Vector (one value now)
metric_name[5m]    → Range Vector   (many values, can't graph)
rate(metric[5m])   → Instant Vector (one rate value, can graph)
sum(rate(...))     → Instant Vector (aggregated, can graph)
