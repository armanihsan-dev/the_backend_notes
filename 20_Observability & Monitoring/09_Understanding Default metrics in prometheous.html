DEFAULT METRICS IN PROMETHEUS

WHAT THEY MEASURE, WHY THEY MATTER & HOW TO READ THEM

1️⃣ process_cpu_seconds_total

Easy Definition

A running total of how many seconds your app has actually used the CPU since it started. Like a car's odometer for CPU time.

Purpose

Find out if your app is doing heavy computation. Use rate() to see CPU usage per second.

Get the Value in Node.js

const cpuSeconds = (process.cpuUsage().user + process.cpuUsage().system) / 1000000;

What the Numbers Mean

ScenarioCPU SecondsMeaning
App running 1 hour 600s Used 10 min of CPU — idle most of the time ✅
App running 1 hour 3600s Used full 1 hour of CPU — always busy ⚠️

2️⃣ process_start_time_seconds

Easy Definition

The exact Unix timestamp (in seconds) when your app was born / started.

Purpose

Calculate uptime, detect unexpected restarts, know when counters reset to zero.

Get the Value in Node.js

const startTime = Math.floor(performance.timeOrigin / 1000);

What It Tells You

  • 1743878400 means your app started at that exact Unix timestamp
  • Current time − this value = how many seconds your app has been running
  • If this value suddenly changes → your app restarted unexpectedly

3️⃣ process_resident_memory_bytes

Easy Definition

How much physical RAM your app is actually using right now. The real memory cost the OS sees.

Purpose

Predict when your app might crash from Out Of Memory (OOM).

Get the Value in Node.js

const rssBytes = process.memoryUsage().rss;

What It Tells You

✅ Healthy

500 MB RSS on a 1 GB server → using half the RAM

⚠️ Warning

RSS keeps growing over time → potential memory leak

4️⃣ nodejs_eventloop_lag_max_seconds

Easy Definition

The worst delay in your event loop. Shows how long your app froze and couldn't handle new requests.

Purpose

Detect blocking code like synchronous file reads, heavy loops, or large JSON parsing that freezes your app.

Get the Value in Node.js

const { monitorEventLoopDelay } = require('perf_hooks');
const lagMonitor = monitorEventLoopDelay({ resolution: 10 });
lagMonitor.enable();

// Later, get the max lag
const maxLagSeconds = lagMonitor.max / 1e9;
lagMonitor.reset(); // Reset to measure next interval

What the Numbers Mean

ValueStatusMeaning
0.01s (10ms)✅ HealthyNormal, responsive app
0.5s (500ms)⚠️ WarningUsers notice slowness
3s+❌ CriticalApp appears completely frozen
Common Causes of High Lag
  • Synchronous file reads (fs.readFileSync)
  • Heavy JSON.parse() on large payloads
  • Long-running for loops
  • Blocking crypto operations

5️⃣ nodejs_heap_size_used_bytes

Easy Definition

Memory currently used by your JavaScript objects — arrays, objects, strings, functions, closures.

Purpose

Track JS memory growth and detect JavaScript memory leaks.

Get the Value in Node.js

const heapUsed = process.memoryUsage().heapUsed;

What It Tells You

  • Heap keeps growing but never goes down → likely a memory leak
  • Sudden spike then drop → garbage collection happened (normal)
  • Approaches heap limit → JavaScript heap out of memory crash coming

6️⃣ nodejs_external_memory_bytes

Easy Definition

Memory used by Buffers, native addons, and data outside JavaScript's main heap.

Purpose

Explain why total RAM (RSS) is high even when heapUsed looks normal.

Get the Value in Node.js

const external = process.memoryUsage().external;

What It Tells You

High external + Low heap

Your app uses lots of Buffers — file uploads, streams, database results

External grows, never shrinks

Native memory leak — investigate Buffer usage

THE BIG PICTURE: HOW THESE METRICS WORK TOGETHER

Total RAM (RSS) = heapUsed + external + Node.js internals + code

Example Scenario

RSS (Total)
500 MB — what the OS sees
heapUsed (JS objects)
100 MB
external (Buffers)
300 MB
Node.js overhead
100 MB
Key Insight

Without nodejs_external_memory_bytes, you'd wonder "Where's the other 400 MB going?" — it's in Buffers from file uploads and streams.

ONE HELPER FUNCTION TO GET ALL METRICS

function getAllMetrics() {
  const cpu = process.cpuUsage();
  const mem = process.memoryUsage();

  return {
    cpu_seconds:       (cpu.user + cpu.system) / 1e6,
    start_time:        Math.floor(performance.timeOrigin / 1000),
    rss_bytes:         mem.rss,
    heap_used_bytes:   mem.heapUsed,
    external_bytes:    mem.external
  };
}

console.log(getAllMetrics());
