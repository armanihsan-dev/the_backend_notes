LINKING LOGS & TRACES

CONNECTING LOKI LOGS TO TEMPO TRACES — AND TRACES BACK TO LOGS — IN GRAFANA

PART 1: CORE CONCEPT

Linking logs to traces in Grafana creates a seamless two-way navigation between your application logs and the distributed traces they belong to. This is done through configuration between your Loki (logs) and Tempo (traces) data sources.

Logs → Traces

You're reading a log line in Loki. Grafana detects the trace_id field inside it and renders it as a clickable link that opens the full trace in Tempo.

Traces → Logs

You're inspecting a span in Tempo. Grafana uses the span's trace ID, service name, and time range to automatically query Loki and show the matching logs alongside the trace. 

Loki Log View                        Tempo Trace View
──────────────────                   ──────────────────
Log line with trace_id  ──────────►  Full trace + all spans
                         click link
                        ◄──────────  Click span → matching logs
                         "View logs"

Prerequisite — Your Logs Must Contain Trace IDs

The most important prerequisite is that your application injects the trace ID into its log lines. OpenTelemetry instrumentation does this automatically. Your logs should contain a field like trace_id="...": 

time="2026-06-15T12:00:00Z" level=info msg="User order placed" trace_id="a1b2c3d4e5f6"
OpenTelemetry does this for you

When you use OpenTelemetry's logging bridge (e.g. with pino + @opentelemetry/winston-transport or similar), the active traceId and spanId are automatically injected into every log line emitted during an active span.

PART 2: LOGS → TRACES (CONFIGURE LOKI)

This is where you create the link from a log line to its trace. Grafana calls this a Derived Field — it scans each log line with a regex, extracts the trace ID, and renders it as a clickable link to Tempo.

Navigation

Grafana → Connections → Data sources → [Your Loki source] → Derived fields

Derived Fields Configuration

Click Add and fill in the following fields:

Field Value Notes
Name TraceID Any descriptive label
Type Regex Extracts a value from the raw log message
Regex (logfmt) trace_id=(\w+) Capture group (\w+) extracts the ID
Regex (quoted) trace_id="(\w+)" Use this if your log wraps the value in quotes
Internal link ✅ Enabled Turns the extracted value into a clickable link
Data source Your Tempo data source The link will open traces in this backend
Query ${__value.raw} Passes the extracted trace ID directly to Tempo

Click Save & test when done.

How ${__value.raw} works

${__value.raw} is a Grafana variable that holds the value captured by the regex capture group. So if your log contains trace_id="a1b2c3", Grafana passes a1b2c3 directly to Tempo's trace lookup API.

PART 3: TRACES → LOGS (CONFIGURE TEMPO)

This configures the reverse direction: when you're inspecting a trace in Tempo, you can click a span and jump directly to the logs from that service and time window in Loki.

Navigation

Grafana → Connections → Data sources → [Your Tempo source] → Trace to logs

Step-by-Step Setup

Step 1 — Fill in the 4 Core Fields

Field Value What it does
Data source Loki Tells Tempo where to send the log query
Span start time shift -1m Fetch logs starting 1 min before the span started
Span end time shift 1m Fetch logs ending 1 min after the span ended
Filter by trace ID ${__trace.traceId} Always scopes logs to this specific trace

Step 2 — Map Tags (Optional but Recommended)

Tags map span attributes to Loki labels so Grafana can narrow the log query to the exact service and host instead of fetching all logs in the time window. 

service.name  →  service_name    # filters logs to the right service
host.name     →  host            # filters logs to the right pod/machine

Step 3 — Save & Test

Click Save & test. Grafana will verify the connection to Loki is healthy.

How It Works Internally

When you click "View logs" on a span in Tempo, Grafana runs this sequence:

Trace View: Click on "User Service" span
    │
    ▼
Grafana automatically:
    1. Takes trace_id from the span
    2. Takes service name from the span
    3. Takes start/end time from the span (+ your configured shifts)
    4. Builds and runs a Loki query:
       {service_name="user-service", trace_id="abc123"}
    5. Shows you the matching logs inline

Complete LogQL Query Examples

// Minimal — just filter by trace ID
{trace_id="${__trace.traceId}"}

// With service filter (most common)
{service_name="${service.name}", trace_id="${__trace.traceId}"}

// With JSON parsing (if logs are JSON-structured)
{service_name="${service.name}"} | json | trace_id="${__trace.traceId}"
Variable What it contains
${__trace.traceId} The trace ID of the trace currently being viewed
${service.name} The service.name attribute from the clicked span
${__value.raw} The value captured by the Derived Field regex in Loki
