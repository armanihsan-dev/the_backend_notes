WHAT IS TRACING?

Tracing is the third pillar of observability (alongside metrics and logs). A trace records the full journey of a single request as it travels through your system — every function call, database query, and external API call, all linked together.

Metrics

What is happening?

Logs

Why did it happen?

Traces

Where did it happen?

Without Tracing vs With Tracing

❌ Without Tracing

  • Request took 2 seconds — but where?
  • Was it the DB? The auth service? The cache?
  • You have logs but they are disconnected
  • No way to see the full request path

✅ With Tracing

  • See every step of the request as a timeline
  • Instantly see DB query took 1.8s of the 2s
  • All logs linked to the same trace ID
  • Full request path visualized in Grafana

WHAT IS OPENTELEMETRY?

OpenTelemetry (OTEL) is an open-source observability framework that provides a single standard for collecting traces, metrics, and logs from your application — regardless of which backend you send them to.

One Line

OTEL is the collector. Grafana Tempo / Jaeger / Zipkin are the viewers. You instrument once with OTEL, then switch backends freely.

Component Role Example
SDK Instruments your code @opentelemetry/sdk-node
API Creates spans manually @opentelemetry/api
Auto Instrumentation Auto-traces Express, HTTP, DB @opentelemetry/auto-instrumentations-node
Exporter Sends traces to a backend OTLP, Jaeger, Zipkin

WHY OPENTELEMETRY?

Problem Before OTEL OTEL Solution
Every vendor had its own SDK One SDK works with all backends
Switching backends required rewriting code Change exporter config, keep instrumentation
No standard for trace context propagation W3C TraceContext standard built-in
Manual instrumentation for every library Auto-instrumentation for 100+ libraries

├── SPAN: HTTP GET /users              [0ms ──────────────── 250ms]

│     spanId:  span-1
│     attributes: { http.method: GET, http.url: /users }
│
│   ├── SPAN: middleware auth          [5ms ──── 20ms]
│   │     parentSpanId: span-1
│   │
│   ├── SPAN: db.query SELECT users    [25ms ───────────── 200ms]
│   │     parentSpanId: span-1
│   │     attributes: { db.statement: "SELECT * FROM users" }
│   │
│   └── SPAN: serialize response       [205ms ── 245ms]
│         parentSpanId: span-1
Term What It Is
Trace The full journey of one request — a collection of spans
Span A single unit of work with start time, end time, and attributes
Trace ID Unique ID shared by all spans in one request
Span ID Unique ID for one specific span
Parent Span ID Links child spans to parent — builds the tree
Attributes Key-value metadata on a span (URL, DB query, user ID)

otel-loader.js

import { register } from "node:module";
import { pathToFileURL } from "node:url";

register("@opentelemetry/instrumentation/hook.mjs", pathToFileURL("./"));
Why Does This File Exist?

Node.js ESM (ES Modules) uses a module loader hook system. When you use import statements, Node loads modules through its own ESM loader. OTEL needs to intercept that loading process to patch libraries like Express, HTTP, and pg before your code uses them.

register() tells Node: "before you load any module, run OTEL's hook so it can monkey-patch it for instrumentation." Without this file, auto-instrumentation silently does nothing in ESM projects.

Without otel-loader.js With otel-loader.js
OTEL SDK starts after modules are already loaded OTEL hook runs before any module loads
Auto-instrumentation patches arrive too late Express, HTTP, DB libs are patched at import time
No spans generated automatically Every request, DB call, outgoing HTTP is traced

instrumentation.js

This file configures the OTEL SDK — what to trace, where to send traces. 

import { NodeSDK } from '@opentelemetry/sdk-node';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';
import { resourceFromAttributes } from '@opentelemetry/resources';
import { SEMRESATTRS_SERVICE_NAME } from '@opentelemetry/semantic-conventions';

const exporter = new OTLPTraceExporter({
    // Grafana Tempo default OTLP endpoint
    url: 'http://localhost:4318/v1/traces',
});

const sdk = new NodeSDK({
    // Name your service — shows up in Grafana
   resource: resourceFromAttributes({
        [SEMRESATTRS_SERVICE_NAME]: 'my-express-app',
    }),

    traceExporter: exporter,

    // Auto-instruments: Express, HTTP, fetch, pg, mongodb, redis, etc.
    instrumentations: [
        getNodeAutoInstrumentations({
            '@opentelemetry/instrumentation-fs': { enabled: false }, // too noisy
        }),
    ],
});

sdk.start();

// Graceful shutdown — flushes remaining spans before process exits
process.on('SIGTERM', () => sdk.shutdown());
process.on('SIGINT',  () => sdk.shutdown());
What getNodeAutoInstrumentations() Does

It automatically instruments 100+ popular Node.js libraries — Express routes, incoming/outgoing HTTP, fetch, pg, mysql, mongodb, redis, grpc, and more. Every call to these libraries generates a span automatically with zero code changes in your app.

.vscode/launch.json

This tells VS Code how to start your app with OTEL loaded before your application code runs. 

{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Launch Program",
      "skipFiles": ["<node_internals>/**"],
      "runtimeArgs": [
        "--import=./otel-loader.js",
        "--import=./instrumentation.js"
      ],
      "program": "${workspaceFolder}\\app.js"
    }
  ]
}

Why --import and Not --require?

--require (CJS only)

Works for CommonJS. Fails with ESM import statements.

--import (ESM ✅)

Works with ES Modules. Runs the file before anything else loads.

Load Order When App Starts

1. --import=./otel-loader.js     → registers ESM module hook
2. --import=./instrumentation.js → starts OTEL SDK, patches libraries
3. app.js                         → your Express app starts
                                    (Express is already patched — spans flow!)
Order Matters

otel-loader.js must come before instrumentation.js in runtimeArgs. The loader registers the hook, then instrumentation uses that hook to patch libs.

app.js — Your Express App

Your app code stays completely clean — no OTEL imports needed. Auto-instrumentation handles everything automatically. 

import express from 'express';

const app = express();
app.use(express.json());

app.get('/users', async (req, res) => {
    // This entire route is automatically traced:
    // - The incoming HTTP span is created by OTEL
    // - Any DB calls inside will be child spans
    const users = [{ id: 1, name: 'John' }, { id: 2, name: 'Jane' }];
    res.json(users);
});

app.get('/users/:id', async (req, res) => {
    // OTEL auto-traces this route too
    // http.method, http.url, http.status_code all captured automatically
    res.json({ id: req.params.id, name: 'John' });
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});
What Gets Traced Automatically
  • Every incoming HTTP request → span with method, URL, status code, duration
  • Every outgoing HTTP/fetch call → child span
  • Every database query (pg, mysql, mongo) → child span with query text
  • Every Redis command → child span

CUSTOM SPANS — MANUAL INSTRUMENTATION

Auto-instrumentation covers libraries. For your own business logic, add custom spans manually: 

import { trace, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('my-express-app');

app.post('/orders', async (req, res) => {
    // Create a custom span for the full order flow
    const span = tracer.startSpan('process-order');

    try {
        span.setAttributes({
            'order.userId': req.body.userId,
            'order.itemCount': req.body.items.length,
            'order.totalAmount': req.body.total,
        });

        // Nested custom span for payment
        const paymentSpan = tracer.startSpan('validate-payment', {
            parent: span,
        });
        await validatePayment(req.body.payment);
        paymentSpan.end();

        // Nested span for inventory
        const inventorySpan = tracer.startSpan('update-inventory', {
            parent: span,
        });
        await updateInventory(req.body.items);
        inventorySpan.end();

        span.setStatus({ code: SpanStatusCode.OK });
        res.json({ success: true });

    } catch (err) {
        span.setStatus({ code: SpanStatusCode.ERROR, message: err.message });
        span.recordException(err);
        res.status(500).json({ error: err.message });
    } finally {
        span.end(); // Always end the span
    }
});

Adding Span Events (Like Log Entries Inside a Span)

span.addEvent('cache miss — fetching from DB', {
    'cache.key': 'user:123',
    'timestamp': Date.now(),
});

span.addEvent('DB query complete', {
    'db.rows_returned': 42,
});

Linking Traces to Logs

Add traceId and spanId to your pino logs so you can jump from a log entry directly to the trace in Grafana: 

import { trace } from '@opentelemetry/api';

app.use((req, res, next) => {
    const span = trace.getActiveSpan();
    const ctx = span?.spanContext();
    req.log = logger.child({
        traceId: ctx?.traceId,
        spanId:  ctx?.spanId,
    });
    next();
});

WHY otel-loader.js EXISTS — DEEP DIVE

Node.js ESM loads modules asynchronously using a loader hook chain. When you write import express from 'express', Node resolves, loads, and evaluates the module. OTEL needs to intercept the load step to wrap exported functions with tracing code. 

Normal ESM load:
  Node resolves 'express' → loads express/index.js → your code uses it

With otel-loader.js:
  Node resolves 'express' → OTEL hook intercepts → wraps Router methods
                          → loads express/index.js → your code uses patched version
                                                       ↑ spans generated here
The Key Insight

otel-loader.js is a one-time registration that tells Node's module system to use OTEL's loader hook for every subsequent import. It must run before everything else — that is exactly what --import=./otel-loader.js in launch.json guarantees.

HOW AUTO-INSTRUMENTATION WORKS

Library What OTEL Patches Span Created
express Router.handle, middleware chain GET /users with status, duration
http/https http.request, http.get Outgoing HTTP calls with URL, method, status
pg Client.query DB span with SQL query text
mongodb Collection methods DB span with collection, operation
redis Command execution Redis span with command name
fetch globalThis.fetch Outgoing fetch with URL, method
