Sending Express.js Logs to Loki

There are two main approaches to send your Express.js logs to Loki. I'll cover both, but the push approach using pino-loki is the most direct and common method.

Architecture Overview

Express.js App → Pino → pino-loki transport → Loki → Grafana

Loki typically gets logs through Promtail which reads log files, but pino-loki sends logs directly from your application to Loki - no additional infrastructure needed.

Method 1: Push Approach with pino-loki (Recommended)

Installation

npm install pino pino-http pino-loki

Basic Setup - Single Transport

Create a logger.js file:

import pino from 'pino';
import pinoHttp from 'pino-http';

const transport = pino.transport({
  target: "pino-loki",
  options: {
    batching: true,           // Send logs in batches
    interval: 5,              // Send every 5 seconds
    host: 'http://localhost:3100',  // Your Loki instance
    // Optional: Authentication
    basicAuth: {
      username: process.env.LOKI_USERNAME,
      password: process.env.LOKI_PASSWORD
    },
    // For Grafana Cloud Loki:
    headers: {
      'X-Scope-OrgID': 'your-tenant-id'
    }
  }
});

export const logger = pino(transport);

Complete Express.js Integration

Here's a full working example (index.js):

import express from 'express';
import pino from 'pino';
import pinoHttp from 'pino-http';
import 'dotenv/config';

const app = express();
const port = process.env.PORT || 3000;

// Configure Loki transport
const transport = pino.transport({
  target: "pino-loki",
  level: process.env.LOG_LEVEL || 'info',
  options: {
    batching: true,
    interval: 5,
    host: process.env.LOKI_HOST || "http://localhost:3100",
    basicAuth: {
      username: process.env.LOKI_USERNAME,
      password: process.env.LOKI_PASSWORD
    },
    labels: {
      app: process.env.APP_NAME || "my-express-app",
      environment: process.env.NODE_ENV || "development",
      runtime: `nodejs/${process.version}`
    }
  }
});

// Create logger instance
const logger = pino(transport);

// Use pino-http middleware for automatic HTTP request logging
app.use(pinoHttp({
  logger,
  autoLogging: true,
  customLogLevel: (req, res, err) => {
    if (res.statusCode >= 500) return 'error';
    if (res.statusCode >= 400) return 'warn';
    return 'info';
  }
}));

app.use(express.json());

// Example routes
app.get('/', (req, res) => {
  req.log.info('Home page accessed');
  res.send('Hello World!');
});

app.post('/users', (req, res) => {
  req.log.info({ body: req.body }, 'Creating new user');
  res.status(201).json({ message: 'User created' });
});

app.get('/error', (req, res) => {
  req.log.error('Something went wrong!');
  res.status(500).send('Internal Server Error');
});

app.listen(port, () => {
  logger.info(`Server started on port ${port}`);
});

Method 2: Multiple Transports (Loki + Console Pretty Print)

This is useful for development - you get pretty console output while still sending logs to Loki: 

import pino from 'pino';

const transport = pino.transport({
  targets:[
    {
      target: "pino-loki",
      level: 'info',
      options: {
        batching: true,
        interval: 5,
        host: process.env.LOKI_HOST || "http://localhost:3100",
        labels: {
          app: "my-express-app",
          environment: process.env.NODE_ENV
        }
      }
    },
    {
      target: 'pino-pretty',
      level: 'debug',
      options: {
        colorize: true,
        translateTime: 'SYS:standard',
        ignore: 'pid,hostname'
      }
    }
  ]
});

const logger = pino(transport);

Environment Variables Setup

Create a .env file:

# Loki Configuration
LOKI_HOST=http://localhost:3100
LOKI_USERNAME=your-username
LOKI_PASSWORD=your-password

# Application
APP_NAME=my-express-app
NODE_ENV=development
LOG_LEVEL=info
PORT=3000

Key pino-loki Options Explained

Option Default Description
batching true Send logs in batches for better performance
interval 5 How often to send batched logs (seconds)
timeout 30000 Request timeout in milliseconds
silenceErrors false If false, shows errors in console
replaceTimestamp false Replace log timestamp with Date.now()
labels {} Additional labels added to all logs

Labels: Why They Matter

Labels in Loki are what make logs searchable and filterable - similar to tags. Always include: 

labels: {
  app: "my-app",           // Which application
  service: "auth-api",     // Which service
  environment: "production", // dev/staging/prod
  version: "2.1.0"         // App version
}

In Grafana, you can then filter logs with queries like:

{app="my-app", environment="production", level="error"}

Method 3: Pull Approach (Promtail + File)

If you prefer not to send logs directly from your app, you can write logs to files and let Promtail collect them: 

import pino from 'pino';

// Write logs to file instead of sending directly
const transport = pino.transport({
  target: 'pino/file',
  options: { destination: './logs/app.log' }
});

const logger = pino(transport);

Then configure Promtail to read and forward these logs to Loki.

Testing Your Setup

1. Verify Loki is running:

curl http://localhost:3100/ready
# Should return: ready

2. Check if logs are arriving:

# List available labels
curl http://localhost:3100/loki/api/v1/labels

# Query logs from the last hour
curl "http://localhost:3100/loki/api/v1/query_range?query={app=\"my-express-app\"}&limit=10"

3. View in Grafana:

  • Add Loki as a data source (URL: http://localhost:3100)
  • Go to Explore
  • Query: {app="my-express-app"}

Troubleshooting

Logs not appearing in Loki?

  • Check Loki is running: curl http://localhost:3100/ready
  • Check your app logs for errors from pino-loki
  • Set silenceErrors: false to see errors
  • Verify the host URL is correct
