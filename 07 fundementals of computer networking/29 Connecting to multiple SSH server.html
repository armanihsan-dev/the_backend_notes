SSH Troubleshooting Notes

❌ The Error You Saw 
ssh local-server
ssh: Could not resolve hostname local-server: No such host is known.

ssh aws-server
ssh: Could not resolve hostname aws-server: No such host is known.

This happens because ssh is trying to interpret local-server and aws-server as actual hostnames.

But your system has no idea what those names mean. They are not:

  • Real domain names (like google.com)
  • Real IP addresses (like 192.168.1.10)
  • Or aliases defined in your SSH config or hosts file

So the system responds: "No such host is known."

🔑 Why It Happens

SSH command syntax is:

ssh <user>@<host>

where <host> must be:

  • A real IP address (192.168.1.10)
  • A real DNS hostname (ec2-11-22-33-44.compute-1.amazonaws.com)
  • An alias you define yourself in either:
    • SSH config (~/.ssh/config)
    • Or Windows hosts file (C:\Windows\System32\drivers\etc\hosts)

Since you typed local-server and aws-server, but they aren’t defined anywhere, SSH cannot resolve them.

✅ How to Fix

Option 1: Use the Real IP/Domain Directly

Instead of ssh local-server, run:

ssh arman@192.168.1.10       # Example: local machine
ssh ubuntu@3.22.45.67        # Example: AWS EC2
ssh ubuntu@ec2-xx-xx-xx-xx.compute-1.amazonaws.com

Option 2: Create SSH Aliases (💡 Best Way)

Aliases let you connect with short names like ssh local-server.

Open your SSH config file:

nano ~/.ssh/config

(In Windows + WSL or Git Bash, the path is the same: ~/.ssh/config)

Add entries:

Host local-server
    HostName 192.168.1.10
    User arman

Host aws-server
    HostName ec2-xx-xx-xx-xx.compute-1.amazonaws.com
    User ubuntu

Save and exit.

Now you can connect with:

ssh local-server
ssh aws-server

Option 3: Use Windows Hosts File

This makes names like local-server behave like real DNS names.

Open this file as Administrator:

C:\Windows\System32\drivers\etc\hosts

Add mappings:

192.168.1.10    local-server
3.22.45.67      aws-server

Save. Now you can run:

ssh arman@local-server
ssh ubuntu@aws-server

📌 Summary

The error happens because local-server and aws-server don’t mean anything to your system by default.

You must use real IPs/domains OR define aliases in either ~/.ssh/config or hosts file.

Best practice: use ~/.ssh/config so you can also store User, Port, and IdentityFile (private key) all in one place.
