Ports in Networking 🏠

Think of an IP address as a **house address**, like `123 Main Street`. A **port** is like an **apartment number** in that house. It's a virtual, software-based endpoint on a device where network connections begin and end. Ports allow a single device to run multiple network services simultaneously and differentiate between different kinds of data traffic. 🏠

For example, your computer might be running a web browser, a streaming service, and an email client all at the same time. All this traffic arrives at your computer's IP address, but it's the **port number** that tells the computer which application should receive which data. Your web browser uses one port (e.g., 80 or 443), while your email client might use another (e.g., 25 or 110). Ports operate at Layer 4 of the OSI model, the **Transport Layer**.

How Ports Work

When an application on your computer wants to communicate with a server on the internet, it creates a **socket**, which is a combination of an IP address and a port number. For instance, to view a website, your browser might establish a connection to a web server at 142.250.190.78:443.

  • The **IP address** (142.250.190.78) gets the data to the correct computer on the network.
  • The **port number** (443) directs the data to the specific application (the web server) running on that computer.

Without ports, every single service would require its own physical network connection, which is not feasible. Ports allow for a process called **multiplexing**, where a single network connection is used for many different services.

Port Number Ranges

Ports are assigned unique numbers from 0 to 65535. These are divided into three main ranges:

  • Well-Known Ports (0-1023): These are reserved for common, standardized services and protocols. For instance, HTTP always uses port 80, and HTTPS uses port 443.
  • Registered Ports (1024-49151): These can be used by applications and are assigned by the IANA (Internet Assigned Numbers Authority) for specific services that are less common than those in the well-known range.
  • Dynamic/Private Ports (49152-65535): These are used for temporary connections and are often assigned automatically by the operating system for client-side applications when they initiate a connection.

Common Port Numbers and Protocols

A few ports are particularly important to know:

  • Port 21: FTP (File Transfer Protocol) for file transfers.
  • Port 22: SSH (Secure Shell) for secure remote access.
  • Port 25: SMTP (Simple Mail Transfer Protocol) for sending email.
  • Port 53: DNS (Domain Name System) for translating domain names into IP addresses.
  • Port 80: HTTP (Hypertext Transfer Protocol) for standard web traffic.
  • Port 443: HTTPS (Hypertext Transfer Protocol Secure) for secure, encrypted web traffic.
  • Port 3389: RDP (Remote Desktop Protocol) for remote control of a computer.

Port Forwarding

Port forwarding is a technique used to redirect network traffic from a specific port on your public router to a specific device on your private local network. This is necessary to allow external devices to access services hosted on your home network, such as a game server, a security camera, or a remote desktop connection. It works by creating a rule in your router that maps an external port number to an internal IP address and port, effectively creating a dedicated "doorway" through your firewall.

Something else about ports

There's more to ports than just a number. They're also defined by the type of protocol they use and their current status on a network, which is critical for security.

TCP vs. UDP Ports ⚙️

Ports are used by two primary Transport Layer protocols: **TCP (Transmission Control Protocol)** and **UDP (User Datagram Protocol)**. These two protocols handle data differently, which affects the function of the port.

  • TCP Ports: These are used for **connection-oriented** and **reliable** communication. Before any data is sent, TCP establishes a formal connection between the client and server through a "three-way handshake." This ensures that every data packet is received, and if a packet is lost, it is resent. This makes TCP ideal for applications where data integrity is paramount, such as web browsing (HTTP/HTTPS) and file transfers (FTP).
  • UDP Ports: These are used for **connectionless** and **unreliable** communication. UDP doesn't establish a connection or guarantee that packets will arrive. It simply sends the data and hopes it gets there. This "fire and forget" approach makes it much faster than TCP. UDP is perfect for applications where speed is more important than perfect data delivery, like online gaming, video streaming, or DNS queries.

Port States: Open, Closed, and Filtered 🔒

When a device is probed by a port scanner, its ports can be in one of three states:

  • Open: An application is actively listening and accepting connections on this port. An open port is a potential entry point for both legitimate users and attackers. For example, a web server would have port 80 or 443 open.
  • Closed: The port is accessible, but no application is listening on it. This indicates the host is online, but there's no service running on that specific port to handle the connection.
  • Filtered: The port is not responding to probes because a firewall or other security device is blocking or "filtering" the traffic. This state is a good sign for a network administrator because it means the port is protected from external access.

Ephemeral Ports

Not every port is a well-known service port. When your computer initiates a connection as a client (e.g., your web browser requesting a webpage), it needs to use a port to send the request from. The operating system automatically assigns a temporary, high-numbered port called an **ephemeral port** for this purpose. This allows your computer to handle multiple outbound connections simultaneously, as each one can use a different ephemeral port. These ports are only active for the duration of the connection.

How the router knows which Chrome tab to send bits to

The router doesn't know about "tabs" specifically, but it uses a clever system to keep track of each unique connection, which includes the tabs. The key is the **source port number** and a technology called **Network Address Translation (NAT)**.

1. The Computer's Job: Assigning a Unique Port

When you open a new tab and go to YouTube, your computer's operating system assigns it a unique, temporary number called a **source port**. This number is chosen from a high-numbered range (often 49152-65535). It's essentially a virtual "return address" for that specific YouTube request. When you open another tab and go to TikTok, the operating system assigns that connection a *different* source port.

So, on your computer's private network, the two connections look like this:

  • YouTube Tab: Your private IP address (192.168.1.10) + a unique source port (e.g., 51234)
  • TikTok Tab: Your private IP address (192.168.1.10) + a different unique source port (e.g., 51235)

This is how your computer's OS can differentiate between the two streams of data when they come back.

2. The Router's Job: The NAT Table

Your router receives these two packets. It knows that private IP addresses can't be used on the public internet, so it performs **Network Address Translation (NAT)**. The router has a **NAT table** in its memory. For each outgoing connection, the router creates an entry in this table that maps the private source port to a public source port. The router will use its own public IP address and a unique port to send the request out.

For the two tabs, the NAT table would look something like this:

Private IP & Port Public IP & Port Destination IP & Port
192.168.1.10:51234 39.43.29.189:12345 youtube.com:443
192.168.1.10:51235 39.43.29.189:12346 tiktok.com:443

The router then forwards the packets to YouTube and TikTok, but with the public source IP and port from the NAT table.

3. The Return Trip

When YouTube's servers send a response, they send it back to your router's public IP address (39.43.29.189) and the specific public port the router used for that connection (12345). When the router receives this packet, it checks its **NAT table**. It sees that any data coming in to public port 12345 needs to be sent to private IP 192.168.1.10 and its private source port 51234. The router then performs the NAT in reverse, forwarding the data to your computer. Your computer, seeing the destination port is 51234, knows to pass the data to the correct YouTube tab. The same process happens for TikTok's data, which arrives at the public port 12346 and is correctly mapped back to the TikTok tab on your computer.

In short, the router uses a **NAT table** as a detailed logbook, using unique **source port numbers** to ensure that data coming back from the internet is always delivered to the correct application on the correct device.

Which port does URL "auto" use

URLs do not use one single port; instead, the protocol at the beginning of the URL determines which port is used automatically. When you omit the port number in a URL, your browser defaults to a **well-known port** associated with that protocol.

Common Default Ports

The two most common protocols you see on the web, HTTP and HTTPS, have dedicated default ports that your browser uses automatically.

  • HTTP (http://): This is the protocol for standard, unencrypted web traffic. It uses **Port 80** by default. When you type a URL like http://example.com, your browser automatically connects to the server on port 80.
  • HTTPS (https://): This is the secure, encrypted version of HTTP. It uses **Port 443** by default. When you see a URL like https://youtube.com, your browser automatically connects to the server on port 443 to establish a secure, encrypted connection.

Other Protocols

Other URL schemes also have their own default ports, though you'll see them less frequently in a browser:

  • FTP (ftp://): The File Transfer Protocol uses **Port 21** for command and control traffic, and a different port for data transfer.
  • SSH (ssh://): The Secure Shell protocol uses **Port 22** for secure remote access.

Why It's Called "Auto or Default"

The reason this feels "auto or Default" is because you only need to specify a port number in a URL if the server is using a **non-standard port**. For example, if a developer hosts a web page on a different port, you would have to manually add it to the URL, like http://example.com:8080.
