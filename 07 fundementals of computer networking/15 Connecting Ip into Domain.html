🌐 Guide: Buy a Domain from GoDaddy & Point It to Your Server IP

1. Buy a Custom Domain from GoDaddy

Go to GoDaddy.com.

  • Use the search bar to find a domain (e.g., myapp.com).
  • Add it to your cart and proceed to checkout.
  • You may see upsells like “Privacy Protection” → enable it if you want to hide your name/address from WHOIS lookups.
  • Complete payment and you’ll now own the domain.
  • Log in → Go to GoDaddy Dashboard → My Products → you’ll see your domain listed.
✅ At this point, you own the domain name. Next, you need to link it to your server.

2. Get Your Server’s Public IP

If you’re hosting on your own laptop/PC:

  • Check public IP from whatismyip.com.
  • Make sure your ISP gives you a real public IP (not CGNAT). Otherwise, you need to request one.
  • You must set up port forwarding on your router (e.g., forward port 80 → your local machine).

If you’re using cloud hosting (VPS) like AWS, DigitalOcean, Render, Railway, Vercel, etc.:

  • Your provider gives you a public IP or hostname. Example: 123.45.67.89.

3. Connect Domain to Server (DNS Setup in GoDaddy)

Log in to GoDaddy → My Products → DNS → Manage DNS.

You’ll see the DNS Records Table.

Add/Update these records:

A Record (most important)

  • Host: @ (represents your root domain, e.g., myapp.com)
  • Points to: Your server’s public IP (123.45.67.89)
  • TTL: 1 Hour (or 600 seconds for faster propagation)

A Record for www

  • Host: www
  • Points to: Same server IP (123.45.67.89)
  • (This ensures both myapp.com and www.myapp.com work.)

(Optional) CNAME Record

If your server has a hostname (like myserver.hostingprovider.com), instead of IP, use:

  • Host: @
  • Type: CNAME
  • Points to: myserver.hostingprovider.com

4. Test DNS Propagation

After saving, DNS can take a few minutes to 24–48 hours to fully update worldwide.

Check with tools:

  • https://dnschecker.org
  • Run nslookup myapp.com in terminal
  • Or ping myapp.com → should return your server’s IP

5. Configure Your Server

If you’re running a Node.js/MERN server, make sure:

  • Your app is listening on 0.0.0.0 not just localhost:
app.listen(80, "0.0.0.0", () => {
  console.log("Server running on port 80");
});

If port 80 is blocked (common for local dev), you may:

  • Run app on port 3000 → then use NGINX reverse proxy to forward 80 → 3000.
  • Or configure firewall rules (e.g., on cloud VPS, open port 80/443).

🔄 Reverse Proxy: Deep Dive

1. What is a Proxy in General?

A proxy server is like a middleman between a client (browser) and a server (your app).

Forward Proxy:

Client → Proxy → Internet → Server

Example: You use a VPN. The VPN server acts as a forward proxy, hiding your IP from websites.

Reverse Proxy:

Client → Reverse Proxy → Your App Server

The client doesn’t directly talk to your backend server. Instead, the reverse proxy sits in front of it, receiving all requests, and then forwards them to the actual server(s).

So, reverse proxy = front desk of a hotel. Guests don’t directly go to rooms (servers); they ask the front desk, which routes them appropriately.

2. How Does a Reverse Proxy Work?

Example setup:

Browser (Client) → Reverse Proxy (Nginx) → Node.js App (Express)

  • User requests https://myapp.com.
  • DNS resolves myapp.com to your server’s IP.
  • That IP points to Nginx (reverse proxy).
  • Nginx receives the request → decides where to send it (e.g., your Node.js backend running on port 3000).
  • Nginx forwards response back to client.

So the client never knows your app runs on port 3000. It only sees https://myapp.com.

3. Why Use a Reverse Proxy?

Here’s why MERN apps usually need one:

✅ Port Hiding & Convenience

  • Node apps usually run on non-standard ports (3000, 5000, 8080).
  • Browsers expect websites on port 80 (HTTP) or 443 (HTTPS).
  • A reverse proxy listens on 80/443 and forwards traffic to your app.
  • Example: myapp.com:80 → Node app on :3000.

✅ HTTPS (SSL/TLS) Termination

  • Let’s Encrypt & Certbot integrate with Nginx easily.
  • Nginx handles SSL certificates (HTTPS) and forwards traffic to your app over HTTP internally.
  • Saves you from adding SSL logic inside your Node.js server.

✅ Load Balancing

  • If you run multiple Node.js instances (say on ports 3000, 3001, 3002), Nginx can distribute requests between them.
  • Helps scale your app.

✅ Caching & Performance

  • Reverse proxies can cache static files (JS, CSS, images).
  • Reduces load on your Node.js app.

✅ Security

  • Your Node.js app is not directly exposed to the internet.
  • Nginx can block bad requests, filter IPs, rate-limit, etc.
  • Protects backend servers from DDoS attacks.

✅ Routing Multiple Apps

  • You can host multiple apps on the same server.
  • Example:
    • myapp.com → React frontend
    • api.myapp.com → Node.js backend
  • Nginx (reverse proxy) decides where to route traffic.
