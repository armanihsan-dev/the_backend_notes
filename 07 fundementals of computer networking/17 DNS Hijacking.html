DNS • Security Notes
A compact, developer‑friendly cheat sheet on what it is, how it works, detection, and defense.

What is DNS Hijacking?

DNS hijacking (aka DNS redirection) is when an attacker manipulates the DNS resolution path so a domain (e.g., bank.com) resolves to an attacker‑controlled IP instead of the real server. Think “changing the Internet’s street signs.”

Goal: Phishing, malware delivery, ad injection, censorship, or credential theft.

Quick Flow — How DNS Works

  1. User types example.com in a browser.
  2. OS checks hosts file → local cache → DNS resolver.
  3. Resolver queries authoritative servers if needed.
  4. IP returned; browser connects to that server.

Tamper any step → hijack.

Common Hijack Vectors

1) Local / Device

  • Malware edits hosts file or changes DNS settings.
  • Outcome: only your device is redirected.

2) Router

  • Weak/default router password; attacker changes router DNS.
  • Outcome: all devices on LAN use attacker DNS.

3) MITM / Network

  • Attacker intercepts traffic and forges DNS replies.
  • Public Wi‑Fi risk; no encryption → easy target.

4) Cache Poisoning

  • Resolver is tricked into caching a fake record (Kaminsky‑style).
  • Outcome: affects everyone using that resolver.

5) ISP / Resolver Policy

  • Some ISPs redirect typos or blocked domains to ads or notices.
  • Sometimes misconfig or compromise can be abused.

6) Registrar / DNS Account Takeover

  • Attacker gains control of your domain or DNS provider.
  • Changes authoritative records; global impact.

What Attackers Can Do

  • Phishing Fake login portals for banks/cloud.
  • Malware Drive‑by downloads, payload delivery.
  • Ad Injection Monetize traffic with shady ads.
  • Censorship Redirect or block targeted sites.
  • Data Theft Harvest cookies and credentials.

Red Flags

  • Known sites open but look off or show HTTP.
  • Unexpected cert warnings on https://.
  • Different IP answers between resolvers.
  • Router DNS changed without you.

Detect It (CLI)

Compare multiple resolvers for the same name:

nslookup google.com 1.1.1.1
nslookup google.com 8.8.8.8
nslookup google.com 9.9.9.9

On Linux/macOS:

dig +short A google.com @1.1.1.1
ripgrep -n "nameserver" /etc/resolv.conf

On Windows, verify which IP your host resolves to:

ping redtube.com
ipconfig /displaydns | findstr /i redtube
ipconfig /flushdns  # clear cache

Defend / Hardening

  • Use trusted DNS: Cloudflare 1.1.1.1, Google 8.8.8.8, Quad9 9.9.9.9.
  • Enable DNSSEC: Prefer resolvers and zones with DNSSEC to validate records.
  • HTTPS & HSTS: Certificate mismatch ≠ proceed.
  • VPN wisely: Some VPNs bypass OS resolver/hosts. Test and choose providers that respect local policies.
  • Secure router: Change admin password, update firmware, disable remote admin, lock DNS.
  • Malware hygiene: EDR/AV, least privilege, updates.

Hosts File — What We Practiced

  • Path (Windows): C:\\Windows\\System32\\drivers\\etc\\hosts
  • Format: IP Address + space(s) + hostname
# Block (device-level)
127.0.0.1  example.com
127.0.0.1  redtube.com
127.0.0.1  www.redtube.com

# Force a domain to a known IP (for testing)
142.250.201.238  google.com
142.250.201.238  www.google.com
Note: Hosts only affects DNS resolution. HTTPS still verifies the hostname via certificates, and servers use SNI/Host headers — forcing an unrelated IP won’t "redirect" content.

Better Than Hosts for Family Blocking

Cloudflare Family

  • Primary DNS: 1.1.1.3
  • Secondary DNS: 1.0.0.3
  • Blocks adult domains network‑wide.

OpenDNS Family Shield

  • Primary: 208.67.222.123
  • Secondary: 208.67.220.123
  • Easy router or device setup.

Pi-hole (Advanced)

  • Self‑hosted DNS sinkhole with blocklists.
  • Great visibility and control for home lab.

Real‑World Incidents

  • Kaminsky (2008): Cache poisoning across resolvers globally.
  • Brazil Router Hijack (2018): 100k+ routers had DNS changed; banking creds stolen.
  • Censorship Cases: DNS redirection to government notices in some countries.

Quick Checklist

  • 🔒 Lock router admin + update firmware.
  • 🧭 Set resolver to trusted DNS / family filters.
  • 🧪 Verify answers with nslookup/dig.
  • 🧹 ipconfig /flushdns after changes.
  • 🛑 Heed HTTPS certificate warnings.
