IPv6 Notes

IPv6 (Internet Protocol version 6) is the most recent version of the Internet Protocol, which is the communication protocol that provides an identification and location system for devices on networks. It was developed by the Internet Engineering Task Force (IETF) to address the limitations of its predecessor, IPv4, primarily the exhaustion of its address space.

IPv6 Address Format and Features

An IPv6 address is 128 bits long, compared to the 32-bit addresses used by IPv4. This massive increase in address space provides a virtually unlimited number of unique addresses, solving the problem of address exhaustion for the foreseeable future. A typical IPv6 address is represented as eight groups of four hexadecimal digits, with each group separated by a colon (:). For example: 2001:0db8:85a3:0000:0000:8a2e:0370:7334.

To make addresses easier to read and write, IPv6 has two rules for abbreviation:

  • Leading zeros in each group can be omitted. For example, 0db8 can be written as db8.
  • A single run of consecutive all-zero groups can be replaced with a double colon (::). This can only be used once per address. For example, 2001:0db8:0000:0000:0000:8a2e:0370:7334 can be shortened to 2001:0db8::8a2e:0370:7334.

Key Advantages of IPv6 over IPv4

The transition to IPv6 offers several significant benefits that improve the efficiency, security, and scalability of the internet:

  • Vast Address Space: IPv6's 128-bit address space allows for over 3.4×1038 unique addresses. This eliminates the need for workarounds like Network Address Translation (NAT) that were created to conserve IPv4 addresses.
  • Simplified Header: The IPv6 packet header is simpler and more efficient than IPv4's. It has a fixed size and fewer fields, which allows routers to process packets more quickly and improves overall network performance.
  • Built-in Security: IPv6 has IPsec (Internet Protocol Security) built into its core protocol, providing native encryption and authentication for network communication. This enhances data security and privacy by design, whereas IPsec was an optional add-on for IPv4.
  • Improved Efficiency: IPv6 streamlines routing and packet processing. It also supports better Quality of Service (QoS) with a "Flow Label" field that can be used to identify and prioritize specific traffic, which is beneficial for real-time applications like video streaming and online gaming.
  • Automatic Configuration: IPv6 supports Stateless Address Autoconfiguration (SLAAC), which allows devices to automatically generate their own IP addresses without a central server like a DHCP (Dynamic Host Configuration Protocol) server. This simplifies network management and device deployment.

What is the syntax of using IPv6 in URL with a port number?

To use an IPv6 address in a URL with a port number, you must enclose the IPv6 address in square brackets [ ]. This is necessary to prevent the colons in the IPv6 address from being misinterpreted as the separator for the port number.

The standard syntax is:

http://[ipv6-address]:port_number

Examples

  • HTTP (web) access: http://[2001:0db8:85a3:0000:0000:8a2e:0370:7334]:8080
  • HTTPS (secure web) access: https://[2001:db8::1]:443
  • FTP (file transfer protocol): ftp://[::1]:21

In these examples, the part inside the square brackets is the IPv6 address, and the number after the colon is the port number.

Rules of IPv6

IPv6 is governed by a set of rules that dictate how addresses are formatted, abbreviated, and what different types of addresses are used for. These rules ensure efficient communication and network management.

IPv6 Address Rules

An IPv6 address is 128 bits long, represented in eight groups of four hexadecimal digits separated by colons. The rules for writing and abbreviating them are:

  • Leading zeros can be omitted in any 16-bit group. For example, 0db8 becomes db8. If a group is all zeros, it can be represented by a single 0.
  • A single run of consecutive all-zero groups can be replaced with a double colon (::). This is the most significant abbreviation rule. It can only be used once in a full IPv6 address to avoid ambiguity. For example, 2001:db8:0000:0000:0000:1:2:3 becomes 2001:db8::1:2:3.

IPv6 Address Types

IPv6 addresses are classified by their intended use and routing behavior. The three main types are:

  • Unicast: A unicast address identifies a single network interface. A packet sent to a unicast address is delivered to that specific interface. There are several types of unicast addresses:
    • Global Unicast: These are publicly routable addresses used for internet communication, similar to IPv4's public addresses. They are globally unique and begin with the prefix 2000::/3.
    • Link-Local: These addresses are used only for communication within a single network segment (a "link") and are not routed. Every IPv6-enabled interface automatically configures a link-local address, which always starts with fe80::/10. They're used for a variety of tasks, including the Neighbor Discovery Protocol.
    • Loopback: The address ::1 is the loopback address, equivalent to IPv4's 127.0.0.1. It is used by a device to send a packet to itself for testing or communication between local processes.
    • Unspecified: The address :: is the unspecified address. It indicates the absence of an address and is used as a source address when a device hasn't yet been assigned an address.
  • Multicast: A multicast address identifies a group of network interfaces. A packet sent to a multicast address is delivered to all members of that group. This is used for one-to-many communication, such as video streaming or sending updates to multiple devices simultaneously. Multicast addresses always begin with the prefix ff00::/8.
  • Anycast: An anycast address also identifies a group of interfaces, but a packet sent to an anycast address is delivered to the "closest" interface in that group, according to the routing protocol's metric. This is commonly used for services like DNS to provide load balancing and high availability. Anycast addresses are syntactically indistinguishable from unicast addresses and their function is determined by how they are configured on the network.

IPv6 Header and Fragmentation

The IPv6 packet header is simpler and more efficient than its IPv4 counterpart. The IPv6 header has a fixed size of 40 bytes and removes several fields found in IPv4, such as header checksum, identification, and fragmentation fields.

Instead of fragmentation at intermediate routers (which happens in IPv4), IPv6 handles fragmentation at the source host using an optional Fragment Extension Header. This simplifies router design and improves performance, as routers only need to process the main header, not fragmentation information.

When I try to access a server with IPv6 it gets accessed directly which looks like I have bought a public IP? Why?

Your observation is correct, and it's happening by design. In the world of IPv6, your device is assigned a publicly routable IPv6 address by your internet service provider (ISP), which is the functional equivalent of a public IPv4 address.

This is a key difference from IPv4, and it's why you can access the server directly.

The Problem with IPv4

With IPv4, there's a severe shortage of addresses. To solve this, a technology called Network Address Translation (NAT) was developed. NAT allows multiple devices on a private network (like your home Wi-Fi) to share a single public IPv4 address. When you connect to a server, your router uses NAT to translate your device's private IP address into the router's public IP address.

This creates a barrier. Incoming connections from the internet can only reach the router, not the specific device behind it. To make a server accessible from the internet, you have to manually configure port forwarding on your router, which tells it to send traffic on a specific port to a specific device on your internal network. In essence, you "buy" or get a public IPv4 address to be reachable from the internet, but behind your router you're still on a private network.

The IPv6 Solution

IPv6 was created to solve the address exhaustion problem, with a massive address space that makes NAT unnecessary.

  • Global Unicast Addresses: When your device connects to an IPv6 network, it's assigned a Global Unicast Address (GUA). This is a globally unique, publicly routable address. Every single device on your network gets its own unique, public IP address.
  • No NAT Required: Because each of your devices has its own public IPv6 address, there's no need for address translation. A server on the internet can send a packet directly to your device without any router translation. This is why it "looks like you've bought a public IP"—you essentially have one for every single device that needs it.
  • The Firewall: Even though your device has a public IPv6 address, it's not automatically vulnerable. Your router still acts as a firewall, and by default, it will block most incoming connections to protect your devices. However, you can easily configure firewall rules on the router to allow specific incoming connections to a particular device, which is a cleaner and more direct process than port forwarding with NAT.

In short, the direct accessibility is not a mistake; it's a fundamental feature of IPv6. It's designed to restore true end-to-end connectivity on the internet, which was lost with IPv4's dependence on NAT.

How many unique IPv6 addresses are there in the world?

There are a staggering 3.4×1038 unique IPv6 addresses. 🤯

To put that number in perspective, it's approximately 340 undecillion, or 340 trillion trillion trillion. This massive number is a direct result of the 128-bit address length of IPv6 (2128), compared to the 32-bit addresses of its predecessor, IPv4 (232), which only provided about 4.3 billion unique addresses.

Why so many addresses?

The vast address space of IPv6 was designed to solve the problem of address exhaustion that plagues IPv4. Instead of being a limitation, the abundance of addresses in IPv6 is a fundamental feature that allows for:

  • No more Network Address Translation (NAT): Every device can have its own public, routable IP address, restoring true end-to-end connectivity.
  • Massive scalability: The address space is large enough to assign an IP address to every single device on the planet for the foreseeable future, including phones, cars, home appliances, and sensors (the Internet of Things).
  • Simplified network management: Network design is simpler and more flexible with the availability of huge blocks of addresses for each network segment.

Why do you take two base and 128 power? Does IPv6 use the hexadecimal number system?

You are asking why IPv6 addresses are expressed as 2128 and if the addresses use the hexadecimal number system. The answer is yes to both questions, and they are related.

2128 and the Binary System

The number 2128 represents the total number of unique IPv6 addresses because a computer's fundamental language is binary, a base-2 system. Each bit in the 128-bit address can be either a 0 or a 1. Therefore, the total number of unique combinations is 2 multiplied by itself 128 times, or 2128.

This is the same reason why an IPv4 address, which is 32 bits long, has 232 total unique addresses. Regardless of how we humans represent the address for convenience, the underlying protocol always uses binary.

Hexadecimal for Human Readability

While computers use binary, humans use a more convenient way to write and read IPv6 addresses: the hexadecimal number system. A hexadecimal number system is a base-16 system that uses 16 distinct symbols: 0-9 and A-F.

  • Why hexadecimal? Each hexadecimal digit represents exactly 4 bits of binary data. Since an IPv6 address is 128 bits, it can be neatly represented by 32 hexadecimal digits (128 bits / 4 bits per hex digit = 32 hex digits).
  • A more compact representation: Instead of writing out a long string of 128 ones and zeros, such as 00100000000000010000110110111000..., we can use the much shorter and more readable hexadecimal format, such as 2001:0db8:.... This is similar to how we use shorthand to write large numbers in our everyday lives.

Benefits and Drawbacks of IPv6

IPv6 represents the future of the internet, but like any major technological transition, it comes with its own set of benefits and drawbacks.

Benefits of IPv6

  • Vast Address Space: The most significant advantage is the virtually unlimited number of unique addresses (2128 or 3.4×1038). This solves the problem of IPv4 address exhaustion, providing a sustainable foundation for the growth of the Internet of Things (IoT) and future connected devices.
  • Elimination of NAT: Because every device can have its own public IPv6 address, there is no need for Network Address Translation (NAT). This restores true end-to-end connectivity, simplifying network architecture, enabling easier peer-to-peer communication, and improving the functionality of real-time applications like online gaming and VoIP.
  • Simplified Header for Efficiency: The IPv6 packet header is streamlined and has a fixed size (40 bytes), which allows routers to process packets more quickly. Fields like the checksum have been removed, shifting that responsibility to the transport layer (e.g., TCP), which speeds up routing decisions and improves network performance.
  • Built-in Security: IPv6 has IPsec (Internet Protocol Security) built into its core. While IPsec is an optional add-on for IPv4, its native integration in IPv6 provides a robust framework for authentication and encryption, making the protocol more secure by design.
  • Improved Quality of Service (QoS): The IPv6 header includes a "Flow Label" field that can be used to identify and prioritize specific traffic flows (e.g., video streaming or voice calls) without needing to inspect the packet's contents. This ensures a more reliable experience for delay-sensitive applications.
  • Enhanced Mobility: IPv6 is optimized for mobile networks, allowing mobile devices to maintain a consistent IP address as they move between different networks, which provides a more seamless user experience.
  • Simplified Autoconfiguration: IPv6 supports Stateless Address Autoconfiguration (SLAAC), which allows devices to automatically generate their own unique IP address when they connect to a network. This simplifies network management and reduces the reliance on DHCP servers.

Drawbacks of IPv6

  • Lack of Backward Compatibility: IPv6 is not backward-compatible with IPv4. This is the biggest challenge of the transition. Devices and networks must be configured to run both protocols simultaneously in a "dual-stack" environment to ensure communication with the vast majority of the internet that still runs on IPv4. This adds complexity and cost.
  • Slow Adoption Rate: Despite its clear advantages, the adoption of IPv6 has been slow due to a lack of urgency. IPv4 workarounds like NAT have proven to be resilient and have effectively masked the immediate need for a full transition for many organizations and consumers.
  • Complexity and Learning Curve: IPv6 introduces new concepts and a different address format that can be more complex to work with for network administrators accustomed to IPv4. The longer hexadecimal addresses are more difficult for humans to read, write, and remember, which can increase the potential for manual configuration errors.
  • Transition Costs: Migrating to IPv6 can be a significant financial investment for large organizations and ISPs. It may require new hardware, software upgrades, and training for IT staff. Many entities are hesitant to make this investment as long as IPv4 remains functional.
  • Security Concerns: While IPv6 has built-in security features, it also introduces new potential attack vectors. The complexity of a dual-stack environment can create security gaps if not managed properly, and the sheer size of the address space can make some security techniques, like port scanning, less effective for attackers, but also make it harder for administrators to monitor.
