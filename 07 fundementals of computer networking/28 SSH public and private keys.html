SSH Keys: A Secure Authentication Method

SSH keys are an authentication method that uses cryptographic keys to log in to a remote server. They consist of a public and private key pair.

SSH Private and Public Keys

SSH private and public keys are a pair of mathematically linked files used for secure, encrypted communication between a client and a server. 🔑 The private key is kept secret on the client's machine and must never be shared. The public key can be shared with anyone and is placed on the remote server you wish to connect to. The public key can encrypt data, but only the corresponding private key can decrypt it.

They are needed because they provide a more secure method of authentication than traditional passwords. A password can be guessed or brute-forced, but the mathematical relationship between the public and private keys makes this virtually impossible. Passwordless Authentication

Passwordless authentication is a login method that allows a user to connect to a server without needing to enter a password. SSH private and public keys enable this by using a challenge-response mechanism. When you attempt to connect, the server uses your public key to create a challenge (a message encrypted with the public key). Your SSH client then uses your private key to decrypt this challenge and send the correct response back to the server, which authenticates you and grants access without a password.

How do we log in using public and private keys, and what are the related command-line commands?

1. Generate key pair:

ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

o just

ssh-keygen

2. Copy public key to server:

ssh-copy-id user@remote-server

(Or manually paste the public key into ~/.ssh/authorized_keys on the server).

3. Login using keys:

ssh user@remote-server

SSH will automatically use your private key stored in ~/.ssh/id_rsa (or specified with -i).

Why does pasting the public key into the authorized_keys file allow auto-login?

  • You paste your public key into the server’s ~/.ssh/authorized_keys file.
  • This tells the server: “This client is trusted if they can prove they have the matching private key.”
  • When you connect (ssh user@server), the server looks at your authorized_keys file.
  • It sees the public key you pasted earlier.
  • The server sends a random challenge (like a puzzle) encrypted with that public key.
  • Only the matching private key (which stays safely on your laptop) can solve/decrypt this challenge.
  • Your SSH client uses your private key to solve the challenge and sends the answer back.
  • No password is needed, just the math from the key pair.
  • If the answer is correct → login succeeds.

That’s why you get logged in automatically.

👉 In short: Public key on server + private key on your machine = auto-login.

No one else can log in without your private key, even if they know your username.
