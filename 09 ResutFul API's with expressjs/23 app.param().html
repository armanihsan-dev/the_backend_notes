Express.js `app.param()` or `router.param()` Function

The app.param() or router.param() function in Express.js lets you create reusable logic for validating or pre-loading data for a route parameter. Instead of writing the same code in multiple route handlers, you can define it once for a specific parameter name.

Syntax and Explanation

The syntax is app.param('name', callback).

  • name: This is a 'string' representing the parameter you want to handle. For example, if your route is /users/:id, the name would be 'id'.

  • callback: This is a middleware function with the signature (req, res, next, value, name).

    • req: The request object.

    • res: The response object.

    • next: A function to call to pass control to the next middleware or route handler.

    • value: The actual value of the parameter from the URL. For /users/123, this would be '123'.

    • name: The name of the parameter itself (e.g., 'id').

When a route with a matching parameter is hit, Express executes the param() callback before any of the route's other middleware or handler functions. This makes it a great place to perform tasks like:

  • Data Validation: Checking if the parameter value is a valid format (e.g., an integer).

  • Database Lookup: Fetching a user from the database based on their ID.

  • Error Handling: Sending a 404 Not Found response if the data doesn't exist.

Practical Example with All HTTP Methods

Let's imagine you're building a simple API for managing blog posts. All your routes will need to work with a :postId parameter. Instead of fetching the post from the database in every GET, PUT, and DELETE handler, you can use router.param().

Here's a full example using express.Router():

const express = require('express');
const router = express.Router();

// A simple in-memory database of posts
const posts = {
    '1': { title: 'First Post', content: 'This is the first post.' },
    '2': { title: 'Second Post', content: 'This is the second post.' }
};

// Use router.param to handle the ':postId' parameter
router.param('postId', (req, res, next, postId) => {
    console.log(`Param middleware is running for postId: ${postId}`);
    const post = posts[postId];

    // If the post is not found, send a 404 response and stop the request.
    if (!post) {
        return res.status(404).json({ error: 'Post not found' });
    }

    // Attach the found post to the request object for later use.
    req.post = post;
    // Call next() to pass control to the next middleware or route handler.
    next();
});

// GET Method
router.get('/:postId', (req, res) => {
    console.log('GET route handler is running.');
    // The post is already available on req.post, thanks to router.param().
    res.json(req.post);
});

// PUT Method (for updating a post)
router.put('/:postId', (req, res) => {
    console.log('PUT route handler is running.');
    // In a real app, you would update the post in the database.
    // Here, we just acknowledge the update.
    // The found post is available at req.post.
    // The new data would be in req.body.
    res.json({ message: 'Post updated successfully', updatedPost: { ...req.post, ...req.body } });
});

// DELETE Method
router.delete('/:postId', (req, res) => {
    console.log('DELETE route handler is running.');
    // In a real app, you would delete the post from the database.
    // The found post is available at req.post.
    delete posts[req.params.postId];
    res.json({ message: 'Post deleted successfully' });
});

// A simple POST route to create a new post (no param handling needed here)
router.post('/', (req, res) => {
    const newId = (Object.keys(posts).length + 1).toString();
    posts[newId] = req.body;
    res.status(201).json({ message: 'Post created', post: posts[newId] });
});

const app = express();
app.use(express.json()); // Middleware to parse JSON bodies
app.use('/posts', router);

app.listen(3000, () => {
    console.log('Server is running on port 3000');
});

To run this example, save the code as a file (e.g., server.js), install Express (npm install express), and then run it (node server.js). You can then test it with a tool like Postman or curl.

Testing the Endpoints:

  • GET /posts/1: The router.param function runs first, finds the post with ID 1, and attaches it to req.post. The GET handler then sends this post as the response.

  • GET /posts/3: The router.param function runs, but since there's no post with ID 3, it sends a 404 Not Found response immediately, and the GET handler is never executed.

  • PUT /posts/2: The router.param runs, finds the post with ID 2, and the PUT handler then receives the req object with the req.post property already populated.

  • DELETE /posts/1: The router.param runs, finds the post with ID 1, and the DELETE handler then receives the req object with the req.post property already populated.

Using router.param() significantly reduces code duplication and makes your routes cleaner and more maintainable, especially when dealing with multiple operations on the same resource. 🚀

When does `app.param()` run?

app.param() middleware runs before the actual route handler.

When a request is made, Express.js first checks if the URL contains a parameter that has a corresponding app.param() middleware. If it does, Express executes that middleware. The app.param() middleware has the opportunity to perform actions like fetching data from a database or validating the parameter. The next() function must be called inside the app.param() middleware to pass control to the next middleware or, ultimately, the final route handler. If next() isn't called, the request-response cycle stops, which is useful for sending an error response, for example. The final route handler will only execute if the app.param() middleware completes successfully by calling next().
