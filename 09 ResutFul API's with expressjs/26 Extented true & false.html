express.urlencoded() Differences

Let's break down the two key differences between extended: false and extended: true in express.urlencoded().

1. Parsing Method and Data Structure

The most significant difference is how the middleware parses the data and the resulting structure of req.body.

extended: false

This option uses the built-in querystring module from Node.js. It's designed to be simple and only handles flat data structures. Nested objects and arrays are not parsed correctly; they are treated as simple keys. For example, user[name]=John would be parsed into { 'user[name]': 'John' }.

// with extended: false
user[name]=John
// becomes:
{ 'user[name]': 'John' }

extended: true

This option uses the more powerful qs library. It can correctly parse complex, nested data. For instance, user[name]=John would be parsed into the more intuitive and structured { user: { name: 'John' } }. This is the recommended and default option for modern applications.

// with extended: true
user[name]=John
// becomes:
{ user: { name: 'John' } }

2. Object Prototype and Security

A deeper, more technical difference lies in the prototype of the resulting req.body object. This is a crucial detail related to security.

extended: false

The querystring module parses the data into an object created with Object.create(null). This means the resulting req.body object has no prototype and does not inherit any properties or methods from Object.prototype. This makes it immune to prototype pollution attacks, a significant security vulnerability where an attacker can modify the behavior of all objects in an application. This is a "stripped-down" and safer object.

extended: true

The qs library creates a regular JavaScript object (like {}). This object inherits from Object.prototype, giving it access to standard methods like toString(), hasOwnProperty(), etc. While more convenient, it makes the application potentially vulnerable to prototype pollution attacks if not handled carefully.

Summary

In summary, extended: true offers more powerful parsing of complex data, while extended: false provides a simpler, flatter parsing method that offers a security benefit by preventing prototype pollution.
