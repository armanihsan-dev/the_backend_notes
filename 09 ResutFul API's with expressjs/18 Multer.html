Multer & File Uploads

Multer is a Node.js middleware primarily used for handling multipart/form-data, which is the encoding type used for uploading files via an HTML form. It is built on top of the busboy library and simplifies the complex process of handling file uploads in web applications, especially when used with the Express.js framework. Without a package like Multer, a developer would have to write significant boilerplate code to parse the incoming file data.

1. Why multipart/form-data exists

JSON is perfect for text. But files are binary streams. Sending a massive video file inside a JSON object is inefficient and complex.

The Protocol The browser says: "I will split the request into parts. I'll separate them with a boundary, and send each part separately."

What really goes over the wire?

When you submit a form with a file, the raw HTTP looks like this:

POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryX

------WebKitFormBoundaryX
Content-Disposition: form-data; name="name"

Arman
------WebKitFormBoundaryX
Content-Disposition: form-data; name="avatar"; filename="me.png"
Content-Type: image/png

(raw binary bytes of the image appear here...)
------WebKitFormBoundaryX--
  • Boundary: A unique string separating parts.
  • Parts: Each field (text or file) gets its own section with headers.
  • Payload: Files are sent as raw bytes, not Base64.

Why app.use(express.json()) fails

Standard Express middleware expects JSON string formats. When it encounters a binary multipart stream, it:

  1. Reads the body once.
  2. Fails to parse binary data.
  3. Returns an empty object.

Result: req.body is empty. This is why we need Multer.

2. Multer Methods

Multer reads the stream, detects boundaries, saves files to disk/memory, and populates req.body for you.

  • For files: streams bytes to disk or memory. For text: fields: puts them in req.body
  • upload.single('field'): One file. Available in req.file.
  • upload.array('field', max): Multiple files, same field name. In req.files.
  • upload.fields([...]): Multiple files, different field names (e.g., avatar + gallery).
  • upload.none(): Text only (no files).
Warning Avoid upload.any(). It accepts all files and can be a security risk if malicious users upload files to unexpected fields.

4. Storage Engines Comparison

It is crucial to distinguish between the two primary ways Multer handles data: saving it to the hard drive (Disk Storage) versus keeping it in the server's RAM (Memory Storage).

Disk Storage (multer.diskStorage)

This engine gives you full control over storing files to the disk. It is the most common method for handling large files or persistent storage.

  • Behavior: Files are streamed directly to the destination folder you specify.
  • Modification to req.file:
    • Adds a path property (the full path to the uploaded file).
    • Adds a destination property (the folder where the file is saved).
    • Adds a filename property (the name of the file inside the destination).
  • Pros: Low memory usage (files aren't held in RAM); good for large files.
  • Cons: Slower I/O (disk writing); you must manage file cleanup/deletion manually. 
const storage = multer.diskStorage({
  destination: (req, file, cb) => { 
    cb(null, '/tmp/my-uploads'); 
  },
  filename: (req, file, cb) => { 
    cb(null, file.fieldname + '-' + Date.now()); 
  }
});
Memory Storage (multer.memoryStorage)

The memory storage engine stores the files in memory as Buffer objects.

  • Behavior: The file is never written to the hard drive by Multer. It stays in the server's RAM.
  • Modification to req.file:
    • Adds a buffer property containing the entire raw binary data of the file.
    • Does NOT include path, destination, or filename (since the file doesn't exist on disk).
  • Pros: Extremely fast access; perfect for immediate processing (e.g., resizing an image with Sharp or uploading to Cloudinary/AWS S3 without saving locally first).
  • Cons: Dangerous for large files. If multiple users upload large files simultaneously, your server will run out of RAM and crash (Heap out of memory). 
const storage = multer.memoryStorage();
const upload = multer({ storage: storage });

5. Summary of req.file Properties

Depending on the engine you choose, the req.file object will look different. Use this table for your notes:

Property Description Disk Storage Memory Storage
fieldname Field name specified in form ✔ ✔
originalname Name of the file on user's computer ✔ ✔
mimetype Mime type of the file ✔ ✔
size Size of the file in bytes ✔ ✔
buffer A Buffer of the entire file ✘ ✔
destination Folder where file is saved ✔ ✘
filename Name of file in destination ✔ ✘
path Full path to uploaded file ✔ ✘

Implementation Tip: When to use which?

  • Use diskStorage if you are building a simple app where you want to serve the files directly from your own server's uploads folder.
  • Use memoryStorage if you are using a 3rd party service (Cloudinary, S3, Firebase). You take the req.file.buffer, send it to the cloud, and the file never touches your server's hard drive.

Configuration & Storage Engine

Using diskStorage gives you full control over filenames and destinations. 

import multer from 'multer';
import path from 'path';
import fs from 'fs';
import { fileURLToPath } from 'url';

// Fix for __dirname in ES Modules
const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

// 1. Define Storage
const storage = multer.diskStorage({
    destination: (req, file, cb) => {
        const uploadPath = path.join(__dirname, '../storage/uploads');
        // Ensure folder exists
        if (!fs.existsSync(uploadPath)) {
            fs.mkdirSync(uploadPath, { recursive: true });
        }
        cb(null, uploadPath);
    },
    filename: (req, file, cb) => {
        const uniqueSuffix = Date.now() + '-' + Math.round(Math.random() * 1e9);
        const ext = path.extname(file.originalname);
        cb(null, `${file.fieldname}-${uniqueSuffix}${ext}`);
    },
});

// 2. Export Upload Middleware
export const upload = multer({
    storage,
    limits: { fileSize: 5 * 1024 * 1024 }, // 5MB limit
});

Understanding Callbacks (cb)

The "Chef" Analogy

Node.js is non-blocking. Instead of stopping the program to wait for a file task, it continues working.

The Callback (cb) is like a restaurant buzzer:

  1. You order food (Function starts).
  2. Waiter gives you a buzzer (The callback).
  3. You sit down (Non-blocking).
  4. Food is ready -> Buzzer goes off (Callback executes).

In Multer: cb(null, './uploads') means:
  • First arg null: "No error, everything is fine."
  • Second arg: "Here is the result (the folder path)."
Example: 
            
function downloadFile(fileName, cb) {
    // Simulate a file download with a timeout
    console.log(`downloading file ${fileName}`);

    setTimeout(() => {
        console.log("Download complete!");
        // 2. We trigger the callback function
        // We pass 'null' for the error, and the "data" as the second argument
        cb(null, `Contents of ${fileName}`);
    }, 3000);
}

downloadFile('fancy.jgp', (err, data) => {
    if (err) {
        console.error("Error downloading file:", err);
    }
    else {
        console.log("File data:", data);
    }
})

3. Full Stack Implementation

Frontend: React + FormData

We cannot send a simple JSON object. We must use FormData() to handle binary content. 

const handleSubmit = async (e) => {
    e.preventDefault();
    
    // 1. Create FormData object
    const multipartData = new FormData();
    multipartData.append('name', formData.name);
    multipartData.append('mobile', formData.mobile);
    
    // IMPORTANT: 'document' must match backend field name
    multipartData.append('document', file); 

    try {
      const res = await fetch('http://localhost:3000/account/multipart', {
        method: 'POST',
        // Note: Do NOT set Content-Type header manually. 
        // The browser sets it with the correct boundary automatically.
        body: multipartData,
      });
      
      const data = await res.json();
      console.log(data);
    } catch (err) {
      console.error(err);
    }
};

Backend: Express Routes

const app = express();

accountRoutes.js

import express from 'express';
import { upload } from '../config/multerConfig.js';

const router = express.Router();

// 'document' matches the formData.append name from React
router.post('/multipart', upload.single('document'), (req, res) => {
    try {
        // Text fields are in req.body
        const { name, mobile } = req.body;
        
        // File details are in req.file
        console.log('File uploaded:', req.file);
        
        res.status(200).json({ 
            message: "Upload successful", 
            filePath: req.file.path 
        });
    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});

export default router;
