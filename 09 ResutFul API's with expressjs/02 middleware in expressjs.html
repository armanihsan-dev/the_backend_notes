Express.js Middleware

Middleware in Express.js is a function that has access to the request object (req), the response object (res), and the next function in the application’s request-response cycle. It can execute any code, make changes to the request and response objects, end the request-response cycle, or call the next middleware function in the stack.

Middleware Execution

Middleware is executed in the order it's defined. When a request comes in, Express routes it to the first middleware function. If that function calls next(), the request is passed on to the next middleware function in the stack, and so on. If a middleware function does not call next(), it's expected to handle and end the request-response cycle itself (e.g., by sending a response with res.send()), and no subsequent middleware functions will be executed for that request.

Syntax and Definition

The basic syntax for a middleware function is:

function myMiddleware(req, res, next) {
  // Your middleware logic here
  console.log('Middleware executed!');
  next(); // Call next to pass control to the next middleware
}

req: The request object, containing information about the HTTP request.

res: The response object, used to send a response back to the client.

next: A function that, when called, executes the next middleware function in the stack.

You use app.use() to apply middleware at the application level, or you can apply it to specific routes.

Example:

Here's an example of a simple logging middleware that logs the URL of every incoming request. 

const express = require('express');
const app = express();
const port = 3000;

// This is our custom middleware
const requestLogger = (req, res, next) => {
  console.log(`Request received for URL: ${req.originalUrl}`);
  next(); // Don't forget this!
};

// Use the middleware for all incoming requests
app.use(requestLogger);

// Define a simple route
app.get('/', (req, res) => {
  res.send('Hello World!');
});

app.listen(port, () => {
  console.log(`Server running at http://localhost:${port}`);
});

When you visit http://localhost:3000, the requestLogger middleware runs first, logs the request URL, and then calls next(), which allows the app.get('/') route handler to execute and send the "Hello World!" response.

Types of Middleware

Express.js has several types of middleware:

  • Application-level Middleware: This middleware is bound to an instance of the app object using app.use() or app.METHOD(). It's executed for every request to the application.
  • Router-level Middleware: This works in the same way as application-level middleware but is bound to an instance of express.Router(). This is useful for grouping middleware and routes for specific parts of an application.
  • Built-in Middleware: Express has built-in middleware functions for handling static files, JSON, and URL-encoded data.
    • express.static(): Serves static assets like images, CSS files, and JavaScript files.
    • express.json(): Parses incoming requests with JSON payloads.
    • express.urlencoded(): Parses incoming requests with URL-encoded payloads.
  • Error-handling Middleware: This middleware has four arguments: (err, req, res, next). It's specifically designed to handle errors that occur during the request-response cycle. It's defined last in the middleware stack.
  • Third-party Middleware: These are external modules installed via npm to add extra functionality, such as body-parser (often replaced by express.json() now), cors for Cross-Origin Resource Sharing, or morgan for HTTP request logging. You install them with npm install and then require() them in your application.

Error-handling Middleware

Error-handling middleware is a special type of middleware in Express.js that is executed specifically when an error occurs during the request-response cycle. It's designed to catch and handle errors that might be thrown by other middleware or route handlers.

When Error-handling Middleware is Executed

This type of middleware is executed when you call the next() function with an error object as its argument, like next(err). Express recognizes this signature and skips all subsequent regular middleware and route handlers, jumping directly to the first error-handling middleware in the stack.

Important Note: To function correctly as error-handling middleware, it must have four arguments: (err, req, res, next). If you define it with fewer arguments, Express will treat it as a regular middleware function.

Example and Usage

Error-handling middleware is typically defined at the very end of your middleware stack, after all other app.use() and route definitions. This ensures that it's the last thing to be called, only after all other parts of your application have had a chance to run.

Here's a breakdown of a typical setup:

Define a regular route or middleware that can throw an error.

app.get('/error-route', (req, res, next) => {
  // Simulate an error
  const err = new Error('Something went wrong!');
  err.status = 500;
  next(err); // Pass the error to the next middleware
});

Define the error-handling middleware.

app.use((err, req, res, next) => {
  // Set a default status code and message if not already defined
  res.status(err.status || 500);
  res.send({
    error: {
      message: err.message,
      status: err.status || 500
    }
  });
});

In this example, when a user accesses /error-route, the route handler creates an Error object and passes it to next(). Express sees the error and skips any other middleware defined after this route, jumping directly to the error-handling middleware. This final middleware then sends a structured JSON response back to the client with the error details.

How to handle error with error handler middleware

To handle errors with error-handling middleware in Express.js, you define a special middleware function that takes four arguments: (err, req, res, next). This function must be placed at the very end of your middleware stack. When any other middleware or route handler encounters an error, it calls next(err), which causes Express to skip all subsequent normal middleware and jump directly to your error-handling function.

Steps to Implement Error-Handling Middleware

Define the Error-Handling Function: Create a function with the signature (err, req, res, next). This is the key that tells Express it's an error handler. The err parameter will contain the error object that was passed to next(). 

app.use((err, req, res, next) => {
  // Logic to handle the error
});

Place it Last: Ensure the error-handling middleware is the last app.use() call in your application's setup. This is crucial because middleware is executed in the order it's defined. 

const express = require('express');
const app = express();

// Normal middleware and routes come first
app.get('/', (req, res) => {
  res.send('Welcome to the homepage!');
});

app.get('/broken-route', (req, res, next) => {
  // Simulate an error
  const error = new Error('This route is broken!');
  error.status = 500;
  next(error); // Pass the error to the next middleware
});

// The error handler middleware comes last
app.use((err, req, res, next) => {
  console.error(err.stack); // Log the stack trace for debugging
  const statusCode = err.status || 500;
  res.status(statusCode).send({
    error: {
      message: err.message || 'An unexpected error occurred.',
      status: statusCode
    }
  });
});

app.listen(3000, () => {
  console.log('Server running on port 3000');
});

Trigger the Error Handler: In any of your normal routes or middleware, if an error occurs (e.g., a database connection fails, a file is not found, or an external API call fails), you simply call next(err). Express will then take care of routing the request to the error handler.

This method allows you to centralize your error logic, preventing repetitive try...catch blocks in every route and ensuring a consistent response format for errors.
