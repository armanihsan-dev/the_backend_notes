Dynamic Routing in Express.js

Dynamic routing in Express.js is a powerful feature that allows you to create flexible routes that can handle variable parts in the URL. This is essential for building **RESTful APIs**, where you often need to identify and interact with a specific resource based on a unique identifier.

Definition

Dynamic routes are defined using **named placeholders** called "route parameters." These placeholders are prefixed with a colon (`:`), such as `:id` or `:username`, in the route path. When a request is made, Express parses the URL, extracts the value of the dynamic segment, and makes it available as a property on the **`req.params`** object.

For example, the route `'/users/:id'` will match URLs like `/users/123` or `/users/abc`. The value `123` or `abc` can then be accessed via `req.params.id` in your route handler.

Proper Syntax

The basic syntax for a dynamic route is to use a colon followed by the parameter name in the route path string.

JavaScript
app.get('/api/resource/:paramName', (req, res) => {
  // Access the parameter value
  const paramValue = req.params.paramName;
  // ... rest of your code
});
  • **`app.get()`**: Specifies the HTTP method for the request. Other methods like `app.post()`, `app.put()`, or `app.delete()` can also use dynamic routes.
  • **`'/api/resource/:paramName'`**: The route path. `:paramName` is the dynamic segment.
  • **`req.params`**: An object containing the extracted route parameters. The keys match the parameter names (e.g., `paramName`), and the values are the corresponding parts of the URL.

Complete Examples

Let's look at complete examples for different HTTP methods. We'll use a simple in-memory array to simulate a data store.

JavaScript
const express = require('express');
const app = express();
app.use(express.json()); // Middleware to parse JSON bodies

// Sample data store
let files = [
  { id: '1', name: 'report.pdf' },
  { id: '2', name: 'invoice.docx' },
  { id: '3', name: 'photo.jpg' },
];

const port = 3000;

GET Request: Retrieve a Specific File

This route handles a GET request to retrieve a single file by its unique ID.

JavaScript
// GET /api/files/:id
app.get('/api/files/:id', (req, res) => {
  // 1. Get the ID from the URL using req.params
  const fileId = req.params.id;

  // 2. Find the file in our data store
  const file = files.find(f => f.id === fileId);

  // 3. Handle cases where the file is not found
  if (!file) {
    return res.status(404).send('The file with the given ID was not found.');
  }

  // 4. Send the file data back as a JSON response
  res.json(file);
});

Code Explanation:

  • `const fileId = req.params.id;`: The value of the `:id` parameter (e.g., `1` from `/api/files/1`) is extracted and stored.
  • `files.find(...)`: We search the `files` array for an object where the `id` property matches `fileId`.
  • `if (!file) ...`: A check to ensure a file was found. If not, we return a `404 Not Found` status.
  • `res.json(file);`: If the file is found, we send it as a JSON response.

DELETE Request: Delete a File

This route handles a DELETE request to remove a file from the server using its ID.

JavaScript
// DELETE /api/files/:id
app.delete('/api/files/:id', (req, res) => {
  // 1. Get the ID from req.params
  const fileId = req.params.id;

  // 2. Find the index of the file to delete
  const fileIndex = files.findIndex(f => f.id === fileId);

  // 3. Handle case where the file is not found
  if (fileIndex === -1) {
    return res.status(404).send('The file with the given ID was not found.');
  }

  // 4. Remove the file from the array using its index
  const deletedFile = files.splice(fileIndex, 1)[0];

  // 5. Send back the deleted file as a confirmation
  res.json(deletedFile);
});

Code Explanation:

  • `const fileId = req.params.id;`: We get the ID of the file to be deleted.
  • `files.findIndex(...)`: We get the index of the file, which is required for `splice()`.
  • `if (fileIndex === -1) ...`: If the file isn't found, we return a `404`.
  • `files.splice(fileIndex, 1)`: This modifies the array by removing one element at the specified index.
  • `res.json(deletedFile);`: We send back the deleted file's data to confirm the action.

PATCH Request: Rename a File

A PATCH request is used for partial modifications. Here, we'll use it to rename a file.

JavaScript
// PATCH /api/files/:id
app.patch('/api/files/:id', (req, res) => {
  // 1. Get the ID from req.params
  const fileId = req.params.id;

  // 2. Find the file
  const file = files.find(f => f.id === fileId);

  // 3. Handle case where file is not found
  if (!file) {
    return res.status(404).send('The file with the given ID was not found.');
  }

  // 4. Check if the new name is provided in the request body
  if (!req.body.name) {
    return res.status(400).send('New file name is required.');
  }

  // 5. Update the file's name
  file.name = req.body.name;

  // 6. Send the updated file back
  res.json(file);
});

Code Explanation:

  • `const fileId = req.params.id;`: The ID is extracted to identify the file.
  • `const file = files.find(...)`: The file object is found.
  • `if (!file) ...`: We handle the not-found case with a `404`.
  • `if (!req.body.name) ...`: We check if the request body contains a new `name`. If not, we send a `400 Bad Request` error.
  • `file.name = req.body.name;`: The `name` property is updated with the new value from the request body.
  • `res.json(file);`: We return the modified file object to confirm the change.

Optional Dynamic Routing

Sometimes you need a route parameter to be optional. For example, you might want to retrieve a list of all users, but also have the option to get users from a specific city. Express allows you to define optional parameters by adding a question mark (`?`) after the parameter name in the route path.

Syntax
'/api/resource/:paramName?'

This route will match both `/api/resource/` and `/api/resource/someValue`.

Practical Example

Let's create a route that can either return a list of all files or find a file by its ID if the ID is provided.

JavaScript
// GET /api/files/:id?
app.get('/api/files/:id?', (req, res) => {
  // Check if the 'id' parameter is present in the URL
  const fileId = req.params.id;

  // If an ID is provided, find and return that specific file
  if (fileId) {
    const file = files.find(f => f.id === fileId);
    if (!file) {
      return res.status(404).send('File not found.');
    }
    res.json(file);
  } else {
    // If no ID is provided, return the entire list of files
    res.json(files);
  }
});

Code Explanation:

  • The route `'/api/files/:id?'` tells Express that the `id` parameter is optional.
  • Inside the route handler, we check if `req.params.id` exists. If it does, a specific file was requested.
  • If `req.params.id` is undefined, no parameter was provided in the URL, and we serve the full list of files.

This technique is a great way to consolidate multiple similar routes into a single, more flexible one.
