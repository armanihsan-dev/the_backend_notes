Cookies are small pieces of data that a server sends to a user's web browser. The browser stores these pieces of data and sends them back to the same server with every subsequent request. This mechanism allows for a stateful experience over the stateless HTTP protocol. Cookies are essential for functions like session management, personalization, and tracking.

Why We Need Cookies

The Hypertext Transfer Protocol (HTTP) is stateless, meaning each request from a browser to a server is independent and doesn't retain any memory of previous requests. Think of it like a forgetful waiter who remembers nothing about your last order. This is a problem for things like shopping carts or user logins, where the server needs to know who you are and what you were doing. Cookies provide the "memory" for the web. They're the little notes that the server can send to the browser to remind it of the user's state.

Cookies are primarily used for three key purposes:

  • Session Management: They store information that lets a website recognize a user across multiple page views. This is how you stay logged into your email or social media account without having to re-enter your password on every page.
  • Personalization: Cookies remember user preferences, like language settings or theme choices, to create a more customized experience. This is also how websites can recommend products based on your browsing history.
  • Tracking: They're used to record and analyze user behavior. This allows advertisers to show targeted ads and website owners to understand how their site is being used.

How to Work with Cookies in JavaScript

Basic: Document.cookie

The most fundamental way to interact with cookies in JavaScript is using the document.cookie property. It's a string that contains all the cookies for the current document, separated by semicolons.

Setting a Cookie:

To set a cookie, you assign a string to document.cookie. The format is key=value; expires=date; path=/. 

document.cookie = "username=JohnDoe";
document.cookie = "preference=darkmode; expires=Fri, 31 Dec 2027 12:00:00 UTC; path=/";
  • expires: This sets an expiration date. If not set, the cookie is a session cookie and will be deleted when the browser closes.
  • path: This specifies the URL path that the cookie is valid for. A value of / makes it accessible across the entire website.

Getting a Cookie:

Reading cookies is tricky because document.cookie returns the entire string of all cookies. You have to parse the string yourself to find a specific cookie. 

const allCookies = document.cookie; // Returns "username=JohnDoe; preference=darkmode"
// To get a specific cookie, you'll need a function to parse the string
function getCookie(name) {
  const value = `; ${document.cookie}`;
  const parts = value.split(`; ${name}=`);
  if (parts.length === 2) {
    return parts.pop().split(';').shift();
  }
}
const username = getCookie('username');
console.log(username); // "JohnDoe"

Deleting a Cookie:

To delete a cookie, you set its expiration date to a time in the past. 

document.cookie = "username=; expires=Thu, 01 Jan 1970 00:00:00 UTC; path=/;";

Advanced: Cookie Properties and Security

Beyond the basic key=value pair, cookies have several attributes that control their behavior and security.

  • Secure: When this flag is set, the cookie will only be sent to the server over a secure HTTPS connection. This is crucial for protecting sensitive information.
  • HttpOnly: This attribute prevents client-side JavaScript from accessing the cookie via document.cookie. This is a vital security measure against cross-site scripting (XSS) attacks, where a malicious script could otherwise steal a user's session cookie.
  • SameSite: This attribute protects against cross-site request forgery (CSRF) attacks. It controls whether a cookie is sent with cross-site requests. It has three possible values:
    • Lax (default): Cookies are sent with top-level navigation GET requests but not with requests from different origins (e.g., an image tag).
    • Strict: Cookies are only sent with requests from the same site.
    • None: Cookies are sent with all cross-site requests. This requires the Secure attribute to be set.
  • Domain: This specifies the domain the cookie is valid for. For example, a cookie set with domain=.example.com would be available to both www.example.com and sub.example.com.

Best Practices and Alternatives

While cookies are a powerful tool, modern web development often uses other storage mechanisms for specific tasks, especially for large amounts of data.

  • localStorage and sessionStorage: These APIs offer a much simpler way to store data on the client side. They are key-value stores that can hold much more data than cookies.
    • localStorage persists even when the browser is closed.
    • sessionStorage is cleared when the session ends (i.e., when the browser tab is closed).
  • Why use cookies then? The key difference is that data in localStorage and sessionStorage is never automatically sent to the server. You have to explicitly send it yourself. Cookies, by contrast, are automatically sent with every request to the server, which is essential for server-side session management.

Here is a simple comparison table:

Feature Cookies localStorage sessionStorage
Storage Limit ~4KB ~5-10MB ~5-10MB
Data Sent to Server Yes (automatically) No No
Expiry Yes (can be set) Never (until deleted) Session-based

What if Max-Age and Expires both are set .. which one will be high prior?

If both Max-Age and Expires are set for a cookie, Max-Age will take precedence. Modern browsers and HTTP specifications prioritize Max-Age because it's more straightforward and less prone to errors related to different time zones or system clocks.

What is Max-Age?

Max-Age is a directive that specifies the number of seconds from the current time that the cookie should remain valid. It is a relative value. For example, Max-Age=3600 means the cookie will expire in one hour.

What is Expires?

Expires is a directive that specifies an exact date and time when the cookie should be deleted. This value must be in a specific format, and it's an absolute timestamp. For example, Expires=Fri, 31 Dec 2027 12:00:00 UTC.

Why Max-Age is Preferred

The Expires attribute can cause issues because it relies on the client's system clock. If a user's clock is set incorrectly, the cookie's expiration time might be calculated incorrectly, leading to unexpected behavior. Max-Age, being a relative value, avoids this problem entirely. It simply counts down from the moment the cookie is created, making it a more reliable and robust option for setting a cookie's lifetime.

The HTTP State Management Standard (RFC 6265) explicitly states that if a cookie has both attributes, Max-Age should be used to determine the cookie's expiration. This ensures consistent behavior across all modern web browsers.

For what purpose cookies were developed

The term "cookies" in web development was developed for a simple, yet crucial, purpose: to give the stateless HTTP protocol "memory."

The internet, at its core, is a series of isolated requests. When you navigate from one page to another on a website, the server has no built-in way to know that the new request is from the same person who just requested the previous page. This is like a forgetful clerk who treats every customer as if they've never been to the store before.

Cookies were invented to solve this fundamental problem. They provide a mechanism for the server to send a small piece of data to the user's browser, which the browser then stores. On every subsequent request to that same server, the browser automatically sends that data back. This allows the server to recognize the user and maintain a consistent "state" or "session."

This invention paved the way for many of the basic functions of the modern web, including:

  • Session Management: The most important and original purpose. This is how websites can keep you logged in as you browse, remember the items in your shopping cart, or track your progress in a multi-page form. The server can send a cookie with a unique session ID, and as long as the browser sends that cookie back, the server knows which user it's dealing with.
  • Personalization: Websites can use cookies to remember your preferences and tailor the content to you. This includes things like:
    • Remembering your language or region settings.
    • Displaying a specific theme, such as "dark mode."
    • Providing personalized recommendations based on your past browsing or purchase history.
  • Tracking and Analytics: Cookies are used to gather data on how users interact with a website. This allows website owners to understand traffic patterns, see which pages are most popular, and measure the effectiveness of their marketing campaigns. This is also the basis for targeted advertising, where advertisers can show you ads for products you have previously viewed or searched for.

In summary, cookies were developed to overcome the stateless nature of HTTP, allowing for a persistent, personalized, and functional user experience across multiple page visits.
