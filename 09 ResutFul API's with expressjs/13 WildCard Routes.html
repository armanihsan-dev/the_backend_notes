Wildcard Routes in Express.js

Wildcard routes in Express.js are a type of route that can match a variety of paths. They are also known as catch-all routes because they "catch" requests that haven't been matched by other, more specific routes. They are primarily used for handling routes that follow a certain pattern or for creating a fallback for 404 "Not Found" errors.

How Wildcard Routes Work

Wildcard routes work by using a special symbol, the asterisk *, in the path string. The asterisk acts as a wildcard that matches any sequence of characters.

Here's the basic syntax:

app.get('/path/*', (req, res) => {
  // This route will match /path/something, /path/another/thing, etc.
  res.send('This is a wildcard route.');
});

A common use case for a wildcard is as the last route in your application's middleware chain. If a request reaches this route, it means no other, more specific route has matched it.

Here's a good example:

app.get('/users/:id', (req, res) => {
  res.send('This is a specific user route.');
});

// Wildcard route for 404 errors
app.use('*', (req, res) => {
  res.status(404).send('Sorry, that page cannot be found.');
});

In this example, a request to /users/123 will be handled by the first route. A request to /about or any other non-existent route will fall through to the wildcard route and return a 404 status. This is because Express processes routes in the order they are defined.

Practical Nested Example: Reading and Writing Files

Let's look at a practical, nested example of using wildcard routes to handle file operations. In this scenario, we'll create a system where a user can request to read or write to a file within a specific directory, and the wildcard will help us handle the different file paths.

We'll use Node.js's built-in fs module for file system operations.

Server-side Code

const express = require('express');
const fs = require('fs');
const path = require('path');

const app = express();
const PORT = 3000;

app.use(express.json()); // Middleware to parse JSON request bodies
app.use(express.text()); // Middleware to parse text request bodies

// Define the base directory for our files
const dataDir = path.join(__dirname, 'data');

// Create the data directory if it doesn't exist
if (!fs.existsSync(dataDir)) {
  fs.mkdirSync(dataDir);
}

// ----------------------
// READ Wildcard Route
// ----------------------
// This route will handle GET requests for any file within the '/read' path.
app.get('/read/*', (req, res) => {
  // The wildcard part of the URL is captured in req.params[0]
  const filePath = path.join(dataDir, req.params[0]);

  // Check if the file exists
  if (!fs.existsSync(filePath)) {
    return res.status(404).send('File not found.');
  }

  // Read the file and send its content
  fs.readFile(filePath, 'utf8', (err, data) => {
    if (err) {
      return res.status(500).send('Error reading file.');
    }
    res.send(data);
  });
});

// ----------------------
// WRITE Wildcard Route
// ----------------------
// This route will handle POST requests to write to any file within the '/write' path.
app.post('/write/*', (req, res) => {
  // The wildcard part of the URL is captured in req.params[0]
  const filePath = path.join(dataDir, req.params[0]);

  // The content to write comes from the request body
  const content = req.body;

  // Write the content to the file
  fs.writeFile(filePath, content, 'utf8', (err) => {
    if (err) {
      return res.status(500).send('Error writing file.');
    }
    res.status(200).send(`File saved successfully to ${req.params[0]}`);
  });
});

// Fallback 404 Route
app.use((req, res) => {
  res.status(404).send('The requested URL was not found.');
});

// Start the server
app.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
  console.log('To read a file: GET /read/your-filename.txt');
  console.log('To write a file: POST /write/your-filename.txt with text in the body');
});

How the Code Works

  • app.get('/read/*', ...):
    • This is our read wildcard route. It will match any GET request to /read/ followed by anything. For example, /read/documents/report.txt.
    • req.params[0] is a special property that holds the value matched by the wildcard *. In /read/documents/report.txt, req.params[0] will be 'documents/report.txt'.
    • We use path.join() to safely construct the full file path, preventing directory traversal attacks.
    • We then check if the file exists and, if so, read and send its contents.
  • app.post('/write/*', ...):
    • This is our write wildcard route. It will match any POST request to /write/ followed by anything, like /write/notes/my-notes.md.
    • Again, req.params[0] is used to get the desired file path.
    • We get the file content from the req.body and use fs.writeFile() to save it.
  • Order of Operations:
    • Because the read and write routes are defined before the final 404 route, they will be matched first. This ensures our file operations are handled correctly.
    • If a request doesn't match either of these, it "falls through" to the app.use((req, res) => ...) middleware, which sends the 404 message.

Example Usage with cURL

Writing a File

To write the file hello.txt inside a new files directory: 

curl -X POST -H "Content-Type: text/plain" -d "Hello, this is a test file." http://localhost:3000/write/files/hello.txt

This will create the directory data/files and a file named hello.txt inside it with the specified content.

Reading a File

To read the file you just wrote:

curl http://localhost:3000/read/files/hello.txt

The server will respond with the content: "Hello, this is a test file." You can get the route that is inside a wildcard by using req.params[0]. This property in Express.js contains the matched substring from the route's URL.

How it Works

When you define a route with a wildcard *, Express captures the part of the URL that matches the wildcard and stores it in an array attached to the request object. The first element of this array, req.params[0], holds the entire path segment that was matched by the *.

Example

Let's say you have the following wildcard route:

app.get('/files/*', (req, res) => {
  // `req.params[0]` will contain the part of the URL after `/files/`
  const filePath = req.params[0];
  console.log('Requested file path:', filePath);
  res.send(`You requested the file located at: ${filePath}`);
});

If a user navigates to http://localhost:3000/files/documents/report.pdf, here's what happens:

  • The request URL is /files/documents/report.pdf.
  • The route definition is /files/*.
  • The part of the URL that matches the * is documents/report.pdf.
  • Express stores this value in req.params[0].
  • The filePath variable will be assigned the string 'documents/report.pdf', allowing you to use it for further logic, such as reading a file from a directory.
