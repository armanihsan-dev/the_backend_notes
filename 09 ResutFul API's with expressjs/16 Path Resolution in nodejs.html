Path Resolution in Node.js

⚡ So the name of this concept is: Path resolution in Node.js → specifically the difference between module resolution and filesystem resolution.

1. What is a “path”?

A path tells Node (or your OS) where a file/directory lives. Two main types:

  • Absolute path → starts from root of disk
    • C:\Users\Arman\project\storage\file.txt   (Windows)
/home/arman/project/storage/file.txt       (Linux/Mac)
  • Relative path → starts from some reference point
    • ./storage/file.txt
../filesDB.json

👉 The confusion is always: relative to what?

2. Two contexts in Node.js

(A) Module Resolution (import / require)

When you do:

import filesData from '../filesDB.json';

../filesDB.json is relative to the file where this import is written. Node’s module loader resolves it. Doesn’t care about where you run node.

📌 Think: “relative to this source file”.

(B) Filesystem Resolution (fs module)

When you do:

import { writeFile } from "node:fs/promises";
await writeFile("./storage/file.txt", "hello");

./storage/file.txt is relative to the current working directory (process.cwd()). If you cd into different folders before running node, the meaning of ./storage changes. Doesn’t care about where the code file is saved.

📌 Think: “relative to where I started node”.

3. Visual Example

Project structure:

F:\node application\Storify - Procodrr\
  ├── project\
  │     ├── app.js
  │     ├── routes\DirectoryRoutes.js
  │     └── storage\
  │           └── hello.txt

Case A: Run from inside project

cd project
node app.js

process.cwd() = ...Storify - Procodrr\project

./storage/hello.txt ✅ works

Case B: Run from parent folder

cd "F:\node application\Storify - Procodrr"
node project/app.js

process.cwd() = ...Storify - Procodrr

./storage/hello.txt ❌ fails (no storage here)

4. The Fix: Always Anchor Paths

To avoid surprises, anchor paths to your file’s location using import.meta.url: 

import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
const storagePath = path.join(__dirname, "../storage", "hello.txt");

✅ Always points to project/storage/hello.txt, no matter where you run node.

5. Golden Rules (Cheat Sheet)

  • Imports (import/require) → relative to the source file.
  • fs paths (writeFile, readFile) → relative to process.cwd() (the folder you ran node in).
  • Safe solution → use __dirname (ESM: build it yourself with import.meta.url) to always get file-relative paths.

6. Why Node.js is like this?

  • import/require are about modules → naturally, relative to the file that uses them.
  • fs functions are about filesystem → naturally, relative to where your program is running (like any shell command).
