Express.js Global Middleware

In Express.js, global middleware is a function that runs for every single incoming request to your application, regardless of the HTTP method (GET, POST, etc.) or the route. It's often used for tasks that apply to the entire application, such as logging, authentication, or parsing request bodies. 🌐

How and When Global Middleware Executes

Global middleware is executed in the order it's defined in your application's main file (typically app.js or index.js), and it runs before any route-specific handlers.

  • Request arrives: A client sends a request to your Express server.
  • Global Middleware runs: Express processes the request through all the global middleware functions, in the order they were defined.
  • Next() is called: Each middleware function must call next() to pass control to the next middleware function in the stack. If a middleware function doesn't call next(), the request-response cycle is stalled and no further handlers will be executed.
  • Route Handler executes: Once all global middleware functions have called next(), the appropriate route handler (e.g., app.get('/', ...) or app.post('/users', ...)) is executed.
  • Response is sent: The route handler sends a response back to the client.

How to Create Global Middleware

You create global middleware by using app.use() and passing your middleware function as an argument. The function has three parameters: req (request object), res (response object), and next (a function to call the next middleware).

Syntax

app.use(function(req, res, next) {
  // Your middleware logic here
  // ...
  next(); // Pass control to the next middleware or route handler
});

Here's a breakdown of the parameters:

  • req: The request object, containing information about the HTTP request.
  • res: The response object, used to send a response back to the client.
  • next: A callback function that, when called, tells Express to move on to the next function in the middleware chain.

Practical Examples

Let's look at some common use cases for global middleware.

1. Logging Middleware 📝

A simple but effective example is a logger that logs every incoming request to the console. 

const express = require('express');
const app = express();
const PORT = 3000;

// Global logging middleware
app.use((req, res, next) => {
  console.log(`Request received at: ${new Date().toISOString()} for ${req.originalUrl}`);
  next(); // Don't forget to call next()!
});

// A simple route handler
app.get('/', (req, res) => {
  res.send('Welcome to the homepage!');
});

app.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
});

In this example, every time you visit http://localhost:3000, the logging middleware will execute first, printing a timestamped message to your console, and then the route handler will send the "Welcome" message.

2. Body Parser Middleware

This is one of the most common types of global middleware. Body parsers are used to extract data from the body of incoming requests (e.g., from form submissions or JSON payloads). The express.json() and express.urlencoded() functions are built-in Express middleware for this purpose. 

const express = require('express');
const app = express();
const PORT = 3000;

// Global middleware to parse JSON request bodies
app.use(express.json());

// Global middleware to parse URL-encoded request bodies
app.use(express.urlencoded({ extended: true }));

// A route handler that needs access to the request body
app.post('/submit-data', (req, res) => {
  console.log('Received data:', req.body);
  res.send('Data received successfully!');
});

app.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
});

In this case, express.json() will run for every request. If a POST request with a JSON body is sent to /submit-data, this middleware will parse the body and populate req.body so the route handler can access it.

3. Authentication Middleware 🔑

You can use global middleware to check if a user is authenticated on every request, ensuring that only logged-in users can access certain parts of your application. 

const express = require('express');
const app = express();
const PORT = 3000;

const isAuthenticated = (req, res, next) => {
  // Imagine a simple check for a 'token' in the request header
  const token = req.headers.authorization;
  if (token) {
    // A real app would validate this token
    console.log('User is authenticated!');
    next();
  } else {
    console.log('Access denied!');
    res.status(401).send('Unauthorized');
  }
};

// Apply the authentication middleware globally
app.use(isAuthenticated);

// This route will only be accessible if isAuthenticated calls next()
app.get('/dashboard', (req, res) => {
  res.send('Welcome to the protected dashboard!');
});

// The app.listen() call would go here
app.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
});

Here, the isAuthenticated middleware runs for every request. If a request is made to /dashboard without a valid authorization header, the middleware will send a 401 Unauthorized response and will not call next(), preventing the route handler from ever executing.
