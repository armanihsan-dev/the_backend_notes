View

The **View** is the component in the Model-View-Controller (MVC) architectural pattern responsible for **presenting data** to the user and **handling user interaction**.

View: Purpose and Working

Aspect Description
**Purpose** To render the application's user interface (UI). It displays the data received from the **Model** (or via the **Controller**), typically in the form of HTML, XML, or other display formats.
**Need** It enforces the **Separation of Concerns (SoC)** principle, ensuring that the application's data structure (Model) and business logic (Controller) are decoupled from the presentation logic. This makes the codebase more organized, maintainable, and testable.
**How it Works** The **Controller** selects which View to display based on the user's request and passes the necessary data (often a "ViewModel") to the View. The View then uses this data to generate the final output (e.g., an HTML page) which is sent back to the client. Crucially, the View **does not** contain business logic or directly interact with the database.

Practical Example: Todo App (Express & MongoDB)

While the full implementation of a complete CRUD app using express-react-views is quite extensive for this format, here is a conceptual breakdown and a partial syntax focusing on the **View's role** in a basic Express application utilizing Mongoose (for MongoDB) and a React-based view engine.

1. Model (Data Structure)

Define the schema for your Todo items using Mongoose.

models/Todo.js

JavaScript
const mongoose = require('mongoose');// Define the schema for a single Todo item
const todoSchema = new mongoose.Schema({
    task: {
        type: String,
        required: true,
        trim: true
    },
    completed: {
        type: Boolean,
        default: false
    }
});
module.exports = mongoose.model('Todo', todoSchema);

2. View (Presentation Logic)

The view component is responsible for the UI. It will receive data (the list of todos) and render the HTML.

views/TodoListView.jsx

JavaScript
import React from 'react';// This is the View Component. It receives the 'todos' data as props from the Controller.
function TodoListView({ todos }) {
    return (
        <html>
            <head>
                <title>Simple Todo App</title>
                {/* Basic styling for demonstration */}
                <style dangerouslySetInnerHTML={{__html: `
                    body { font-family: sans-serif; }
                    .todo-item { margin-bottom: 10px; padding: 10px; border: 1px solid #ccc; }
                    .completed { text-decoration: line-through; color: gray; }
                `}} />
            </head>
            <body>
                <h1>My Todos</h1>

                {/* 'Create' operation form */}
                <form method="POST" action="/todos">
                    <input type="text" name="task" placeholder="New todo task" required />
                    <button type="submit">Add Todo</button>
                </form>

                <hr />

                {/* 'Read' operation: list the todos */}
                {todos.map(todo => (
                    <div key={todo._id} className="todo-item">
                        <span className={todo.completed ? 'completed' : ''}>
                            {todo.task}
                        </span>
                        
                        {/* 'Update' operation: Toggle completion (Form for simplicity) */}
                        <form method="POST" action={`/todos/${todo._id}/toggle`} style={{}}>// style={{ display: 'inline', marginLeft: '10px' }} removed for brevity and formatting
                            <button type="submit">
                                {todo.completed ? 'Mark as Not Done' : 'Mark as Done'}
                            </button>
                        </form>
                        
                        {/* 'Delete' operation (Form for simplicity) */}
                        <form method="POST" action={`/todos/${todo._id}/delete`} style={{}}>// style={{ display: 'inline', marginLeft: '10px' }} removed for brevity and formatting
                            <button type="submit">Delete</button>
                        </form>
                    </div>
                ))}
            </body>
        </html>
    );
}
export default TodoListView;

// Note: In a production app, the update/delete actions would typically use
// client-side JavaScript (AJAX) with PUT/DELETE methods.
// Here, we use POST with specific paths for simple browser form submission (as browsers don't natively support PUT/DELETE in HTML forms).

3. Controller (Business Logic and View Selection)

The controller handles the request, interacts with the Model, and selects the View.

server.js

JavaScript
const express = require('express');
const mongoose = require('mongoose');
const Todo = require('./models/Todo'); // Import Model
const app = express();

// Database Connection
mongoose.connect('mongodb://localhost:27017/todoapp', { useNewUrlParser: true, useUnifiedTopology: true })
    .then(() => console.log('MongoDB connected'))
    .catch(err => console.log(err));

// Configure express-react-views as the view engine
app.set('views', __dirname + '/views');
app.set('view engine', 'jsx');
app.engine('jsx', require('express-react-views').createEngine({ transformViews: true }));

// Middleware
app.use(express.urlencoded({ extended: true })); // To parse form data

// === CONTROLLER LOGIC (CRUD Operations) ===

// R - READ (Display all Todos) - Renders the View
app.get('/todos', async (req, res) => {
    try {
        const todos = await Todo.find({}); // Get data from Model
        // The Controller renders the 'TodoListView' and passes the 'todos' data to it.
        // The View uses this data to render the HTML list.
        res.render('TodoListView', { todos: todos });
    } catch (error) {
        res.status(500).send('Error reading todos');
    }
});

// C - CREATE (Add a new Todo) - Redirects to READ after action
app.post('/todos', async (req, res) => {
    try {
        const newTodo = new Todo({ task: req.body.task });
        await newTodo.save(); // Save data via Model
        res.redirect('/todos'); // Go back to the list (which calls the READ Controller/View)
    } catch (error) {
        res.status(500).send('Error adding todo');
    }
});

// U - UPDATE (Toggle completion) - Redirects to READ after action
app.post('/todos/:id/toggle', async (req, res) => {
    try {
        const todo = await Todo.findById(req.params.id);
        if (todo) {
            todo.completed = !todo.completed; // Update data in Model
            await todo.save();
        }
        res.redirect('/todos');
    } catch (error) {
        res.status(500).send('Error toggling todo');
    }
});

// D - DELETE (Remove a Todo) - Redirects to READ after action
app.post('/todos/:id/delete', async (req, res) => {
    try {
        await Todo.findByIdAndDelete(req.params.id); // Delete data via Model
        res.redirect('/todos');
    } catch (error) {
        res.status(500).send('Error deleting todo');
    }
});

// Start the server
const PORT = 3000;
app.listen(PORT, () => {
    console.log(`Server is running on http://localhost:${PORT}/todos`);
});

Data Flow and Server-Side Rendering (SSR)

That's an excellent follow-up question that gets to the heart of **Server-Side Rendering** (SSR) in your specific Express/React setup.

In the provided Express/MongoDB MVC example, the View is responsible for **Server-Side Rendering** (SSR), meaning the complete HTML page is generated on the server before being sent to the client.

1. Data Flow and Request Handling

The entire process begins when the client (browser) makes a request and ends when it receives the rendered HTML.

A. The "Read" Request (Initial Page Load)

The data flow for displaying the list of todos (the "Read" operation) is a classic MVC cycle:

Step Component Involved Action Data Flow
1. Request Client (Browser) User navigates to GET /todos. Request $\rightarrow$ Server (server.js)
2. Routing server.js (Express) The Express router finds the matching route handler in the Controller. Request $\rightarrow$ Controller
3. Logic & Data Fetch Controller Executes the handler (app.get('/todos', ...). Controller $\rightarrow$ **Model** (Todo.find({}))
4. Data Retrieval Model (Todo.js / Mongoose) Connects to MongoDB and fetches the list of todos. MongoDB $\rightarrow$ Model $\rightarrow$ Controller
5. Rendering (SSR) Controller $\rightarrow$ View The Controller calls res.render('TodoListView', { todos: todos }). This is the SSR step. Controller $\rightarrow$ **View** (TodoListView.jsx)
6. HTML Generation View (express-react-views) The React component runs on the server. It takes the {todos: todos} data and translates the JSX markup into a single, complete **HTML string** (including all the <h1>, <form>, and <div> tags). View $\rightarrow$ Express (as HTML string)
7. Response Express $\rightarrow$ Client Express sends the final, pre-rendered HTML back to the browser. HTML Response $\rightarrow$ Browser

B. The "Write" Request (Create/Update/Delete)

For CRUD operations that modify data, the flow is slightly different:

Step Action Data Flow
1. Request User submits the "Add Todo" form (e.g., POST /todos). Request $\rightarrow$ Controller
2. Logic & Data Manipulation Controller Validates the input and calls the Model to save or modify the data (newTodo.save()). Controller $\rightarrow$ Model $\rightarrow$ MongoDB
3. Redirect Controller After the database operation succeeds, the controller executes res.redirect('/todos'). Server $\rightarrow$ Browser (sends a 302 Redirect header)
4. New Request Client (Browser) The browser receives the redirect and immediately sends a new GET /todos request. New Request $\rightarrow$ Server
5. Re-Rendering Entire "Read" flow (Steps 1-7) The server runs the full SSR cycle again (Step A), fetches the new list, and sends the updated HTML to the client.

2. View's Role in Server-Side Rendering (SSR)

In this setup, the **View** is the core component that enables SSR, and the express-react-views engine is the tool that makes it happen.

How the View is Responsible for SSR

**Engine Installation:** The key is this line in server.js:

JavaScript
app.engine('jsx', require('express-react-views').createEngine({ transformViews: true }));

This tells Express: "When you encounter a .jsx file, use the express-react-views engine to process it."

**Server-Side Execution:** When the Controller calls res.render('TodoListView', { todos: todos }):

  • The express-react-views engine uses React and Babel (via transformViews: true) on the **Node.js server** to compile the TodoListView.jsx file.
  • It executes the React function component (TodoListView) and passes the todos data as a JavaScript object (the props).

**Static Markup Generation:** React's API provides methods (like ReactDOMServer.renderToString) to render a component into a static HTML string. The View engine uses this to perform the conversion:

**Input (JSX + Data):**

JavaScript
// Inside TodoListView.jsx, with data: [{_id: '1', task: 'Buy Milk', completed: false}]
{todos.map(todo => (
    <div key={todo._id}>
        <span>{todo.task}</span>
        {/* ... forms ... */}
    </div>
))}

**Output (HTML String):**

HTML
<div class="todo-item">
    <span>Buy Milk</span>
    <!-- ... forms ... -->
</div>
<!-- ... other todos ... -->

**Complete Response:** The final HTML string, which represents the complete webpage structure and content, is then returned to Express, which sends it to the browser.

Key Takeaway

The **View** component (TodoListView.jsx) itself doesn't know or care if it's running in a browser or on the server. Its sole responsibility is to map the data it receives (props.todos) into a presentation format (JSX/HTML markup). By using express-react-views, we force this mapping to happen on the **server**, delivering a fully constructed HTML page to the client, which is the definition of **Server-Side Rendering** (SSR).
