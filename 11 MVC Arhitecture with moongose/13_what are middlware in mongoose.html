Mongoose Middlewares (Hooks)

Middlewares in Mongoose, also known as pre and post **hooks**, are functions that are executed at specified stages during the lifecycle of a schema operation.1 They allow you to define logic that runs **before** or **after** a certain event (like saving, validating, or removing a document) occurs.2

They're essential for adding custom validation, modifying data, logging, or handling related document updates before or after Mongoose interacts with MongoDB.3

Common Types of Mongoose Middleware

Mongoose middlewares are categorized primarily by **when they run** (pre or post) and **what operation** they are associated with.4

1. Pre-Middlewares (Hooks)

Pre-middlewares execute **before** the specified event occurs.5 They are useful for tasks like:

  • Data validation or modification before saving.6
  • Hashing passwords before a new user is saved.
  • Setting default values or timestamps.
Hook Name Associated Methods Description
pre('save', ...) document.save(), Model.create() Runs before a document is saved to the database. Very common for password hashing.
pre('validate', ...) document.validate() Runs before Mongoose's built-in validation.
pre('remove', ...) document.remove() Runs before a document is removed.
pre('updateOne', ...) Model.updateOne(), Model.findOneAndUpdate() Runs before a query update operation. This type is generally a query middleware (as opposed to a document middleware like save or remove).
pre('find', ...) Model.find(), Model.findOne() Runs before a find query. Useful for query modifications like adding filtering conditions.

2. Post-Middlewares (Hooks)

Post-middlewares execute **after** the specified event and its associated logic (like saving to the database) have completed.7 They are useful for tasks like:

  • Logging the outcome of an operation.
  • Sending notifications or emails after a successful action.8
  • Cleanup or cascading deletes (e.g., deleting a related profile after a user is deleted).
Hook Name Associated Methods Description
post('save', ...) document.save(), Model.create() Runs after a document has been successfully saved.
post('remove', ...) document.remove() Runs after a document has been successfully removed.
post('init', ...) document.init() Runs after a document is initialized (e.g., when retrieved from the database).
post('findOneAndDelete', ...) Model.findOneAndDelete() Runs after a query-based delete operation completes.

Middleware Categories: Document vs. Query (and Model)

A. Document Middleware

These hooks operate on an actual Mongoose document (instance of a Model).9 They have access to the document being modified via this.

  • **Examples:** save, validate, remove, init.
  • **Usage:** Used for single document operations like user.save().10

B. Query Middleware

These hooks operate on a Mongoose Query object. They **do not** have access to the document via this (except in some special cases like findOneAndUpdate). Instead, this refers to the query object, allowing you to modify the query.

  • **Examples:** find, findOne, updateMany, deleteOne, updateOne.
  • **Usage:** Used for bulk or lookup operations like UserModel.find({ status: 'active' }).

Key Distinction: When dealing with updates, operations like Model.updateOne() or Model.findOneAndUpdate() fire **query middleware**, while operations like retrieving a document and then calling document.save() fire **document middleware**.

Is there a middleware called Model middleware?

is there a middleware called Model middleware : Yes, Model middleware (or Model hooks) is one of the four main types of middleware in Mongoose.1

The primary role of Model middleware is to intercept operations that are called directly on the Mongoose Model class rather than on an individual document or a query object.

Middleware Type Operation Type this Context Common Hooks
Model Static Model function The Model itself insertMany
Document Document instance method The Document being modified save, validate, remove
Query Query method The Query object find, updateOne, deleteOne
Aggregate Aggregate method The Aggregate object aggregate

Key Characteristics of Model Middleware

  • Supported Method: The most common operation that fires Model middleware is the static Model.insertMany().2
  • Context (this): Inside a Model middleware function, the this keyword refers to the Mongoose Model (the class itself, like UserModel), not a single document or a query.3
  • Purpose: It's used for logic that affects the entire collection or multiple documents in a batch operation.4 For example, you might use a pre('insertMany') hook to validate or transform an array of documents before they are inserted. 
userSchema.pre('insertMany', function(next, docs) {
    // 'this' refers to the Mongoose Model (e.g., UserModel)
    // 'docs' is the array of documents being inserted
    console.log(`Model Hook: Inserting ${docs.length documents.`);
    
    if (docs.some(doc => doc.status === 'pending')) {
        // Modify documents or stop the operation
        return next(new Error('Pending status is not allowed for bulk insert.'));
    }
    
    next();
});
