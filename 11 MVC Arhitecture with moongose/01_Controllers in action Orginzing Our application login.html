Controller in MVC Architecture

The Controller is an essential component in the MVC (Model-View-Controller) architecture. It acts as the middleman between the Model (data, business logic) and the View (user interface). Its main job is to receive user input, interpret it, perform any needed operations by invoking the model, and then decide which view to display to the user.

Key Responsibilities of the Controller:

  • Receives and processes user input (e.g., HTTP requests).
  • Calls and manipulates models to update or fetch data.
  • Decides which view to render with the data.

How Controller Works:

Imagine a bookstore app:

  • User searches for a book → sent as a request to Controller.
  • Controller asks Model "find all books matching keyword".
  • Model fetches data from database and returns it.
  • Controller sends data to View.
  • View displays the list of books.

This clean separation helps organize your code, making it easier to maintain and scale.

Practical Example of Controller in Express.js

Express.js is a web framework for Node.js that fits nicely into MVC. Here is how you can create a Controller:

Step 1: Create a Controller file (userController.js)

// userController.js

exports.getAllUsers = (req, res) => {
  // Imagine fetching all user data from Model
  const users = [{id: 1, name: 'Alice'}, {id: 2, name: 'Bob'}];
  res.json(users); // Send response as JSON
};

exports.getUserById = (req, res) => {
  const userId = req.params.id;
  // Fetch user based on id from Model
  const user = {id: userId, name: 'Alice'};
  res.json(user);
};

Step 2: Connect Controller to Routes (userRoutes.js)

const express = require('express');
const router = express.Router();
const userController = require('./userController');

router.get('/users', userController.getAllUsers);
router.get('/users/:id', userController.getUserById);

module.exports = router;

Step 3: Use Routes in Main App (app.js)

const express = require('express');
const app = express();
const userRoutes = require('./userRoutes');

app.use('/api', userRoutes);

const PORT = 3000;
app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});

This setup keeps:

  • Controllers focused on receiving requests, using models, and sending responses.
  • Clear separation of concerns improves code readability and maintenance.

does controller are handlerFunction that handle each http route

Yes, in Express.js, a controller is essentially a handler function (or a set of handler functions) that handles each HTTP route. When you define an Express route, you provide one or more callback functions—often referred to as route handlers or controller functions—that process incoming requests to that route. These handler functions receive the HTTP request and response objects and contain the logic for what should happen when that route is accessed.

  • Extracting parameters and data from the request
  • Calling business logic or models to retrieve or manipulate data
  • Sending an appropriate response back to the client

For example, in Express

app.get('/users', (req, res) => {
  // This is the controller function, handling GET requests to /users
  res.send('List of users');
});

In more organized MVC codebases, controllers are separated into modules or classes exporting these handler functions, which are then linked to routes. This separation keeps request handling (controllers) distinct from routing definitions and data logic (models).

You can also have multiple controller functions handle the same route in sequence or in arrays, enabling middleware-like chaining of logic

In short, controller functions are the handler functions responsible for dealing with HTTP routes in Express.js, acting as the "C" in MVC by processing input, retrieving data from models, and sending views or responses
