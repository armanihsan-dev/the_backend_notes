Document Middleware (Document Hooks)

Document middleware, often called **document hooks**, are functions executed during the lifecycle of a **single Mongoose document** before or after a specific operation. They are the most common and fundamental type of Mongoose middleware.

How Document Middleware Works

Document middleware is defined on the **Mongoose Schema** and is triggered when you call certain methods directly on an instance of a Model (a document).

1. The Context (this)

The key feature of document middleware is that the keyword this inside the middleware function refers to the **Mongoose document** being acted upon. This grants you full access to the document's properties and methods.

  • You can modify fields: this.name = this.name.toUpperCase();
  • You can check if fields were changed: this.isModified('password')

2. Supported Hooks (Syntax & Definitions)

Document middleware is supported for the following methods:

Hook Type Hook Name (Syntax) Definition
Pre-Hooks (Before) schema.pre('save', function(next) { ... }) Runs before a document is saved (to create or update) or when using Model.create(). Most common hook.
schema.pre('validate', function(next) { ... }) Runs before Mongoose's built-in validation.
schema.pre('remove', function(next) { ... }) Runs before a document is removed using doc.remove().
schema.pre('deleteOne', function(next) { ... }) Runs before a document is deleted using doc.deleteOne().
Post-Hooks (After) schema.post('save', function(doc, next) { ... }) Runs after a document has been successfully saved. The saved document is passed as the first argument (doc).
schema.post('init', function(doc) { ... }) Runs after a document has been initialized (e.g., when retrieved from the database).
schema.post('remove', function(doc, next) { ... }) Runs after a document has been successfully removed.

⚠️ Important Note on Updates: Document middleware **does not** fire for most **Query** update methods like Model.updateOne(), Model.findOneAndUpdate(), or Model.updateMany(). These methods execute **Query Middleware** instead, as they don't load the document into Mongoose memory first.

Practical Use Cases (Real-World Scenarios)

Document middleware is critical for maintaining data integrity and encapsulating business logic directly within your schemas.

1. Hashing Passwords (pre('save'))

This is the quintessential use case for pre('save'). Before a new user document is saved, you need to hash the plain-text password. 

// Install bcryptjs package for hashing
const bcrypt = require('bcryptjs'); 

// Pre-save hook for password hashing
userSchema.pre('save', async function(next) {
  // 'this' is the user document being saved
  if (!this.isModified('password')) {
    // Only hash if the password field is new or has been modified
    return next();
  }

  try {
    const salt = await bcrypt.genSalt(10);
    this.password = await bcrypt.hash(this.password, salt);
    next();
  } catch (error) {
    next(error); // Pass the error to stop the save operation
  }
});

2. Auto-Updating Timestamps (pre('save'))

While Mongoose Schemas have a built-in timestamps: true option, you might need custom timestamp logic, like ensuring a slug is only set on creation but an updatedAt field is updated on every save. 

// Pre-save hook for custom modification logic
productSchema.pre('save', function(next) {
  // 'this' is the product document
  
  // 1. Set 'slug' only if it's a new document
  if (this.isNew) {
    this.slug = createSlug(this.name); // Custom slug generation function
  }
  
  // 2. Always update the 'lastModified' field if any field changed
  if (this.isModified()) {
    this.lastModified = new Date();
  }
  
  next();
});

3. Cascading Deletes / Cleanup (post('remove') or post('deleteOne'))

After a parent document is deleted, you often need to clean up related child documents to prevent orphaned data. post hooks are perfect for this, as the parent document has already been successfully removed. 

// Assume a Blog Post has many Comments
postSchema.post('remove', async function(doc, next) {
  // 'doc' is the post that was just removed
  
  // Use the Comment model to delete all comments associated with this post ID
  try {
    await CommentModel.deleteMany({ postId: doc._id });
    console.log(`Deleted all comments for post: ${doc._id}`);
    next();
  } catch (error) {
    // Post-hooks don't stop the main operation, but you can log the error
    console.error('Error during comment cleanup:', error);
    next(error); 
  }
});
