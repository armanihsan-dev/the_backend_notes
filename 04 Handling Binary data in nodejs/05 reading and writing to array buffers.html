DataView in JavaScript Notes

In JavaScript, a DataView provides a low-level interface for reading and writing multiple numeric data types in an ArrayBuffer. It's particularly useful when dealing with binary data, network protocols, or file formats where you need precise control over byte order and data representation.

How do we connect an ArrayBuffer to a DataView in JavaScript?

You connect an ArrayBuffer to a DataView by passing the ArrayBuffer instance (and optionally an byteOffset and byteLength) to the DataView constructor:

const buffer = new ArrayBuffer(16); // Create an ArrayBuffer of 16 bytes
const view = new DataView(buffer); // Connect a DataView to the entire buffer

// You can also connect a DataView to a portion of the buffer
const partialView = new DataView(buffer, 4, 8); // Starts at byte offset 4, 8 bytes long

Can we connect multiple DataView instances to a single buffer?

Yes, you can connect multiple DataView instances to a single ArrayBuffer. Each DataView can operate on the same or different parts of the buffer, allowing for flexible access to the underlying binary data.

const buffer = new ArrayBuffer(16);

const view1 = new DataView(buffer); // View of the entire buffer
const view2 = new DataView(buffer, 0, 8); // View of the first 8 bytes
const view3 = new DataView(buffer, 8, 8); // View of the last 8 bytes

view1.setUint8(0, 100);
console.log(view2.getUint8(0)); // Output: 100

What is the difference between getUint8 and getInt8?

Both getUint8() and getInt8() read an 8-bit (1-byte) integer from the DataView at a specified byte offset. The difference lies in how they interpret the bits:

  • getUint8() (Unsigned 8-bit integer): Interprets all 8 bits as representing a non-negative value. The range is from 0 to 255.
  • getInt8() (Signed 8-bit integer): Interprets the most significant bit (MSB) as the sign bit (0 for positive, 1 for negative) and the remaining 7 bits as the magnitude, using two's complement representation for negative numbers. The range is from -128 to 127.

Why can’t we store numbers greater than 127 at a specific index using view.setInt8(1, 135)?

You can't directly store a number greater than 127 using setInt8() because setInt8() is designed to store a signed 8-bit integer. As explained above, the maximum positive value a signed 8-bit integer can hold is 127.

When you attempt to store a value like 135, which exceeds this limit, the setInt8() method effectively performs a *truncation* or *wraparound* based on two's complement arithmetic.

Why does that number return as a negative value?

When you try to store 135 using setInt8(), it's interpreted in a way that results in a negative value due to two's complement representation.

Let's break it down:

  • Binary representation of 135: In 8 bits, 135 is 10000111.
  • Signed 8-bit interpretation: When this bit pattern 10000111 is read as a signed 8-bit integer:
    • The most significant bit (the leftmost 1) indicates that the number is negative.
    • To find the magnitude of the negative number, you perform the two's complement operation on 10000111:
      1. Invert the bits: 01111000
      2. Add 1: 01111001
    • This binary 01111001 represents the decimal value 121.

Therefore, the original 10000111 is interpreted as -121.

So, view.setInt8(1, 135) will store the bits representing 135, but when you then retrieve it using getInt8(), it will be interpreted as -121.

Explain the properties of DataView.

A DataView instance has the following key properties:

  • buffer: This read-only property returns the ArrayBuffer that the DataView is referencing.
  • byteLength: This read-only property returns the length of the DataView in bytes. This might be the entire length of the ArrayBuffer or a smaller portion if an byteLength was specified in the constructor.
  • byteOffset: This read-only property returns the offset in bytes from the start of the ArrayBuffer that the DataView starts at. This will be 0 if no offset was specified, or the byteOffset passed to the constructor.

By default, do setInt methods write in big-endian? How can we store the value in little-endian instead?

By default, all DataView set methods (like setInt8, setUint16, setFloat32, etc.) write values in big-endian format. This means the most significant byte is stored at the lowest memory address.

To store the value in little-endian format, you need to pass true as the last argument to the set method.

Here's an example:

const buffer = new ArrayBuffer(4);
const view = new DataView(buffer);

// Storing a 16-bit integer (e.g., 256) in big-endian (default)
view.setUint16(0, 256); // Buffer: [0x01, 0x00, 0x00, 0x00] (Hex representation)
console.log(view.getUint8(0)); // Output: 1
console.log(view.getUint8(1)); // Output: 0

// Storing a 16-bit integer (e.g., 256) in little-endian
view.setUint16(0, 256, true); // Buffer: [0x00, 0x01, 0x00, 0x00] (Hex representation)
console.log(view.getUint8(0)); // Output: 0
console.log(view.getUint8(1)); // Output: 1
