Computer Numbers: Signed, Unsigned, and Two's Complement

Signed and Unsigned Values

In computer programming, numbers are stored in fixed-size units of memory (like bytes, words, etc.). The distinction between "signed" and "unsigned" refers to how these bits are interpreted.

Unsigned Values

  • These numbers can only represent non-negative values (zero and positive integers).
  • All the bits in the memory unit are used to represent the magnitude of the number.
  • For an 8-bit unsigned number, the range is from $00000000_2$ (0 decimal) to $11111111_2$ (255 decimal).
  • In general, for an n-bit unsigned number, the range is from $0$ to $2^n - 1$.

Signed Values

  • These numbers can represent both positive and negative values, including zero.
  • One bit (typically the leftmost, or Most Significant Bit - MSB) is reserved to indicate the sign of the number.
    • A 0 in the MSB usually indicates a positive number.
    • A 1 in the MSB usually indicates a negative number.
  • Because one bit is used for the sign, the remaining bits are used for the magnitude, which reduces the range of positive values that can be stored compared to an unsigned number of the same size.
  • The most common method for representing signed numbers is Two's Complement.

How Our System Differentiates in Signed and Unsigned Numbers

The computer hardware itself doesn't inherently "know" if a sequence of bits represents a signed or unsigned number. It's all about interpretation determined by the programmer and the programming language/compiler.

  • When you declare a variable in a programming language (e.g., int, unsigned int, char, unsigned char), you are telling the compiler how to interpret the bits stored in that variable.
  • If you declare an unsigned char (8 bits), the system will interpret all 8 bits as part of the number's magnitude, giving you a range of 0 to 255.
  • If you declare a signed char (8 bits, typically using two's complement), the system will interpret the leftmost bit as the sign bit, and the remaining 7 bits as the magnitude (in a two's complement fashion), giving you a range of -128 to 127.
  • The CPU's arithmetic logic unit (ALU) will perform operations based on whether it's dealing with signed or unsigned numbers. For example, if it's performing a comparison, it will use different logic depending on whether the numbers are treated as signed or unsigned.

Who Has the Authority of Assigning the Label of Signed and Unsigned to a Byte?

The programmer (through the choice of data types in their code) and the programming language/compiler have the authority.

int mySignedNumber;
unsigned int myUnsignedNumber;

You are explicitly telling the compiler how to treat the bits allocated for mySignedNumber and myUnsignedNumber. The compiler then generates machine code that performs operations on these variables according to their signed or unsigned nature.

For instance, the C and C++ languages offer keywords like signed and unsigned to specify this. Many other languages have similar distinctions, even if the keywords differ.

What is Two's Complement? How it Works?

Two's Complement is the most common method for representing signed integers in computers. It's widely used because it simplifies arithmetic operations (addition and subtraction can be performed using the same logic for both positive and negative numbers).

How it Works:

  1. Positive Numbers: A positive number is represented by its ordinary binary representation, with a leading 0 in the MSB.

    Example (using 8 bits): $+5_{10}$ is $00000101_2$.

  2. Negative Numbers: To find the two's complement representation of a negative number:
    1. Step 1: Find the binary representation of the absolute value of the number. Ensure you have enough bits for your desired system (e.g., 8 bits, 16 bits).
    2. Step 2: Invert all the bits (1's Complement). Change every 0 to a 1, and every 1 to a 0.
    3. Step 3: Add 1 to the result from Step 2. Ignore any carry-out from the MSB.

Example: Representing $-5_{10}$ in 8-bit Two's Complement

  • Absolute value of 5 is $00000101_2$.
  • Invert all bits: $11111010_2$ (this is one's complement).
  • Add 1: 
      11111010
+ 00000001
----------
  11111011

So, $-5_{10}$ in 8-bit two's complement is $11111011_2$.

Key Properties of Two's Complement:

  • Sign Bit: The MSB acts as the sign bit. 0 for positive, 1 for negative.
  • Unique Zero: There is only one representation for zero ($00000000_2$), unlike some older systems (like one's complement) that had both +0 and -0.
  • Range: For an $n$-bit system, the range of two's complement numbers is from $-(2^{n-1})$ to $(2^{n-1} - 1)$.

    For 8 bits: $-(2^{8-1})$ to $(2^{8-1} - 1)$ = $-128$ to $127$.

How to Represent Positive and Negative in Binary

In modern computer systems, the primary method for representing positive and negative numbers in binary is Two's Complement.

  • Positive Numbers: Start with a 0 in the MSB, and the remaining bits represent the magnitude directly.

    Example (4-bit): $0101_2$ is $+5_{10}$

  • Negative Numbers: Start with a 1 in the MSB, and the remaining bits represent the magnitude in a two's complement fashion.

    Example (4-bit): $1011_2$ is $-5_{10}$ (derived from inverting $0101_2$ to $1010_2$ and adding 1)

How to Convert Positive Binary to Negative

To convert a positive binary number to its negative equivalent using two's complement:

  1. Start with the positive binary number. Ensure it has the correct number of bits for your chosen system (e.g., 8-bit, 16-bit).
  2. Flip all the bits (perform one's complement). Change all 0s to 1s and all 1s to 0s.
  3. Add 1 to the result. Discard any carry-out from the most significant bit if it extends beyond your fixed number of bits.

Example: Convert positive $12_{10}$ ($00001100_2$) to negative $12_{10}$ in 8 bits

  1. Positive $12_{10}$ is $00001100_2$.
  2. Flip all bits: $11110011_2$.
  3. Add 1: 
      11110011
+ 00000001
----------
  11110100

So, $-12_{10}$ in 8-bit two's complement is $11110100_2$.

Understanding Binary Notation: The "$\_2$" Suffix

The "$_2$" after a binary number (like $00000000_2$ or $11111111_2$) simply indicates that the number is in base 2, which is binary.

It's a common notation used in mathematics and computer science to clarify the base of a number, especially when different bases (like decimal base 10, hexadecimal base 16, or octal base 8) might be involved in the same context.

So, $00000000_2$ means "the binary number 00000000".

What is Meant by "n-bit" and the Range Formula $0$ to $2^n - 1$?

This section addresses a fundamental concept in computer science: how many different values can be represented with a given number of bits.

What is meant by "n-bit"?

  • In "n-bit unsigned number," 'n' represents the number of binary digits (bits) used to store the number.
  • Each bit can be either a 0 or a 1.
  • If you have 'n' bits, you have 'n' positions, and each position can have two possibilities (0 or 1).
  • This means the total number of unique combinations or patterns you can create with 'n' bits is $2 \times 2 \times \dots \times 2$ (n times), which is $2^n$.

Examples:

  • 1-bit:
    • 0
    • 1

    Total combinations: $2^1 = 2$

  • 2-bit:
    • 00
    • 01
    • 10
    • 11

    Total combinations: $2^2 = 4$

  • 8-bit:
    • $00000000$ to $11111111$

    Total combinations: $2^8 = 256$

The Formula: $0$ to $2^n - 1$

This formula applies to unsigned numbers because all $2^n$ possible combinations are used to represent non-negative values.

  • Smallest value: The smallest possible unsigned number is when all bits are 0. In binary, this is $00\dots0_2$, which equals 0 in decimal.
  • Largest value: The largest possible unsigned number is when all bits are 1.
    • For 1 bit, it's $1_2 = 1_{10}$.
    • For 2 bits, it's $11_2 = 3_{10}$.
    • For 8 bits, it's $11111111_2 = 255_{10}$.

Notice a pattern: the largest number you can represent with 'n' bits is always one less than the total number of combinations ($2^n$). This is because you are starting your count from 0.

So, for an n-bit unsigned number:

  • The minimum value is $0$.
  • The maximum value is $2^n - 1$.
  • The range is from $0$ to $2^n - 1$.

Let's test it with our 8-bit example:

  • Here, $n=8$.
  • The range is from $0$ to $2^8 - 1$.
  • $2^8 = 256$.
  • So, the range is from $0$ to $256 - 1$, which is $0$ to $255$.

This matches exactly what we discussed earlier for 8-bit unsigned numbers.

For a 12-bit unsigned number:

  • Here, $n=12$.
  • Total number of unique combinations: $2^{12} = 4096$.
  • Smallest value: $0_{10}$.
  • Largest value: $2^{12} - 1 = 4096 - 1 = 4095_{10}$.

So, for a 12-bit unsigned number, the range is from $0$ to $4095$.

Benefit of N-bit Fixed-Size Representation

The "why" behind using fixed-size, N-bit binary representations for numbers in computers boils down to several crucial benefits related to hardware design, efficiency, predictability, and standardization:

  1. Hardware Simplicity and Efficiency:
    • Transistors are Binary: The fundamental building blocks of modern computers are transistors, which are natural two-state devices (on/off, high voltage/low voltage). This maps perfectly to binary (0s and 1s). It's much simpler and more reliable to design circuits that distinguish between two states than, say, ten states (for decimal).
    • Consistent Operations: When you know a number is stored in exactly 'N' bits, the hardware (CPU's Arithmetic Logic Unit or ALU) can be designed to perform operations (addition, subtraction, multiplication, etc.) on those fixed-size units very efficiently. It knows exactly how many bits to process and where the numbers begin and end.
    • Memory Addressing: Memory is organized into fixed-size units (bytes, words). When you store a number, the system needs to know exactly how much space it will occupy. N-bit representation provides this predictability.
  2. Predictability and Determinism:
    • Fixed Range: Knowing the number of bits (n) immediately tells you the exact range of values that can be stored (e.g., $0$ to $2^n - 1$ for unsigned, or $-(2^{n-1})$ to $2^{n-1} - 1$ for signed two's complement). This predictability is vital for programmers to avoid overflows (when a calculation result exceeds the maximum representable value) or underflows.
    • Consistent Behavior: Operations on N-bit numbers will always behave consistently, provided they stay within the defined range. This makes software more reliable and easier to debug.
  3. Standardization:
    • Interoperability: Fixed-size integer types (like 8-bit, 16-bit, 32-bit, 64-bit) are standardized across different computer architectures and programming languages. This means that a number stored in a 32-bit int on one computer will be interpreted the same way on another, facilitating data exchange and program compatibility.
    • Compiler Optimization: Compilers can heavily optimize code when they know the exact size and nature (signed/unsigned) of the numbers they are dealing with.
  4. Memory Management:
    • Allocating Space: When a program needs to store a number, the operating system and compiler allocate a specific, fixed amount of memory for it. This allows for efficient memory management and prevents programs from arbitrarily consuming memory.
    • No Dynamic Resizing: Unlike some abstract mathematical concepts of numbers, computer hardware doesn't "grow" or "shrink" the number of bits dynamically for a single value during computation. This would be incredibly inefficient and complex to implement.

While there are concepts like "arbitrary precision arithmetic" in some software libraries that can handle numbers of virtually any size, these are typically built on top of the underlying fixed-size hardware operations and come with a significant performance cost. For most general-purpose computing, the benefits of fixed-size N-bit representation far outweigh the limitations.
