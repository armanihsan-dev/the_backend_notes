Memory Inspector: Understanding Bytes and Endianness

Context: Viewing a 4-byte ArrayBuffer in Chrome Memory Inspector.

Initial Scenario (Big Endian)

🧠 What’s happening?

  • You’re viewing a 4-byte ArrayBuffer in the Chrome Memory Inspector.
  • You selected byte offset 2.

🧾 Bytes in Memory (in hex):

Offset Value
0 0x00
1 0x01
2 0x04
3 0x00

You're in Big Endian mode.

📍 Current Selection: Byte 2 (value: 0x04)

🔹 Integer 8-bit: dec → 4

Shows the value at byte offset 2 interpreted as a single 8-bit integer:

Byte 2 = 0x04 = 4 ✅

🔹 Integer 16-bit: dec → 1024

Shows the value starting at byte 2 and reading 2 bytes: byte 2 and byte 3.

  • Byte 2 = 0x04
  • Byte 3 = 0x00

In Big Endian, this means:

Value = 0x04 × 256 + 0x00 = 1024 + 0 = 1024

✅ That’s why the inspector shows Integer 16-bit = 1024.

💡 So what does 1024 mean here?

It’s just the raw 2-byte value starting from byte 2, interpreted as a 16-bit integer in Big Endian order.

In other words:

0x0400 (hex) = 1024 (decimal)

This doesn't necessarily represent a variable or operation — it’s just what those 2 bytes represent numerically.

🧪 Summary (Initial Scenario - Big Endian):

Term Meaning
Integer 8-bit Byte 2 = 0x04 = 4
Integer 16-bit Bytes 2–3 = 0x04 0x00 → 0x0400 → 1024 in decimal
Big Endian Most significant byte first → 0x04 is high byte, 0x00 is low byte

Understanding the '256' in Big Endian Formula

🧠 Why do we multiply by 256?

We're interpreting 2 bytes (16 bits) as a single unsigned integer in Big Endian order:

  • Byte at offset 2 = 0x04 (this is the most significant byte - MSB)
  • Byte at offset 3 = 0x00 (this is the least significant byte - LSB)

In Big Endian, the formula to compute the 16-bit value is:

Value = MSB × 256 + LSB

Why 256?

🧮 Because: Each byte = 8 bits.
→ So when you shift one byte to the left by 8 bits, it's the same as multiplying by:
28 = 256
So: The byte 0x04 (MSB) goes to the high 8 bits: 
→ 0x04 << 8 = 0x0400 = 1024
The byte 0x00 (LSB) stays in the low 8 bits.
So:
0x04 × 256 + 0x00 = 1024 + 0 = 1024

✅ Summary (256 Explanation):

Byte Hex Decimal Role
2 0x04 4 Most significant byte (× 256)
3 0x00 0 Least significant byte (+ 1×)
Final value = 4 × 256 + 0 = 1024

This is how multi-byte values are built from individual bytes in memory.

Deep Dive: Why the Big Endian Formula Contains 256

Why does the Big Endian formula use 256?

📦 1. Each byte is 8 bits

A byte can represent values from 0 to 255:

28 = 256 possible values

When you combine 2 bytes into a 16-bit integer, you need to assign one byte to the high-order bits and the other to the low-order bits.

📚 2. Big Endian stores the Most Significant Byte (MSB) first

Let’s say you have two bytes:

Byte Value
Byte 0 A (MSB)
Byte 1 B (LSB)

In Big Endian, you compute the value like this:

Value = A × 28 + B

Why 28? Because you’re shifting A into the higher byte position of a 16-bit number.

Visual Example:

Let’s say:

  • Byte 0 = 0x04 (MSB)
  • Byte 1 = 0x00 (LSB)

Then:

Binary:
0x04 = 00000100
0x00 = 00000000

Combined in 16 bits:
00000100 00000000 → This is 0x0400

That’s 4 * 256 = 1024 in decimal.

So:

Why 256? Because it’s the weight of the high byte in a 16-bit system.

🧮 General Formula (Big Endian):

For n bytes, the value is:

Value = b0 × 28(n-1) + b1 × 28(n-2) + &dots; + bn-1 × 20

For 2 bytes:

Value = MSB × 28 + LSB × 20 = MSB × 256 + LSB

✅ Final Summary (Why 256):

256 is used because the first byte (MSB) in Big Endian represents the higher-order bits — essentially multiplied by 28 = 256.

It’s how binary positional values work:

  • Byte 0 = 256's place
  • Byte 1 = 1's place

Understanding 28: Where do 2 and 8 come from?

Let’s now break down why exactly we use 28 in computing with bytes and binary.

🔹 Step 1: Why Base 2?

We use base 2 (binary) in computers because:

  • Computers use bits, which are either 0 or 1.
  • So every value is stored in powers of 2.

Examples:

2^0 = 1
2^1 = 2
2^2 = 4
...
2^7 = 128

🔹 Step 2: Why the exponent is 8?

Because 1 byte = 8 bits.

So a byte can represent any number from:

000000002 = 0 to 111111112 = 255

That’s 256 possible values:

28 = 256

🔹 Step 3: Why multiply by 28 in 16-bit numbers?

Let’s say you store a 16-bit number using two 8-bit bytes:

Byte1 (MSB) | Byte2 (LSB)

If:

  • Byte1 = 0x04
  • Byte2 = 0x00

You want to reconstruct the 16-bit value:

  • The first byte goes in the high position.
  • The second byte goes in the low position.

So:

Value = Byte1 × 28 + Byte2

Because you're "shifting" Byte1 8 bits to the left → this is how binary place value works.

It’s like how in decimal:

53 = 5×10^1 + 3×10^0

In binary:

0x0400 = 0x04 × 2^8 + 0x00

So 28 is the weight of a full byte (shifted up one byte).

✅ Final Summary (Why 28):

Symbol Meaning
2 Base of binary (0s and 1s)
8 Number of bits in a byte
28 256 → The number of values one byte can represent, or its positional weight

So: We use 28 because we are moving one byte (8 bits) to the left — same as multiplying by 256.

Endianness Formulas: Big Endian vs. Little Endian

Let’s write both formulas clearly and explain them side-by-side.

✅ Big Endian

In Big Endian, the most significant byte (MSB) comes first (at the lower memory address).

Formula:

Value = Byte1 × 28 + Byte2

Example:

If memory has:

Offset Value
0 0x04
1 0x01

Then:

Value = 0x04 × 28 + 0x01 = 1024 + 1 = 1025

✅ Little Endian

In Little Endian, the least significant byte (LSB) comes first (at the lower memory address).

Formula:

Value = Byte1 + Byte2 × 28

Example:

Same bytes, but stored in reverse:

Offset Value
0 0x01
1 0x04

Then:

Value = 0x01 + 0x04 × 28 = 1 + 1024 = 1025

📌 Key Differences:

Endian Memory Order (Byte0, Byte1) Formula
Big Endian MSB, LSB Byte0 × 256 + Byte1
Little Endian LSB, MSB Byte0 + Byte1 × 256

🧠 Why does Little Endian reverse it?

Because in Little Endian, the low byte is stored at the lowest address — it's a CPU-level design choice. Intel CPUs use Little Endian; some network protocols use Big Endian.
