Typed Arrays in JavaScript

What are Typed Arrays?

Typed Arrays are array-like objects in JavaScript designed for accessing and manipulating raw binary data. Unlike regular JavaScript arrays (which are dynamic and can hold any data type), Typed Arrays:

  • Store elements of a single, specified numeric type (e.g., 8-bit integers, 32-bit floating-point numbers).
  • Have a fixed size.
  • Are significantly more efficient for binary data (images, audio, video, network data).

Why Use Typed Arrays?

Traditional JavaScript arrays have overhead due to object-based elements. Typed Arrays offer:

  • Improved Performance: Faster read/write operations due to direct memory access (no boxing/unboxing).
  • Reduced Memory Consumption: No per-element overhead for type information.
  • Interoperability: Seamless integration with binary data from various sources (WebSockets, File API, WebGL, WebAssembly).

How to Work with Typed Arrays

Involves two primary components:

  • ArrayBuffer: A generic, fixed-length raw binary data buffer. Cannot be directly manipulated; it's a container for bytes.
  • Typed Array Views: Objects that provide a "view" into an ArrayBuffer, allowing data to be read/written in a specific format.

Creating an ArrayBuffer

Specify its length in bytes:

const buffer = new ArrayBuffer(16); // Creates a 16-byte buffer
console.log(buffer.byteLength); // Output: 16

Creating Typed Array Views

Constructors represent different data types:

  • Int8Array: 8-bit signed integers
  • Uint8Array: 8-bit unsigned integers
  • Int16Array: 16-bit signed integers
  • Uint16Array: 16-bit unsigned integers
  • Int32Array: 32-bit signed integers
  • Uint32Array: 32-bit unsigned integers
  • Float32Array: 32-bit floating-point numbers
  • Float64Array: 64-bit floating-point numbers (double-precision)
  • BigInt64Array: 64-bit signed big integers
  • BigUint64Array: 64-bit unsigned big integers
  • Uint8ClampedArray: 8-bit unsigned integers, clamping values to 0-255

Methods to create views:

  1. From an ArrayBuffer: 
    const buffer = new ArrayBuffer(16); // 16 bytes
const int32View = new Int32Array(buffer); // View of 4 32-bit integers
const uint8View = new Uint8Array(buffer);   // View of 16 8-bit unsigned integers
  2. With a specified length (creates its own ArrayBuffer): 
    const myUint8Array = new Uint8Array(8); // Creates an 8-byte buffer and a Uint8Array view
console.log(myUint8Array.byteLength); // Output: 8
console.log(myUint8Array.length);     // Output: 8 (number of elements)
  3. From another Typed Array or an iterable: 
    const sourceArray = new Uint8Array([1, 2, 3, 4]);
const newUint8Array = new Uint8Array(sourceArray); // Creates a new Uint8Array with the same values

const fromRegularArray = new Int16Array([10, 20, 30]);

Read and Write Operations

Use array-like syntax:

const buffer = new ArrayBuffer(16);
const int32View = new Int32Array(buffer); // 4 elements (16 bytes / 4 bytes per Int32)

// Write operations
int32View[0] = 10;
int32View[1] = 20;
int32View[2] = -30;
int32View[3] = 40;
console.log(int32View); // Output: Int32Array [ 10, 20, -30, 40 ]

// Read operations
console.log(int32View[0]); // Output: 10
console.log(int32View[2]); // Output: -30

// Multiple views on the same ArrayBuffer
const uint8View = new Uint8Array(buffer);
console.log(uint8View);
// Output depends on endianness. e.g., for int32View[0]=10, uint8View might show [10, 0, 0, 0, ...]

Important Note on Endianness:

Order of bytes in memory (Little-endian vs. Big-endian). JavaScript's Typed Arrays use the platform's native endianness. For guaranteed endianness (e.g., network protocols), use DataView.

  • Little-endian: Least significant byte (LSB) comes first.
  • Big-endian: Most significant byte (MSB) comes first.

Properties of Typed Arrays

All Typed Array objects inherit common properties from TypedArray.prototype:

buffer
Read-only. Returns the ArrayBuffer the Typed Array view references.
const myUint8Array = new Uint8Array(8);
console.log(myUint8Array.buffer); // Returns the underlying ArrayBuffer
byteLength
Read-only. Returns the length of the Typed Array in bytes (total bytes occupied by elements).
const myInt32Array = new Int32Array(4); // 4 elements * 4 bytes/element = 16 bytes
console.log(myInt32Array.byteLength); // Output: 16
byteOffset
Read-only. Returns the offset in bytes from the start of its ArrayBuffer where the view begins. Useful for views over a portion of a buffer.
const buffer = new ArrayBuffer(16);
const partialView = new Uint8Array(buffer, 4, 8); // View starting at byte offset 4, covering 8 bytes
console.log(partialView.byteOffset); // Output: 4
console.log(partialView.byteLength); // Output: 8
length
Read-only. Returns the number of elements in the Typed Array (not the byte length).
const myFloat32Array = new Float32Array(10); // 10 elements
console.log(myFloat32Array.length);     // Output: 10
console.log(myFloat32Array.byteLength); // Output: 40 (10 elements * 4 bytes/element)
BYTES_PER_ELEMENT
Static read-only property on the Typed Array constructor. Indicates the size in bytes of each element.
console.log(Int8Array.BYTES_PER_ELEMENT);   // Output: 1
console.log(Float32Array.BYTES_PER_ELEMENT); // Output: 4
constructor
A reference to the constructor function that created the instance.
const myArr = new Uint8Array(5);
console.log(myArr.constructor === Uint8Array); // Output: true

Key Typed Array Methods

Typed Arrays inherit many methods from Array.prototype (e.g., forEach(), map(), slice(), sort()). Key specific methods include:

  • set(array [, offset]): Writes contents of an array or another Typed Array into the current one. 
    const target = new Uint8Array(10);
const source = new Uint8Array([1, 2, 3]);
target.set(source, 2); // Copies source into target starting at index 2
console.log(target); // Uint8Array [ 0, 0, 1, 2, 3, 0, 0, 0, 0, 0 ]
  • subarray([begin [, end]]): Returns a new Typed Array view on the same ArrayBuffer for a specified range. 
    const original = new Uint8Array([10, 20, 30, 40, 50]);
const sub = original.subarray(1, 4); // Elements from index 1 to 3
console.log(sub); // Uint8Array [ 20, 30, 40 ]

// Modifying the subarray modifies the original buffer
sub[0] = 25;
console.log(original); // Uint8Array [ 10, 25, 30, 40, 50 ]

DataView for Granular Byte Control and Endianness

For reading/writing different data types at arbitrary byte offsets or controlling endianness explicitly, use DataView.

Provides methods like getUint8(), getInt16(), setFloat32(), etc., with optional endianness flags.

const buffer = new ArrayBuffer(8); // 8 bytes
const dataView = new DataView(buffer);

// Write a 32-bit integer at offset 0 (little-endian)
dataView.setInt32(0, 12345678, true); // true for little-endian

// Write a 16-bit float at offset 4 (big-endian)
dataView.setFloat32(4, 3.14, false); // false for big-endian (or omit)

console.log(dataView.getInt32(0, true)); // Read back with little-endian
console.log(dataView.getFloat32(4, false)); // Read back with big-endian

Use Cases for Typed Arrays

  • WebSockets and Network Communication (efficient binary data transfer)
  • File API (reading/writing binary file contents)
  • WebGL and Canvas API (pixel data manipulation)
  • WebAudio API (raw audio sample manipulation)
  • WebAssembly (Wasm) (data exchange between JS and Wasm)
  • Image Processing
  • Data Serialization/Deserialization

Summary: Typed Arrays are powerful for high-performance manipulation of raw binary data, bridging JavaScript's high-level nature with low-level data requirements.

Which Number System Does TypedArray Use?

Typed Arrays do not use a "number system" like decimal or hexadecimal for storage. Instead, they interpret raw binary data (sequences of 0s and 1s) within an ArrayBuffer based on their specified numeric type.

  • ArrayBuffer is Raw Binary: It's just a contiguous block of memory (bytes).
  • Typed Array Interprets the Binary: The Typed Array view (e.g., Int32Array) dictates how these binary sequences are read as numbers.
    • Integer Types: Use binary representation. Signed integers use two's complement.
    • Floating-Point Types: Use the IEEE 754 standard for floating-point representation.
    • BigInt Types: Also use binary representation and two's complement for signed BigInts, but with 64 bits.
const buffer = new ArrayBuffer(4); // 4 bytes
const int32View = new Int32Array(buffer);
int32View[0] = 10; // Stores decimal 10 as 32-bit binary (0000...00001010)

const uint8View = new Uint8Array(buffer);
console.log(uint8View); // On little-endian: Uint8Array [ 10, 0, 0, 0 ]

In essence: Typed Arrays store raw binary data, and the view defines how that binary data is interpreted as a numeric value according to standard binary encodings.

Properties of `ArrayBuffer`

These properties provide crucial information about the underlying raw binary data storage of an ArrayBuffer:

byteLength
Value (example): 4
Description: Read-only. The total length of the ArrayBuffer in bytes. Determines the allocated memory.
detached
Value (example): false
Description: Read-only boolean. Indicates if the ArrayBuffer's underlying memory has been released (e.g., after transfer via postMessage()). false means it's still accessible.
maxByteLength
Value (example): 4
Description: Read-only. The maximum size (in bytes) a resizable ArrayBuffer can grow to. If not resizable, it's equal to byteLength.
resizable
Value (example): false
Description: Read-only boolean. Indicates if the ArrayBuffer can be resized using ArrayBuffer.prototype.resize(). false means fixed size.

Example of Resizable ArrayBuffer:

// Create a resizable ArrayBuffer
const resizableBuffer = new ArrayBuffer(16, { maxByteLength: 32 });

console.log(resizableBuffer.byteLength);     // Output: 16
console.log(resizableBuffer.maxByteLength);  // Output: 32
console.log(resizableBuffer.resizable);      // Output: true

// Resize the buffer
resizableBuffer.resize(24);
console.log(resizableBuffer.byteLength);     // Output: 24

// Attempt to resize beyond maxByteLength will throw an error
try {
    resizableBuffer.resize(40);
} catch (e) {
    console.error(e); // RangeError: byteLength is out of range.
}

These properties offer a clear view of an ArrayBuffer's size, resize capabilities, and memory validity.
