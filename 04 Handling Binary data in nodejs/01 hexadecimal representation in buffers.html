Understanding Hexadecimal Representation in Buffers

const a = new ArrayBuffer(4);

console.log(a);

node main.js

ArrayBuffer { [Uint8Contents]: <00 00 00 00>, byteLength: 4 }

Is "00 00 00 00" Hexadecimal?

Yes, exactly! The sequence 00 00 00 00 (as seen in console outputs like ArrayBuffer { [Uint8Contents]: <00 00 00 00>, byteLength: 4 }) is indeed in hexadecimal (hex) notation.

Why is Memory Often Shown in Hex?

  • Compactness: 1 byte is represented by just 2 hex digits, which is much shorter than 8 binary digits.
  • Proximity to Machine Data: Hexadecimal is a base-16 system, making it a convenient bridge between human-readable numbers and the binary (base-2) data that computers use internally.
  • Readability: It's significantly easier for humans to read and parse long sequences of hex digits compared to binary.

Breakdown of Number Systems:

Format Binary Decimal
00 (Hex) 00000000 0
04 (Hex) 00000100 4
FF (Hex) 11111111 255

So, <00 00 00 00> means: 4 bytes, with each byte holding a value of 0.

Example: Hexadecimal in Action

const buf = new Uint8Array([65, 66, 67, 68]);
console.log(buf.buffer);

Will print something like:

ArrayBuffer { [Uint8Contents]: <41 42 43 44>, byteLength: 4 }

Because:

  • 65 (Decimal) = 0x41 (Hex) = 'A' (ASCII character)
  • 66 (Decimal) = 0x42 (Hex) = 'B'
  • 67 (Decimal) = 0x43 (Hex) = 'C'
  • 68 (Decimal) = 0x44 (Hex) = 'D'

Do Buffers Use Hex to Represent Binary?

Yes, absolutely! Buffers (like Node.js Buffer or JavaScript's ArrayBuffer when viewed) use hexadecimal to represent their underlying binary data in a more compact and human-readable form.

What's Really Happening:

  • Internally: Buffers store data as raw binary – a sequence of bits (0s and 1s). Each byte is 8 bits.
  • When Printed: When you display a buffer (e.g., using console.log()), environments like Node.js or browser developer tools show the contents in hexadecimal for readability.

Example: Raw Binary vs. Hex Output

const buf = Buffer.from([0, 1, 2, 255]); // Node.js Buffer example
console.log(buf);

Output:

<Buffer 00 01 02 ff>

Here, 00, 01, 02, ff are hexadecimal representations of the binary values:

  • 00 (Hex) → 00000000 (Binary)
  • 01 (Hex) → 00000001 (Binary)
  • FF (Hex) → 11111111 (Binary)

Why Hex and Not Binary for Display?

Format Example (1 Byte) Easier to Read? Compactness
Binary 11111111 ❌ Hard to scan long sequences Long
Hex FF ✅ Much easier to scan Compact (2 hex digits per byte)

Conclusion: Buffers store binary, but for human interaction (logs, debugging), they are formatted in hex for better readability.

How Buffers Represent Data in Node.js

Let's break down how Buffer objects (specific to Node.js, but the concept applies to ArrayBuffer views) handle data representation:

1. Internally: Stored as Binary

Buffers fundamentally store raw binary data — sequences of 0s and 1s in memory. Each element (byte) within a buffer consists of 8 bits. 

const buf = Buffer.from([65, 66, 67]);

Internally, this would be stored as:

  • 65 (Decimal) → 01000001 (Binary)
  • 66 (Decimal) → 01000010 (Binary)
  • 67 (Decimal) → 01000011 (Binary)

So, the buffer in memory holds: 01000001 01000010 01000011 (3 bytes of binary data).

2. When Printed: Represented in Hexadecimal

When you use console.log(buf);, Node.js displays the binary data using hexadecimal values: 

<Buffer 41 42 43>
  • 41 is hex for 65
  • 42 is hex for 66
  • 43 is hex for 67

You are seeing the binary data concisely represented in hexadecimal.

3. Can Be Interpreted Differently

The same underlying binary data in a buffer can be interpreted in various ways depending on the context or method used: 

const buf = Buffer.from([0x41, 0x42, 0x43]); // Initialize with hex values
console.log(buf.toString());      // 'ABC' (interpreted as UTF-8 characters)
console.log(buf.readUInt8(0));    // 65 (interpreted as an unsigned 8-bit integer)

The binary data can be interpreted as:

  • Characters: (e.g., UTF-8, ASCII)
  • Numbers: (e.g., integers, floats, big integers)
  • Raw Data: (e.g., for images, audio, or other file formats)

Real-World Use Cases of Buffers:

Scenario What's in the Buffer? Why Hex Output Helps
File Read (fs module) Raw file bytes Hex shows byte values clearly for debugging file formats.
TCP Socket Data Incoming binary packets Helps debug network protocols by inspecting raw packet data.
Image/PDF Parsing Raw image/PDF bytes Allows manual inspection of file headers and content structure.

Summary:

  • Buffers store data in their raw binary form (0s and 1s).
  • They are primarily displayed in hexadecimal for human readability and compactness.
  • The content of a buffer can be interpreted differently based on the data type or encoding it represents (text, numbers, media, etc.).
