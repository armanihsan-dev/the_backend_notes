🔁 1. Transfer — What It Really Means

In JavaScript (specifically during structured cloning or with Web Workers), transfer is not a method, but an option used to transfer ownership of certain data types like ArrayBuffer.

Instead of copying data (which is slow), JavaScript allows you to move the memory to another context — like from main thread to a Web Worker.

✅ Where You Can Use transfer

  • postMessage() (in Web Workers)
  • structuredClone() (in modern JavaScript)

📦 Syntax Example (structuredClone):


const buffer = new ArrayBuffer(4);
const clone = structuredClone(buffer, { transfer: [buffer] });

In this case:

  • The buffer is transferred.
  • The original buffer becomes detached (unusable).
  • clone gets full ownership of the memory.

❌ 2. Detached ArrayBuffer

A detached ArrayBuffer means:

  • Its memory has been moved elsewhere.
  • It has no data, no valid memory.
  • Any operation on it will fail.

🔍 Example:


const buffer = new ArrayBuffer(4);
const clone = structuredClone(buffer, { transfer: [buffer] });

console.log(buffer.byteLength); // 0 ✅ detached
console.log(clone.byteLength);  // 4 ✅ usable

❗ What Happens to Views (TypedArrays, DataView)?

If a TypedArray or DataView was viewing the transferred buffer, it now views nothing: 


const buffer = new ArrayBuffer(4);
const view = new Uint8Array(buffer);

structuredClone(buffer, { transfer: [buffer] });

console.log(view[0]); // ❌ Throws: "Cannot perform 'get' on a detached ArrayBuffer"

✅ Summary Table

Concept Meaning
transfer A way to move ownership of memory from one context to another (like a Web Worker), used with structuredClone() or postMessage()
Detached A state of an ArrayBuffer after it's transferred — its memory is invalid and all views on it are useless
