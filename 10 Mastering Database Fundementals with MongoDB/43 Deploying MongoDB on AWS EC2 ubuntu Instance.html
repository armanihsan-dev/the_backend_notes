That's a great, comprehensive goal! Deploying a MongoDB server on an AWS EC2 Ubuntu instance, configuring it for production use, and connecting to it from a Node.js application involves several distinct steps.

I'll break down the complete process, explaining every significant command-line interface (CLI) action.

Since this process involves many specific, up-to-date commands (especially for installation and firewall configuration), I must first verify the current best practices and stable versions. This guide covers the **deployment, security, configuration (Replication Set), data restoration, and Node.js connection** for your MongoDB server on an AWS EC2 Ubuntu instance.

The commands assume you are logged into your Ubuntu EC2 instance as a user with sudo privileges (e.g., **ubuntu** or **ec2-user**).

1. AWS EC2 Setup and Network Configuration 🌐

Before starting, ensure you've done the following in the AWS Console:

  • Launched an EC2 Instance: Use a recent Ubuntu Server AMI (e.g., 22.04 LTS).
  • Configured the Security Group (Firewall):
    • Inbound Rule 1 (SSH): Allow TCP on port 22 from your IP or 0.0.0.0/0 (for testing, but less secure).
    • Inbound Rule 2 (MongoDB): Allow TCP on port 27017 from your local machine's IP, your Node.js server's IP, or a secure range. Never expose port 27017 to the public Internet (0.0.0.0/0) without strong authentication.

2. MongoDB Installation on Ubuntu EC2 💾

This section installs the official MongoDB Community Edition packages.

Import the MongoDB Public GPG Key

Bash
wget -qO - https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg
Explanation:
  • wget -qO - ...: Downloads the MongoDB GPG public key (used to verify package authenticity) from the URL (-q for quiet, -O - to output to standard output).
  • |: Pipe the output of wget to the next command.
  • sudo gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg: De-armors the key (converts ASCII to binary GPG key format) and saves it as a keyring file.

Create the MongoDB Source List File

Bash
echo "deb [ arch=amd64,arm64 signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
Explanation:
  • echo "...": Prints the repository line for MongoDB 7.0 (for Ubuntu 22.04, codenamed "jammy") to standard output.
  • | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list: **Pipe** the output and write it to the new source list file, allowing sudo to write to a protected directory.

Install MongoDB Packages

Bash
sudo apt update
sudo apt install -y mongodb-org
Explanation:
  • sudo apt update: Refreshes the local package index to include the newly added MongoDB repository.
  • sudo apt install -y mongodb-org: Installs the mongodb-org meta-package, which includes the MongoDB server, shell (mongosh), and other tools. The -y confirms the installation.

Start and Enable MongoDB Service

Bash
sudo systemctl start mongod
sudo systemctl enable mongod
sudo systemctl status mongod
Explanation:
  • sudo systemctl start mongod: Starts the mongod background process (the MongoDB server).
  • sudo systemctl enable mongod: Configures MongoDB to automatically start upon system boot.
  • sudo systemctl status mongod: Checks the server's status (should show active (running)).

3. Data Restoration (mongorestore) ↩️

If you have a local MongoDB backup (usually a directory of BSON files), you need to get it onto the EC2 instance (e.g., using scp) and then restore it.

Transfer Backup to EC2 (Local Machine Command)

Run this from your local machine, assuming your backup is in a directory called dump/: 

Bash
scp -i /path/to/your-key.pem -r dump/ ubuntu@<EC2-Public-IP>:/home/ubuntu/
Explanation (Local Command):
  • scp: Secure Copy Protocol, used to securely copy files over SSH.
  • -i /path/to/your-key.pem: Specifies your private key file for authentication.
  • -r dump/: Recursively copies the dump/ directory (your backup).
  • ubuntu@<EC2-Public-IP>:/home/ubuntu/: The destination: user (ubuntu), host (EC2 IP), and path on the EC2.

Restore Data on EC2 (EC2 Command)

Run this on your EC2 Instance:

Bash
mongorestore --drop /home/ubuntu/dump/
Explanation:
  • mongorestore: The command-line utility for restoring a MongoDB dump.
  • --drop: Crucial flag. It drops the collections from the database **before** restoring the corresponding collections in the dump file. This ensures a clean restore.
  • /home/ubuntu/dump/: The path to the BSON data directory containing your databases and collections.

4. Enable Authentication and Remote Access (Security) 🔒

For production, you **must** enable authentication and configure external access.

A. Modify MongoDB Configuration File

Bash
sudo nano /etc/mongod.conf
Explanation:
  • sudo nano /etc/mongod.conf: Opens the main MongoDB configuration file for editing using the nano text editor.

In the file, find the net and security sections and modify them as follows:

Enable Remote Access (Binding IP): Change the bindIp setting to allow connections from all network interfaces, not just localhost. 

YAML
# /etc/mongod.conf
net:
  port: 27017
  bindIp: 0.0.0.0  # <== Change this from 127.0.0.1 to 0.0.0.0

Enable Authentication: Uncomment the security: section and add authorization: enabled. 

YAML
# /etc/mongod.conf
security:
  authorization: enabled # <== Uncomment and set to enabled

Save and close the file (Ctrl+O, then Enter, then Ctrl+X in nano).

B. Restart MongoDB Service

Bash
sudo systemctl restart mongod
Explanation:
  • sudo systemctl restart mongod: Restarts the MongoDB service to load the new configuration (bindIp: 0.0.0.0 and authorization: enabled).

C. Create an Admin User

Authentication is now **enabled**, so you must create a user to log in.

Access the Shell (without authentication, for the last time): 

Bash
mongosh

Switch to the admin database:

JavaScript
use admin
Explanation: The admin database is where administrative users are created and stored.

Create the Admin User:

JavaScript
db.createUser(
  {
    user: "adminUser",
    pwd: passwordPrompt(),
    roles: [
      { role: "userAdminAnyDatabase", db: "admin" },
      "readWriteAnyDatabase"
    ]
  }
)
Explanation:
  • db.createUser(...): Creates a new user in the current database (admin).
  • passwordPrompt(): Prompts for a password securely, instead of having it visible in the command history.
  • roles: Assigns roles. userAdminAnyDatabase allows the user to create other users. readWriteAnyDatabase allows CRUD operations on any database.

Exit the Shell:

JavaScript
exit

5. Enable Replication Set (Standalone Instance) ⚙️

You requested a replica set setup, which is essential for production but typically involves three or more EC2 instances. For a **single EC2 instance**, you can configure it as a **single-member replica set** to enable features like transactions, which require a replica set.

A. Modify Configuration for Replica Set

Bash
sudo nano /etc/mongod.conf

In the mongod.conf file, find the replication section and add/uncomment the replSetName: 

YAML
# /etc/mongod.conf

# ... other settings ...

# Listen to all IPs and ensure port is 27017 (already done)
net:
  port: 27017
  bindIp: 0.0.0.0

# Security (already done)
security:
  authorization: enabled

# Replication settings
replication:
  replSetName: rs0  # <== Add this line (replace rs0 with your name if desired)

Save and close the file.

B. Restart MongoDB Service (Again)

Bash
sudo systemctl restart mongod

C. Initialize the Replica Set

Connect to the Shell (with authentication):

Bash
mongosh -u adminUser -p --authenticationDatabase admin
Explanation:
  • -u adminUser: Connects using the user you just created.
  • -p: Prompts for the password.
  • --authenticationDatabase admin: Tells MongoDB to check the credentials against the admin database.

Initialize the Replica Set:

JavaScript
rs.initiate()
Explanation:
  • rs.initiate(): Initializes the replica set with the configuration defined in mongod.conf (i.e., replSetName: rs0). Since only one member is running, it will automatically configure itself as the **PRIMARY**.

Verify Status:

JavaScript
rs.status()
Explanation: Shows the status of the replica set. Look for "stateStr" : "PRIMARY".

Exit the Shell:

JavaScript
exit

6. Connecting from Node.js and Operations 💻

You are now ready to connect your Node.js application using the official **MongoDB Driver** or a library like **Mongoose**.

Node.js Project Setup (Local Machine)

  • Initialize your project: npm init -y
  • Install the Mongoose library: npm install mongoose

Connection Code (app.js)

Create a file named app.js with the connection string format for a replica set. Replace <EC2-Public-IP> and credentials. 

JavaScript
// app.js (on your local machine or Node.js server)

const mongoose = require('mongoose');

// !!! IMPORTANT: Replace placeholders below !!!
const DB_USER = 'adminUser';
const DB_PASS = 'YourStrongPassword'; // The password you set in step 4.C
const EC2_IP = '<EC2-Public-IP>'; // e.g., 54.123.45.67
const REPLICA_SET_NAME = 'rs0';

// The connection string for a replica set (even a single-member one)
const uri = `mongodb://${DB_USER}:${DB_PASS}@${EC2_IP}:27017/?authSource=admin&replicaSet=${REPLICA_SET_NAME}`;

async function run() {
  try {
    // 1. Connect to the Database
    await mongoose.connect(uri);
    console.log("✅ Successfully connected to MongoDB on AWS EC2!");

    // 2. Define a Schema and Model
    const userSchema = new mongoose.Schema({
      name: String,
      email: { type: String, unique: true }
    });
    const User = mongoose.model('User', userSchema);

    // 3. Operations: INSERT/CREATE
    const newUser = await User.create({ name: 'Alice Smith', email: 'alice@example.com' });
    console.log("➕ Inserted User:", newUser);

    // 4. Operations: READ/FIND
    const user = await User.findOne({ name: 'Alice Smith' });
    console.log("🔎 Found User:", user);

    // 5. Operations: UPDATE
    if (user) {
        user.name = 'Alice Johnson';
        await user.save();
        console.log("🔄 Updated User:", user);
    }
    
    // 6. Operations: DELETE
    await User.deleteOne({ name: 'Alice Johnson' });
    console.log("🗑️ Deleted User.");


  } catch (error) {
    console.error("❌ MongoDB Connection or Operation Error:", error);
  } finally {
    // Close the connection
    await mongoose.connection.close();
  }
}

run();

Run the Node.js Script

Bash
node app.js

Expected Output: A sequence of success messages confirming connection, insertion, retrieval, update, and deletion, demonstrating that your Node.js application has successfully performed CRUD operations against your secured, replica-set-configured MongoDB on AWS EC2.
