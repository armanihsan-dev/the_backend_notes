In **MongoDB's Schema Validation**, **validation action** and **validation level** are two distinct settings that determine how validation rules are enforced on a collection.

1. Validation Action (`validationAction`)

The **validation action** specifies **what MongoDB does** when a document fails the defined validation rules.

Value Description
error (Default) MongoDB **rejects** the insert or update operation and returns a validation error. The invalid document is **not** written to the collection. Use this for strict data integrity.
warn MongoDB **allows** the insert or update operation (the document is written), but it logs a **warning message** to the MongoDB log file. Use this for monitoring violations before strictly enforcing the rules.

2. Validation Level (`validationLevel`)

The **validation level** specifies **which documents** the validation rules apply to during an update operation, especially in collections that already contain existing documents.

Value Description
strict (Default) Validation rules are applied to **all** document inserts and updates. Any existing documents that do not meet the rules **cannot be updated** unless the update fixes the invalid parts of the document.
moderate Validation rules are applied to all inserts, but for updates, they are **only applied to documents that already satisfy the validation rules**. Existing documents that were invalid before the validation was set up (or became invalid due to a rule change) can still be updated as long as the update doesn't violate the rules that the document was already following.
off Schema validation is **disabled** for the collection.

The Distinction is:

  • **Action** answers the question: "If a document is invalid, what is the consequence?" (**Reject** or **Log a warning**)
  • **Level** answers the question: "Which documents should be checked against the rules?" (**All writes**, or just **inserts and updates to already valid documents**)
