MongoDB Upsert

Upsert in MongoDB is an option that tells an update operation to insert a new document if no documents match the query criteria. It's a combination of "update" and "insert."

When you perform an update operation in MongoDB using the Node.js driver, you typically pass three arguments: the query, the update document, and the options. Setting the upsert: true option is what enables this behavior.

1. How the Upsert Logic Works 🤔

When you execute an update operation with upsert: true, MongoDB follows a simple conditional logic:

  • Find a Match? MongoDB first executes the query you provided to see if any documents meet the criteria.
  • Yes (Match Found) → UPDATE: The update operation is performed on the matching document(s) as normal.
  • No (No Match) → INSERT: A new document is created and inserted into the collection. This new document is a combination of the query criteria and the update document.

2. Node.js Implementation with updateOne()

The most common way to use upsert is with the updateOne() method.

A. The Syntax

// 1. Query: Specifies the document to search for.
const query = { _id: 100 }; 

// 2. Update: Specifies the changes to make, typically using update operators like $set or $inc.
const updateDocument = {
  $set: { name: "New Product", price: 50.00 },
  $inc: { version: 1 } // Used for updates, ignored on insert.
};

// 3. Options: The crucial part is setting 'upsert' to true.
const options = { upsert: true }; 

try {
  const result = await collection.updateOne(query, updateDocument, options);
  
  // The 'result' object tells you exactly what happened.
  if (result.upsertedCount > 0) {
    console.log(`Document inserted with _id: ${result.upsertedId.id}`);
  } else if (result.modifiedCount > 0) {
    console.log(`${result.modifiedCount} document(s) updated.`);
  } else {
    console.log("No change (document was found but content was the same).");
  }

} catch (error) {
  console.error("Upsert failed:", error);
}

B. Scenario 1: Document Exists (Update) 🔄

Assume the collection contains:

{ "_id": 100, "name": "Old Product", "price": 40.00 }

Using the code above:

  • Query Match: The document is found.
  • Result: The document is updated according to the $set and $inc operators.

The document becomes:

{ "_id": 100, "name": "New Product", "price": 50.00, "version": 1 }

C. Scenario 2: Document Does Not Exist (Insert) ➕

Assume the collection does not contain a document with _id: 100.

  • Query Match: No document is found.
  • Result: A new document is inserted. The inserted document is constructed using the fields in the query and the fields in the update document.

The newly inserted document becomes:

{ 
  "_id": 100,             // from the query
  "name": "New Product",  // from the $set in the update
  "price": 50.00          // from the $set in the update
  // The $inc operator is ignored for the initial insert.
}

3. Important Considerations for Upsert

Consideration Explanation
$setOnInsert Operator This is highly useful for upsert. It specifies fields that should only be set if an insert occurs, and are ignored during an update.
Insert Document Structure The final document created by an upsert operation is a mix of the query fields and the update fields. If you use a field in the query (like _id), you don't need to specify it in the $set for the insert.
Atomicity An upsert operation is atomic. This means the search for a document and the subsequent update or insert happens as a single operation, preventing race conditions where two clients might try to insert the same document simultaneously.
updateMany() and Upsert While you can set upsert: true on updateMany(), this is rarely done. It will only ever create a single new document if zero matches are found. If one or more matches are found, it performs the update on all matches.

Example with $setOnInsert

You want to update a document's content, but if it's new, you also want to track the initial creation date.

const query = { email: "user@example.com" };
const updateDocument = {
  $set: { lastActive: new Date() },
  $setOnInsert: { createdAt: new Date(), role: "basic" } // Only runs on INSERT
};
await collection.updateOne(query, updateDocument, { upsert: true });

If inserted:

{ 
  "email": "user@example.com", 
  "lastActive": ISODate("..."), 
  "createdAt": ISODate("..."), 
  "role": "basic" 
}

If updated (existing document):

{ 
  "email": "user@example.com", 
  "lastActive": ISODate("..."), 
  // 'createdAt' and 'role' are untouched
  "role": "basic" 
}
