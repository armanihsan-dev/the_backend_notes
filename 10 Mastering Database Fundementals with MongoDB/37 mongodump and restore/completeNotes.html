Let me teach you everything about mongodump and mongorestore with clear explanations and practical examples.

1. What are mongodump and mongorestore?

mongodump

  • Definition: mongodump is a command-line utility that creates a **binary export (backup)** of the contents of a MongoDB database. It reads data from a MongoDB instance and writes **BSON (Binary JSON) files** to disk.
  • Key Features:
    • Creates complete database backups
    • Preserves indexes, collections, and documents
    • Can backup specific databases or collections
    • Supports compression (gzip)
    • Works with local and remote MongoDB servers

mongorestore

  • Definition: mongorestore is a command-line utility that **restores data** from backups created by mongodump. It reads BSON files and imports them into a MongoDB instance.
  • Key Features:
    • Restores complete or partial backups
    • Can restore to different databases
    • Supports selective collection restoration
    • Works with compressed backups

3. Creating Backups with mongodump

Basic Syntax:

bashmongodump --host=<hostname> --port=<port> --db=<database> --collection=<collection> --out=<output-directory> --username=<user> --password=<password> --authenticationDatabase=<auth-db>

Practical Examples:

Example 1: Backup ALL Databases (Local Server)

bashmongodump --out=/backup/mongodb_backup
Explanation:
  • Connects to localhost:27017 (default)
  • Backs up **all** databases
  • Saves to /backup/mongodb_backup directory
  • Creates subdirectories for each database

Result Structure:

/backup/mongodb_backup/
├── admin/
│   ├── system.version.bson
│   └── system.version.metadata.json
├── myDatabase/
│   ├── users.bson
│   ├── users.metadata.json
│   ├── products.bson
│   └── products.metadata.json
└── config/

Example 2: Backup a Specific Database

bashmongodump --db=myDatabase --out=/backup/mydb_backup
Explanation:
  • --db=myDatabase: Only backs up **"myDatabase"**
  • Creates folder structure: /backup/mydb_backup/myDatabase/

Example 3: Backup a Specific Collection

bashmongodump --db=myDatabase --collection=users --out=/backup/users_backup
Explanation:
  • Backs up only the **"users" collection** from "myDatabase"

Example 4: Backup with Authentication

bashmongodump --host=localhost --port=27017 --username=admin --password=secretPass --authenticationDatabase=admin --db=myDatabase --out=/backup/secure_backup
Explanation:
  • --username and --password: Credentials
  • --authenticationDatabase=admin: Where user credentials are stored

Example 5: Backup with Compression (gzip)

bashmongodump --db=myDatabase --archive=/backup/mydb.archive.gz --gzip
Explanation:
  • --archive: Creates a **single archive file** instead of directory structure
  • --gzip: **Compresses** the backup (reduces size by 70-90%)
  • Output: Single file mydb.archive.gz

Without --archive (directory with gzip):

bashmongodump --db=myDatabase --out=/backup/mydb_gzip --gzip
Creates directory with .gz compressed BSON files.

4. Running MongoDB Server on Different Port

Why?

  • To restore backups to a test server without affecting production.

Method 1: Start New mongod Instance

bash# Create data directory
mkdir -p /data/testdb

# Start MongoDB on port 27018
mongod --port 27018 --dbpath=/data/testdb --logpath=/var/log/mongodb_test.log --fork
Explanation:
  • --port 27018: Custom port
  • --dbpath: Separate data directory
  • --logpath: Log file location
  • --fork: Run as background process (Linux/Mac)

For Windows (no --fork):

bashmongod --port 27018 --dbpath=C:\data\testdb --logpath=C:\logs\mongodb_test.log
Run this in a separate command prompt window.

Method 2: Using Configuration File

Create mongod_test.conf:

yamlstorage:
  dbPath: /data/testdb
net:
  port: 27018
  bindIp: 127.0.0.1
systemLog:
  destination: file
  path: /var/log/mongodb_test.log

Start with config:

bashmongod --config mongod_test.conf

Verify the Server is Running:

bash# Check if port is listening
netstat -an | grep 27018

# Or connect using mongosh
mongosh --port 27018

5. Restoring Backups with mongorestore

Basic Syntax:

bashmongorestore --host=<hostname> --port=<port> --db=<target-database> --drop <backup-directory>

Practical Examples:

Example 1: Restore ALL Databases

bashmongorestore --drop /backup/mongodb_backup
Explanation:
  • --drop: **Drops existing collections** before restoring (prevents duplicates)
  • Restores all databases from backup directory

Example 2: Restore to Different Port Server

bashmongorestore --host=localhost --port=27018 --drop /backup/mongodb_backup
Explanation:
  • Restores to MongoDB instance running on port 27018
  • Useful for testing backups

Example 3: Restore Single Database

bashmongorestore --db=myDatabase --drop /backup/mongodb_backup/myDatabase
Explanation:
  • Restores only **"myDatabase"**
  • Must specify the database folder path

Example 4: Restore Single Database to Different Name

bashmongorestore --host=localhost --port=27018 --db=myDatabase_test /backup/mongodb_backup/myDatabase
Explanation:
  • Restores **"myDatabase"** backup as **"myDatabase\_test"**
  • Original: /backup/mongodb_backup/myDatabase
  • Target: myDatabase_test on port 27018 server

Example 5: Restore Single Collection

bashmongorestore --db=myDatabase --collection=users /backup/mongodb_backup/myDatabase/users.bson
Explanation:
  • Restores only **"users"** collection
  • Must specify the .bson file path

Example 6: Restore from Compressed Archive

bashmongorestore --gzip --archive=/backup/mydb.archive.gz --drop
Explanation:
  • --gzip: Indicates backup is compressed
  • --archive: Specifies archive file
  • Restores to default server (localhost:27017)

Example 7: Restore Compressed Archive to Different Database

bashmongorestore --host=localhost --port=27018 --nsFrom="myDatabase.*" --nsTo="myDatabase_restored.*" --gzip --archive=/backup/mydb.archive.gz
Explanation:
  • --nsFrom: Source namespace pattern
  • --nsTo: Target namespace pattern
  • Renames database during restore

6. Remote Server Backup (Deployed MongoDB)

Scenario: MongoDB is running on a remote server (cloud, VPS, etc.)

Method 1: Direct Connection (If accessible)

Example: Backup from Remote Server

bashmongodump --host=remote.server.com --port=27017 --username=dbAdmin --password=securePass123 --authenticationDatabase=admin --db=productionDB --out=/local/backup/remote_backup --gzip
Explanation:
  • --host=remote.server.com: Remote server address (IP or domain)
  • Backup is saved **locally** on your machine
  • Use strong credentials

Example: With Connection String (MongoDB Atlas)

bashmongodump --uri="mongodb+srv://username:password@cluster0.mongodb.net/myDatabase" --out=/backup/atlas_backup --gzip
Explanation:
  • --uri: Complete connection string (includes host, auth, SSL)
  • Works with MongoDB Atlas and other cloud providers

Method 2: SSH into Remote Server

bash# Step 1: SSH into remote server
ssh user@remote.server.com

# Step 2: Run mongodump on remote server
mongodump --db=productionDB --out=/tmp/remote_backup --gzip

# Step 3: Download backup to local machine
exit # Exit SSH
scp -r user@remote.server.com:/tmp/remote_backup /local/backup/

# Step 4: Clean up remote backup (optional)
ssh user@remote.server.com "rm -rf /tmp/remote_backup"

Method 3: Automated Remote Backup Script

Create remote_backup.sh:

bash#!/bin/bash
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/backup/mongodb_${TIMESTAMP}"

# Remote MongoDB details
REMOTE_HOST="remote.server.com"
REMOTE_PORT="27017"
DB_NAME="productionDB"
USERNAME="dbAdmin"
PASSWORD="securePass123"

# Create backup
mongodump \
  --host=$REMOTE_HOST \
  --port=$REMOTE_PORT \
  --username=$USERNAME \
  --password=$PASSWORD \
  --authenticationDatabase=admin \
  --db=$DB_NAME \
  --archive=${BACKUP_DIR}.gz \
  --gzip

# Verify backup
if [ $? -eq 0 ]; then
    echo "Backup successful: ${BACKUP_DIR}.gz"
else
    echo "Backup failed!"
    exit 1
fi

# Optional: Delete backups older than 7 days
find /backup -name "mongodb_*.gz" -mtime +7 -delete

Make executable and run:

bashchmod +x remote_backup.sh
./remote_backup.sh

7. Different Backup Formats

Format Comparison:

Format Extension Compression Use Case
BSON .bson None Standard format, fast
BSON + gzip .bson.gz High Space-efficient, directory structure
Archive .archive None Single file, all databases
Archive + gzip .archive.gz High Best for storage/transfer

Practical Examples:

1. Standard BSON (No Compression)

bashmongodump --db=myDatabase --out=/backup/bson_backup

Output:

/backup/bson_backup/myDatabase/
├── users.bson            (10 MB)
├── users.metadata.json
├── products.bson         (25 MB)
└── products.metadata.json
  • Pros: Fast backup/restore
  • Cons: Large file sizes

2. BSON with gzip Compression

bashmongodump --db=myDatabase --out=/backup/gzip_backup --gzip

Output:

/backup/gzip_backup/myDatabase/
├── users.bson.gz            (2 MB - 80% smaller)
├── users.metadata.json.gz
├── products.bson.gz         (5 MB - 80% smaller)
└── products.metadata.json.gz
  • Pros: 70-90% size reduction
  • Cons: Slightly slower

Restore:

bashmongorestore --gzip --drop /backup/gzip_backup

3. Archive Format (Single File)

bashmongodump --db=myDatabase --archive=/backup/mydb.archive

Output:

/backup/mydb.archive  (35 MB - single file)
  • Pros: Single file, easy to manage
  • Cons: No compression

Restore:

bashmongorestore --archive=/backup/mydb.archive --drop

4. Compressed Archive (Best for Storage)

bashmongodump --db=myDatabase --archive=/backup/mydb.archive.gz --gzip

Output:

/backup/mydb.archive.gz  (7 MB - single compressed file)
  • Pros: Maximum compression, single file
  • Cons: None (recommended for production)

Restore:

bashmongorestore --gzip --archive=/backup/mydb.archive.gz --drop

5. Archive to stdout (Stream to another process)

# Backup and upload to cloud

bashmongodump --archive --gzip | aws s3 cp - s3://my-bucket/backup.gz

# Backup and transfer to another server

bashmongodump --archive --gzip | ssh user@remote "cat > /backup/db.gz"

8. Complete Real-World Workflow

Scenario: Backup production database, test on separate server, restore to production

bash# Step 1: Backup production database with compression
mongodump \
  --host=production.server.com \
  --port=27017 \
  --username=admin \
  --password=prodPass \
  --authenticationDatabase=admin \
  --db=productionDB \
  --archive=/backup/prod_$(date +%Y%m%d).gz \
  --gzip

# Step 2: Start test MongoDB server on different port
mongod --port 27018 --dbpath=/data/testdb --fork --logpath=/var/log/test.log

# Step 3: Restore to test server
mongorestore \
  --host=localhost \
  --port=27018 \
  --gzip \
  --archive=/backup/prod_$(date +%Y%m%d).gz \
  --drop

# Step 4: Verify test database
mongosh --port 27018 --eval "db.getMongo().getDBNames()"

# Step 5: If tests pass, restore to production (if needed)
mongorestore \
  --host=production.server.com \
  --port=27017 \
  --username=admin \
  --password=prodPass \
  --authenticationDatabase=admin \
  --gzip \
  --archive=/backup/prod_$(date +%Y%m%d).gz \
  --drop

# Step 6: Shutdown test server
mongod --port 27018 --shutdown

9. Important Options Reference

mongodump Options:

bash--host              # MongoDB server address
--port              # Port number (default: 27017)
--db                # Specific database to backup
--collection        # Specific collection to backup
--out                # Output directory path
--archive           # Output to single archive file
--gzip              # Compress output
--username          # Authentication username
--password          # Authentication password
--authenticationDatabase # Auth database (usually 'admin')
--uri                # Complete connection string
--query              # Backup documents matching query
--excludeCollection # Skip specific collections

mongorestore Options:

bash--host              # Target MongoDB server
--port              # Target port number
--db                # Target database name
--drop              # Drop collections before restoring
--gzip              # Input is gzipped
--archive           # Restore from archive file
--nsFrom            # Source namespace (for renaming)
--nsTo              # Target namespace (for renaming)
--nsInclude         # Only restore matching namespaces
--nsExclude         # Skip matching namespaces

10. Best Practices

  • Always use --gzip for production backups (saves 70-90% space)
  • Use --archive for simpler file management
  • Add **timestamps** to backup filenames
  • **Test restores** regularly on test servers
  • **Automate backups** with cron jobs or scheduled tasks
  • Store backups in **multiple locations** (local + cloud)
  • Use --drop **carefully** in production
  • **Encrypt sensitive backups** before storing
