MongoDB Fundamentals

💾 MongoDB Fundamental Hierarchy

The terms fit into a hierarchy, from the largest and most encompassing to the smallest unit of data:

Database Server (or MongoDB Instance/Daemon): The running process or software application on a computer that manages all the databases. It's the engine.
Analogy: The library building itself.
Database: A container for collections. A single server can host multiple, separate databases.
Analogy: A specific section of the library (e.g., the Science Fiction section).
Collection: A grouping of MongoDB documents. It's the rough equivalent of a **table** in a relational database. It doesn't enforce a fixed schema (structure) for its documents.
Analogy: A shelf within the section, holding related books.
Document: The fundamental unit of data in MongoDB. It's a set of key-value pairs (stored in BSON format, which is like a binary version of JSON). It's the rough equivalent of a **row** in a relational database.
Analogy: A single book on the shelf.

💻 Related MongoDB Terminal Commands

You'll use the **mongosh** interactive shell to interact with the MongoDB server and its data.

1. Database Server (Instance)

This is the software running in the background. You typically interact with it by connecting to it.

Action Command Explanation
Start Server `mongod` Starts the MongoDB daemon (server process). You'd usually run this in a separate terminal or as a service.
Connect `mongosh` Opens the interactive shell, connecting to the running server (usually on the default port 27017).
Check Status `db.hostInfo()` While connected in mongosh, this provides information about the server.

2. Database

You must first select or create a database to work with collections and documents.

Action Command Explanation
Show Databases `show dbs` Lists all databases on the server.
Select/Create DB `use myNewDatabase` Switches context to myNewDatabase. If it doesn't exist, MongoDB will create it implicitly the first time you insert data into a collection within it.
Check Current DB `db` Shows the name of the database you are currently using.
Drop Database `db.dropDatabase()` Permanently deletes the current database. Use with caution!

3. Collection

Collections reside inside a database and hold your documents.

Action Command Explanation
Show Collections `show collections` Lists all collections in the current database.
Create Collection `db.createCollection("users")` Explicitly creates a collection named "users". (Usually, collections are created implicitly upon the first document insert.)
Drop Collection `db.users.drop()` Permanently deletes the "users" collection from the current database.

4. Document

Documents are the actual data units inserted into collections.

Action Command Explanation
Insert Document `db.users.insertOne({ name: "Alice", age: 30 })` Inserts a single document into the users collection.
Find Documents `db.users.find()` Retrieves all documents from the users collection.
Find with Filter `db.users.find({ age: { $gte: 25 } })` Retrieves documents where the age field is greater than or equal to 25.
Update Document `db.users.updateOne( { name: "Alice" }, { $set: { age: 31 } } )` Finds the document with name: "Alice" and changes her age to 31.
Delete Document `db.users.deleteOne({ name: "Alice" })` Deletes a single document matching the filter.
