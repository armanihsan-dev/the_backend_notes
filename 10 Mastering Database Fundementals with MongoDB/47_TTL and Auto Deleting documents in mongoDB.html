TTL (Time-To-Live) Indexes in MongoDB & Mongoose

TTL (Time-To-Live) indexes are a powerful and easy way to automatically delete documents from a MongoDB collection after a specified duration. This is perfect for time-sensitive data like user sessions, log data, or temporary caches.

🕰️ TTL Index Definition

A TTL index is a special, single-field index in MongoDB that allows you to automatically remove documents from a collection after a certain number of seconds has passed since the document's date field value.

  • Requirement: The indexed field must be of the BSON date type (Date in Mongoose/Node.js).
  • Mechanism: It uses the value of the indexed date field in the document plus the configured expiration time (expireAfterSeconds) to determine the document's "death time."

💻 Mongoose/Node.js Implementation

In Mongoose, you define a TTL index directly in your schema definition using the expires property on a Date type field.

Clear Syntax (Mongoose Schema)

JavaScript
const mongoose = require('mongoose');
const mySchema = new mongoose.Schema({
    // The date field that the TTL index will monitor
    createdAt: {
        type: Date,
        default: Date.now, // Set the creation time automatically
        expires: 3600      // The TTL in seconds (1 hour = 3600 seconds)
    },
    data: String,
    // other fields...
});
const MyModel = mongoose.model('MyModel', mySchema);
  • type: Date: Specifies the field is a date type, which is mandatory for a TTL index.
  • default: Date.now: Ensures the date field is automatically set to the current time when a document is created.
  • expires: <seconds>: This is the Mongoose-specific way to apply the TTL index. It corresponds to the MongoDB index option expireAfterSeconds. The value must be the lifespan of the document in seconds. You can also use a string like '1h', '1d', etc., and Mongoose will convert it to seconds.

Complete Example (Node.js)

Here's a complete, minimal example of using Mongoose in a Node.js environment:

JavaScript
const mongoose = require('mongoose');
// 1. Define the Schema with the TTL Index
const SessionSchema = new mongoose.Schema({
    // TTL is set to 60 seconds for quick testing (1 minute)
    // The document will be deleted 60 seconds after the time in 'createdAt'
    createdAt: {
        type: Date,
        default: Date.now,
        expires: 60 // 60 seconds
    },
    userId: String,
    sessionToken: String,
}, { timestamps: false }); // timestamps:false to avoid conflict/confusion with the custom createdAt

const Session = mongoose.model('Session', SessionSchema);

// 2. MongoDB Connection and Test Function
async function runTTLTest() {
    try {
        await mongoose.connect('mongodb://localhost:27017/ttlDemoDB');
        console.log('MongoDB connected.');

        // 3. Create a Document
        const newSession = await Session.create({
            userId: 'user123',
            sessionToken: 'abcd-efgh-ijkl',
        });
        console.log(`\nDocument inserted: ${newSession._id}`);
        console.log('Expiration time is approximately 60 seconds after the current time.');

        // 4. Wait for the TTL to expire (give it a little extra time)
        console.log('Waiting for documents to expire (1.5 minutes)...');
        await new Promise(resolve => setTimeout(resolve, 90000)); // Wait 90 seconds (1.5 min)

        // 5. Check if the Document Still Exists
        const expiredDocument = await Session.findById(newSession._id);

        if (!expiredDocument) {
            console.log('\n✅ Success: Document was automatically deleted by the TTL index.');
        } else {
            console.log('\n❌ Failure: Document still exists. There might be a slight delay.');
        }

    } catch (error) {
        console.error('An error occurred:', error);
    } finally {
        await mongoose.disconnect();
    }
}

// runTTLTest(); // Uncomment to run the test

⚙️ How TTL Indexes Work Behind the Scenes

The automatic deletion process is managed by a dedicated background thread within the MongoDB server (mongod) process.

1. The TTL Monitor Background Thread

  • Periodicity: A special background thread, called the TTL Monitor, runs approximately every 60 seconds on the primary replica set member (or standalone server).
  • Purpose: The monitor's sole job is to check all collections that have a TTL index for expired documents.

2. Identifying Expired Documents

  • The TTL Monitor queries the collection's TTL index to find documents whose indexed date field value plus the expireAfterSeconds value is less than the current time.
  • Expiration Threshold: document.dateField + expireAfterSeconds < CurrentTime
  • Because the TTL index is ordered by the date field, the monitor can efficiently find all candidates for deletion without scanning the entire collection.

3. Deletion Process

  • The monitor issues delete operations for the expired documents it finds. These deletes are foreground operations, just like a standard db.collection.deleteMany() command.
  • Throttling: To prevent the cleanup process from consuming too many resources and impacting the main database workload, the monitor has built-in limits. For each TTL index, it will delete documents until one of these conditions is met:
    • It has deleted 50,000 documents.
    • It has spent one second deleting documents.
    • All expired documents from that index are deleted.

⚠️ Important Note on Deletion Timing

The TTL index does not guarantee immediate deletion upon expiration. Since the monitor thread only runs every 60 seconds, a document that expires might remain in the collection for up to 60 seconds after its calculated expiration time, until the next time the background thread runs and performs the cleanup.
