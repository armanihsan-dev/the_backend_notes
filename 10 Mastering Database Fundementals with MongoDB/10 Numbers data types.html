The core concept is that MongoDB stores numbers using the **BSON (Binary JSON)** data format, which has specific types for different numerical representations.

1. Primary Number Data Types in MongoDB (BSON)

MongoDB handles numbers using three primary types to balance precision and performance:

A. Double (Decimal)

  • BSON Type: 1
  • Description: This is the default and most common way to store floating-point numbers (numbers with a decimal point). It's a standard **64-bit IEEE 754** floating-point format.
  • Use Case: Storing prices, latitude/longitude coordinates, percentages, or any value that requires decimal precision.
  • Example (Shell):

    JavaScript

    { "price": 49.99, "latitude": -12.0464 } // Stored as Double

B. Integer (Int32)

  • BSON Type: 16
  • Size/Range: **32-bit signed integer**. It can store whole numbers from −2,147,483,648 to 2,147,483,647.
  • Use Case: Storing counts, quantities, or small ID numbers that fit within the 32-bit limit. It uses less memory than an Int64.
  • Example (Shell):

    JavaScript

    { "count": 15000, "user_id": 1001 } // Stored as Int32

C. Long (Int64)

  • BSON Type: 18
  • Size/Range: **64-bit signed integer**. It can store a much larger range of whole numbers, from −9,223,372,036,854,775,808 to 9,223,372,036,854,775,807.
  • Use Case: Storing large quantities, timestamps (like milliseconds since epoch), or large ID numbers that exceed the Int32 limit.
  • Example (Shell):

    JavaScript

    { "timestamp_ms": 1678886400000000, "large_count": 3000000000 } // Stored as Int64

2. Special Number Data Type: Decimal128

Decimal128 (High-Precision Decimals)

  • BSON Type: 19
  • Description: This **128-bit decimal format** is essential for **financial and monetary data**. It uses a decimal representation, which means it avoids the potential rounding errors of standard 64-bit doubles when dealing with precise decimal arithmetic.
  • Use Case: Storing currency, tax rates, or any value where exact decimal representation is mandatory.
  • Example (Shell):

    JavaScript

    // Use the Decimal128() constructor in the shell
{ "balance": Decimal128("99.99"), "tax_rate": Decimal128("0.075") }

3. How to Handle Different Number Types

The way MongoDB handles the number type depends on the value and the driver you are using.

A. Automatic Handling (The Int32 vs Double Issue)

When you insert a simple number into the MongoDB shell or most programming language drivers:

  • If it's a whole number within the Int32 range, it is usually stored as a **32-bit Integer**.
  • If it includes a decimal point (e.g., 10.0 or 10.1), it is stored as a **Double**.

This automatic casting can sometimes lead to issues if you insert a number like 2,200,000,000 (which is larger than 2.147 billion):

  • The MongoDB shell will automatically store it as a **64-bit Double** (if a driver doesn't force a type), **potentially losing precision** if you later try to use it for exact integer math.

B. Explicit Handling (The Recommended Approach)

To ensure your data is stored as the intended type, especially for Int64 or Decimal128, you should **explicitly cast** the value:

Target Type Shell/Driver Method Purpose
Int64 NumberLong(value) For large integers or timestamps.
Decimal128 Decimal128("value") For high-precision currency and financial data.

Example of Explicit Int64:

JavaScript

// This ensures it's stored as a 64-bit integer, not a Double
db.sales.insertOne({ "order_id": 999999999999, "value": NumberLong("999999999999") })

C. Handling in Different Programming Languages

Language Default Integer Type How to Force Int64
Python int (arbitrary precision) Use the driver's Int64 object (e.g., bson.Int64(value))
JavaScript/Node.js number (float) Use BigInt or a Long BSON type wrapper (due to JavaScript's 53-bit safe integer limit).
Java int Use the driver's Long class for 64-bit numbers.

The key takeaway is to use the **Int64** or **Decimal128** types whenever the value exceeds the **Int32** limit or requires guaranteed decimal precision.
