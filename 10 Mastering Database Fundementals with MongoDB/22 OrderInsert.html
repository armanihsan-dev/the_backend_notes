Ordered Insert in MongoDB with Node.js

Ordered insert in MongoDB, typically using the collection.insertMany() method in Node.js, ensures that documents are processed and inserted in the exact order they appear in the input array. The key characteristic is that the operation will stop immediately if an error occurs while inserting any document.

1. What is an Ordered Insert?

An ordered insert is the default behavior for the insertMany() and bulkWrite() methods in MongoDB.

  • Execution Order: Documents are inserted one by one, serially, in the sequence they are provided in the array.
  • Error Handling (Crucial): If an error occurs during the insertion of a document (e.g., a duplicate _id violation or a schema validation error), the entire batch operation is aborted. Any documents after the failing document in the array will not be inserted. Documents before the failing one will have already been successfully inserted.
  • Performance: Generally slower than unordered inserts, especially in a sharded cluster, because each operation must wait for the previous one to complete before starting.

2. Node.js Implementation with insertMany()

The insertMany() method in the official MongoDB Node.js driver accepts an array of documents and an optional options object. Since ordered is the default, you often don't need to specify any options.

A. Syntax (Default - Ordered is true)

In the Node.js driver, you call insertMany() on your collection object.

const documents = [
  { _id: 1, item: "A" },
  { _id: 2, item: "B" },
  { _id: 3, item: "C" }
];
// Ordered is the default behavior, so no options are needed, 
// but you can explicitly set it to true.
const options = { ordered: true }; 

try {
  const result = await collection.insertMany(documents, options);
  console.log(`${result.insertedCount} documents inserted successfully.`);
} catch (error) {
  // Catches the error and aborts the entire batch
  console.error("Ordered insert failed:", error);
  // Documents before the error were inserted.
}

B. Example Scenario (Ordered)

Assume the collection already contains a document with _id: 2.

const documents = [
  { _id: 1, name: "First" },     // Document 1: Success
  { _id: 2, name: "Duplicate" }, // Document 2: Fails (Duplicate Key Error)
  { _id: 3, name: "Third" }      // Document 3: NOT attempted
];

try {
  await collection.insertMany(documents, { ordered: true });
} catch (error) {
  // A BulkWriteError is thrown
  console.log("Error caught. Documents not inserted after the duplicate."); 
}

Result in Database:

  • { _id: 1, name: "First" } is inserted.
  • { _id: 2, name: "Duplicate" } fails, and the operation stops.
  • { _id: 3, name: "Third" } is not inserted.

3. Comparison to Unordered Insert

An ordered insert is best understood in contrast to its alternative: unordered insert.

Feature Ordered Insert (ordered: true, default) Unordered Insert (ordered: false)
Execution Serially (one after another). In parallel (can be reordered by the server).
Error Handling Stops at the first error. Continues processing remaining documents after an error.
Atomicity Provides a checkpoint. Data integrity is maintained up to the point of failure. Sacrifices strict ordering for higher throughput.
Performance Slower (waits for each to complete). Faster (can run operations concurrently).

Unordered Example (for Contrast)

If you ran the same documents with ordered: false:

const documents = [
  { _id: 1, name: "First" },     
  { _id: 2, name: "Duplicate" }, // Document 2: Fails (Duplicate Key Error)
  { _id: 3, name: "Third" }      
];

try {
  await collection.insertMany(documents, { ordered: false });
} catch (error) {
  // A BulkWriteError is still thrown, but with an array of all errors.
  console.log("Error caught. The batch is finished, but some documents failed."); 
}

Result in Database (Unordered):

  • { _id: 1, name: "First" } is inserted.
  • { _id: 2, name: "Duplicate" } fails.
  • { _id: 3, name: "Third" } is still inserted (because the operation continued).

4. When to Use Ordered Insert

Use an ordered insert when the order of operations is critical or when you need a guaranteed state up to the point of failure.

  • Sequential Logic: When document A must exist before document B is inserted. For example, inserting parent records before child records.
  • Data Integrity Check: When you want the entire batch to fail if even a single document violates a unique constraint or schema rule, to prevent a partial, inconsistent state.
  • Transactions: When using insertMany() within a multi-document transaction, the first error will always cause the transaction to abort, regardless of the ordered setting.
