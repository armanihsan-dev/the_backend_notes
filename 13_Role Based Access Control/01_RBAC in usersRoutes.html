The Express Middleware Flow for /users

The route definition specifies the execution order, which acts as a "chain of responsibility": 

router.get('/users', checkAuth, checkRole, getAllUsers);
// 1. checkAuth (Authentication: Is the user logged in?)
// 2. checkRole (Authorization: Is the user allowed to do this?)
// 3. getAllUsers (Execution: Get the data)

1. checkAuth (Authentication)

This function's responsibility is to verify the identity of the user and retrieve their data. If this fails, the request stops immediately.

Code Explanation Response/Action
const { sid } = req.signedCookies; Get Session ID: Extracts the session ID (sid) from the signed HTTP cookies.
if (!sid) { ... } No Session ID: If the cookie is missing, the user is not authenticated. Stops, returns 401 ("Not logged!").
const session = await Session.findById(sid) Validate Session: Queries the database to ensure the sid corresponds to an active session.
if (!session) { ... } Invalid Session: If the session is not found (e.g., expired or manually logged out). Stops, returns 200 ("Logged Out!") and clears the invalid cookie.
const user = await User.findOne({ _id: session.userId }).lean() Fetch User: Uses the userId from the session to retrieve the full user object from the database.
if (!user) { ... } User Not Found: If the session is valid but the linked user account was deleted. Stops, returns 401 ("Not logged!").
req.user = user
next() 		Success and Handoff: Attaches the full, authenticated user object (including their role) to the Express request object (req.user). The next() call then passes control to the next middleware: checkRole. Continues to checkRole.

2. checkRole (Authorization - The RBAC Logic)

This function implements the core security policy, determining if the authenticated user has the necessary privileges to view the user list. 

export const checkRole = async (req, res, next) => {
    if (req.user.role !== 'User') return next()
    res.status(403).json({ error: "You can't access users." })
}
Code Explanation Response/Action
if (req.user.role !== 'User') Role Check: This is the core logic. It accesses the user object previously attached by checkAuth. It checks if the user's role is anything other than 'User'.
return next() Access Granted: If the user is an Admin, a Manager, or any role other than 'User', they are authorized. next() is called, and the request proceeds to the getAllUsers function. Continues to getAllUsers.
res.status(403).json(...) Access Denied: If the user's role is exactly 'User', they are explicitly forbidden from seeing the list. Stops, returns 403 (Forbidden).

3. getAllUsers (Route Handler)

This function only executes if and only if both checkAuth and checkRole were successful.

Code Block Purpose
const users = await User.find().select(...).lean(); Since the request has been authenticated and authorized, this line securely fetches all user records from the database, excluding sensitive fields like passwords and refresh tokens.
const usersWithStatus = await Promise.all(...) This processes the raw user data, linking it back to the Session model to determine if each individual user is currently 'Logged-In' or 'Logged-Out'.
res.status(200).json(...) The secure, enhanced list of users is returned to the client.

Summary of Role Control

The logic in checkRole creates a simple but effective hierarchy:

  • Allowed Roles (Pass): Any role except 'User' (e.g., 'Admin', 'Manager', or custom roles).
  • Denied Role (Fail): The 'User' role.

This means that only privileged accounts (Admin, Manager) are allowed to access the full list of users, while standard users are blocked with a 403 Forbidden error.
