🔥 1. What is Soft-Delete?

Soft-delete means:

  • Instead of actually deleting a record from the database, you mark it as deleted.
  • Usually by adding fields like: 
    deleted: true,
deletedAt: Date,
deletedBy: ObjectId
  • This means the data still exists in the database, but the application treats it as if it is deleted.

🎯 Why Soft-Delete Is Common in RBAC?

In systems with Role-Based Access Control (RBAC), users and permissions are sensitive.

You don't want to permanently destroy anything, because:

  • ✔ Logs & audits require historical data
    You must show that “Admin X deleted User Y at time Z”.
  • ✔ Prevent accidental deletion
    If someone deletes a user, you can recover the account later.
  • ✔ Relationships stay intact
    Deleting a user permanently might break:
    • files
    • directories
    • activity logs
    • notifications
    • references in other collections
    Soft-delete avoids all those problems.

🧠 2. Soft Delete vs Hard Delete

Feature Soft Delete Hard Delete
Record removed? ❌ No ✔ Yes
Reversible? ✔ Yes ❌ No
Safer? ✔ Yes ❌ No
DB size grows? ✔ Slightly ❌ No
Best for RBAC? ✔ Yes ❌ No

🔒 3. What Soft Delete Looks Like (Schema)

Here is a clean, scalable soft-delete structure:

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  role: String,

  deleted: { type: Boolean, default: false },
  deletedAt: { type: Date },
  deletedBy: { type: mongoose.Schema.Types.ObjectId, ref: "User" }
});

🚀 4. How To Implement Soft Delete in Express + Mongoose

4.1 Soft Delete Handler (Instead of Hard Delete) 

router.delete('/deleteuser/:userid', checkAuth, async (req, res) => {
  try {
    const { userid } = req.params;

    const user = await User.findById(userid);
    if (!user) return res.status(404).json({ message: "User not found" });

    if (user._id.toString() === req.user._id.toString()) {
      return res.status(403).json({ message: "You cannot delete yourself" });
    }

    await User.findByIdAndUpdate(
      userid,
      {
        deleted: true,
        deletedAt: new Date(),
        deletedBy: req.user._id
      }
    );

    return res.json({ message: "User soft-deleted successfully" });

  } catch (err) {
    return res.status(500).json({ error: err.message });
  }
});

🔍 5. Always Exclude Deleted Users Automatically

Instead of adding deleted: false manually every time…

⭐ Use Query Middleware (Best Practice) 

userSchema.pre(/^find/, function(next) {
  this.where({ deleted: { $ne: true } });
  next();
});

Now these queries:

  • User.find()
  • User.findById(id)
  • User.findOne()
  • User.countDocuments()

WILL AUTOMATICALLY exclude deleted users.
No need to manually filter them every time. 🔥

🔄 6. Restore User (Undo Soft Delete) 

router.patch("/restore/:userid", checkAuth, async (req, res) => {
  const { userid } = req.params;

  await User.findByIdAndUpdate(userid, {
    deleted: false,
    deletedAt: null,
    deletedBy: null
  });

  return res.json({ message: "User restored successfully" });
});

🧹 7. Optional: Auto-Hard-Delete After X Days (TTL Index)

If you want soft-deleted data to be removed from DB after (say) 30 days: 

userSchema.index(
  { deletedAt: 1 },
  { expireAfterSeconds: 30 * 24 * 60 * 60 }
);

This automatically removes soft-deleted users after 30 days.

🧱 8. Should Related Data Also Be Soft-Deleted?

In RBAC systems, yes.

Example: When deleting a user, you may want to soft-delete:

  • their files
  • directories
  • sessions
  • logs

Using:

File.updateMany({ userId }, { deleted: true, deletedAt: new Date() })

You can do this inside a transaction so it's atomic.
