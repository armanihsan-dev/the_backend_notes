Readable Streams in Node.js

A Readable Stream is an abstraction for a source from which data can be consumed. It represents data flowing from a source (like a file, an HTTP request, or a database query) to your application. Think of it as a water faucet: data flows out, and your application collects it.

Syntax and Example

The most common way to create a readable stream is from a file. You can do this using the fs module.

const fs = require('fs');
const readableStream = fs.createReadStream('./example.txt');

// Listen for data events
readableStream.on('data', (chunk) => {
  console.log('Received a chunk of data:', chunk.toString());
});

// Listen for the end event
readableStream.on('end', () => {
  console.log('All data has been read.');
});

// Listen for errors
readableStream.on('error', (err) => {
  console.error('An error occurred:', err);
});
  • fs.createReadStream(): This function creates a Readable stream for a specified file path.
  • .on('data', ...): The 'data' event is emitted whenever the stream has a chunk of data available. The event handler receives a Buffer or string object containing the data.
  • .on('end', ...): The 'end' event is emitted when there's no more data to be consumed from the stream.
  • .on('error', ...): The 'error' event is emitted if an error occurs during the reading process.

Chunk Size and highWaterMark

By default, a readable stream reads data in chunks. The default chunk size is 64 KB (65,536 bytes). This is controlled by the highWaterMark option.

The highWaterMark is the maximum number of bytes that a readable stream will buffer internally before it stops reading from the underlying resource. Once the internal buffer reaches the highWaterMark, the stream will pause until the data is consumed.

Differences between highWaterMark values:

The highWaterMark value is specified in bytes.

  • { highWaterMark: 100 }
    This sets the buffer size to 100 bytes. The stream will read data in chunks and store a maximum of 100 bytes in its internal buffer. This is a very small buffer, which could lead to more frequent 'data' events and overhead.
  • { highWaterMark: 100 * 1024 }
    This sets the buffer size to 102,400 bytes, which is 100 KB. This is a larger buffer, which will reduce the number of 'data' events and can be more efficient for larger files.
  • { highWaterMark: 100 * 1024 * 1024 }
    This sets the buffer size to 104,857,600 bytes, which is 100 MB. This is a very large buffer. While it reduces the frequency of 'data' events to a minimum, it can consume a significant amount of memory, which may not be suitable for all applications.
  • { highWaterMark: 1 * 1024 * 1024 }
    This sets the buffer size to 1,048,576 bytes, which is 1 MB. This provides a good balance between memory usage and performance for many applications.

In summary, highWaterMark allows you to control the internal buffer size of the stream. A smaller value means less memory usage but potentially more overhead from frequent 'data' events. A larger value means better throughput for large files but higher memory consumption. You should choose a value that balances these factors for your specific use case.
