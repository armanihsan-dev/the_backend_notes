🏴󠁧󠁢󠁥󠁮󠁧󠁿 Node.js Readable Streams States

Readable streams in Node.js don't have a single "state" but a combination of internal states managed by properties, methods, and events.

Readable Stream States: Definition

A readable stream can operate in one of three main modes:

  • Flowing: Data is read automatically and pushed to the consumer via the 'data' event. This is the default mode.
  • Paused: Reading is temporarily stopped. You must explicitly call stream.read() to get data chunks.
  • Closed/Destroyed: The stream is no longer functional. The underlying resources have been released, and no more data can be read.

Properties and Methods to Work with States

These tools help you interact with a readable stream's state:

  • .readable: A boolean; true if the stream is ready to be read.
  • .readableHighWaterMark: An integer for the maximum buffer size before the stream pauses.
  • .readableEnded: A boolean; true after the 'end' event.
  • .closed: A boolean; true after the 'close' event.
  • .isPaused(): A method that returns true if the stream is in a paused state.
  • .pause(): Switches the stream to paused mode.
  • .resume(): Switches the stream to flowing mode.
  • .read(): Pulls a data chunk from the buffer in paused mode.
  • .pipe(destination): Connects to a writable stream and manages states to prevent backpressure.

Important Events for Readable Stream States

Events are the primary way streams communicate state changes:

  • 'data': Emitted with a data chunk in flowing mode.
  • 'readable': Emitted when a chunk is available in the buffer, used in paused mode.
  • 'end': Emitted when all data has been read.
  • 'close': Emitted after the stream and its resources have been closed.
  • 'error': Emitted if a reading error occurs.

Example: Reading from a File Stream


const fs = require('fs');

// Create a readable stream from a file
const readableStream = fs.createReadStream('example.txt');

readableStream.on('data', (chunk) => {
  console.log(`Received a chunk of data. Size: ${chunk.length} bytes`);
});

readableStream.on('readable', () => {
    console.log('Stream is readable. Calling .read() to get a chunk.');
    let chunk;
    while (null !== (chunk = readableStream.read())) {
      console.log(`Read ${chunk.length} bytes from buffer.`);
    }
});

readableStream.on('end', () => {
  console.log('All data has been read. The stream has ended.');
});

readableStream.on('close', () => {
  console.log('The readable stream has been closed.');
});

readableStream.on('error', (err) => {
  console.error('An error occurred:', err.message);
});

console.log(`Is the stream currently readable? ${readableStream.readable}`);

setTimeout(() => {
  console.log('Pausing the stream...');
  readableStream.pause();
}, 100);

setTimeout(() => {
  console.log('Resuming the stream...');
  readableStream.resume();
}, 500);

Note on Stream States: The internal properties like readableFlowing and readableEnded are for a more detailed, internal view. The public properties and events are what you'll typically use to interact with and monitor a stream's state in your code.
