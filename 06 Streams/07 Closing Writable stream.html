1. Why ending a writable stream is important

Signals “No More Data”

  • stream.end() tells Node.js that you have finished writing data.
  • Without it, the stream will remain open and keep waiting for more chunks — which can lead to memory leaks or a process that never exits.

Flushes Remaining Data

  • Some data may still be buffered inside the stream.
  • end() ensures all buffered data is flushed to the destination (file, socket, etc.) before closing.

Triggers the finish event

  • You can listen for finish to know when all data has been written and the file/socket is safely closed.

2. How to end a writable stream

There are two ways:

(A) Write some final data and then end

import fs from 'fs';
const writeStream = fs.createWriteStream('output.txt');

writeStream.write('Hello, ');
writeStream.write('world!');

// End the stream and write a final piece of data
writeStream.end(' This is the end.', () => {
  console.log('Stream ended.');
});

writeStream.on('finish', () => {
  console.log('All writes are finished.');
});

(B) End without extra data

const writeStream = fs.createWriteStream('output.txt');

writeStream.write('First line.\n');
writeStream.write('Second line.\n');

// End without additional data
writeStream.end();

writeStream.on('finish', () => {
  console.log('Done writing!');
});
💡 Tip: If you forget to call end(), especially in file writes or network requests, your program may hang because Node.js thinks you're still sending data.
