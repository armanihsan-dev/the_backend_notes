Writable Stream States in Node.js

1. Writable State (writable.writable)

In Node.js, a Writable stream goes through a few important states during its lifecycle. You can think of these as moods the stream gets into while writing data.

Boolean indicating if the stream is still open for writing.

  • true → You can still write.
  • false → The stream is closed or destroyed.

Changes when:

  • You call .end() and it finishes writing.
  • An error occurs and the stream is destroyed.

2. writable.writableEnded

Boolean showing if .end() has been called.

It means "No more writes allowed", but it may still be flushing the last chunks.

3. writable.writableFinished

Boolean that becomes true when:

  • .end() was called.
  • All buffered writes have been flushed.
  • The finish event has been emitted.

4. writable.destroyed

true if .destroy() was called or an error caused destruction.

Once destroyed, you can’t write again.

5. Buffer/Backpressure State

These are tied to internal write buffering:

Property Meaning
writable.writableNeedDrain true if the internal buffer is full and you should wait for the "drain" event before writing again.
writable.writableCorked How many .cork() calls are active (delays flushing until .uncork() is called).
writable.writableHighWaterMark Max buffer size before backpressure kicks in.
writable.writableLength How many bytes/chunks are currently queued in the buffer.

6. Events That Reflect State Changes

  • drain → Internal buffer emptied, you can write more.
  • finish → All data flushed after .end().
  • close → Stream closed (may happen after finish or destroy).
  • error → Something went wrong.

State Flow in Practice

  1. Start: writable = true, writableEnded = false
  2. You write chunks (.write()).
  3. Buffer fills → writableNeedDrain = true.
  4. "drain" event → buffer ready for more writes.
  5. Call .end() → writableEnded = true.
  6. All buffered data flushed → "finish" event → writableFinished = true.
  7. Stream closes → writable = false.

What is cork()?

In Node.js writable streams, cork() is like telling the stream: "Hold your horses — don’t actually send the chunks right now. I’ll let you know when to flush them all at once."

What it does

Normally, when you call .write(chunk), the chunk may be processed and flushed to the underlying resource immediately. writable.cork() tells Node.js to buffer all writes in memory instead of sending them right away.

Later, when you call writable.uncork(), all buffered writes are flushed together in one batch.

Why use it?

  • Performance optimization: If you know you’ll be doing several small .write() calls in quick succession, corking them reduces the number of syscalls by batching writes.
  • This is especially useful for file or network writes, where each write has overhead.

Example:

import fs from 'fs';

const stream = fs.createWriteStream('example.txt');

// Start corking (buffer writes)
stream.cork();

stream.write('Hello ');
stream.write('world!');
stream.write('\n');

// Now flush all at once
stream.uncork();

// End the stream
stream.end();

Without corking, each .write() might trigger a separate system call. With corking, all three writes are batched and flushed together when uncork() is called.

Things to remember

  • You can cork multiple times; you’ll need to call uncork() the same number of times to actually flush (this is tracked by writable.writableCorked).
  • If you call .end() while corked, Node will automatically uncork and flush the data before closing.
  • It’s mainly an internal optimization, but you can use it manually if you know your writes will come in quick bursts.
