File Descriptors

A file descriptor is an abstract indicator used to access a file or other I/O resource, like a pipe or a network socket. It's essentially a small, non-negative integer that the operating system assigns to an opened file to identify it. When you perform an I/O operation (like reading or writing), you use this descriptor instead of the file's name.

How File Descriptors Work in Node.js

Node.js provides access to file descriptors through its built-in fs (File System) module. When you open a file using an asynchronous method like fs.open() or fs.promises.open(), the callback function or promise resolves with the file descriptor. You then use this descriptor in subsequent operations.

Example 1: Reading with Streams (Recommended)

JavaScript

import { open } from 'node:fs/promises';

async function readFileWithStream(filePath) {
  let filehandle;
  try {
    // Open file and get file descriptor wrapped in FileHandle
    filehandle = await open(filePath, 'r');
    console.log('File descriptor:', filehandle.fd);

    // Create a readable stream from the filehandle
    const readStream = filehandle.createReadStream({
      highWaterMark: 16, // read 16 bytes at a time
      start: 0, // start at byte 0
    });

    // Handle "data" events to receive chunks
    readStream.on('data', (chunk) => {
      console.log('Received chunk:', chunk.toString());
    });

    // Handle "end" event when reading is finished
    readStream.on('end', () => {
      console.log('Finished reading file.');
    });

    // Handle "error" if something goes wrong
    readStream.on('error', (err) => {
      console.error('Stream error:', err);
    });

  } catch (err) {
    console.error('An error occurred:', err);
  } finally {
    // Close filehandle (releases file descriptor)
    if (filehandle) {
      await filehandle.close();
      console.log('File closed.');
    }
  }
}

readFileWithStream('example.txt');

🔑 Key Explanations:

  • open(filePath, 'r') opens the file in read mode and returns a FileHandle with .fd.
  • filehandle.createReadStream() turns the file into a readable stream.
  • Streams are event-based → you listen for 'data', 'end', and 'error'.
  • highWaterMark controls the chunk size (e.g., 16 bytes per chunk).
  • Each chunk is a Buffer (convert with .toString() for text).
  • You should still call filehandle.close() when done to free resources.

Example 2: Reading Fixed Bytes

JavaScript

const fs = require('fs/promises');

async function readFileWithDescriptor(filePath) {
  let filehandle;
  try {
    // Open the file and get a file descriptor
    filehandle = await fs.open(filePath, 'r');
    console.log('File descriptor:', filehandle.fd);

    // Now you can use the filehandle to perform operations
    const { buffer } = await filehandle.read(Buffer.alloc(10), 0, 10, 0);
    console.log('Read 10 bytes:', buffer.toString());

  } catch (err) {
    console.error('An error occurred:', err);
  } finally {
    // Always close the file handle to release the resource
    if (filehandle) {
      await filehandle.close();
      console.log('File closed.');
    }
  }
}

readFileWithDescriptor('example.txt');

In this second example:

  • fs.open() is called with the file path and mode ('r' for read).
  • The promise resolves with a FileHandle object, which contains the file descriptor (.fd).
  • We then use this filehandle to perform a read() operation of exactly 10 bytes.
  • Finally, filehandle.close() is called to free up the resource.

Why Use File Descriptors?

Using file descriptors offers a more granular and efficient way to manage file operations, especially for complex tasks. Here are a few reasons you might choose them:

  • Concurrency: They allow multiple processes or threads to access different parts of the same file simultaneously without conflict.
  • Performance: For repeated operations on the same file, using a file descriptor is often faster than repeatedly opening and closing the file by its path.
  • Control: They give you direct control over low-level operations like reading from or writing to a specific position in a file (random access).

Is there any event that fires when a file gets opened?

There is no built-in, general-purpose event that fires automatically when any file on the system is opened. This is by design, as monitoring all file open events would be extremely inefficient and a major security and privacy concern.

However, Node.js does provide a way to listen for events on specific resources:

  • Streams: When you create a read stream for a file using fs.createReadStream(), the stream itself is an EventEmitter and will emit an 'open' event once the file has been successfully opened.

Here's an example:

JavaScript

const fs = require('fs');
const readStream = fs.createReadStream('myfile.txt');

readStream.on('open', () => {
  console.log('The file has been opened!');
  // Now you can start listening for 'data', 'end', or 'close' events
});

readStream.on('error', (err) => {
  console.error('An error occurred:', err);
});

This is the recommended approach if you need to know when a file is opened by your own application for reading. For monitoring file system activity across a directory, you would use a different approach like fs.watch().
