Node.js Streams and Child Processes

In Node.js, standard input, standard output, and standard error are three fundamental data streams that are automatically available to every running process. They're part of a system called stdio (standard input/output), a concept that originated in the Unix operating system and is now used universally.

1. Standard Input (stdin)

Standard input (stdin) is a readable stream used to take data into a program. By default, it's connected to the keyboard, allowing a user to type and send data to the process. In a more automated context, a program's stdin can be piped from the stdout of another program. In Node.js, you can access it through the global process.stdin object.

How it works: process.stdin is a readable stream that emits data events whenever input is received. You can listen for these events to read data.

Example:

process.stdin.on('data', (data) => {
  console.log(`You typed: ${data.toString()}`);
});
console.log('Please type something:');

When you run this code, it will prompt you to type, and it will echo back whatever you enter.

2. Standard Output (stdout)

Standard output (stdout) is a writable stream used to send normal data out of a program. By default, it's connected to the terminal screen, which is why when you use console.log(), the text appears there. In Node.js, you can access it through the global process.stdout object.

How it works: process.stdout is a writable stream. You can use its write() method to send data to the console or whatever destination it's connected to.

Example:

process.stdout.write('This is standard output.\n');

This is the underlying mechanism that console.log() uses, but process.stdout.write() gives you more direct control.

3. Standard Error (stderr)

Standard error (stderr) is a writable stream used to send error messages or diagnostics out of a program. Like stdout, it's also connected to the terminal screen by default. The key distinction is that stderr is kept separate from stdout so that you can filter or redirect normal output without losing important error messages. In Node.js, you access it via process.stderr.

How it works: process.stderr is a writable stream, just like stdout. You use its write() method to output error messages.

Example:

process.stderr.write('An error occurred during processing!\n');

This is the stream that console.error() writes to.

Summary: Key Differences and a Practical Analogy

Stream Type Default Destination Purpose
stdin Readable Keyboard Receiving input
stdout Writable Terminal Screen Normal program output
stderr Writable Terminal Screen Error messages and diagnostics

Think of a process as a small factory:

  • stdin is the conveyor belt that brings raw materials in.
  • stdout is the conveyor belt that sends the finished products out.
  • stderr is a separate emergency chute that sends broken parts or safety warnings out, ensuring they're not mixed with the good products.

This separation is crucial when you want to automate tasks. For example, you can redirect a program's stdout to a file to log its results, while still having stderr print to the console so you can see any errors in real-time.

Redirecting Streams in the Terminal

You can store console data directly into files using redirection operators. This is helpful for logging and debugging.

1. Redirect Only Standard Error (stderr)

Use the file descriptor 2 followed by the redirection operator >.

Overwrite the file:

command 2> error.log

(Example: ls /nonexistent_directory 2> error.log will put the error message in error.log and nothing will be displayed on the screen.)

Append to the file:

command 2>> error.log

2. Redirect Both stdout and stderr to the Same File

Use this to capture all output in a single log file.

command &> all_output.log

OR

command > all_output.log 2>&1

(The 2>&1 command redirects file descriptor 2 (stderr) to file descriptor 1 (stdout), which has already been redirected to the file.)

3. Display on Console AND Save to File

If you want to see the output live while also saving it, use the pipe operator | with the tee command.

command 2>&1 | tee error.log

(This redirects stderr to stdout first, then uses tee to read the combined stream and write it to both the screen and the file.)

What is spawn() and Child Processes in Node.js?

In Node.js, spawn() is a method from the child_process module that launches a new process to execute a given command. It's the most fundamental way to create a child process.

Key Characteristics of spawn()

  • Non-Blocking and Asynchronous: spawn() doesn't wait for the child process to finish. It returns immediately with a ChildProcess object. The main Node.js process can continue to run while the child process works in the background.
  • Streams for I/O: The primary feature of spawn() is its use of streams for input and output. The ChildProcess object it returns has stdin, stdout, and stderr streams. This allows you to send data to the child process and receive data from it in real-time, which is crucial for long-running tasks or processes that produce large amounts of data. This approach avoids buffering all the output in memory, which can be a significant advantage over other methods like exec().
  • Arguments as an Array: The command and its arguments are passed as separate strings in an array. For example, to run ls -lh /usr, you would use spawn('ls', ['-lh', '/usr']). This is safer and more secure than passing the command as a single string, as it prevents shell injection vulnerabilities.
  • Events: The ChildProcess object is an EventEmitter and emits events that allow you to manage the lifecycle of the child process. The most common events are:
    • data: Emitted on stdout and stderr streams when data is available.
    • exit: Emitted when the child process has terminated.
    • close: Emitted after the exit event and when all I/O streams have been closed.

Practical Example: Communication between Processes

Here's a practical example of communication between a parent and child process using spawn() and standard streams.

Project Structure:

parent.js
child.js

child.js


// Listen for incoming data from parent via stdin
process.stdin.on("data", (data) => {
  const message = data.toString().trim();
  console.log(`Child received: ${message}`);

  // Send a processed response back via stdout
  process.stdout.write(`Processed in child: ${message.toUpperCase()}\n`);
});

// If there's an error
process.stdin.on("error", (err) => {
  console.error(`Child stdin error: ${err}`);
});

parent.js


import { spawn } from "child_process";

const child = spawn("node", ["child.js"]);

// Listen to stdout from the child
child.stdout.on("data", (data) => {
  console.log(`Parent got from child: ${data}`);
});

// Listen to stderr from the child
child.stderr.on("data", (data) => {
  console.error(`Child error: ${data}`);
});

// Send data to the child's stdin
child.stdin.write("hello child\n");
child.stdin.write("this is parent speaking\n");

// Close stdin so child knows no more input is coming
setTimeout(() => {
  child.stdin.end();
}, 1000);

// When child exits
child.on("close", (code) => {
  console.log(`Child process exited with code ${code}`);
});

How It Works
Parent runs spawn("node", ["child.js"]).
Anything the parent writes to child.stdin is sent to the child process’s process.stdin.
The child reads it, transforms it (.toUpperCase()), and sends it back via process.stdout.
Parent listens to child.stdout and logs the response.

How to Read This

  • stdin: Parent writes to child.stdin → Child reads via process.stdin.
  • stdout: Child writes to process.stdout → Parent reads via child.stdout.
  • stderr: Child writes errors to process.stderr → Parent reads via child.stderr.

What .on("close", ...) Means

When you spawn a process in Node.js (spawn, exec, etc.), the returned ChildProcess object emits various events:

  • close: Emitted when the process has completely ended and all stdio streams (stdin, stdout, stderr) are closed.
  • exit: Emitted when the process exits, but might happen before the stdio streams are fully flushed.

Why We Use It

child.on("close", (code) => {
  console.log(`Child process exited with code ${code}`);
});

code: The exit code given by the process.

  • 0: Success / no errors.
  • Non-zero: Some error occurred.

This callback runs after:

  • The process stops running.
  • All input/output streams are done.

Difference Between exit and close

Event When Fired Streams Closed?
exit When the process stops running ❌ Not guaranteed
close When process ends and all stdio streams are closed ✅ Yes
