🔐 What are AWS S3 Signed URLs?

AWS S3 Signed URLs (also known as pre-signed URLs) are URLs that you can generate to grant temporary access to a specific S3 object (a file) to a user who does not have AWS security credentials or permissions to access it normally.

Key Concepts:

  • Temporary Access: The most important feature is the X-Amz-Expires parameter, which defines how long the URL remains valid (e.g., 1 hour, 1 day). Once the expiry time is reached, the URL will no longer work.
  • Specific Action: A signed URL is typically generated for a specific HTTP method, such as:
    • GET: To allow someone to download a private object.
    • PUT: To allow someone to upload a file directly to a specific location in your bucket (without needing your credentials).
  • Security: Access is controlled by the security credentials of the IAM user or role that generates the URL, and it is validated by the signature included in the URL.

🛠️ How are S3 Signed URLs Created?

The short answer, as demonstrated by your example code, is that S3 Signed URLs are created on your computer/server, not by sending a request to the AWS S3 server to generate them.

This process is a core part of AWS security called Signature Version 4 (SigV4).

The overall process happens entirely on your application server (or your local computer, if you run the script there) using your AWS Access Key ID and Secret Access Key. Creating our own signurl function : 

        
import crypto from "crypto";

const region = "eu-north-1";
const service = "s3";
const algorithm = "AWS4-HMAC-SHA256";

// read once
const accessKeyId = process.env.AWS_ACCESS_KEY_ID;
const secretAccessKey = process.env.AWS_SECRET_ACCESS_KEY;

if (!accessKeyId || !secretAccessKey) {
  throw new Error("AWS credentials are missing in environment variables");
}

export function getSignedS3Url({
  method = "GET",
  bucketName,
  objectKey,
  expiresInSeconds = 3600,
}) {
  const now = new Date();
  const amzDate = now.toISOString().replace(/[:-]|\.\d{3}/g, "");
  const dateStamp = amzDate.slice(0, 8);

  const credentialScope = `${dateStamp}/${region}/${service}/aws4_request`;
  const host = `${bucketName}.s3.${region}.amazonaws.com`;
  const canonicalUri = `/${encodeURIComponent(objectKey)}`;

  const queryParams = {
    "X-Amz-Algorithm": algorithm,
    "X-Amz-Credential": `${accessKeyId}/${credentialScope}`,
    "X-Amz-Date": amzDate,
    "X-Amz-Expires": expiresInSeconds,
    "X-Amz-SignedHeaders": "host",
  };

  const canonicalQueryString = Object.keys(queryParams)
    .sort()
    .map(
      key =>
        `${encodeURIComponent(key)}=${encodeURIComponent(queryParams[key])}`
    )
    .join("&");

  const canonicalHeaders = `host:${host}\n`;
  const signedHeaders = "host";
  const payloadHash = "UNSIGNED-PAYLOAD";

  const canonicalRequest = [
    method,
    canonicalUri,
    canonicalQueryString,
    canonicalHeaders,
    signedHeaders,
    payloadHash,
  ].join("\n");

  const hashedCanonicalRequest = crypto
    .createHash("sha256")
    .update(canonicalRequest)
    .digest("hex");

  const stringToSign = [
    algorithm,
    amzDate,
    credentialScope,
    hashedCanonicalRequest,
  ].join("\n");

  const hmac = (key, data) =>
    crypto.createHmac("sha256", key).update(data).digest();

  const signingKey = hmac(
    hmac(
      hmac(
        hmac("AWS4" + secretAccessKey, dateStamp),
        region
      ),
      service
    ),
    "aws4_request"
  );

  const signature = crypto
    .createHmac("sha256", signingKey)
    .update(stringToSign)
    .digest("hex");

  return `https://${host}${canonicalUri}?${canonicalQueryString}&X-Amz-Signature=${signature}`;
}


Example usage

const url = getSignedS3Url({
    bucketName: "storifyy-prod-user-uploads",
    objectKey: "fancy.jpg",
});


//uploading signed-url
const upload_url = getSignedS3Url({
    bucketName: "storifyy-prod-user-uploads",
    objectKey: "rohee.jpg",
    method: "PUT"
});

console.log(upload_url);

Step-by-Step Breakdown (Based on Your Code Example):

Your JavaScript code follows the exact steps of the AWS Signature Version 4 signing process for a URL request:

Step Code Section Description
1. Create the Canonical Request canonicalRequest This is a standardized string that contains all the essential parts of the request (HTTP method, URI, query parameters, headers, and payload hash).
2. Create the String to Sign stringToSign This string combines the algorithm (AWS4-HMAC-SHA256), the timestamp, the credential scope (the region, service, and date), and a hash of the Canonical Request.
3. Calculate the Signing Key signingKey This is a complex, chained HMAC-SHA256 process that uses your Secret Access Key along with the date, region, and service to create a unique temporary key. This is the most secure step as it incorporates your secret.
4. Calculate the Signature signature The final signature is calculated by taking the String to Sign and signing it with the Signing Key using HMAC-SHA256.
5. Construct the Final URL The return statement The final URL is constructed by taking the original S3 endpoint, all the query parameters (including X-Amz-Algorithm, X-Amz-Date, X-Amz-Expires, etc.), and appending the final Signature as the X-Amz-Signature query parameter.

Conclusion on Creation

When a user tries to access the generated signed URL, the S3 server receives the request and performs the exact same calculation using the X-Amz-Date, X-Amz-Credential, and other parameters.

  • If the signature the S3 server calculates matches the X-Amz-Signature provided in the URL, and the expiration time has not passed, S3 grants the access (downloads the file or allows the upload).
  • If the signatures don't match, or if the URL has expired, the request is denied with an Access Denied error.

This decentralized creation method means your application can generate signed URLs very quickly without waiting for a network round-trip to the AWS server.
