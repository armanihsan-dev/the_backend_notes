Node.js Connection Management: res.header('Connection', 'close') and req.destroy()

The two commands mentioned, res.header('Connection', 'close') and req.destroy(), serve similar, but **distinct**, purposes in controlling the lifespan of a connection, especially when you need to **abruptly terminate a request**.

1. res.header('Connection', 'close')

This is a **response header** set by the server to instruct the **client** (browser, API caller, etc.) how to handle the underlying TCP connection **after** the current HTTP response has been fully delivered.

How It Works:

  • Mechanism: It sets the Connection header in the HTTP response to the value close.
  • Result: When the client receives this header, it knows that the server intends to close the TCP connection immediately after sending the last byte of the response body.
  • Context: This is mainly relevant for **HTTP/1.1 connections**. By default, HTTP/1.1 uses persistent connections (or Keep-Alive), allowing multiple requests/responses to share the same TCP connection for efficiency. Setting Connection: close tells the client to **not reuse** the connection for subsequent requests.

When to Use It:

  • When you are sending a complete response but want to guarantee the TCP socket is closed afterwards, preventing connection reuse.
  • When a non-critical error or planned shutdown occurs, and you want to clean up resources cleanly on the server and client side.

2. req.destroy()

This is a **Node.js method** available on the http.IncomingMessage object (req) and is used to **immediately terminate the underlying socket connection** from the server side.

How It Works:

  • Mechanism: It directly calls the destroy() method on the associated TCP socket.
  • Result: The connection is **forcibly closed** without waiting for any response to be sent or any remaining request data to be processed. This often results in a socket/connection error on the client side (e.g., ECONNRESET).
  • Context: It's a low-level, immediate termination. It's often used when an error or condition is encountered during the request processing that makes it **impossible or undesirable to continue** (e.g., a file upload is too large, the client is unauthorized, or a timeout occurs).

When to Use It:

  • To **stop a connection immediately** before the request body is even fully received (crucial for stopping large uploads like in your example).
  • When a fatal error occurs and you cannot send a proper HTTP response.

Real-World Example: Stopping Large File Uploads

Your scenario—stopping a connection if a file size is greater than 50MB—is a perfect use case for **combining** res.header('Connection', 'close') and req.destroy() within a file upload handler. Since the file data arrives in chunks (an **incoming stream**), we can listen for the chunks and check the size as they arrive.

Node.js Example (using the built-in http module):

This example simulates a server that accepts an incoming file stream and checks the content length against a limit. 

const http = require('http');
const MAX_FILE_SIZE_MB = 50;
// Convert MB to bytes
const MAX_FILE_SIZE_BYTES = MAX_FILE_SIZE_MB * 1024 * 1024;

const server = http.createServer((req, res) => {
    // Only apply logic to POST requests that might contain a file
    if (req.method === 'POST') {
        let uploadedSize = 0;
        let connectionDestroyed = false;

        // --- Core Logic: Check size as data arrives ---
        req.on('data', (chunk) => {
            if (connectionDestroyed) {
                // If we've already destroyed the request, ignore incoming data
                return;
            }

            uploadedSize += chunk.length;

            if (uploadedSize > MAX_FILE_SIZE_BYTES) {
                console.log(`[ALERT] Upload exceeded limit: ${uploadedSize} bytes. Terminating.`);
                
                // 1. Send a small, non-standard response with a 'Connection: close' header
                //    This *may* help the client understand why the connection is closing, 
                //    but it might not be delivered if the destroy is too fast.
                res.writeHead(413, { 
                    'Content-Type': 'text/plain',
                    'Connection': 'close' // <-- Instructs the client to close the connection after this response
                });
                res.end(`File size exceeds the ${MAX_FILE_SIZE_MB}MB limit.`);

                // 2. Immediately destroy the request/socket
                //    This is the most critical step to stop receiving more data and free up resources.
                req.destroy(); // <-- Abruptly closes the underlying TCP socket

                connectionDestroyed = true;
            }
        });

        // --- Handle End of Upload (Success) ---
        req.on('end', () => {
            if (!connectionDestroyed) {
                // Only send success if the connection was not terminated mid-stream
                console.log(`[SUCCESS] File uploaded successfully. Size: ${uploadedSize} bytes.`);
                res.writeHead(200, { 'Content-Type': 'text/plain' });
                res.end('File uploaded successfully.');
            }
        });

        // --- Handle Connection Errors ---
        req.on('error', (err) => {
            // Handle errors like client abruptly closing the connection
            console.error('Request error:', err.message);
        });

    } else {
        res.writeHead(200, { 'Content-Type': 'text/plain' });
        res.end('Send a POST request to upload a file.');
    }
});

const PORT = 3000;
server.listen(PORT, () => {
    console.log(`Server running on http://localhost:${PORT}`);
});

Explanation of the Solution:

  • Limit Definition: We define MAX_FILE_SIZE_BYTES.
  • req.on('data', ...): We listen for the data chunks coming from the client. The req object (the incoming stream) emits a 'data' event for every chunk received.
  • Size Check: Inside the 'data' listener, we increment uploadedSize and check if it exceeds the limit.
  • Termination Logic:
    • res.writeHead(413, {..., 'Connection': 'close'}): We attempt to send a brief response with status **413 Request Entity Too Large** and the Connection: close header.
    • res.end(...): We send the error message body.
    • req.destroy(): **This is the critical step.** It stops the network flow immediately. The server ceases to read the rest of the stream, saving bandwidth and memory. The client will likely get a socket error instead of the 413 response, but the goal of stopping the upload is achieved.

Frontend Prevention (ReactJS Example)

The best practice is to **prevent the upload entirely** on the frontend before sending any data, which saves the server resources completely.

✅ Step 1: Calculate 50MB in bytes

Browsers give file sizes in bytes, so:

1MB = 1024 * 1024 bytes
50MB = 50 * 1024 * 1024 bytes

So:

const MAX_FILE_SIZE = 50 * 1024 * 1024; // 50MB

✅ Step 2: Add the size check inside handleFileChange

Add this before uploading:

async function handleFileChange(e) {
  const files = e.target.files;
  if (!files || files.length === 0) return;

  const MAX_FILE_SIZE = 50 * 1024 * 1024; // 50MB

  for (let file of files) {
    if (file.size > MAX_FILE_SIZE) {
      toast.error(`${file.name} is larger than 50MB`);
      continue; // skip this file
    }

    await uploadSingleFile(file);
  }

  setShouldRefresh(true);
}
