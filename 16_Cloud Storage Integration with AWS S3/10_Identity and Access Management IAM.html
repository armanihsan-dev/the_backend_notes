🔒 What is AWS IAM?

AWS Identity and Access Management (IAM) is a web service that helps you securely control access to AWS resources.

IAM allows you to manage who is authenticated (signed in) and authorized (has permissions) to use resources. Think of it as the gatekeeper and the permission manager for your entire AWS account.

🏗️ Key Building Blocks of IAM

IAM uses four primary components to manage access:

  1. Users

    What they are: An entity in IAM that represents the person or service that interacts with AWS.

    How they authenticate: They can have a password for the AWS Management Console and/or access keys (an access key ID and a secret access key) for programmatic access (CLI, SDKs).

  2. Groups

    What they are: A collection of IAM users. Groups are a convenient way to specify permissions for multiple users at once.

    Key point: Groups can only contain users; they cannot contain other groups. A user can belong to multiple groups.

  3. Policies

    What they are: Documents that formally define the permissions and are attached to a User, Group, or Role.

    Structure: They are written in JSON (JavaScript Object Notation).

    The core components of a policy statement:

    • Effect: Either Allow or Deny.
    • Action: The specific AWS service API calls (e.g., s3:GetObject, ec2:RunInstances).
    • Resource: The specific AWS resources the action can be performed on (e.g., a specific S3 bucket or EC2 instance).

  4. Roles

    What they are: An IAM identity that you can create with specific permission policies. They are designed to be assumed by trusted entities (like an AWS service, an application, or another AWS account) who need temporary access.

    Key difference from Users: Roles do not have standard long-term credentials (password or access keys) associated with them. The entity that assumes the role receives temporary security credentials.

🎯 What You Can Do with IAM

Capability Description
Manage Access Create and manage IAM users, groups, and roles to grant access to your AWS account and resources.
Fine-Grained Control Control who can do what with which AWS resource (e.g., allow a developer to only read files from one specific S3 bucket).
Shared Access Grant other AWS accounts or users access to your resources without sharing your security credentials.
Authentication Provide different authentication mechanisms (password, access keys, multi-factor authentication (MFA)).
Federation Integrate with corporate directories (like Active Directory) so employees can use their existing credentials to access AWS.

🔑 Why IAM is Important

IAM is critical for security and compliance for several key reasons:

  • Security: It enforces the Principle of Least Privilege (PoLP), meaning a user, application, or service should only be granted the minimum permissions necessary to perform its job. This drastically limits the damage a compromised or malicious entity can do.
  • Auditability: IAM integrates with AWS CloudTrail, allowing you to track and log every action taken by an IAM entity, which is vital for security auditing and compliance.
  • Cost Management: By limiting access, you prevent accidental or unauthorized changes (like deleting a core database or creating expensive resources), which helps manage costs.

💻 Creating IAM Users from the AWS CLI

The AWS Command Line Interface (CLI) is a powerful tool for interacting with AWS services. Here's how you can create an IAM user, add them to a group, and generate their access keys.

Prerequisites

  • You must have the AWS CLI installed on your machine.
  • You must have your own administrator or power user credentials configured for the CLI.

Step 1: Create the IAM User

Use the create-user command. It's best practice to give the user a meaningful name.

Syntax Example
aws iam create-user --user-name <username> aws iam create-user --user-name john.doe

Step 2: Create a Group and Attach a Policy (Optional but Recommended)

Instead of attaching policies directly to the user, it is a best practice to use Groups.

A. Create the Group (e.g., DevTeam)

Syntax Example
aws iam create-group --group-name <groupname> aws iam create-group --group-name DevTeam

B. Attach a Policy to the Group (e.g., AmazonS3ReadOnlyAccess)

Syntax Example
aws iam attach-group-policy --group-name <groupname> --policy-arn <policy-arn> aws iam attach-group-policy --group-name DevTeam --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess

Note: Managed policies like AmazonS3ReadOnlyAccess have a predefined Amazon Resource Name (ARN).

C. Add the User to the Group

Syntax Example
aws iam add-user-to-group --user-name <username> --group-name <groupname> aws iam add-user-to-group --user-name john.doe --group-name DevTeam

Step 3: Create Access Keys for Programmatic Access

This step is necessary if the user needs to interact with AWS using the CLI, SDKs, or API.

Syntax Example
aws iam create-access-key --user-name <username> aws iam create-access-key --user-name john.doe

Output of Step 3:


{
    "AccessKey": {
        "UserName": "john.doe",
        "Status": "Active",
        "CreateDate": "2025-12-14T18:47:07Z",
        "SecretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
        "AccessKeyId": "AKIAIOSFODNN7EXAMPLE"
    }
}

CRITICAL: The SecretAccessKey is only displayed once. You must securely store and share these credentials with the user, as they cannot be retrieved again!

Step 4: Create a Login Profile (for Console Access)

If the user needs to sign in to the AWS Management Console, you must set a password.

Syntax Example
aws iam create-login-profile --user-name <username> --password <password> --password-reset-required aws iam create-login-profile --user-name john.doe --password P@sswOrd1234 --password-reset-required

Note: The --password-reset-required flag forces the user to choose a new password on their first login, which is a good security practice.

Creating a Custom JSON Policy for S3 Read Access

The following details the process of creating a custom JSON policy that grants permission to only read files from one specific S3 bucket.

📄 Custom IAM Policy for S3 Read-Only Access

The goal of this policy is to allow the IAM entity (User, Group, or Role) to perform two actions:

  1. List the objects inside a specific bucket.
  2. Retrieve (read) the data of objects inside that bucket.

1. The JSON Policy Document

This document, often saved as s3-read-policy.json, defines the precise permissions. 


{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowListBucket",
            "Effect": "Allow",
            "Action": [
                "s3:ListBucket"
            ],
            "Resource": "arn:aws:s3:::my-unique-data-bucket"
        },
        {
            "Sid": "AllowGetObject",
            "Effect": "Allow",
            "Action": [
                "s3:GetObject"
            ],
            "Resource": "arn:aws:s3:::my-unique-data-bucket/*"
        }
    ]
}

Breakdown of the Policy

Key Component Value Explanation
Version "2012-10-17" The standard version for all IAM policies.
Statement [] A list of individual permission statements.
Sid "AllowListBucket" A unique identifier for the statement (optional, but helpful for logging/auditing).
Effect "Allow" The action is permitted (the opposite is "Deny").
Action "s3:ListBucket" The permission to view the list of objects in the bucket. This action must be applied to the bucket ARN.
Resource arn:aws:s3:::my-unique-data-bucket Specifies the resource this action applies to: the S3 bucket itself.
Action "s3:GetObject" The permission to download (read) the contents of an object. This action must be applied to the objects inside the bucket.
Resource arn:aws:s3:::my-unique-data-bucket/* Specifies the resources this action applies to: all objects (/*) within the bucket.

🛠️ Step-by-Step CLI Execution

Once you have your JSON file (s3-read-policy.json) ready, you can create and attach the policy using the AWS CLI. We will assume you already have an IAM Group named S3Readers.

Step 1: Create the Custom Policy

You use the create-policy command and reference your JSON file.

CLI Command Explanation
aws iam create-policy --policy-name S3BucketReadPolicy --policy-document file://s3-read-policy.json Creates the policy in IAM and names it S3BucketReadPolicy.

Successful Output:

This command returns the newly created policy's ARN, which you will need for the next step. 


{
    "Policy": {
        "PolicyName": "S3BucketReadPolicy",
        "PolicyId": "ANPAI...EXAMPLE",
        "Arn": "arn:aws:iam::123456789012:policy/S3BucketReadPolicy",
        "CreateDate": "2025-12-14T19:00:00Z",
        "IsAttachable": true
    }
}

Step 2: Attach the Policy to an IAM Group

Now, attach the newly created policy to the group that contains the users who need this access (e.g., S3Readers).

CLI Command Explanation
aws iam attach-group-policy --group-name S3Readers --policy-arn arn:aws:iam::123456789012:policy/S3BucketReadPolicy Attaches the policy to the S3Readers group.

Result

Every user in the S3Readers group is now authorized to list the contents and download files from my-unique-data-bucket, and nothing else (they cannot write, delete, or access any other bucket).
