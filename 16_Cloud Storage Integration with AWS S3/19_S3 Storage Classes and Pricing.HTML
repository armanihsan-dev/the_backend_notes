AWS S3 Storage Classes: The Real Meaning

PART 1 — What S3 actually is (real meaning)

Amazon S3 = Simple Storage Service

At the core, S3 is just:

  • A place to store objects (files)
  • + rules about how often you access them

Every S3 storage class answers ONE question:

❓ How often will I read this file again?

That’s it.

PART 2 — The BIG IDEA behind S3 pricing (this is critical)

AWS pricing is not random.

It’s a trade-off between:

Factor Meaning
💾 Storage cost How much you pay per GB per month
📤 Retrieval cost How much you pay to read/download
⏳ Access speed How fast you get the file
🔒 Durability Chance of data loss (almost always same)

👉 Cheaper storage = more restrictions

PART 3 — The main S3 storage classes (you MUST know these)

We’ll go one by one, slowly.

1️⃣ S3 Standard (default)

What it is:

  • Hot storage
  • Files accessed frequently

Examples:

  • Website images
  • App uploads
  • User profile pictures
  • Logs used daily

Pricing logic:

Thing Cost
Storage 💰 Higher
Retrieval ❌ Free
Minimum storage ❌ None

Mental model: “I might need this file anytime.”

2️⃣ S3 Intelligent-Tiering (smart but misunderstood)

What it is:

  • AWS automatically moves files based on access
  • You don’t decide → AWS decides

Important truth:

AWS does NOT guess your future.

It reacts after 30 days of no access.

Pricing logic:

Thing Cost
Storage Slightly higher than Standard
Retrieval ❌ Free
Monitoring fee 💰 Small extra

When to use:

  • You don’t know access pattern
  • Mixed hot & cold data

When NOT to use:

  • Very small files (monitoring cost hurts)
  • Predictable workloads

3️⃣ S3 Standard-IA (Infrequent Access)

What it is:

  • Files you rarely read
  • But when you do → need fast access

Examples:

  • Monthly reports
  • Old invoices
  • User uploads not often opened

Pricing logic:

Thing Cost
Storage 💸 Cheaper
Retrieval 💰 Paid
Min storage ⏱ 30 days

Key rule: If you delete before 30 days → AWS still charges 30 days

4️⃣ S3 One Zone-IA (cheap but risky)

Difference from Standard-IA:

Stored in one AZ, not three

Trade-off:

Gain Loss
Cheaper Less availability

Use only if:

  • Data can be re-created
  • Non-critical backups

5️⃣ Glacier (this is ARCHIVE, not storage)

People misunderstand Glacier a LOT.

5️⃣ a) Glacier Instant Retrieval

  • Archive data
  • Still millisecond access
Storage Very cheap
Retrieval More expensive
Min storage 90 days

5️⃣ b) Glacier Flexible Retrieval

  • Old backups
  • Retrieval time: Minutes → hours
Storage Cheaper
Retrieval Expensive
Min storage 90 days

5️⃣ c) Glacier Deep Archive (cheapest ever)

What it means: “I hope I never need this.”

Storage 🪙 Dirt cheap
Retrieval 🧨 Very expensive
Access time 12–48 hours
Min storage 180 days

Examples:

  • Legal archives
  • Compliance data
  • Old backups

PART 4 — The PRICING FORMULA (this applies to ALL classes)

Every S3 bill is calculated like this:

Total Bill =
(Storage GB × Price per GB × Time)
+ Retrieval costs
+ Requests (PUT/GET)

Storage is charged how?

AWS uses:

Average GB stored per day × days in month

Example:

Store 100 GB for 30 days

100 × price × 30/30 = full month charge

Delete after 10 days?

100 × price × 30/30   ❌

👉 Minimum storage duration still applies.

PART 5 — Why AWS pricing feels evil (truth)

Because:

  • Units change (GB vs TB)
  • Tiers exist
  • Minimum durations exist
  • Retrieval is separate
  • Requests are separate

AWS optimizes for enterprise scale, not beginners.

PART 6 — Simple decision table (save this)

Your data Use this
Accessed daily Standard
Unpredictable Intelligent-Tiering
Rarely accessed Standard-IA
Re-creatable One Zone-IA
Archive, maybe needed Glacier Instant
Long-term archive Glacier Deep Archive

PART 7 — Coach advice (important)

Don’t memorize prices.

Instead:

  • Ask how often accessed
  • Ask how fast needed
  • Ask can I lose it
  • Ask minimum duration

Pricing will make sense automatically.
