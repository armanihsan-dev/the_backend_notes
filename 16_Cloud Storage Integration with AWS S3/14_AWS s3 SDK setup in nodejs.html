AWS S3 SDK for Node.js (v3) Deep Dive

💻 Setup and Configuration (AWS SDK v3)

The AWS SDK for JavaScript v3 uses a modular approach, where you only install the client for the service you need (e.g., S3).

Step 1: Initialize Project and Install Dependencies

Initialize your Node.js project:

npm init -y

Install the S3 Client package: The modern package for S3 operations is @aws-sdk/client-s3. 

npm install @aws-sdk/client-s3

Step 2: Configure AWS Credentials

The SDK automatically looks for credentials in several places, but the most common and recommended ways for a Node.js application are:

Shared Credentials File (Recommended for local development):

Create a file at ~/.aws/credentials (or %USERPROFILE%\.aws\credentials on Windows) and add your access keys: 

[default]
aws_access_key_id = YOUR_ACCESS_KEY_ID
aws_secret_access_key = YOUR_SECRET_ACCESS_KEY

Environment Variables (Recommended for CI/CD and certain deployments):

Set the following environment variables:

export AWS_ACCESS_KEY_ID=YOUR_ACCESS_KEY_ID
export AWS_SECRET_ACCESS_KEY=YOUR_SECRET_ACCESS_KEY
export AWS_REGION=your-region-code (e.g., us-east-1)

Step 3: Instantiate the S3 Client

In your Node.js code, you import the client and instantiate it. If you have your credentials configured via the methods above, the SDK will automatically load them. 

import { S3Client } from "@aws-sdk/client-s3";

// Create an S3 client instance.
// If you don't pass configuration, it will automatically look for
// credentials and region in environment variables or the shared config file.
const s3Client = new S3Client({
  // You can optionally specify the region here if not using environment variables:
  // region: "us-west-2",
});

📝 Basic Example: Listing S3 Buckets

To perform an action like listing buckets, you need to import the specific Command for that action, create an instance of the command, and pass it to the client's send() method. This modern approach uses Promises and async/await.

listBuckets.js Example

// listBuckets.js (Using modern ESM syntax with 'type': 'module' in package.json)
import { S3Client, ListBucketsCommand } from "@aws-sdk/client-s3";

// Initialize the S3 client (loads credentials/region from environment or shared config)
const s3Client = new S3Client({});

/**
 * Lists all S3 buckets in the AWS account.
 */
async function listAllBuckets() {
  try {
    // 1. Create the command object (no parameters needed for ListBuckets)
    const command = new ListBucketsCommand({});

    // 2. Send the command to the S3 client
    const data = await s3Client.send(command);

    // 3. Process the response
    if (data.Buckets) {
      console.log("✅ Successfully retrieved the list of S3 buckets:");
      data.Buckets.forEach((bucket) => {
        console.log(`- ${bucket.Name} (Created: ${bucket.CreationDate.toLocaleDateString()})`);
      });
    } else {
      console.log("No buckets found.");
    }

  } catch (error) {
    console.error("❌ Error listing buckets:", error);
  }
}

listAllBuckets();

To Run the Example:

  • Ensure you have completed **Steps 1 and 2** (project initialization, package installation, and credentials configured).
  • Save the code above as listBuckets.js.
  • Add "type": "module" to your package.json file to enable the import syntax.
  • Run the script: 
    node listBuckets.js

🔑 Understanding AWS Credentials File Profiles

AWS profiles are a mechanism to organize and manage multiple sets of credentials and configuration settings for different AWS users, roles, or accounts on your local machine. They are stored in two plaintext files located in the ~/.aws/ directory (or %USERPROFILE%\.aws\ on Windows):

  • ~/.aws/credentials: Stores the **long-term credentials** (Access Key ID and Secret Access Key).
    • Profile names here are enclosed in brackets, e.g., [my-dev-user]. The default profile is named [default].
    • **Crucially, it does NOT use the profile prefix** in the section name (e.g., [my-dev-user], not [profile my-dev-user]).
  • ~/.aws/config: Stores **configuration settings** like the default region, output format, and complex settings like **role assumption** (IAM Roles via source_profile).
    • Named profiles here must use the profile prefix, e.g., [profile my-dev-user]. The default profile is named [default].

The [default] Profile

By default, any AWS tool (CLI or SDK) will look for a profile named [default]. This is the core profile unless you explicitly specify another one.

🛠️ How to Create a Second Profile

You can create additional profiles either manually by editing the files or using the AWS Command Line Interface (CLI).

Option 1: Using the AWS CLI (aws configure)

This is the recommended and easiest method, as the CLI manages both the config and credentials files for you.

Run the command with the --profile flag:

aws configure --profile my-second-profile

You will be prompted to enter the details for this new profile:

AWS Access Key ID [None]: AKIAIOSFODNN7EXAMPLE
AWS Secret Access Key [None]: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
Default region name [None]: us-west-2
Default output format [None]: json

This will automatically update both files.

Option 2: Manually Editing the Files

You must ensure the profile name matches in both files (with the required prefix difference).

Edit ~/.aws/credentials:

[default]
aws_access_key_id = AKIA-DEFAULT-KEY
aws_secret_access_key = DEFAULT_SECRET_KEY

[my-second-profile]  <-- NO 'profile' prefix here
aws_access_key_id = AKIA-SECOND-KEY
aws_secret_access_key = SECOND_SECRET_KEY

Edit ~/.aws/config:

[default]
region = us-east-1
output = json

[profile my-second-profile] <-- MUST have 'profile' prefix here
region = us-west-2

⚙️ Using the Named Profile in Node.js (AWS SDK v3)

The AWS SDK for JavaScript v3 makes using a named profile very straightforward by passing the profile name in the client's constructor configuration object.

Clear Node.js Syntax Example

You can pass the profile name to the S3Client constructor (or any other AWS client). 

// import the S3 Client and Command from the modular package
import { S3Client, ListBucketsCommand } from "@aws-sdk/client-s3";

// The name of the profile you want to use from ~/.aws/credentials and ~/.aws/config
const PROFILE_NAME = "my-second-profile";

// Initialize the S3 client with the specific profile
const s3Client = new S3Client({
  // Pass the name of the profile you want the SDK to load
  profile: PROFILE_NAME, 
  // You can also explicitly set the region if you want to override the config file:
  // region: "eu-central-1", 
});

/**
 * Lists S3 buckets using the specified profile's credentials/config.
 */
async function listBucketsWithProfile() {
  try {
    const data = await s3Client.send(new ListBucketsCommand({}));

    console.log(`✅ Successfully listed buckets using the '${PROFILE_NAME}' profile.`);
    data.Buckets.forEach((bucket) => {
      console.log(`- ${bucket.Name}`);
    });
  } catch (error) {
    console.error(`❌ Error listing buckets with profile '${PROFILE_NAME}':`, error.message);
  }
}

listBucketsWithProfile();
