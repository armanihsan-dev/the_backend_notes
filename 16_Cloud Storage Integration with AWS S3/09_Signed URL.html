🔑 What is an S3 Signed URL?

A **Signed URL** (or **Pre-Signed URL**) is a standard HTTP URL that is temporarily granted permission to access a private Amazon S3 object.

Instead of requiring the user to have permanent AWS credentials (like an IAM user), the URL itself contains all the authentication information needed for a temporary, specific action.

What a Signed URL Allows

A Signed URL allows anyone who possesses it to perform a specific S3 operation on a specified object for a limited time, without needing your permanent AWS security credentials.

  • **Temporary Access:** The URL has a built-in expiration timestamp, after which it is no longer valid.
  • **Specific Action:** It authorizes a single type of action, such as:
    • **GET** (Download/Read): To retrieve an object. (Most common)
    • **PUT** (Upload): To upload a new object or replace an existing one.
    • **DELETE**: To delete an object.
  • **Security:** It keeps your S3 bucket and objects **private** by default, only granting temporary access for the one file.

🗓️ When to Use Signed URLs

You use Signed URLs anytime you need to grant **temporary, limited access** to a private S3 object to a third party (like a web browser user) who does not have or should not have permanent AWS credentials.

Use Case Operation
Secure Downloads You have a private file (e.g., a software installer, a confidential report, or a paid e-book) that you only want authenticated users of your application to download for a short time.
Direct User Uploads You want to allow a user on your website (e.g., uploading a profile picture or a document) to upload a file directly to your private S3 bucket without routing the large file through your own application server first.
Controlled Access You want to prevent a download link from being shared indefinitely or indexed by search engines.

⚙️ Key Properties of a GET Signed URL

A GET Signed URL is specifically for **retrieving** an object. Its key properties are embedded as query parameters in the URL:

Property Description
Object and Bucket Specifies the exact S3 bucket and object key (file path) being requested.
X-Amz-Algorithm The signing algorithm used (usually AWS4-HMAC-SHA256).
X-Amz-Credential The AWS Access Key ID used to create the signature, along with the scope (date, region, service). The **Secret Access Key is never included**.
X-Amz-Date The timestamp when the URL was generated.
X-Amz-Expires The duration (in seconds) the URL is valid, starting from the X-Amz-Date. The **default is 3600 seconds (1 hour)** for the AWS CLI.
X-Amz-Signature The cryptographic hash (signature) generated using the signing credentials, the request details, and the expiry time. This proves the URL's authenticity.

🔬 Components of a Signed URL

A signed URL is a standard S3 endpoint URL with additional query parameters for authentication, which is based on the **AWS Signature Version 4 (SigV4)** signing process.

An example structure of a Signed URL looks like this:

https://<bucket-name>.s3.<region>.amazonaws.com/<object-key>?
X-Amz-Algorithm=AWS4-HMAC-SHA256
&X-Amz-Credential=<AccessKeyID>%2F<Date>%2F<Region>%2Fs3%2Faws4_request
&X-Amz-Date=<Timestamp>
&X-Amz-Expires=<Seconds>
&X-Amz-SignedHeaders=host
&X-Amz-Signature=<CryptographicSignature>

The components are:

  • **Base S3 URL:** https://<bucket-name>.s3.<region>.amazonaws.com/<object-key>
    • Identifies the target object's location.
  • **Query Parameters (Authentication Data):** These are the key properties listed above, which replace the need for an Authorization HTTP header. The most critical are:
    • X-Amz-Expires: The validity window.
    • X-Amz-Signature: The proof of authenticity, generated using a hash of the request details (bucket, object, date, expiry, HTTP method) and the **Secret Access Key** of the user/role generating the URL (which is **never** included in the URL itself).

💻 How to Generate a GET Signed URL using AWS CLI

You can easily generate a GET Signed URL using the aws s3 presign command.

Prerequisites

  • AWS CLI installed and configured.
  • Your configured AWS credentials must have the s3:GetObject permission for the specified bucket and object.

Command Syntax

Use the aws s3 presign command, specifying the S3 URI (s3://<bucket-name>/<object-key>) and the desired expiration time in seconds.

Example: Default 1-Hour Expiration

The default expiration is 3600 seconds (1 hour). 

aws s3 presign s3://my-private-bucket-001/documents/my-secret-file.pdf

Example: Custom 5-Minute Expiration

You can use the --expires-in flag for a custom duration (e.g., 300 seconds for 5 minutes). 

aws s3 presign s3://my-private-bucket-001/images/temporary-image.jpg --expires-in 300

The output will be the complete, signed URL string.

✅ What AWS Checks When You Use the URL

When a user tries to access the Signed URL, Amazon S3 performs several critical checks:

  1. Signature Validation:

    S3 takes the parameters embedded in the URL (Access Key ID, date, object key, expiry, etc.) and attempts to re-create the signature (X-Amz-Signature) using the **Secret Access Key** associated with the provided X-Amz-Credential.

    Result: If the generated signature matches the signature in the URL, S3 knows the URL is authentic and has not been tampered with. If it doesn't match, access is denied (403 Forbidden).

  2. Expiration Check:

    S3 checks the X-Amz-Date and X-Amz-Expires to ensure the current time is within the specified validity window.

    Result: If the URL has expired, access is denied (403 Forbidden).

  3. Signer's Permissions:

    S3 checks the permissions of the IAM user or role whose credentials were used to generate the URL. This check is performed **at the time of the request**.

    **Crucial Point:** If the signing user's s3:GetObject permission is **revoked** *after* the URL was generated, the URL becomes invalid immediately, even if the expiration time has not passed.

This multi-layered validation ensures that the URL is legitimate, temporary, and that the signing authority still has the required permissions.
